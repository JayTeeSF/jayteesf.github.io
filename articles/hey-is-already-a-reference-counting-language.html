Hey language · runtime design note · 12 August 2026

Hey Is Already a Reference-Counting Language

The plan to stop copying memory is not to design reference counting. Most of it is built, and some of it has been shipping for weeks. What remains is one missing value kind, one switched-off flag, and a blocker that costs a single environment variable to test.

Proposal — nothing here is implemented

TL;DR

  • Four of seven heap value kinds already reference-count and ship default-on. Bytes, callables, and I/O handles bump a counter on copy rather than duplicating anything.
  • Two more are complete behind a default-off flag. Objects and arrays have copy-on-write, falsification hooks, an A/B gate and sanitiser coverage. The remaining work is discharging memory-safety blockers, not writing code.
  • One kind has no refcount at all: strings. Every copy is a fresh allocation. It is the kind the front end touches most, and a red gate already names it as the fix.
  • The success metric already exists in the runtime and is exported today: drive deep_value_clones to zero while refcount_value_clones and program output stay unchanged. One number, and it cannot be gamed by tuning a threshold.
  • Value representation comes last, deliberately. Copying is measured and superlinear. The 32-byte value box is hypothesised and constant-factor. Fix the measured one first.
  • Falsifiability: each phase must move one named kind from the copy counter to the bump counter with byte-identical program output and an unmoved negative control. A phase that improves both counters has broken its own measurement.

Hey does not need a reference-counting system designed. It needs the one it has finished — and the order that work happens in is not the intuitive one.

The success metric is already in the runtime

The scheduler profile already separates the two outcomes this entire programme is about, and exports both as JSON:

deep_value_clones       objects, arrays, strings   ← the copies
refcount_value_clones   bytes, callables, handles  ← the bumps

That is exactly the counter A Dynamic Value Is Not a Copy asks for when it says the gates must be "blunt and hard to game." It gives the whole campaign a single target:

Drive deep_value_clones to zero on a steady-state workload, while refcount_value_clones and program output stay unchanged.

Every phase below moves one named kind from the first counter to the second. No new instrumentation is required to judge any of them — with one exception noted in phase S0, which is that nothing counts bytes copied per actor message, and the actor phase cannot be judged without it.

Giving strings a backing costs nothing

The obvious objection to refcounting strings is that it makes every value bigger. It does not, and the reason is a quirk of the existing layout worth seeing directly.

Why value representation comes last

The instinct is that the 32-byte box is the problem: boxing, unboxing, wide copies. Boxed Values and Fast Languages exists specifically to stop that jump. Its audit table rates "unboxed storage is wasted if access remains a call" as too absolute, and "inlining only pays when storage is unboxed" as false. Its recommendation is a cost ladder before a redesign.

Meanwhile the copying story is already measured and already superlinear. The front end's copied bytes fit at an exponent of roughly 1.93 — quadratic — even with copy-on-write enabled and the cursor tokenizer in place. And the scaling gate that tracks it names its own fix in its purpose text: it goes green when refcounted string backing lands, not by moving the threshold.

Fix what is measured and superlinear — the copying — before what is hypothesised and constant-factor: the representation width.

The blocker nobody has scheduled

This is the one finding that came from reading the runtime against the research rather than from either alone, and it sits on the critical path for the actor half of the plan.

Designing Hey's Actors decides that immutable messages should be shared by reference. Today the mailbox does the opposite: it makes a deep isolating copy of every message. That copy is not an oversight. It is what makes the plain, non-atomic refcount on objects and arrays safe. Remove it and two threads race the counter.

The obvious answer is to make the counter atomic. The runtime's own design note explains why that is not enough: object shape names are cached lazily, on first read. Two threads reading one shared object both write that cache. An atomic counter fixes one race and leaves a second one live.

The discharge already exists, and is connected to nothing. There is a live flag that computes an object's shape at construction instead of on first read. That makes a published object immutable in fact rather than only in language semantics — which is precisely the property the zero-copy argument needs. Nobody has measured what it costs. It is the cheapest experiment in this document: one environment variable, no code change, and it decides whether the entire actor phase is a research problem or a default.

Six phases

Each phase names the kind it moves from the copy counter to the bump counter, and each ends at a gate rather than at a feeling. The numbering is a real dependency chain, not decoration.

S0 · no code changes

Baseline with the instruments that already exist

A sweep harness already varies the copy-on-write flag across input sizes. Record both clone counters on the front end, a web steady state, and a 100,000-actor run. Add the one missing counter — bytes copied per actor send — because phase S3 cannot be judged without it. Run the eager-shape flag from the section above and record its cost.

Gate: a committed baseline table. This project's own record contains four separate cases of a fix built against a number nobody re-derived.

S1 · start here

Give strings a refcounted immutable backing

The only kind with no refcount, the named cause of a red gate, and the one measured superlinear term. Critically, immutable strings are never written, so this phase needs no write barriers at all — every hard part of the collection work simply does not apply. Copy the existing bytes-backing pattern verbatim rather than inventing a second one.

Migration technique: let the compiler enumerate the work. Rename the field so that all 538 access sites become compile errors, then fix them mechanically. A silent miss becomes impossible, because the build will not complete until every site has been visited. The one genuine audit is the subset of those sites that writes through or frees the buffer.

Gate: the red scaling row goes green at its unmoved threshold and full sweep · copied-byte exponent falls toward linear · a negative control shows the counters move with byte-identical output · memory sanitiser green.

S2

Promote copy-on-write for objects and arrays

Already complete and shipping, switched off. The remaining work is not implementation — it is discharging three named memory-safety blockers: enumerating every thread boundary as a derived fixed point rather than a hand-maintained list, the lazy shape cache above, and getting the thread sanitiser watched red. There is no isolation-violation hook today; one has to be added, because a sanitiser nobody has seen fail is a hope rather than a gate.

Gate: the existing A/B gate green in all three flag states · blockers discharged by checks rather than by argument · at least one adversarial workload that mutates through shared receivers, where copy-on-write pays a spine copy plus a uniqueness test.

S3 · blocked on S2 and on the cycle decision

The actor send becomes a refcount bump

The phase the actor research was written for. What one production runtime does only for large binary values becomes Hey's general case, because nothing can mutate a shared immutable value. Keep the copy-small, reference-large heuristic — it avoids paying for an atomic operation on a three-byte string.

Say in advance what this will not do. The existing 100,000-actor benchmark is dominated by a quadratic list append as results move back up the tree, not by message copying. Predicting that now is worth more than explaining it afterwards.

Gate: bytes copied per send reaches zero for immutable payloads · thread sanitiser green on a workload that genuinely shares values across threads.

S4

Precise compile-time reference counting

Phases S1 to S3 make sharing cheap at runtime. This is what stops the compiler generating traffic that never needed to exist. The existing ownership work has already hand-derived three fragments of it: ownership belongs to bindings, ownership transfers at calls, and a temporary is released at its last use.

The two missing pieces are, by the source paper's own ablation, the majority of the win: reusing storage in place when a value is provably unique, and specialising the release path when the type is statically known. Removing both more than doubled the reference benchmark's running time.

Ordering constraint: annotate every producer before converting any consumer. Two sites are currently sound only by accident of upstream string matching; converting consumers first would silently turn working releases into leaks.

S5 · only now

Value representation

Run the eight-variant cost ladder — one feature added at a time, from an 8-byte integer with inlined access up to a specialised store behind a typed helper — capturing optimised intermediate code and final assembly for each, and sweeping sizes that cross real cache boundaries. The published analysis already states what each outcome implies, which is the entire point of running it.

Rejected as a premise: encoding values inside floating-point bit patterns. It is a whole-runtime change with portability, foreign-function and collector implications, and the claim that it delivers typed arrays with no guards is incorrect as stated. It is a candidate for this phase's conclusion, never its opening move.

Where immutability does not save us

What Makes an Actor Cheap? argues that reference-counted binary values need no cycle collector, and proposes generalising that to all of Hey's data. It states the reason correctly and then generalises one step past it. Those values are safe because they are immutable and pointer-free.

Hey's collections are immutable. They are not pointer-free — an array holds values, and each of those may hold another collection. The argument does not transfer for free, and the actor article is the more careful of the two: it says explicitly that immutability prevents write races but does not by itself make cyclic graphs impossible.

The real basis for acyclicity is construction order, not immutability. If a value can only be built out of values that already exist, every edge points backwards in time and the graph is a directed acyclic graph by construction. That holds only if no primitive can close a loop, and two candidates have to be checked before relying on it:

  • Setting a key on an object the caller still holds. The existing acyclicity assertion catches only a direct self-store, and the runtime's own note says the transitive containment check is explicitly not claimed.
  • A closure's captured environment. A callable holds a value. A closure that captures a collection which later contains that closure closes a cycle — through a refcounted record. This is the likeliest real cycle in the language and it is on nobody's list.
Decision required before S3, not after. Either enforce acyclicity as a load-bearing invariant with a named gate, or accept cycles and plan a collector. Reference counting has no backup collector today, so "we assumed it was acyclic" becomes an unbounded leak in exactly the long-running server workload this campaign exists to protect.

What must not be done

Every one of these has already cost this project something.

  • Do not release caller-side by a freshness test. Measured: it breaks 40 of 106 corpus modules, with use-after-free surfacing as a freed value's kind reading back as an actor. The test is both type-blind and scope-blind.
  • Do not add callee-name lists, body-shape lists, or text scans for "does this pointer look fresh." All are recorded dead ends. There are already around 27 copies of that scan in one file; an ownership bit only wins if each converted site deletes its scan in the same commit.
  • Do not free early to win a benchmark. Leaking is the safe direction. A premature free is a wrong answer at exit code zero that varies between runs of the identical binary, and only a sanitiser can see the difference.
  • Do not promote on a run that excluded the memory sanitiser. It is the only instrument that can see a fix which frees too early, and such a fix looks like a success to every other one.
  • Do not green the scaling gate by moving its threshold or shortening its sweep. That row is red precisely because it was once green for having stopped measuring one doubling early.
  • Do not describe any of this as "removing boxing." The word names three different costs. The target is tag and share: the cost of uncertainty is one tag check, not zero.

What this plan is not

It is a plan, not a result. Nothing in it was measured while writing it, and the two claims most likely to be wrong are named here so that they get checked rather than assumed.

  • That eager shape computation is cheap. The critical-path finding rests on it and it has never been measured. If it turns out expensive, both the copy-on-write promotion and the entire actor phase need a different discharge.
  • That the string migration is mechanical. 538 sites is a count, not an audit. The subset that writes through the buffer is the real risk and has not been enumerated.

The first action is the baseline, and the cheapest useful thing in this document is one environment variable.

Terms used here

Reference counting
Tracking how many holders a shared value has, and reclaiming it when the last one goes away. A copy becomes an increment rather than a duplication.
Backing store
The single allocation that holds a value's actual payload. Several values can point at one backing store; giving strings one is phase S1.
Copy-on-write
Sharing storage until something writes, then duplicating only if the writer is not the sole owner.
Write barrier
The check placed before an in-place modification that asks whether the value is uniquely owned. Immutable strings need none, which is what makes phase S1 small.
Negative control
A measurement that must not move when a fix lands. It rules out the possibility that the improvement came from somewhere else, or that the measurement itself broke.
Use-after-free
Reading memory that has already been reclaimed. It rarely crashes; it produces wrong answers that can differ between runs of the identical program, which is why only a sanitiser reliably catches it.
Sanitiser
An instrumented build that detects memory and threading faults a normal build executes silently. Here it is the only oracle that can distinguish a correct fix from one that frees too early.
Acyclic / directed acyclic graph
A value graph with no loops. Plain reference counting reclaims everything only if the graph is acyclic, because a cycle keeps its own counts above zero forever.
