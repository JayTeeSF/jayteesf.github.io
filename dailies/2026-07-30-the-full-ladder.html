  • 471a–473a the P1 familyclosed + certified▸ show the three bugs▾ hide

    The type-guessing disease — the compiler deciding what a value is from its spelling — is out of the language. Every catalogued site converted, and Linux certified the closure independently.

     
    # 471a wtakeput — the indexed store stopped copying the array:

Now — in flight and queued

Two implementers are running as this page is generated; their landings get their own verification chains before anything ships.

  • 475a wfloatordin flight now▸ show the bug▾ hide

    Ordering comparisons on a float variable take the wrong branch in the binary — the surviving member of the float family, mechanism pinned by measurement.

     
    let a = 1.5
says a > 1        # script: true   # binary: false   # 1.5 truncates to 1
says a > 1.4      # both lanes: true            # float literal RHS is fine
if a > 1          # script: takes the branch   binary: skips it
  says 'big'
end

    The discrimination table that pinned this (integer-literal right side truncates; float-literal right side compares correctly; == unaffected) came from the Linux seat and is the fix's acceptance spec verbatim. Wrong control flow is worse than wrong arithmetic — a working script silently takes a different path when compiled. Same fix pattern as 472a, in the comparison family.

  • next wbytesbuildin flight now▸ show the gap▾ hide

    Bytes can be taken apart but not put together — so no decoder can be written in Hey at all. Filed by an app team this morning with a user-visible casualty.

     
    import 'stdlib:Bytes'
let b = Bytes.from_text('é', 'utf-8')
says Bytes.at(b, 0)              # 195   # reading bytes: fine
says Bytes.at(b, 1)              # 169
says Bytes.decode([195, 169], 'utf-8')
                                 # today: error — an integer array is not a bytes value
                                 # and there is NO other way to make one

    Percent-decoding, base64, any binary framing — every decoder must synthesize bytes from numbers it computed, which is exactly the missing operation. The reporting team's app ships a deck named "Cellules Végétales" as "Cellules V g tales" because they had to sanitize instead of decode. The fix is a validation-boundary change: Bytes.decode accepts an integer array and routes it through the same decoder the existing path uses — one decoder, two entry shapes, loud errors on non-byte values.

    Re-derived on our box against the shipping binary before it was queued; their probe passes verbatim when this lands. A wider audit rides along: any other standard-library surface that can consume a thing but not construct it.

  • 476a division by zeroqueued · surveyed today▸ show the bug▾ hide

    Integer division by zero produces a garbage value instead of an error. The fix makes every by-zero shape fail loudly with the script's exact diagnostic.

     
    says 7 / 0          # script: error "/ by zero", exit 70
                    # binary today: a garbage value, exit 0

    A 19-probe survey across every shape and lane ran today and became the acceptance spec. One genuinely good result: float division by zero already fails closed identically in every lane — that half of the slice demoted itself to a control. The integer half fails open in more shapes than the one shown here; after 476a they all produce the script's exact error and exit code.

  • ~477a+ the collision programruled · queued▸ show the bugs + the design▾ hide

    Your data, your functions, and your names always win — with a warning when you shadow a builtin. The rulings stand; a third defect joined the train today.

     
    # Bug 1 — your DATA loses (32 reserved names steal the dot):
let h = {type: 'admin', count: 5}
says h.count      # today: 1        # the FIELD COUNT, not your 5

# Bug 2 — your CODE loses, and the two lanes disagree (213 of 214 names):
fn find(n) return 99 end
says find(1)      # script: (empty — the BUILTIN ran)   # binary: 99

# Bug 3 — NEW: a local named like an imported file's PRIVATE function
# resolves to the wrong thing, differently per lane. Found in a
# production server, where it silently served null JSON.

# The ruled design — builtins are module functions; sugar is opt-in:
import Sys                    # one line: the recommended defaults
fn find(n) return 99 end      # YOURS wins, both lanes — with a warning
                              # you can suppress only explicitly

    Rulings unchanged: exposing-import, uniform scope, the warning channel as its own slice (warnings can harden into errors per-code), user-wins in both lanes. Bug 3 rides the same train because it is the same root — one flat name table with no module sealing — and dies with registry scoping.

    The one new finding: the shipped source archive failed a compiler-output check that the producing tree passes. Confirmed on a quiet box, then mechanism found the same day: the emitted artifact's header echoes the fixture path as spelled at emit time, the pinned reference recorded the relative spelling, and the archive check runs from a different directory — so the gate could never pass from an extracted archive, on any machine. The gate gets a voice first.

The retirement ladder — R2 → R8

"Get rid of native C." Two separate deletions, marked red. Only groundwork is done; neither deletion has started.

  • R2 ~490alive rung▸ what it means▾ hide

    The Hey-owned compiler must accept every program the old C one accepts. ~12–18 refusals left, was ~30.

     
    # Every build prints a receipt naming which emitter did the work:
selfhost_consumer=hey-llvm-text   # the Hey-owned emitter — the future
selfhost_consumer=direct-mir      # fell back to the C emitter — debt

# R2 = drive the fallback count to zero. One refused call currently
# forces the WHOLE program back to the C emitter.

    All 106 corpus examples already route through the Hey-owned emitter with zero fallbacks; the remaining reds are harder shapes in the wider spec suite.

  • R3 ~515adeletion #1▸ what gets deleted▾ hide

    DELETES the native LLVM emitter — ~14,900 lines of heyc.c.

    Today two emitters exist: the C-hosted one (heyc.c) and the Hey-owned one (stdlib/HeyLlvm.hey), and every landing proves them byte-identical on the whole corpus. R3 deletes the C copy: first pin golden .ll files as the reference (done, 393a), then split the string helpers it shares with the bootstrap backend, then delete the emitter island batch by batch with the goldens as the gate.

    This is why this week's fixes put semantics in shared runtime helpers, never in emitter branches — code written there dies with the file. Needs R2 closed plus a conformance corpus that doesn't exist yet.

  • R4small · any time after R2▸ what it means▾ hide

    Honest labels, and a tripwire against new native code.

    Rename the comparison-only "native-c" labels to explicit stage0 everywhere, and add a checker that fails the build if ordinary tooling ever grows a new call into the native backend outside the allowlisted bootstrap set. Cheap insurance that the debt only shrinks.

  • R5 ~500agates R6 + R7▸ why it gates everything▾ hide

    The test suite itself must stop running on the thing being deleted.

     
    # Every spec today executes on the interpreter inside hey_repl.c:
heyc specs/language/1302_… --test     # runs on the C interpreter

# After R5 the same spec compiles and the BINARY's output is asserted:
spec 'value semantics across lanes'
  expect stdout "true\ntrue\n"        # checked against the compiled program
end

    You can't certify the deletion of the interpreter with gates that run on it — that's circular. R5 builds the compiled spec runner, migrates suites in batches with both lanes agreeing, then flips heyc --run to compile-and-run by default.

  • R6 ~530adeletes hey_repl.c▸ what gets deleted▾ hide

    The REPL stops being a second implementation of the language. Largest schedule risk on the board.

    The interactive session moves onto a JIT (compile each fragment with the ordinary pipeline, load it hot — target <100ms per entry); Eval moves with it; the shell itself becomes Hey code. Then hey_repl.c — ~2,600 lines of C expression evaluator that must agree with the real compiler forever — is deleted. Research is banked; one unproven runtime re-entry probe is the swing item (5–8 agent-days).

  • R7 ~540adeletion #2▸ what gets deleted▾ hide

    The bootstrap C backend goes — the deletion that actually ends native C.

     
    # The fixed-point proof that makes the seed compiler deletable:
stage1 = hey_compiler_built_by_C_seed(source)
stage2 = hey_compiler_built_by_stage1(source)
assert bytes(stage1_output) == bytes(stage2_output)   # byte-identical

    Once Hey-built-by-Hey reproduces itself byte-for-byte without the C seed, the seed backend (~1,650 lines) is deleted and recovery becomes published per-platform bootstrap binaries — the same model Go and Rust use.

  • R8 ~550athe end · realistic ~Aug 14▸ the end state▾ hide

    semantic_debt_files = 0 — no language semantics live in C.

    heyc.c shrinks to what a launcher honestly needs: CLI argument handling, build-mode dispatch into Hey-owned tooling, and object/link mechanics. Every rule about what Hey programs mean lives in Hey source, compiled by Hey, verified by compiled specs.

Past R8 — what the ladder is for

After the cruft is gone, the language program. Ordered by leverage, not by calendar.

1 · Names, finished

ruled 2026-07-29 ▸▾

Zero reserved names anywhere. Your data, your functions, your names — always.

 
let order = {count: 12, type: 'rush', items: [...]}
says order.count        # after: 12   # today: 3 (the key count)
import Sys              # the one-line ergonomic opening —
                        # an ordinary, forkable module, not magic

The collision train carried to completion: exposing-import everywhere, the Sys module as the recommended defaults, warnings hardening per-code on your schedule — and module sealing, so a private name in one file can never capture a call in another (today's bug 3).

2 · Recursion, guaranteed

▸▾

Full tail-call depth in both lanes; a clean error where depth is real.

 
fn countdown(n)
  if n == 0 return 'done' end
  return countdown(n - 1)      # tail position
end
says countdown(1000000)
# compiled today: done (scalar tail calls already become loops)
# script today:   segfault ~depth 500, no message
# target: 'done' in both lanes; non-tail overflow says
#         "recursion depth exceeded", never a crash

This is also the Erlang idiom Hey's actors want — the server loop as tail recursion. The research workflow is saved and scheduled; the fix follows it, and recursion returns to the tutorial once guaranteed.

4 · Tight loops — fannkuch, and the Ruby correction

corrected 2026-07-30 ▸▾

The published "~3× behind Ruby" was measured against end-of-life Ruby 2.6. Same box, current Ruby: the honest number is ~13×. The correction goes against us, which is exactly why it's here.

 
# Same box, same session, five lanes interleaved, answers verified first
# (fannkuch n=10 · i7-1165G7 · medians of 5):
C -O2          185.5 ms
Go             191.3 ms
Ruby 4.0.6   2,492   ms      # current stable — 13.4× of C
Ruby +YJIT   2,492.6 ms      # the JIT buys 1.0002× — NOTHING on this shape
Hey         32,215   ms      # 12.93× behind current Ruby

# What changed vs the old row: nothing about Hey. The old comparison
# used the macOS SYSTEM ruby — v2.6, end-of-life, three majors old —
# on a busy box. Modern Ruby is a much faster interpreter than the
# folklore says, so the bar we published was artificially low.

Two more measurements landed today, and they agree about where the cost lives. Ruby's brand-new ZJIT compiler was tried on the maintainer's question — it made this workload 2.06× slower (so the Ruby column stays plain interpreter, its best mode here). And link-time inlining of Hey's own runtime boundary — the same move ZJIT's headline demos make — bought only ~6%, with the allocations surviving intact. Calls are ~6% of the cost; allocation is the rest. The bill of materials from yesterday stands: two heap allocations per array element store, both sites named. The fix (wputfuse) removes the dead-on-arrival one first, and it is now triple-confirmed as aimed at the right layer.

Honesty note carried with the number: the 13× cell ran with Ruby lanes sharing the box (fair within a rep, contended across cells); the quiet-box Hey/C figure remains 161× from the 471a cell. And the clean version A/B finished as this page was written: the float-correctness landings cost fannkuch +11.0% ± 1.4% (interleaved, non-overlapping distributions, C control flat, corroborated by a ~9% malloc-count rise on identical work) — correctness paid for with per-operation allocation, which is the same bill wputfuse is scoped to claw back. Localized the same day: the boxed-arithmetic landing (472a) carries all of it — the has/has? landing adds nothing measurable — and the +15 ns/op cost its own landing note disclosed is arithmetically sufficient to explain the whole delta. A correctness fix with a published price tag, queued for claw-back by the same allocation work. Every future Ruby row prints its interpreter version.
