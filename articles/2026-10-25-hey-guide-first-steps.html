First steps with Hey

In about fifteen minutes you'll have Hey installed, a program running as native code, a binary you can copy to another machine, a test that lives next to the code it checks, and an actor keeping count. No type annotations anywhere.

Who this is for: you write Ruby, Go or Python and have never seen Hey. You know a terminal.

What every badge means: Works today you can do it now. Partly works it works with a stated hole. Decided, coming ruled, not built yet. Proposed designed or asked for, no ruling yet. Being removed exists, but is ruled to go.

Every command on this page was run with the 0.99.606a candidate (per the toolchain clone's DOCS-TOOLCHAIN-README.txt; the clone has no .git) on an Apple Silicon Mac. Outputs are pasted exactly; long noise is trimmed only where the page says so.

1. Install Hey

Works today on macOS (Apple Silicon) and Linux x64.

Today Hey installs from a checkout of its source repository. The installer finds your package manager, can install the C, LLVM and OpenSSL build tools it needs (only if you allow it), builds Hey, and links four commands into ~/.local/bin: hey, heyc, hey-repl and hey-install.

Complete output. Only the paths were rewritten: the real run printed this machine's checkout path, a scratch home folder and a scratch cache folder.

Then run it for real with ./install.sh (add --yes to let it install missing packages, or --system to link into /usr/local/bin). Open a new shell, or run the . ~/.config/hey/env.sh line it prints.

Be ready for a long first build. The source installer compiles the whole compiler, which takes a long time on a laptop. A one-download, no-compiler-needed archive exists as a build step (hey target release, see Guide 6), but no signed archive is published yet.

2. Hello, world

Make a file called hello.hey:

program
  says 'Hello, world'
end

program ... end is where execution starts. says prints a value and a newline. Run it:

$ hey hello.hey
Hello, world

That's a native program. Hey didn't interpret your file; it compiled it to machine code and ran that.1 Works today

3. What just happened: the native cache

Predict: the first run compiles. What happens on the second run of the same unchanged file?

Turn on the trace and run it twice from an empty cache:

$ HEY_RUN_TRACE=1 hey hello.hey        # first run: 6.04 s
hey-run: index_reason=missing_record
hey-run: index=miss source=.../hello.hey
hey-run: authority=c1f7eabb...dd43 files=64 stamps=64
hey-run: cache=miss key=e85b93c7cc1a97d4c7b8fb08
hey-run: cache=published backend=llvm
Hello, world
$ HEY_RUN_TRACE=1 hey hello.hey        # second run: 0.02 s
hey-run: index=hit key=e85b93c7cc1a97d4c7b8fb08
hey-run: cache=hit backend=llvm key=e85b93c7cc1a97d4c7b8fb08
Hello, world

Trimmed: each traced run also prints 65 hey-run: identity=... path=... lines, one per file that decides the cache key (your file plus 64 compiler and standard library files).2 Times are wall clock from /usr/bin/time -p.

The second run never started the compiler. A tiny native launcher checked that your file, everything it imports, and the compiler itself were unchanged, then jumped straight into the cached program. backend=llvm says the cached program is native code built by LLVM, the same compiler back end Rust and Swift use.

Change one character in hello.hey, or in any file it imports, and the next run compiles again. The cache key covers the whole import graph, so you never run stale code.

A contradiction, and what the trace shows: the repo doc and the ruling say hey file.hey compiles natively, while the post-606a plan (and forecast row 8) still lists moving heyc file --run off the interpreter. The trace above shows what happens today for hey file.hey: backend=llvm, native code. The open item is about the other command. The interpreter is a different command, heyc file.hey --run, covered in section 7. The ruling behind this ("hey file.hey compiles then runs, like go run") is entry L-CLI-15 in the decision ledger.

The cache lives in your user cache folder (on a Mac, ~/Library/Caches/Hey; on Linux, ~/.cache/hey). hey cache path shows it; hey cache gc cleans it. Guide 6 has the details.

4. Build a binary you can ship

Works today

$ hey build hello.hey -o build/hello
built /Users/you/hello/build/hello
$ ./build/hello
Hello, world
$ ls -l build/hello
-rwxr-xr-x  1 you  staff  134328 build/hello

Known noise: on 0.99.606a, hey build also prints 30 compiler diagnostic lines starting with selfhost_ to standard output before the built line (trimmed above). They're harmless but they shouldn't be there. If a script reads the output, filter with grep -v '^selfhost_'.

When to use which:

Use hey file.hey whenUse hey build file.hey -o app when
you're editing and running, or it's a personal script (start it with #!/usr/bin/env hey and chmod +x)you'll copy it somewhere: a server, a container, a release, another person's machine
you want edits picked up automaticallya build must fail before deploy, not on first run
a 20 ms cache check on each start is fineyou're benchmarking, signing, or putting it in an app bundle

The binary's size, what it links, and how to ship it are in Guide 6. heyc build file.hey -o app is the same build under the compiler-oriented command name.

5. Values and functions

Hey values never change. You make new ones from old ones. Here's tour_01_values.hey from the Hey examples folder:

program
  let user = {name: 'Ada', visits: 1}
  let next = {...user, visits: user.visits + 1}
  let names = ['Ada', 'Grace']
  let expanded = [...names, 'Katherine']

  says next.name + ' has ' + next.visits + ' visits'
  says expanded.to_json
  says user.name + ' still has ' + user.visits + ' visit'
end

Predict the third line before you look. next was made from user with visits bumped. How many visits does user have now?

$ hey tour_01_values.hey
Ada has 2 visits
["Ada","Grace","Katherine"]
Ada still has 1 visit

Still 1. {...user, visits: ...} copies user's fields into a new object and overrides one. let names a value; nothing can change what it names. (Why this is still fast, even in a loop, is the subject of values, memory and Strings.)

Functions are values too. tour_02_functions.hey:

fn greet(name)
  return "Hello, #{name}!"
end

fn add(a, b)
  return a + b
end

program
  let formatter = greet
  let operations = [add]
  says formatter('Ada')
  let operation = operations[0]
  says operation(40, 2)
end
$ hey tour_02_functions.hey
Hello, Ada!
42

No types written anywhere. The compiler works them out from how values are used. "#{name}" inside double quotes is string interpolation, like Ruby. The language reference covers all of it.

6. A test in the same file

Works today

A spec block says what the program should print. It sits in the same file as the code.

Here's one with a bug in it. The spec wants an exclamation mark; the function forgot it:

spec 'greets by name'
  expect stdout "Hello, Ada!\n"
end

fn greet(name)
  return "Hello, #{name}"
end

program
  says greet('Ada')
end
$ heyc greet.hey --test
FAIL: greets by name
expected stdout: Hello, Ada!

actual stdout:   Hello, Ada

$ echo $?
1

Fix the return line to "Hello, #{name}!" and run it again:

$ heyc greet.hey --test
PASS: greets by name

The exit code is 0 on pass and 1 on fail, so heyc file.hey --test drops straight into CI. Every file in the Hey examples folder carries its own spec; heyc hello.hey --test prints PASS: hello world.

7. Check without running, and the other heyc switches

Works today

--check parses and resolves the file, then stops. It's the fast "did I break anything" button.

$ cat oops.hey
program
  says greet('Ada')
end
$ heyc oops.hey --check
heyc: unknown function: greet [source=oops.hey]
$ heyc hello.hey --check        # no output, exit 0: all good

The same mistake through hey oops.hey fails at compile time with the exact place, oops.hey:2:8: greet, wrapped in more compiler detail than a beginner needs. Use --check for a short answer.

8. The REPL

Works today

hey repl is for trying things. It uses the same parser and name rules as compiled programs; definitions persist for the session, and multi-line blocks continue until they're complete.

$ hey repl
Hey now. Hey REPL v0.99.606a-C. Type help or quit.
hey> let x = 40 + 2
hey> says x
42
hey> fn greet(name)
...>   return 'Hello, ' + name
...> end
defined fn greet/1
hey> says greet('Ada')
Hello, Ada

Captured by piping those lines into hey repl; typed interactively it looks the same.

The REPL evaluates your fragments rather than compiling them to native code (the ruling keeps the evaluator for the REPL only). Don't time anything in it. import 'stdlib:Text' exposing: [trim] works in the REPL just as in a file.

Proposed A compiled REPL, where each fragment runs as native code, is planned work with no ruling yet (task compiled-repl-and-eval).

9. Your first actor

When some state has to live and change over time (a counter, a connection, a game room), Hey gives it an owner: an actor. An actor is a small independent worker with a private mailbox. Other code can't touch its state; it can only send it messages, and the actor handles them one at a time.

spec 'tour actors own state'
  expect stdout "visits=1\nvisits=2\n"
end

actor Counter(label)
  state count = 0
  receive message

  if message == 'increment'
    set count = count + 1
    says label + '=' + count
  else
    if message == 'stop'
      exit
    end
  end
end

program
  let counter = spawn Counter('visits')
  send counter, 'increment'
  send counter, 'increment'
  send counter, 'stop'
  join counter
end
$ hey tour_03_actors.hey
visits=1
visits=2
$ heyc tour_03_actors.hey --test
PASS: tour actors own state

Read it top to bottom:

  • state count = 0 is the actor's private memory. set count = ... replaces it for the next message. set is the only way state changes in Hey, and only inside the owner.
  • receive message names the message being handled; the code after it runs once per message.
  • spawn starts the actor, send drops a message in its mailbox and returns at once, exit ends the actor, join waits for it to finish.

Actors run on a pool of threads across your CPU cores, and a failure inside one stops that actor, not your program. All of that is in actors and failure.
