The two-machine run

The 548a milestone was stated as a single falsifiable event: two native Hey nodes, on two machines, over TLS, exchange an immutable value and a reply, one node is killed, the remote monitor fires. This cycle it happened on real hardware — a macOS host and a Linux host on the same fast ethernet, coordinated so that Linux stood up node B and the macOS session connected as node A.

01_ping_pong — Remote.call over the wire. Node A on macOS connected to node B on Linux over TLS (the client verifies the server certificate by SNI, so a single fixture cert works across any peer IP), and received a structured reply:

A handshake ok with peer=B incarnation=inc-8c48db05…
A got reply=pong echo.ping=hello from A from=node-B

The peer incarnation node A printed is exactly the one node B advertised when it came up — this is a genuine cross-host request/reply, not a loopback echo.

04_stale_incarnation — the enforcement, over the wire. On a second connection, node A sent a message through a RemotePid bearing a prior incarnation, then made an ordinary call:

A handshake ok peer_incarnation=inc-239d4256…
A stale-incarnation send dispatched (server must reject, not route)
A current-incarnation call reply=pong

Node B's serve loop rejected the prior-incarnation frame (event=stale_incarnation, not routed to the local actor) while answering the current-incarnation call — a restarted node is a new logical runtime, and an old reference must not silently resurrect. A wrong-CA client fails the handshake closed with no data exchanged. The Linux box also reproduced the whole same-host preflight green independently, so the substrate is not macOS-specific.

What this is, precisely. This is the true two-physical-host / real-NIC L2 gate, now complete across all four legs — Remote.call, Remote.send (at-most-once), the kill→NODE_DOWN monitor (node A observed exactly the incarnation node B advertised, then NODE_DOWN+DOWN on peer loss), and stale-incarnation rejection. Only the deterministic partition / at-most-once matrix (L3) and a Docker two-container recipe are the next rungs. The nodes run interpreted today — the LLVM backend does not yet lower the cross-unit Dist*/Codec calls (the extern-facade frontier) — but the transport, codec, handshake and TLS are the real thing over a real socket.

What landed on the Distributed track

At 548a this track was announced: a ruling (distribution is runtime/library work, not compiler/VM work) and a census (12/15 primitives ready, the one gap being TLS server accept). At 550a the v0 substrate landed as four separately-attributable commits (each layer reviewable on its own), and at 551a it ran and was verified across two machines:

  • Layer 1 — TLS server accept. The one native gap the D0 census named: SSL_accept / TLS_server_method over the existing TLS path, exposed as Tls.listen / Tls.accept, with a round-trip regression. This is a native primitive — zero syntax, MIR, or LLVM change — exactly as the stdlib-first ruling predicted.
  • Layer 2 — the wire codec. stdlib/Codec.hey: a versioned tagged binary format over immutable acyclic values (nil / bool / int / float / string / bytes / array / object), insertion-order preserving, bounded and adversarially fuzzed, with an O(n log n) join. Its encode is measured O(n) (slope ~1.0) — it builds a list of byte chunks and joins once, sidestepping the quadratic string-concat trap that still bites naive s = s + x.
  • Layer 3 — transport / node / remote. DistTransport (framing, a handshake advertising node identity + incarnation + app/build, backpressure, heartbeats, bounded reconnect), DistNode (identity + incarnation, the serve loop, remote-monitor delivery), and DistRemote (RemotePid + Remote.send at-most-once + Remote.call = request_id + reply_to + ordinary send + wait — ordinary messaging with correlation, not a second RPC protocol).
  • Stale-incarnation enforcement (folded into the transport layer): the wire envelope carries the target node_incarnation, and Node.serve_once rejects a frame addressed to a different incarnation than the receiver's own. Falsified two ways — a deterministic spec over a TCP pair (stale send/call rejected, current delivered, unaddressed delivered), and an end-to-end demo that kills node B, restarts it with a new incarnation, and confirms the old RemotePid does not deliver while the reconnect observes the new incarnation.

Two showcase demos and a dashboard shipped alongside, to make the distribution visible: 05_mandelbrot.hey fans 32 image tiles across four real worker nodes (8 tiles each, with genuine per-tile node attribution — the seed of a rendered fractal plus a “who-computed-what” mosaic), and 06_wordcount.hey is a MapReduce word-count over four shards to four workers. A minimal stdlib/Dashboard.hey formats the per-worker table. One honest v0 limit: dispatch is sequential round-robin — the parallelism is topological (work spread across distinct worker processes with real attribution), not wall-clock concurrent, because an io-handle cannot yet cross the actor boundary. A practical “How to run distributed Hey” walkthrough accompanies this ladder.

Distributed Hey now closes, not expands. With the L2 gate green across two machines, the main engineering thread returns to core compiler work — the 1BRC interprocedural map-ownership cliff is the next priority.

v0 guardrails held: no Registry / Rinda / Jobs / gossip yet; at-most-once send with no auto-replay; and socket IO stays in its owning context because an io-handle cannot cross the actor boundary — a documented v0 deviation, with a follow-up filed for a transferable / actor-owned IO capability rather than silently dropping it.

What carried forward on the compiler track

The O(n²) campaign reached its dictionary milestone. Its pieces stay named separately — they are distinct mechanisms:

  • 549a — interprocedural consuming-ownership transfer: landed. A2-core 3b/4 authorizes a consuming operand to move across a call boundary, wired into both emitters (self-host and native) and gated by the MIR ownership verifier. set acc = step(acc, x) — where step is an eligible same-unit consuming callee — now transfers ownership instead of cloning the growing accumulator: a direct interprocedural-reduce receipt collapses clones from N²/2 to N, identical with COW on and off.
  • 549a — W9 map overwrite reuse: landed. A has?/get/keys receiver read in an if/while/until condition is a non-retaining borrow, so a sole-owned set m = put(m, existing_key, v) keeps its in-place reuse instead of deep-cloning the whole map — ~66× on the overwrite micro, and the missing half of the dictionary cliff.
  • The cross-language re-measure confirms it. The independent bench re-ran the matrix on 549a: W9 dict 76.3s → 0.63s (~122×), W10 wordfreq 37.7s → 0.96s (~39×), Hey now ~6.5× C on W9 and ~21× C on W10, no W1–W8 regression. The dictionary workloads no longer lose to the dynamic languages by orders of magnitude.
  • Track C2 — string self-append: the last O(n²), scoped and censused. s = s + x is still quadratic because a str accumulator is a raw C-string, so its bytes are copied into a fresh string value every iteration before ownership can help. This is a representation problem, categorically distinct from the interprocedural ownership work — a read-only census of every place str (a raw char*) meets a refcounted string backing has landed, with the representation ruling deferred to the maintainer. It is not claimed fixed.
  • A Binary safety fix. Binary.from_integers / to_integers / concat no longer SIGSEGV at ~500+ elements — three recursive helpers became iterative loops (O(1) stack). Round-trip at N=5000 is clean; the stdlib spec is byte-identical.

Verification & falsification

The version at stdlib/Version.hey now reads 0.99.551a; version-smoke is green and the 48 HIR/MIR goldens were regenerated to 551a (version-line-only, no body drift). The compiler levers carry their own mutation contracts and the differential-verify standard.

On the Distributed track, the 548a falsification commitments are now checks that pass, with their scope stated honestly:

  • The first milestone is met over the wire — all four legs. Two machines over ethernet: Remote.call (TLS) returned a structured reply, Remote.send (tcp) was accepted at-most-once, the monitor (tcp) fired NODE_DOWN+DOWN on real peer loss, and a prior-incarnation reference was rejected server-side (TLS) while the current call was answered. A wrong-CA client fails closed.
  • Frame falsification passes: the codec/transport reject bad protocol version, oversized length, truncated header, reset mid-payload, unknown type tag, truncated encoding, and a lying length field — each a typed error, never a crash.
  • Honest failure detection: no rung claims perfect detection; partition and death are observationally indistinguishable, so monitors report DOWN/NODE_DOWN as observations.
  • Delivery honesty: at-most-once — a successful Remote.send means accepted for transport, not processed remotely; reconnect does not auto-replay.
  • Still pending: the full D17 partition / at-most-once / slow-receiver matrix on real NICs, and a Docker two-container reproduction — the next rungs, not claimed today.
