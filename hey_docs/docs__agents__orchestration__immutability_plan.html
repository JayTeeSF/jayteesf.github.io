THE IMMUTABILITY PLAN — Hey is a value-semantic language, and every

defect this week was a failure to implement that efficiently or correctly

Status: **ADOPTED (maintainer directive, 2026-07-27).** This is the

organizing principle that was missing. Supersedes the framing in

`architecture_decision.md` where the two conflict — that document asked

"should we delete native-C"; this one asks the question that actually

generates the work.

---

0. THE REFRAME

We lost sight of immutability and then spent a week fixing its

symptoms one at a time without naming the family. Re-read through this

lens, the week's findings are ONE finding:

defectwhat it actually is
leak family, ~13.2 KB/req (406a/413a/416a/419a)clone to preserve value semantics, then abandon the original
`put_key` chain is O(n^2)immutability implemented as EAGER FULL COPY
object literal lowers to a `put_key` chainthe most idiomatic construction IS the quadratic path
`HeyJsonObject` is a linked listevery copy is a chain rebuild instead of a memcpy
loop-carried slot overwriten-1 abandoned copies per loop
`boxed == 42` wrong in BOTH lanes**value EQUALITY is broken — and for a value language, equality is THE observation**

None of these is a violation of immutability. All of them are the cost

of implementing it naively, plus one case where the core operation on

values is simply wrong.

1. THE PRINCIPLE THAT MAKES IT FAST

**Immutability never required copying. It requires that no one can

OBSERVE a mutation.** That single sentence is the whole optimisation

programme, and it has three mechanisms of increasing power:

1. **NO OBSERVER YET** — a value under construction has not been

published. Mutate it freely; freeze on completion. (Clojure's

`transient`/`persistent!`.) **Needs nothing we do not have.**

2. **NO OTHER OBSERVER** — a value with exactly one reference cannot be

observed by anyone else, so in-place update is unobservable and

therefore not a violation. (Perceus.) **Needs a refcount field.**

3. **CHEAP COPY WHEN YOU MUST** — when neither holds, make the copy

itself cheap: flat array + memcpy instead of chain rebuild.

Plus the BEAM discipline, adopted: **share immutable LEAF data by

refcount, copy anything that can contain references** — safe sharing

with no cycle collection. And **per-task heaps bound a leak by a task's

lifetime STRUCTURALLY**, which is a better answer than the empirical

bounding we failed at for a day.

**We are further along than we realised**: both emitters already carry

a fresh-vs-borrow classifier (`heyc_llvm_boxed_binding_borrows_local`

and its HeyLlvm mirror at :639). That IS a uniqueness analysis. 406a,

413a and 419a all lean on it. We built the foundation without naming it.

2. THE WORK, ORDERED

Ordered by value-per-risk, with the value-model-neutral work first so

nothing waits on the architecture ruling.

**I1 — VALUE EQUALITY (correctness, outranks everything).**

`boxed == 42` returns `true` for the string `"42"` in both lanes and

`false` for `42.0` in native. Route both lanes through the tagged

equality they ALREADY use correctly for `boxed == boxed`. Audit the

named sibling `HeyLlvm.hey:4809-4816`. **Behavior specs pin all four

value classes (int/string/float/nil) as OBSERVED OUTPUT, not IR.**

**I2 — FLAT INSERTION-ORDERED ARRAY (highest value-per-risk).**

Replace the linked list up to ~32 entries. Fixes the O(n) LOOKUP —

which nothing else on this list touches — kills per-node allocation,

turns clone into a memcpy. **Do NOT sort** (Erlang sorts and then

linear-scans anyway, paying an O(n) insertion sort per write for

equality/merge, never cashing in the lookup). Unsorted preserves

insertion order, which we VERIFIED is observable on the JSON

round-trip. Construction stays quadratic with a much smaller

coefficient — say so, do not claim otherwise.

**I3 — TRANSIENT LOWERING FOR LITERALS (removes the quadratic).**

Measured: `{ 'a':1,'b':2 }` lowers to chained `put_key`. So the batch

form users already write is turned into a chain BY US. Build the

literal in a private buffer and freeze at the end of the expression —

all keys are statically known, and nothing can observe the object

before the literal completes. **A lowering change with NO new user

surface**, needing no refcount and no architecture ruling.

**I4 — OWNERSHIP: finish the clone-and-abandon family.** 419a

return-side is staged; the loop-carried overwrite is scoped. Then

generalise the fresh/borrow classifier from a per-site reflex into a

real uniqueness analysis.

**I5 — PERCEUS (RULED GO — maintainer, 2026-07-26, "Option A").**

Fixes chained `put_key` transparently, zero API change. The

refcount lands as a VALUE-MODEL change, made once, in one place,

not per lane. Staged: (a) counts maintained + assert-only;

(b) clone-becomes-bump + copy-on-write behind a flag, A/B-gated;

(c) default flip. PREREQUISITE: the falsifiable value-semantics

guard (watched RED under a callee write-through) ships FIRST.

I4-b per-site self-rebind is WITHDRAWN in its favor; R0's

danger-set analysis stays as the independent cross-check.

ACYCLICITY INVARIANT (bench brief 2026-07-26, maintainer-

commissioned): refcount-only reclamation is sound IFF value graphs

stay acyclic. Hey is acyclic today by accident (put/bind clone

before insert; no closures/letrec/laziness). The invariant is now

WRITTEN: no operation may store into a value a reference reachable

back to that value; every in-place path added by I5 stages carries

an O(1) debug assert (child != parent backing) and the trip-wire

spec 1200 (self-embedding attempts must observe copies, never

self-reference) must stay green. Spec 859 "cycle_safety" is

call-graph cycles, NOT heap cycles — no RC-cycle coverage exists

outside 1200.

**I6 — PER-TASK HEAPS.** Structural leak bounding. Large, later,

architecture-dependent.

3. NATIVE-C, HONESTLY

The maintainer's observation — *it may not be worth keeping since it

is not correct anyway* — kills ONE argument for keeping it and leaves

another standing. Precisely:

  • **DEAD: "native is our correctness oracle."** It is wrong about

`boxed == 42` too, by a different mechanism. Neither lane is an

oracle. Byte-identity between two wrong implementations is exactly

the pathology that hand-ported a wrong lowering into HeyLlvm.hey with

a comment explaining it.

  • **ALIVE: "native compiles what the Hey lane cannot."** Measured:

the Hey lane fails closed on **77.8%** of a `specs/language` sample;

native accepts 94% of those; `hey_selfc.hey:867-903` routes the

PRODUCT BUILD to native whenever the Hey lane fails closed. That is

a capability fact, not a correctness one, and deleting native today

would delete the shipping backend for most of the corpus.

**So the path to dropping native is now motivated by CORRECTNESS

rather than by debt, and it runs through closing the acceptance gap

(R2) — not through deleting lines.** Every immutability slice that

teaches the Hey lane a shape it currently refuses moves us toward

deletion. That is a much better reason to do R2 than "retire technical

debt", and it means I1-I4 are R2 work as well as immutability work.

4. BEHAVIOR SPECS — THE STANDING REQUIREMENT

**Every slice in this plan ships with behavior specs that assert

OBSERVED PROGRAM BEHAVIOUR, not emitted bytes.** Non-negotiable, and

it is the same principle as the conformance corpus:

  • Assert stdout and exit code. The interpreter is the reference.
  • **Pin the SEMANTIC property, not the lowering**: that a source value

is unchanged after a derived value is built from it; that equality

agrees across int/string/float/nil; that key order survives; that a

value passed to a function cannot be mutated by it.

  • **Prove each new gate falsifiable by MUTATING the thing it guards**

and watching it fail. Three gates rotted this week — one that could

never fail, one that could never pass, one that silently tested a

stale binary because the run cache is keyed on fixture source. An

assertion nobody has watched go red is not yet a test.

  • Every gate gets a private per-run cache.
  • IR goldens are review artifacts, not correctness gates.
