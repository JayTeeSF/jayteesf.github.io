What happened today was specification, not shipping. You lifted a constraint we had worked under for months — "I can keep running the latest version until this new version is reasonably good" — and that changes what the whole ladder is for. The work was deciding what to build, writing it down so it can be built by people who were not in the room, and finding the places where our own documents lied to each other.

What changed, and why it is bigger than a release

  • The restructure commissioneddirection change▸ what it means▾ hide

    Hey gets one front end, and no later stage is ever again allowed to re-read your source code to work out what you meant.

    Today Hey has no front end. There is no step that reads your program once and turns it into a structure. Instead, five or six different parts of the compiler each look at the raw text again and each make their own guess about what an operator is, where a name ends, and what should happen. That is why arr[0] - 1 fails with "undefined name" while arr[0] -1 works — one of those guessers has a list of characters that may come before a minus sign, and ] is missing from it.

    The replacement is a single pipeline: your text becomes tokens, tokens become a tree, names in the tree get resolved to what they actually refer to, and only then does anything think about machine code. The compiler and the interactive prompt share that pipeline. No stage below it is permitted to look at your source text again.

    Why this is not a rewrite for its own sake. We have fixed fifty-eight defects one at a time. The census that started this found that the same single fact is decided independently in forty-five places for operator precedence, twenty-eight places for what counts as a name, and six places for whole-number division. Fixing the fifty-ninth defect does not touch the other forty-four copies. This is the fix that does.

  • Exit criteria yours, three of themdefined▸ show them▾ hide

    Fast web servers at the per-core bar · fannkuch · 1BRC. Explicitly not "all tests green".

    These three are how we will know the new system is real, and they were chosen because each one breaks a different part of the machine. A web server at the per-core bar means the request path is genuinely fast rather than fast in aggregate. Fannkuch means tight loops and function calls are not paying hidden costs. 1BRC means reading and grouping a billion rows does not fall over.

    "All specs green" is deliberately not on the list. A test suite can be entirely green and prove nothing — which is exactly what today turned up, twice. See the retraction section.

  • 31 rulings D9–D31settled▸ the ones that change code▾ hide

    Every open language question is now answered. Nothing on the decisions page is waiting on you.

    D29 — bindings never change; set changes a state slot. The one contradiction in our own decided set: we had agreed += exists and separately that a name can never be re-pointed. Both could not be true. Immutability won. set count += 1 is valid only inside an actor, monitor or supervisor, on state it privately owns. There is no assignment expression in the language at all.

    D26 — compiler nodes become generated. One schema produces the constructors, the readers, the tree-walkers and the checks. No compiler code writes a node by hand any more.

    D30 — the operator table is generated, with a projection per stage. One registry, one generator, six cut-down views. A stage cannot consult a column it has no business acting on. Your rule, recorded verbatim: the code generator must not reinterpret arithmetic just because it holds an instruction name.

    D31 — the minus fix is not "look at the previous token instead of the previous character". No stage that sees characters is asked at all. Whether a minus is negation or subtraction is a fact about grammar, so the parser decides it.

    Also settled: whole-number division stays as it is with Ruby's version available by opt-in import · ** is non-associative · default argument values are worked out when the function is called, left to right · operator overrides apply only to the file that imports them · precedence always comes from the symbol and never from the module.

The runway — fifteen steps, in this order

The ordering is the part most likely to be got wrong, so it is written down as one list rather than left to judgement.

  • Steps 0–8 the node subsystemnot started▸ show the steps▾ hide

    Build the generated node system and migrate onto it — before any parser exists.

     
     0  preserve behaviour — counters and regression tests, nothing else changes
 1  census every node population — syntax, HIR, MIR, diagnostics
 2  the explicit-index node schema, and the host-side generator that reads it
 3  the exact-sized node constructor
 4  generate the compatibility layer — constructors, readers, walkers, checks
 5  move every node CONSTRUCTION onto the generated constructors
 6  move every READ and every child traversal onto the generated readers
 7  cut the physical keys over to n_ names — one deliberate cutover
 8  direct borrowed slot reads — the late half of the performance fix

    Construction moves early, reading moves late, and that split is deliberate. Every compiler node built today starts by handing the two characters {} to a JSON parser and then adding fields one at a time. That is fixed at step 3. Reading is fixed at step 8, once every read in the codebase goes through one generated door, so the expensive part is changed once rather than at fifteen call sites.

    Step 7 has no dual-key period on purpose. Emitting both the old and new key names would keep stale reads working, which is precisely the thing the rename exists to expose.

  • Steps 9–14 the front end, then deletionnot started▸ show the steps▾ hide

    Build the pipeline, move the interpreter onto it, then delete what it replaced.

     
     9  source manager, tokenizer, parser
10  resolver, imports, operator bindings, module graph
11  rebuild the two intermediate forms so neither carries raw source text
12  interpreter and the interactive prompt onto the shared pipeline
13  drive both legacy counters to zero
14  delete the bootstrap compatibility paths

    The generator is written in a language we already have — Ruby, Python or C — and never in Hey itself. Its output is checked in; the build does not run it. That kills a bootstrap problem that had been recorded as unsolved: a Hey generator would need the compiler in order to build the compiler.

    Step 13 is two counters, not one, and they must not be merged. One counts the old front-end fallbacks. The other counts places where compiler code still re-points a name — a practice the language no longer permits, kept alive only for named compiler files, counted per file, allowed only to decrease. Counting it is what stops "temporary" meaning "forever".

Retractions and corrections

At the same volume as the original claims, with the mechanism rather than just the corrected value.

  • The coverage denominatora number that could not be wrong▸ the mechanism▾ hide

    Three counts of our own test suite disagree. Any percentage built on them was invalid, not approximate.

    We have quoted "42 of 760 tests invoke a real compile" and "18 of 988" — and our own test directory has been counted at both 760 and 773. Today every discrepancy was traced to a mechanism and reproduced exactly:

    760 vs 773   13 helper files live in a support/ sub-folder.
             They are imported BY tests; they are not tests.
             760 is the repo's own convention — the build file
             globs one level deep. 773 is a recursive count.

988 vs 964   964 = 760 + 204, and the compiler folder holds 205
             files with only 204 distinct numbers. Two tests are
             both numbered 988. Anything that counts by NUMBER
             silently loses one of them.

42 vs 18     Two different text searches over two different
             denominators. Neither checks whether a compile
             actually runs. A strict check finds ZERO tests that
             literally invoke a build, and about five that
             genuinely reach one indirectly.

    Six pairs of tests share a number across three directories, each pair holding genuinely different content. That is the defect the number-keyed counting was hiding.

    The rule this earned, which is worth more than the census: a green measurement whose denominator cannot be disproved is the same defect class as a test whose assertion cannot fail. Until the denominator is canonical and independently checkable, a coverage percentage is invalid rather than roughly right. Before quoting any "N of M" — ask where M came from and whether it can be re-derived, then ask what would make the number go down. If nothing can, it is not a measurement.

  • Two gates that could never failgreen for a long time, measuring nothing▸ both mechanisms▾ hide

    One used a quote form the shell silently removes; one checked for a name that had been renamed.

    The first searched its output for a phrase wrapped in a quoting form that the shell collapses before the search ever runs, so the search could never match anything. The second checked that the output mentioned run_chunk — a function renamed to launch_chunk some time ago. Both reported success continuously. Both are fixed and both were validated by breaking them deliberately and confirming they now fail.

    These two are why "all specs green" is not an exit criterion.

  • The published review page was blankfor about a day▸ the mechanism▾ hide

    88 characters of visible text served instead of 15,050, and every step reported success.

    A styling block was opened and never closed. A browser reading that treats everything afterwards as styling instructions rather than as text, so the entire page vanished. Nothing could have caught it: the tools that build the index search for a few tags and never read the document, and there was no checker, no hook and no build step.

    There is one now. It checks that containers are closed and correctly nested, that a page actually contains readable text, and that no tag has an unterminated attribute. It was verified by running it against the broken page as it actually shipped. All 285 pages on the site now pass, which turned up one further genuine defect on an unrelated page.

  • A wrong sentence about exponentiationcaught during review▸ the mechanism▾ hide

    A published page said ** groups right-to-left. The ruling is that it does not group at all.

    2 ** 3 ** 2 is an error in Hey, not a grouping. Right-to-left is what every other language does and therefore exactly what a reader assumes — which is why the table has to say so explicitly and the parser has to enforce it. Corrected in place, with the old sentence quoted so the correction is visible rather than silent.

Not doing — decided against, so nobody resurrects them

  • Adding pattern matching to unblock the compilerrejected on evidence▸ why▾ hide

    It was the plan. Tested against five real defects, it would have caught zero of them.

    The argument was that our defects are forgotten cases, and that a language feature which forces every case to be handled would prevent them. Checked against five actual defects from this codebase: none was a forgotten case. They are all one fact implemented in several places, or a tree walk that skips a branch. The live example is two walkers twenty lines apart, one of which handles for loops and one of which forgets to. Generating the walkers makes that impossible; pattern matching would not have noticed.

  • Shipping a slice a day into trunksuperseded▸ why▾ hide

    The cadence that produced 475a is not the cadence for this work.

    You lifted the always-shippable constraint. Trunk still receives fixes, but the restructure is the work now. Releases also now batch several topics and run the multi-hour test battery once for the batch — with the rule that when it fails, we identify which topic caused each failure and drop that one rather than re-running everything.

  • Adding &&= and ||=rejected▸ why▾ hide

    Not in the closed operator set, and they mix two ideas that deserve separate decisions.

    They would combine changing state with deciding whether to evaluate something at all. Either is fine; arriving at both as a side effect of a different ruling is not.

Owed, and honest about it

  • The fast-Hey noticeowed a third session▸ what it is▾ hide

    v0.99.475a made every standard-library call about 77× faster and nobody was told.

    75.42 microseconds to 0.976 per call, and a roughly 7.9-millisecond process launch removed entirely. One of the four affected functions runs on every request of every routed web application.   • A silent wrong answer, found todayfiled, not fixed▸ what it is▾ hide

    set x += 1 prints an error, reports success, and continues with the old value.

    Measured on the version you are running. In the interpreted route it prints invalid name: count + to the error channel, exits reporting success, and carries on with the stale number. In the compiled route it refuses, with the malformed name having travelled all the way down. A wrong answer with a success code is worse than a crash. Queued against the underlying pattern — what counts as a name is decided in about twenty-eight places — rather than spot-fixed.

Glossary — reference for the shorthand used above

Every term on this page in plain English. Terms coined since the previous ladder are marked NEW.

front end — the part of a compiler that reads your source text and turns it into a structure. Hey does not currently have one; building it is the whole restructure.

tokenizer — the step that chops source text into words and symbols. parser — the step that arranges those into a tree. resolver — the step that works out what each name refers to.

runway NEW — the fifteen ordered steps from today's compiler to the restructured one. Named because the order matters more than the individual steps.

projection NEW — a cut-down view of the operator registry generated for one stage, so that stage cannot consult information it has no business acting on.

declared forms NEW — which shapes an operator has (before a value, between two values, after one, or as a state update). Replaces the old character-list approach to deciding what a minus sign means.

state slot NEW — a private storage location owned by one actor, monitor or supervisor. The only thing in Hey whose contents can be replaced.

binding NEW — the association between a name and a value. Bindings in Hey are permanent; this is what "immutable" means here.

unfalsifiable denominator NEW — a total that nobody can independently check, making any percentage computed from it meaningless rather than approximate.

ratchet — a counter allowed to move in one direction only. Used to retire old practices without pretending they are already gone.

the four-step discipline — write the test; confirm it fails, and fails for the expected reason; fix it; then break the fix again to prove the test can still fail. A test that has never been watched failing is not evidence.

VERIFIED · LANDED · DEPLOYED — three different things, never blurred. VERIFIED means proven on a branch. LANDED means committed and through the full test battery. DEPLOYED means on trunk, which is the only one you can feel. Today: four documents DEPLOYED, no compiler code LANDED or DEPLOYED.

trunk — the branch your installed version is built from. per-core bar — the performance target: within 3% of Go on one core, roughly 97,000 requests a second. Aggregate throughput does not count.

1BRC — the "one billion row challenge", a benchmark that reads a billion rows and groups them. fannkuch — a benchmark dominated by tight loops and function calls.

silent wrong answer — the defect class this project cares most about: the program produces an incorrect result and reports success. Worse than a crash, because nothing tells you to look.

census — a systematic count of some property across the whole codebase, used to find how many places independently decide one thing.
