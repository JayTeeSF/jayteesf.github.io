Now — the named versions

Correctness first: three silent-wrong-answer families found and measured this week. Click any item for the code.

  • 472a wfloatarithin flight▸ show the bug▾ hide

    A float that reaches arithmetic through a variable silently computes as an integer in the compiled binary.

     
    let a = 1.5
says a * 2        # script: 3.0     binary: 2
says a - 2        # script: -0.5    binary: -1
says a / 2        # script: 0.75    binary: 0
says (a) * 2      # script: 3.0     binary: "1.51.5"  # string-repeat!
says 1.5 * 2      # script: 3.0     binary: 3.0      # literal rescues it
says a.type       # both lanes: float            # the VALUE knows!

    The rule choosing int-vs-float arithmetic scans the source text for a float literal — it takes a bare string and has no access to the symbol table, so it cannot ask what a is even in principle. A redundant parenthesis changes which classifier claims the expression, hence the string repeat. The fix routes any operand that isn't statically proven through helpers that dispatch on the runtime value — helpers the interpreter already uses, so the semantics are already shipped.

    Status: native emitter half implemented + committed; the fix agent measured that the Hey-owned mirror emitter also mis-claims boxed *, so its arm is in progress. Zero new runtime ABI.

  • 473a whasimplemented▸ show the bug▾ hide

    A program using has(coll, k) through a function runs in the script and dies in the binary.

     
    fn look(coll, k)
  return has(coll, k)
end
says look([10, 20, 30], 1)   # script: true   # binary: exit 70
                             # "has? string-key fast path expects a JSON object"

    Same disease as 472a: the compiled lane guesses the key's type from its spelling, decides a boxed parameter "must be a string key", and commits to the object-only fast path — which then refuses an array receiver at runtime. The fix (the same pattern that fixed put in 470a) dispatches on the receiver's kind and the key's runtime type. This is the last catalogued type-guessing site — the whole family is then converted.

    Status: implementation complete in its worktree; verification battery interrupted by today's API instability, resumes next.

  • 474a · 475aqueued▸ show the bugs▾ hide

    Comparisons on float variables take the wrong branch; division by zero is undefined behavior instead of an error.

     
    # 474a — ordering comparisons (wrong CONTROL FLOW, worse than wrong math)
let a = 1.5
if a > 1            # script: takes the branch   binary: skips it
  says 'big'        # (1.5 truncates to 1, and 1 > 1 is false)
end

# 475a — integer division by zero
says 7 / 0          # script: error "/ by zero", exit 70
                    # binary: undefined behavior — a garbage value

    474a widens the 472a fix to < <= > >=. 475a makes compiled integer / and % fail closed with the interpreter's exact diagnostic instead of executing a machine divide-by-zero.

  • ~476a+ the collision programruled today▸ show the bugs + the design▾ hide

    Your data, your functions, and your names always win — with a warning when you shadow a builtin. Your four rulings, as code.

     
    # Bug 1 — your DATA loses (32 reserved names steal the dot):
let h = {type: 'admin', count: 5}
says h.type       # today: object   # the runtime's type tag, not your data
says h.count      # today: 1        # the FIELD COUNT, not your 5
says h['count']   # today: 5        # brackets always reach your data

# Bug 2 — your CODE loses, and the two lanes disagree (213 of 214 names):
fn find(n)
  return 99
end
says find(1)      # script: (empty — the BUILTIN ran)   # binary: 99

# The ruled design — builtins are module functions; sugar is opt-in:
import Sys                    # one line: the recommended defaults
says Collections.uniq(xs)     # always available, no import races
says xs.uniq                  # works because Sys exposes it
fn find(n) return 99 end      # YOURS wins, both lanes —
                              # warning: 'find' overrides a builtin
                              #   (suppress with an explicit override marker)

    Ruled in full today: adopt exposing-import, uniformly, warning channel as its own slice (warnings can harden into errors per-code), and user-wins in both lanes with a mandatory, explicitly-suppressible override warning. A system-wide census says the warning would fire in ~191 live files today; an interim hard error would have bricked every shipped dist's stdlib, so: warning, not error.

    Also in this train: recursion (the interpreter currently segfaults with no message around depth 500 — research workflow saved, fix follows), and the resolver memo that stops every delegated call from re-walking the filesystem (~112 probes per run, measured).

The retirement ladder — R2 → R8

"Get rid of native C." Two separate deletions, marked red. Only groundwork is done; neither deletion has started.

  • R2 ~490alive rung▸ what it means▾ hide

    The Hey-owned compiler must accept every program the old C one accepts. ~12–18 refusals left, was ~30.

     
    # Every build prints a receipt naming which emitter did the work:
selfhost_consumer=hey-llvm-text   # the Hey-owned emitter — the future
selfhost_consumer=direct-mir      # fell back to the C emitter — debt

# R2 = drive the fallback count to zero. One refused call currently
# forces the WHOLE program back to the C emitter.

    All 106 corpus examples already route through the Hey-owned emitter with zero fallbacks; the remaining reds are harder shapes in the wider spec suite.

  • R3 ~515adeletion #1▸ what gets deleted▾ hide

    DELETES the native LLVM emitter — ~14,900 lines of heyc.c.

    Today two emitters exist: the C-hosted one (heyc.c) and the Hey-owned one (stdlib/HeyLlvm.hey), and every landing proves them byte-identical on the whole corpus. R3 deletes the C copy: first pin golden .ll files as the reference (done, 393a), then split the string helpers it shares with the bootstrap backend, then delete the emitter island batch by batch with the goldens as the gate.

    This is why today's fixes put semantics in shared runtime helpers, never in emitter branches — code written there dies with the file. Needs R2 closed plus a conformance corpus that doesn't exist yet.

  • R4small · any time after R2▸ what it means▾ hide

    Honest labels, and a tripwire against new native code.

    Rename the comparison-only "native-c" labels to explicit stage0 everywhere, and add a checker that fails the build if ordinary tooling ever grows a new call into the native backend outside the allowlisted bootstrap set. Cheap insurance that the debt only shrinks.

  • R5 ~500agates R6 + R7▸ why it gates everything▾ hide

    The test suite itself must stop running on the thing being deleted.

     
    # Every spec today executes on the interpreter inside hey_repl.c:
heyc specs/language/1295_… --test     # runs on the C interpreter

# After R5 the same spec compiles and the BINARY's output is asserted:
spec 'value semantics across lanes'
  expect stdout "true\ntrue\n"        # checked against the compiled program
end

    You can't certify the deletion of the interpreter with gates that run on it — that's circular. R5 builds the compiled spec runner, migrates suites in batches with both lanes agreeing, then flips heyc --run to compile-and-run by default.

  • R6 ~530adeletes hey_repl.c▸ what gets deleted▾ hide

    The REPL stops being a second implementation of the language. Largest schedule risk on the board.

    The interactive session moves onto a JIT (compile each fragment with the ordinary pipeline, load it hot — target <100ms per entry); Eval moves with it; the shell itself becomes Hey code. Then hey_repl.c — ~2,600 lines of C expression evaluator that must agree with the real compiler forever — is deleted. Research is banked; one unproven runtime re-entry probe is the swing item (5–8 agent-days).

  • R7 ~540adeletion #2▸ what gets deleted▾ hide

    The bootstrap C backend goes — the deletion that actually ends native C.

     
    # The fixed-point proof that makes the seed compiler deletable:
stage1 = hey_compiler_built_by_C_seed(source)
stage2 = hey_compiler_built_by_stage1(source)
assert bytes(stage1_output) == bytes(stage2_output)   # byte-identical

    Once Hey-built-by-Hey reproduces itself byte-for-byte without the C seed, the seed backend (~1,650 lines) is deleted and recovery becomes published per-platform bootstrap binaries — the same model Go and Rust use.

  • R8 ~550athe end · realistic ~Aug 14▸ the end state▾ hide

    semantic_debt_files = 0 — no language semantics live in C.

    heyc.c shrinks to what a launcher honestly needs: CLI argument handling, build-mode dispatch into Hey-owned tooling, and object/link mechanics. Every rule about what Hey programs mean lives in Hey source, compiled by Hey, verified by compiled specs.

2 · Recursion, guaranteed

▸▾

Full tail-call depth in both lanes; a clean error where depth is real.

 
fn countdown(n)
  if n == 0 return 'done' end
  return countdown(n - 1)      # tail position
end
says countdown(1000000)
# compiled today: done (scalar tail calls already become loops)
# script today:   segfault ~depth 500, no message
# target: 'done' in both lanes; non-tail overflow says
#         "recursion depth exceeded", never a crash

This is also the Erlang idiom Hey's actors want — the server loop as tail recursion. Research workflow is saved and runs on demand; the fix follows it, and recursion returns to the tutorial once guaranteed.

4 · Tight loops — fannkuch

first real numbers tonight ▸▾

Fannkuch runs and is CORRECT in Hey for the first time. The asymptotic wall is gone; a harsh constant remains — and it's now precisely localised.

 
# fannkuch-redux is permutation flipping — its inner loop is array stores:
set a = put(a, i, a[j])   # the swap; 471a made this MOVE instead of copy

# The wall, measured against the same box's own prior numbers (ns/put):
N=8    194 → 33      N=64   1,018 → 34      N=512   7,369 → 33
# was LINEAR in N (an O(n) copy per store) — now FLAT: 223× at N=512

# First full run — correct at n=7 AND n=10 against the published reference:
n=10:   C -O2 151 ms  ·  Go 161 ms  ·  Hey 24,354 ms  (161× C)

# The finding is the CONTRAST — same box, same compiled lane:
registers-only loop (no arrays):   Hey/C = 1.058×  # re-cut at 471a
array-touching loop (fannkuch):    Hey/C = 161×

Both rows are 471a, same box, same session — between 6% and 161×, the only thing that changed is touching array elements. The bill of materials is now EXACT: two heap allocations + two frees per element store (64 B, flat in N), both malloc sites named by backtrace — the array READ boxes its result (dead on arrival, never escapes), and the store shim boxes its return (the runtime calling convention). Fix schedule: wputfuse tier 1 removes the read box (2→1 allocations, ~475a–477a window, days) — projected to roughly halve the 33 ns, measured after it lands, never before; tier 2 (unboxed values across the shim boundary) is its own program aligned with R3. Darwin and Ruby columns land when the bench seat lifts the staged harness.
