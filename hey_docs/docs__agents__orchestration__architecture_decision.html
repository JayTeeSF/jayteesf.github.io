ARCHITECTURE DECISION — the three-implementation problem

Status: **RECOMMENDATION, awaiting maintainer.** Written 2026-07-27

after a two-architect tribunal (opposite priors, no coordination) and

primary-source research into Rust, Pony, Go and Nim. Sub-agents are

unavailable until 2026-07-27 17:00 PT; this is the orchestrator's

synthesis of completed work.

---

THE PROBLEM, restated so it survives a restart

Hey has **three independent implementations of its semantics**:

the tree-walking interpreter in `hey_repl.c` (which is ALSO the

spec-test runner), the native LLVM emitter in `heyc.c`, and the

Hey-written emitter in `stdlib/HeyLlvm.hey`. The only systematic

cross-check is **byte-identity of emitted IR between two of them**.

One day of investigation produced, without looking for any of it:

`String.to_i` works interpreted and dies compiled; `Env.executable_path`

does the reverse (and is broken on deployed trunk); `boxed == 42`

returns three answers across three implementations, two wrong by two

different wrong mechanisms; the Hey lane emits IR that `llvm-as`

rejects; the Hey lane fails closed on shapes native compiles; a gate

that could never fail (~360 versions) and one that could never pass

(~170).

---

FINDING 1 — the byte-identity gate is not weak, it is HARMFUL

`stdlib/HeyLlvm.hey:4747-4757` contains a hand-ported copy of the

native emitter's WRONG lowering, with a source comment explaining that

the stringification is deliberate. **The gate imported a bug on

purpose.** Eleven lines earlier the same function does the right thing

for a different RHS kind.

And when the Hey lane emits STRICTLY BETTER IR — one `icmp` instead of

a heap stringification plus `strcmp` — the gate classifies the

improvement as a fail-closed violation.

An identity gate cannot distinguish "agrees and correct" from "agrees

and wrong". It can only propagate. This is the project's own standing

rule — *agreement between under-measuring instruments is not evidence*

— violated structurally, at the centre of the toolchain.

---

FINDING 2 — R3 (delete the native emitter) IS NOT AVAILABLE, and the

numbers are worse than either architect expected

Architect B measured, on a deterministic 1-in-6 sample of

`specs/language` (108 of 645):

Hey lane FAILS CLOSED**77.8%** (84/108)
native accepts those same files**94%** (79/84)

And the decisive structural fact: **`tools/hey_selfc.hey:867-903`

routes the product build to `build-mir --backend llvm` whenever the Hey

lane fails closed.** Native is not a duplicate mirror. It is the

SHIPPING BACKEND for most of the corpus, receipted as

`selfhost_consumer=direct-mir`.

R3.3 as written would not remove redundancy; it would delete the

backend that compiles ~500 `specs/language` files. **And the gate that

would authorise the deletion executes only 44.1% of the code being

deleted.**

R3.1 is ALSO not done as claimed: `check_llvm_goldens.hey:183` calls

the live native emitter unconditionally, and

`regression_hey_llvm_emitter.sh` carries 72 native invocations — whose

BEHAVIOURAL assertions run the `*_native` binaries. The goldens are

checked in; the *reference* is still the living emitter.

---

FINDING 3 — the correction to the orchestrator's own hypothesis

I proposed: one semantic core, interpreter executes MIR, divergence

becomes impossible. **Primary sources say that is half right, and the

missing half is the half that bit us.**

FOR (Rust RFC 1211, the closest precedent that exists): pre-MIR rustc

analysed an AST while executing bitcode — *"the reliability of safety

analyses is reduced because the gap between what is being analyzed and

what is being executed is very wide."* MIR closed that gap; Miri and

const-eval now execute **the same MIR the compiler compiles**, sharing

one `InterpCx`. That migration replaced an evaluator that walked the

AST — the precise analogue of what was proposed here.

AGAINST, and this is the load-bearing correction: **a shared IR fixes

divergence in SHAPE, not at the PRIMITIVE-OPERATION BOUNDARY.** Rust

has one IR and one engine and STILL had to write RFC 3514 to legalise

compile-time/run-time disagreement — *"evaluating the same `const fn`

on the same arguments can produce different results at compile-time and

run-time"* — because the interpreter implements float ops in softfloat

and the hardware does not. `const_eval_select` lets a function

deliberately differ. The lang-team question "must a `const fn` behave

the same at runtime?" is **still open**.

**`boxed == 42` is a primitive-operation-boundary bug, not a shape

bug. Adopting one IR would NOT have fixed it.** The core must own the

VALUE MODEL — boxing, equality, coercion, truthiness — as a single

implementation consumed by all lanes. One IR with three `eq`

implementations behind it reproduces Rust's float situation exactly:

one IR, one engine, two answers, and eventually a document explaining

why that is fine.

---

FINDING 4 — nobody credible pins emitted-IR bytes as a gate

projecthow backends are kept equivalent
rustc `codegen-llvm` / `assembly-llvm`**FileCheck PATTERNS** on the few lines carrying semantics — byte identity is the failure mode this design avoids
rustc `mir-opt` (the one exact pin)explicitly a **review aid**: commit output BEFORE the optimisation so reviewers see a before/after diff. A changelog, not a gate.
rustc vs Cranelift vs GCC backends**run rustc's own behavioural suite**; `test_rustc_tests.sh` deletes what it cannot pass under headings `# missing features` / `# genuine bugs`, one reason per test. **Nothing compares backend output.**
rustc structurally`rustc_codegen_ssa` shares ~10k LOC of MIR lowering; backends implement only `CodegenCx`/`Builder` and **differ only at the leaf emitter**
Pony**220 full-program tests**, one directory each, auto-discovered by scanning, no registration. **Zero IR or assembly goldens anywhere in the tree.**

The field optimises for behavioural conformance against a reference,

plus structural sharing so implementations *cannot* diverge. We

optimised for identity between implementations.

---

THE RECOMMENDATION

**Do NOT delete the native emitter. Do NOT start a redesign. Build the

disagreement set first — it is cheap, it is the input to every

subsequent decision, and we currently do not know the size of our own

problem.**

**STEP 1 (days) — THE CONFORMANCE CORPUS.** Copy Pony's model

literally: one directory per program, auto-discovered by scanning, no

registration, holding the program plus optional `expected-stdout.txt`,

`expected-exit-code.txt`, `stdin.txt`, `args.txt`. Convert the existing

948-program corpus. Then run **all three lanes** against it and publish

the table. This makes the interpreter the reference BY CONSTRUCTION,

commits to no architecture, and turns `boxed == 42` from a discovery

into a row. **Do this even if everything else here is rejected.**

**STEP 2 (same day) — DEMOTE THE IR GOLDENS.** Keep them; regenerate

them with a `--bless` equivalent; make them **non-gating review

artifacts**, in rustc's `mir-opt` framing, documented so nobody

re-promotes them. This retires the obligation that produced the

hand-ported wrong lowering. Replace the gate with a **VALIDATOR**:

`llvm-as` over every golden and every survey output. All 70 goldens

assemble clean today (verified by this seat), so it costs nothing now

and would have caught the 953 malformed IR at the exact column.

**STEP 3 — FIX THE VALUE MODEL, not the lanes.** `boxed == 42` is a

live wrong-answer class on the SHIPPING backend today. Fix against the

interpreter's tagged equality (which both emitters already implement

correctly for `boxed == boxed`), pin all four value classes, audit the

named sibling `HeyLlvm.hey:4809-4816`.

**STEP 4 — SHARE THE LOWERING, NOT THE BYTES.** `rustc_codegen_ssa` is

the template: one lowering, two leaf emitters. This is the structural

fix for "two emitters agree because someone copied a bug across", and

it is a far smaller change than deleting 14.9k lines.

**STEP 5 — THEN, and only then, revisit R3**, against Architect B's

precondition list (P1-P10 in the tribunal record), with the migration

pattern that actually worked: rustc's `-Z borrowck=migrate` ran BOTH

lanes with disagreements downgraded to WARNINGS, ground the set to

zero over two years, then deleted the old lane. **The disagreement set

is the plan.**

WHAT THIS DOES NOT CHANGE

The performance bar and its ordering are untouched: the accept model

(`accepted == workers`) first because until it lands every concurrency

number is invalid; then the leak family (a w16 server dies in 18

seconds of saturation); then per-request cost (58us vs Go's 10.4us).

**None of that work is in `heyc.c`. All of it survives R8.** Deleting

the native emitter buys ZERO requests per second — both architects

agree on this independently.

THE HONEST COUNTER, kept because it is not weak

Architect B's own measurement undercuts part of my framing: **10 of the

last 20 landings were emitter dual-lane**, ~1,873 lines written twice

across 19 commits. The mirror tax IS roughly half the churn on that

horizon. And "close the acceptance gap first" has a receding-horizon

failure mode: at the current rate that is ~500 files of work, and every

landing until then opens a new divergence window. A defensible position

says: accept the capability loss, declare the unsupported 78%

out-of-scope for an alpha, stop paying. I do not hold it — the

capability loss is 4.3x the surface and no behavioural oracle exists

yet — but it is the strongest case against this recommendation.
