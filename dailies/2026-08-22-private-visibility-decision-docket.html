What private should mean for Hey

You lean toward Ruby's weak, advisory privacy. Here is the spectrum, primary-source costs, and six labelled decisions. Answer in ids — D42-c, D43-b, ….

The one fact that reorganizes this. Hey already chose an explicit exposes surface. In every language with an explicit export surface, “private” collapses into “not on the surface” — Go has no privacy keyword at all (lowercase = unexported, compiler-enforced); Rust's pub just defaults it the other way; OCaml hides anything omitted from the signature. So this is not “advisory vs. enforced” in the abstract.

The load-bearing constraint. Hey's P-3 bug proves Ruby-weak privacy is insufficient for the resolver: a private stdlib name currently changes a qualified call's answer because everything shares one flat table with no boundary. And Hey's usual motive for strong access control is absent — immutable values + actor isolation already carry encapsulation — so private here is about namespace hygiene and API clarity, not protecting mutable state. Premise for all options: whatever is chosen, non-exposure is enforced by the resolver (the exposes surface + scope graph), not left to the interpreter's load-time check.
