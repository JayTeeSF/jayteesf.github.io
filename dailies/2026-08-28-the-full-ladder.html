Progress is real. The remaining gaps are now specific enough to finish.

The project has spent too much time proving narrow slices without always turning them into whole product components. This ladder changes the unit of progress: each rung has an end condition you can see from outside the compiler.

Today’s verdict: Hey has crossed several architectural thresholds—semantic function identity, fail-closed link targets, real distributed transport, strong web throughput, stage-0 memory repair—but the compiler is still transitional. The biggest risk is not that the project lacks ideas. It is that coverage gaps and fallback paths can make a narrow green look like a finished component.

The ladder

1 · Language surface — substantial and usable

Values, simple functions, modules, imports, immutable collections, actors, jobs, IO, networking, packages and distributed transport exist. The remaining compiler work should increasingly make these features faster and more trustworthy rather than inventing another source language.

2 · Semantic identity — major threshold crossed

The resolver publishes function target identities and an identity-derived link plan. The production two-helper case now executes 101/201 instead of collapsing both same-spelling functions to one body. Call occurrence work can distinguish two identical callees on the same line by coordinates.

3 · Full call coverage — active blocker

The mechanism can attach identity to every published call occurrence, but global activation exposed 18 downstream production-emitter failures. The right next move is not one patch per failed example: classify those 18 by first structural refusal and fix the smallest shared expression-lowering seam.

Done when: A1a is default-on; the build sweep returns to 124 passing / the same eight baseline failures; A2a remains 101/201; and 1BRC compiles through hey-llvm-text with fallback disabled.

4 · Module-member identity — prepared in parallel

Carry the actual importing-unit → imported-unit → declared-module edge into resolution. Prepare module-member definitions for the same identity. Then switch module-member definitions and calls atomically—never one side first.

Done when: no static function call depends on global uniqueness or filename/module spelling coincidence.

5 · Delete name recovery — the honesty checkpoint

Once producer and consumer coverage are complete, remove @tn and raw hey_fn_ + name recovery. Missing target facts should become compiler-artifact errors, not silently correct-looking code.

6 · Ownership and MIR — turn printed text into records

R-MIR is the next substrate cleanup: inventory every place ownership/effects/reuse are inferred by scanning serialized MIR, decode the MIR row once, then make those analyses consume semantic records. This is how equivalent source spellings stop falling into different performance cliffs.

7 · MAP_PUT and 1BRC — the speed gate

The biggest known asymptotic defect is still the map-update path. Controlled tests show builtin put can be flat while method .put remains O(map). A legacy direct-MIR identity fix removed one O(map) cliff, but the production compiler still needs one semantic MAP_PUT identity and ownership reuse with fallback_count=0.

Done when: method and builtin forms have the same flat scaling, real 1BRC is byte-correct, and the result is within a credible native-performance range on both Darwin and Linux.

8 · FAST suite — prove more than one benchmark

After 1BRC, run fannkuch and web per-core under fixed compiler/artifact identities. Web has already demonstrated that Hey can exceed Go on some controlled native hot paths; the purpose of FAST is to prove that speed is broad, repeatable and not a sidecar/fallback illusion.

9 · Distributed Hey — transport first, clustering second

Transport is real and security behavior now fails closed. Discovery, membership, placement and rolling upgrades remain the next layer. Keep implementation behind compiler/FAST closure so distribution does not become another unfinished frontier.

10 · Documentation freeze — teach the finished product

When the language/compiler boundary stabilizes, durable Developer Docs and a separate Compiler Guide should replace campaign archaeology. Public pages should say what is real, what is transitional and how a user gets from “hello” to a deployed actor/web/distributed program.

That is how the project gains parallelism without repeating the 64GB runaway episode or producing contaminated performance numbers.

The standard for “complete”

A rung closes only when the production path uses the intended authority, fallback is zero or explicitly isolated to bootstrap, real programs pass, and the performance shape matches the semantic claim. That is the difference between a compiler campaign and a product people can trust.
