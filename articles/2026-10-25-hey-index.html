The compiler at a glance

  1. ParserRead source syntax.
  2. AST + resolutionResolve declarations and calls before HIR.
  3. Typed HIRKeep target-free semantic facts.
  4. Ordered MIRName values and make owners explicit.
  5. Linkage + ABI joinBind exact provider links and calling conventions.
  6. Physical MIRIndependently verify machine ABI and cleanup.
  7. LLVMEncode verified operations mechanically.
  8. Native codeCompile and link for the configured target.

This is the architecture explained by the compiler article. The migration to it is on the development line and is not finished; 0.99.605a still has the older routes.

0.99.606a is still in progress

Design and qualified components are not a completed release. Full compiler, archive, application, platform and ordinary-workload performance acceptance remain separate checks. Page examples and earlier measurements retain their recorded version scope.

For dated scorecards and comparison rules, read Performance and measurement.

The String facts below describe the development line. In 0.99.605a a String value is a pointer to an SDS block.

  • A String value is 16 bytes: text of 0–12 bytes is inline. This is a byte limit, not a character limit.
  • Long Owned and Static Strings use SDS backing. Borrowed text may point into another value or foreign storage; owning boundaries promote it when needed.
  • The whole HeyValue remains 32 bytes. The layout alone is not a measured speedup.
