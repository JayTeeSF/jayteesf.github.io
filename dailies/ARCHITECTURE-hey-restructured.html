Hey architecture / reference page / revised 5 August 2026

One front end. One resolved program. Two consumers.

This page separates the target architecture from the current implementation. The target has not changed: source is read once, module and operator meaning are resolved once, HIR is the semantic join point, and no later stage re-parses source text.

target contractcurrent stage labelsauthority still blocked
Why this revision exists: the August 2 page correctly drew the destination, but its stage labels said tokenizer, syntax tree, names, and operator registry were missing. Candidate implementations now exist; the actual blockers have moved to module closure, authoritative structural HIR/MIR, boxed truthiness, full cross-lane identity, and the last compatibility reads.

Tokens with spans. Knows spelling and longest match, not precedence or bindings.

Grouping, arity, precedence, associativity, statements, blocks, interpolation, syntax errors.

Resolver and module graph

Bindings, scopes, imports, exports, aliases, exposures, conceals, re-exports, operator overrides.

Structural HIR

One resolved semantic program. Hey operations and types; no target layout and no raw operand source.

→

Application MIR

Reachable body closure, representation types, instructions, ownership, explicit control flow and boxing.

→

LLVM text emission

A mechanical printer over MIR. It does not parse, resolve names, or infer source-level meaning.

→

Link and runtime

Native executable linked against one runtime value model, actors, builtins, I/O, and intrinsic ABI.

consumer A

Interpreter and REPL

Structural HIR is evaluated directly by a shared HIR walker using the same runtime values and builtins as compiled code.

consumer B

Compiled application

Structural HIR lowers to application MIR, LLVM text, link, and the same runtime.

The module system shape

Resolutionone authority

The resolver turns every identifier and operator use into a stable binding. It applies qualified imports, aliases, explicit exposures, selector aliases, conceals, re-exports, and file-local operator overrides. A runtime Module.load remains a value-producing operation; it is not lexical import resolution.

Application closurecurrent blocker

After resolution, the compiler computes the reachable function and data closure across the module graph and emits one application HIR/MIR program. Imported bodies are included exactly once; unused bodies may be excluded. Import cycles and ambiguous public surfaces receive deterministic resolver diagnostics.

SOURCE FILES + IMPORT GRAPH
        -> RESOLVED BINDINGS
        -> REACHABLE MODULE BODY CLOSURE
        -> ONE APPLICATION HIR
        -> ONE APPLICATION MIR
What is forbiddenno repair downstream
  • No LLVM or self-host emitter may open another source file to find a function body.
  • No MIR pass may infer an import by inspecting a qualified call string.
  • No duplicated logical and physical module representations may coexist as authorities.
  • No special case for hey_frontend_shadow.hey; the fix must compile arbitrary multi-module applications.

The operator system shape

One closed registry, projected by stagetarget contract

One declarative registry covers arithmetic, exponentiation, comparison, boolean, algebraic/collection, range, bitwise, shifts, prefix/postfix forms, and state-update forms. A generator emits only the columns each stage is allowed to know.

ProjectionWhat it may contain
TokenizerSpelling and longest-match data.
ParserDeclared forms, arity, precedence, associativity.
ResolverWhether and where a symbol may be overridden/imported.
HIRSemantic operation and short-circuit meaning.
MIRLowering strategy, representation, failure and fallback behavior.
LLVMInstruction, predicate, or runtime helper symbol.
Truthiness is not numeric conversioncurrent LLVM defect

Conditions require one Hey truthiness contract. LLVM currently routes some boxed conditions through numeric conversion, so a non-numeric non-empty string can become false. The dedicated truthiness primitive must agree for ordinary and borrowed values across interpreter, Stage-0, LLVM-direct, self-host, and REPL.
