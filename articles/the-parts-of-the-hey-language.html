Hey language · guided tour · 28 August 2026

Start with a function. Add an actor only when you need an owner.

Hey is trying to keep the source language small: ordinary values, ordinary functions, and actors for long-lived state. Modules organize the program. Jobs organize background work. Distribution extends the actor model across machines. Native compilation should make all of that fast without asking the programmer to switch to a second, lower-level language.

The whole language in one minute

  • Functions do most of the work. If a transformation can be expressed as input → output, keep it a function.
  • Values look immutable. The compiler is free to reuse storage when it proves nobody can observe the reuse.
  • Actors own changing state. Other code sends messages instead of reaching inside and mutating that state.
  • Remote actors should feel like actors. Crossing a machine adds transport and failure, not a second application model.
  • The compiler should make equivalent operations equivalent. Friendly spellings such as m.put(k,v) should not accidentally cost more than the builtin form.

1 · Values and functions are the center

fn greeting(name)
  return 'Hello, ' + name
end

program
  says greeting('Ada')
end

Why begin here?

Because most programs do not need an object hierarchy to express ordinary work. Numbers, strings, booleans, bytes, arrays and map/record-shaped values flow into functions and come back out as values.

That gives Hey the readable, direct feeling people like in Ruby while leaving the compiler room to specialize the implementation underneath.

2 · Immutability is the contract; reuse is the optimization

Suppose you update a map. The source language should behave as though the old value and the new value are separate. That does not mean the runtime must copy the whole map every time.

What the programmer sees vs. what a good compiler may do

Sourcenext = stats.put(key,value)
MeaningProduce a map with one entry changed.
Ownership proofCan anyone else still observe stats?
Single ownerReuse the backing storage in place.
SharedCopy only when the language semantics require separation.
This is still an important product gap. Controlled measurements show the builtin map-update path can be flat while method-form stats.put(...) can still follow an O(map) route. That is exactly the kind of implementation detail the language is supposed to hide. It is not finished until both spellings reach one semantic operation and the real 1BRC path gets the same scaling.

3 · Modules organize names; they should not define meaning by accident

module Accounts
  fn deposit(account, amount)
    return {...account,
      balance: account.balance + amount}
  end
end

import './accounts.hey'

program
  let next = Accounts.deposit(user, 10)
end

The compiler’s job

A filename, a module spelling and a function spelling are useful to a human. Internally, the compiler should remember the actual imported source unit and the actual function selected there.

That is how two libraries can contain the same helper name without accidentally becoming the same function at link time.

Modules define real functions. Imports choose the local vocabulary: what a file may write bare, what it writes qualified, and what it may write with a dot. Hey is heading toward having no privileged built-in layer at all — every operation gets a real module home, and Sys supplies the recommended everyday vocabulary as an ordinary module you import, narrow or replace.

Dotted syntax belongs to that vocabulary rather than to a separate object system: items.map(f) is imported compile-time sugar for map(items, f), chosen lexically by the importing scope and never by the receiver’s type. Imports that change the flavor of the language covers the whole mechanism and how far it is actually built.

4 · Actors are for owned state

A function describes a transformation. An actor describes something that continues to exist: a session, connection, cache, game, worker, device, coordinator or other stateful service.

FunctionTake values in; return a value.
ActorOwn state that changes over time.
MessageAsk an actor to do something without sharing its mutable state.
Job / supervisorOrganize background work, retry and failure.
The simplicity test: if ordinary functions are enough, use functions. Actors are not “objects by another name”; they exist because mutable state needs a clear owner when work becomes concurrent or long-lived.

5 · Distribution extends the same model across machines

Remote work should not force a new programming style. The application still talks to actors; the distributed layer adds node identity, transport, security, stale-node handling and the possibility that a machine is unavailable. If you want to try it rather than read about it, Distributed Hey: one program, more machines walks through two nodes on one laptop, two containers, and two real machines over TLS.

6 · Native compilation is underneath, not beside, the language

The intended path is straightforward:

ParseFind the structure of the program.
ResolveDecide what every reference means.
HIRCarry those decisions forward.
MIRExpose execution and ownership choices.
LLVMLower to native machine code.

The important architectural word here is not “LLVM.” It is carry. Once the front of the compiler knows which function or operation you meant, later stages should not infer it again from a printed name. The Architecture of Hey is the canonical account of how that pipeline actually works, and of which parts of it are still transitional.

Concrete progress, as of 28 August 2026: the native and Hey-owned emitters agree on all 91 pinned LLVM fixtures. An earlier 90/91 diagnosis was disproved by measuring the actual current producers. The wider examples corpus is a separate, stricter test and still contains four genuine divergences.

7 · “Fast” has to survive real programs

A language can look impressive on a tiny loop and still be slow where applications spend time. Hey’s performance program therefore needs three different proofs.

Algorithmic shape

An update that should be constant-time must stay constant-time as the collection grows. This is where method-form map update still fails today.

Whole-program speed

1BRC and fannkuch test whether the compiler can keep good representations and ownership decisions across functions, loops and data structures.

Server behavior

Web throughput and tail latency test allocation, IO, scheduling and concurrency. Measurements must identify sidecars and fallbacks so the number belongs to the intended path.

About the “1000× faster than Python” kind of claim: it is useful as an ambition, not as a release criterion. Hey should publish pinned workload comparisons and cost curves, not one giant multiplier. The architectural goal is the same one that makes Mojo interesting: high-level source code should not force high-level runtime overhead when the compiler can prove a cheaper representation.

9 · The promise

Hey should feel small even when the program becomes serious. Start with a function. Add a module to organize code. Add an actor when state needs one owner. Let the same actor model cross machines. Let the compiler—not the programmer—do the work required to reach native representations and reuse storage safely. That is the product: Ruby-like ergonomics over simple functions and actors, without accepting Ruby-like overhead as the price.
