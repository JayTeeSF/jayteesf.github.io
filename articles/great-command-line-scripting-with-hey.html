Great Command-Line Scripting with Hey

One job, two implementations, one rule: the outputs must match to the byte. The job is this site's package index: walk the packages/ folder, sort what's there, and write one HTML page. It exists in Ruby and in Hey, side by side. This article shows what idiomatic Hey looks like next to idiomatic Ruby, how to run a Hey script three ways, and the habits that keep a script honest.

Hey can read like Ruby

The two files line up almost name for name: digit_run, trim_leading_zeroes, compare_digit_runs, compare_paths, sorted_unique, relative_path, package_section, render_page, on down the file. Ruby's initialize is Hey's new. Two excerpts, side by side:

Ruby (generate-packages-index.rb)

def sorted_unique(paths)
  paths.uniq.sort { |left, right| compare_paths(left.to_s, right.to_s) }
end

def linkable_files(files)
  sorted_unique(
    files.select { |path| LINKABLE_EXTENSIONS.include?(path.extname.downcase) }
  )
end

Hey (generate-packages-index.hey)

private fn sorted_unique(paths)
  return paths.uniq.sort(PackagesIndex.compare_paths)
end

private fn linkable_files(files)
  let linkable = []

  for path in files
    let lower_path = Text.lower(path)
    if Text.ends_with?(lower_path, '.md') or Text.ends_with?(lower_path, '.html')
      set linkable = [...linkable, path]
    end
  end

  return PackagesIndex.sorted_unique(linkable)
end

sorted_unique reads the same in both: a function value goes where Ruby passes a block. linkable_files shows the difference that's left. Ruby filters with select and a block; the Hey filters with a loop and grows a new list with [...linkable, path]. A Ruby programmer reads it cold, but it is longer.

The explicitness tax

The Hey file is 592 lines against Ruby's 313. Some of that is comments; the rest is Hey's explicitness: let and set, return, and loops where Ruby has blocks. Price it in.

Growing a list is cheap

Hey values don't change in place, so "append" means "make the longer list and keep it": set xs = xs.push(i) or set xs = [...xs, i]. The compiler sees that the old list is never used again and extends it where it stands, so growing a list one item at a time costs about what it costs in Ruby. Try it: 

fn build(n)
  let xs = []
  for i in 0..<n
    set xs = xs.push(i)
  end
  return xs
end

program
  says len(build(256000))
end
$ hey build grow.hey -o grow
...
$ ./grow
256000

Write xs.push(i) on its own line and nothing happens: the longer list is made and thrown away. Hey will warn about a result you drop, and _ = expr says you meant it. Decided, coming.

Running a script three ways

The generator starts with #!/usr/bin/env hey, so the same file runs three ways:

# as a script: hey compiles it, caches the result, and runs it
./generate-packages-index.hey ./packages

# the same, spelled out
hey generate-packages-index.hey ./packages

# as a program you keep: build once, run the binary as often as you like
hey build generate-packages-index.hey -o generate-packages-index
./generate-packages-index ./packages

Running through hey checks its cache on every call, which costs a little each time. For a page generator you run by hand that hardly matters; in a loop, call the binary. Everything after the file name belongs to your program. Guide 3 builds a complete command-line tool, with flags, help text and tests.

Measure output before you measure time

The thesis, and it outranks any speed number: a benchmark without an output-parity gate is a wish. Two stories from this program's history.

An early speed-up rewrote the comparator to read raw bytes from a String. It compiled, and compared every path equal to every other, so the sort did nothing and the benchmark got faster and wrong. The byte-parity check (comparing the two outputs byte for byte) caught it on the first run.

The second is worse, because the gate itself lied. The fastest result this program ever recorded was a binary that exited 0 having written nothing. The parity check blessed it because it never deleted the output file first, and so compared the one left by the previous run. That is why the harness below deletes first.

A harness that cannot lie to you

The ordering is what matters: delete before the run, check the output exists before comparing it, compare before timing. A program that produces nothing fails here instead of posting a record. Make the gate fail on purpose once (run true as a lane; it must report NO OUTPUT) before you trust it. Timing uses hyperfine, which repeats a command and reports the mean and spread. 

set -eu
export PACKAGES_INDEX_GENERATED_AT=2026-01-01T00:00:00Z   # a fixed timestamp, so outputs can match

lane() {                      # $1 = label, then the command
  rm -f packages/index.html
  "${@:2}" >/dev/null
  test -s packages/index.html || { echo "$1: NO OUTPUT"; exit 1; }
  cp packages/index.html "out.$1.html"
}

hey build generate-packages-index.hey -o generate-packages-index
lane ruby   ruby --yjit ./generate-packages-index.rb ./packages
lane script ./generate-packages-index.hey ./packages
lane binary ./generate-packages-index ./packages
cmp out.ruby.html out.script.html
cmp out.ruby.html out.binary.html

uptime                        # the machine's load travels with the number
hyperfine -N --warmup 3 --runs 30 \
  'ruby --yjit ./generate-packages-index.rb ./packages' \
  './generate-packages-index.hey ./packages' \
  './generate-packages-index ./packages'

Compare idiomatic to idiomatic. Anyone who can hand-tune the Hey can hand-tune the Ruby, so a tuned script against an untuned one measures the tuning, not the language.

Doing work in parallel

The generator is serial, like its Ruby twin. When a script has many independent items, Hey's streams run a map on several workers, and worker pools and Jobs handle bigger fan-outs. Reference 4 says which to pick, with measured costs.

Glossary

idiomatic port
A rewrite that mirrors the original's structure rather than tuning for speed.
byte-parity
Comparing outputs byte for byte, not "looks right".
hyperfine
A benchmark runner: repeats a command, reports mean ± standard deviation.
exit code
The number a process returns when it ends; 0 means success, which doesn't mean the output is right.
