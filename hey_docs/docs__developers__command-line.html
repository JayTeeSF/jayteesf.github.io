Hey command line#

The public command surface is intentionally small:

hey        run programs and select command families
heyc       compile, check, test, and inspect source
hey-repl   interactive shell
hey test   repository verification
hey perf   performance and profiling

From a source checkout, use ./bin/...; installed distributions provide the same names without the prefix.

Discover commands#

./bin/hey help
./bin/hey help all
./bin/heyc --help
./bin/test --help
./bin/perf --help

Files under bin/subcmds and tools are implementation plumbing, not additional public commands.

Run and build programs#

./bin/hey hello.hey one two three
./bin/hey build hello.hey -o build/hello
./build/hello one two three

hey FILE.hey content-addresses the absolute source path, transitive import graph, frontend/compiler inputs, and target. An unchanged warm run reuses the native executable.

Application compilation uses one path:

source -> tokens -> final syntax -> names -> HIR -> MIR -> LLVM -> native executable

Check and test source#

./bin/heyc hello.hey --check
./bin/heyc hello.hey --test
./bin/heyc hello.hey --run

--check stops after source validation. --test runs embedded specs. --run is a developer/interpreter lane and is not a native performance benchmark.

Inspect compiler phases#

./bin/hey phase syntax app.hey -o build/app.syntax.json
./bin/hey phase hir build/app.syntax.json -o build/app.hir
./bin/hey phase mir build/app.hir -o build/app.mir
./bin/hey phase llvm build/app.mir -o build/app.ll
./bin/hey phase build build/app.mir -o build/app

See Compiler phases.

REPL#

./bin/hey repl
./bin/hey-repl --llvm-fragment fragment.hey

See REPL guide.

Documentation and learning#

./bin/hey doc SYMBOL
./bin/hey tour list
./bin/hey tour verify
./bin/hey challenge list
./bin/hey challenge verify
./bin/hey learn verify

Publish the curated public documentation atomically:

./bin/hey docs publish

Default destination:

$HOME/dev/jayteesf.github.io/hey_docs

Choose another destination or preview the resolved operation:

./bin/hey docs publish --out build/hey-docs
./bin/hey docs publish --dry-run

hey doc-site remains the low-level renderer for internal audits. Public publication always uses --kind public, validates required pages, excludes agent/history pages, and swaps the complete site only after generation succeeds.

Packages and native extensions#

./bin/hey package --help
./bin/hey native --help
./bin/hey vendor --help
  • package resolves, locks, restores, verifies, audits, and publishes package graphs;
  • native generates/verifies typed native-extension ABI shims;
  • vendor copies a constructed target distribution into an application.

Target distributions#

./bin/hey target matrix
./bin/hey target doctor --target darwin-arm64
./bin/hey target release --target darwin-arm64 --out build/hey-darwin-arm64.tar.gz

A target archive is a self-contained compiler/runtime distribution for one OS/architecture. Structural checks, native execution, signing, and publication are separate receipts. Current target availability belongs in Implementation status and the target matrix, not in the language reference.

Verification#

./bin/test
./bin/test --full
./bin/test --repl
./bin/test --hir-mir
./bin/test --conformance
./bin/test --compiler-contract
./bin/test --docs

Release and promotion suites remain explicit because they are expensive and platform-dependent:

./bin/hey verify focused
./bin/hey verify full
./bin/test --promotion-report

Performance#

./bin/perf --help
./bin/perf compiler-matrix
./bin/perf workloads
./bin/perf scheduler
./bin/perf 1brc-full --help

Performance claims must identify corpus, hardware, cold/warm mode, behavior parity, and a failing threshold.

Source checkout maintenance#

./bin/hey cache path
./bin/hey cache gc
./bin/hey zip --downloads
./bin/hey clean
./bin/hey rebuild

clean and rebuild intentionally discard reusable artifacts. They are not prerequisites for focused source or documentation checks.
