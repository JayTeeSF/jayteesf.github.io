The compiler at a glance

  1. ParserLossless single-pass parse (HeySyntaxTree.hey).
  2. Core AST + resolution67-kind Core AST & (unit_id, node_id) binding (HeyProgramResolution.hey).
  3. Typed Tree HIRMonotone flow lattice & #TypeTuple call-instance typing (HeyHirInference.hey).
  4. SSA-MIRBraun sealed-block SSA with origin & block_scopes (HeyMirSsa.hey).
  5. Facts & workersRange/escape facts & carrier/borrow worker deduplication (HeyMirFacts.hey).
  6. Physical MIR16B HeyStr, zero-RC borrows, Perceus reuse, COW fusion & arenas (HeyMirOwnership.hey).
  7. VerifierIndependent 8-invariant SSA, RC, borrow & region gate (HeyMirVerify.hey).
  8. LLVM & nativeMechanical .ll encoding (HeyMirLlvm.hey), C seed (HeyMirC.hey) & native target link.

This is the unified 8-stage native architecture shipped in 0.99.608a and explained by Compiler 1. Every user program and the self-hosted compiler compile through this single pipeline, bootstrapped from the committed HeyMirC.hey C seed.

What 0.99.608a ships

Release tag v0.99.608a ships the unified compiler, zero-bridge C seed, six-target cross-compilation, self-contained compression/archive stdlib, and command-line contract:

  • Unified eight-stage native pipeline & zero-bridge C seed. Every Hey compilation unit runs through resolve-source -> emit-hir -> lower-mir -> analyze-mir -> plan-mir -> own-mir -> verify-mir -> emit-llvm in tools/hey_selfc_pipeline.hey, with byte-identical stage2 == stage3 self-hosting and the zero-bridge stdlib/HeyMirC.hey C bootstrap seed.
  • Zero-annotation two-layer specialization. Layer 1 (HeyHirInference.hey) types static call tuples (#TypeTuple) and Layer 2 (HeyMirPhysical.hey) deduplicates define linkonce_odr machine workers across unboxed scalars, countable ranges, target-aware 16-byte HeyStr, and shared pointer workers, omitting unused boxed wrappers.
  • Typed lifetimes & dynamic receiver COW fusion. HeyMirLiveness.hey and HeyMirOwnership.hey enforce zero-RC owner-scoped borrows, Perceus reuse, dynamic _take_receiver copy-on-write fusion for map and array accumulators, and hey_region_push/pop arenas on block_scopes, checked by 8 independent invariants in HeyMirVerify.hey.
  • Six-target cross-compilation & self-contained compression/archives. hey build --target supports darwin-arm64, darwin-x64, linux-x64, linux-arm64, linux-musl-x64, and windows-x64, and the standard library includes zero-dependency Deflate, Zlib, Gzip, Xz, Zstd, Compress, Tar, and DEFLATE Archive.
  • Ruling B3 exit-status contract & hirb. Clean runs exit 0; uncaught runtime failures in program (or failed hey test specs) exit 1; CLI usage, missing-file, syntax, and static compile errors exit 2; 70 is reserved for internal compiler invariant bugs. The interactive REPL is hirb, and hey supports -e/--eval, -v/--version, and --.

For benchmark baselines and comparison rules, read Performance and measurement.

The String storage rules in 0.99.608a:

  • A String value is 16 bytes (HeyStr, carried in two 64-bit registers on arm64/SysV x64 and indirect struct ABI on Win64): UTF-8 text of 0–12 bytes lives inline with zero heap allocation and zero reference-count traffic.
  • Long Owned and Static Strings use 32-byte-header SDS backing. Borrowed views point into live owner storage with zero RC traffic; owning boundaries promote them automatically.
  • Generic dynamic HeyValue cells remain 32 bytes.
