BRIEF wfloat — compiled-lane arithmetic/ordering dispatch on RUNTIME VALUE TYPES (slice 1 of 3)

ORCHESTRATOR'S STANDING ADDITIONS (override on conflict):

  • READ FIRST: docs/agents/orchestration/agent_standing_rules.md and

docs/agents/lessons.md.

  • Worktree: .worktrees/wfloat only, own env script + cache home.

FIRST ACTION: pwd + git rev-parse --show-toplevel; abort if wrong.

  • ONE WRITER: never touch the main tree or docs/agents/**.
  • THIS DISPATCH IS SLICE 1 ONLY (boxed `- * / %` value dispatch,

native emitter, rows 1-7+9-verify+10 below). Slices 2 and 3 are

separate future dispatches — do not start them.

  • D5 + WMIXEDRET TRACING ARE REQUIRED TASKS: (a) `print b` prints 1

compiled while `says b` prints true (both bools, both platforms,

direct-mir). (b) NEW (linux, receipt on stock 470a): a MIXED-RETURN

function — one branch returns a comparison, another an int — renders

the bool branch as 1 compiled (`says maybe?(200)` -> 1, oracle true),

while pure-bool returns, bool locals, and bare comparisons are ALL

correct; consistent reading is single-scalar return inference letting

the int branch win and coercing the bool branch to i64. Trace both to

their predicate/site. If a mechanism is this family and the fix is

inside slice 1's touched arms, include it with its own oracle-anchored

acceptance case; if it is a different site, REPORT the trace and leave

the fix out — the report sizes its own slice. Do not silently expand

scope. Also answer: does an explicit `-> bool` annotation change the

mixed-return case?

  • THE PROBE'S DESIGN TEMPLATE EXISTS IN-FILE (linux finding): follow

heyc_llvm_arith_key_term (heyc.c ~:7730) — it takes ctx AND locals,

uses the literal test ONLY for literals, routes identifiers through a

resolved lookup, and returns a TAXONOMY (1=object-rooted, 2=int

literal, 3=i64 scalar local, 0=reject) rather than a boolean. Model

heyc_llvm_boxed_arith_expr's operand classification on it.

  • Spec/gate numbers stay as literal placeholders <NEXT-SPEC> /

<NEXT-GATE>; orchestrator derives at transplant.

  • Commit subject: "fix:" naming wfloat; never docs-prefixed.
  • Commit in the worktree; do NOT push; orchestrator transplants.
  • Verdict-first report; every claim with file:line or a receipt;

perf cost of the boxed helper stated as a measured number.

GOAL

Convert compiled-lane binary arithmetic (`- * / %`; `+` is already

converted) from spelling-gated i64/string dispatch to the 470a

pattern: statically PROVEN types keep their scalar/string fast paths

byte-for-byte; every operand whose type is not proven stays BOXED and

dispatches through the already-shipped runtime helpers

(hey_llvm_add/sub/mul/div/mod_value, hey_runtime.c:25726-25809),

which ARE the interpreter's hey_add/hey_sub/hey_mul/hey_div_op/

hey_mod. After this slice, `let a = 1.5; says a * 2` prints 3.0 in

both emitters and `(a) * 2` stops string-repeating. No new ABI: all

helpers already declared in BOTH preludes (heyc.c:20743-20751,

HeyLlvm.hey:9328-9336) — goldens are expected to move ZERO lines.

STRUCTURAL FINDING (top of brief by ruling): the lexical gate

heyc_llvm_float_arith_operand (heyc.c:8446) has signature

(const char *expr) — NO ctx, NO locals. It cannot consult a variable

type even in principle; its siblings is_string_expr and is_bool_expr

both take ctx. Any fix inside that signature is a heuristic. The

predicate loses AUTHORITY (becomes one disjunct of the new probe and

the falsification restore path), not existence.

NON-GOALS (scope fence)

  • Slices 2 (ordering comparisons) and 3 (scalar div/mod-by-zero

fail-closed) — separate dispatches. EXCEPTION: boxed-operand

division by zero must already match the oracle after slice 1 via

hey_div_op — include it in slice 1's acceptance.

  • The --backend llvm-direct lane ("11.5") — catalogue only.
  • Text repeat semantics and hey_llvm_string_repeat_value itself —

only the CLASSIFIER feeding tier-2 loses authority over boxed

operands.

  • Float FORMATTING — parity is against the oracle's own rendering.
  • heyc_llvm_is_string_expr (:13300) and heyc_llvm_boxed_candidate

(:12056) — 100+-site shared predicates; claim new shapes with an

ADDITIVE probe at the routing sites. (Exception: tier-2's

site-local paren normalization — row 3 — changes the SITE, not the

predicate.)

  • The interpreter and hey_add/hey_sub/hey_mul/hey_div_op/hey_mod/

hey_compare_raw — the oracle's own body.

  • Integer-scalar pinned semantics: 7 / 2 -> 3 (spec 1119), Int×Int

scalar ops, licensed S3 accumulator shapes,

heyc_llvm_boxed_arith_key / hey_llvm_i64_index_expr?.

  • Equality (==/!=) and float-vs-float ordering arms — measured

CORRECT; must not move a byte.

THE DESIGN

No new semantics carriers: the five helpers plus value_cmp_i64 exist,

are delegates to the interpreter's own arithmetic (float promotion,

string repeat, "/ by zero", all inherited verbatim), and are declared

in both preludes. This slice only re-ROUTES: proven-Int → unchanged

scalar ops; proven-String×IntLiteral → unchanged tier-2 repeat;

everything else stays boxed and calls the helper, which decides

NOTHING itself. Additive arms sit AHEAD of any stringifying arm

(is_string_expr answers 1 for every boxed candidate — spec 1274 —

ordering is load-bearing). Because HeyLlvm declines boxed-arith MIR

units to the native consumer, a native-only slice preserves lane

byte-identity by construction — and that same mechanism makes

lane-vs-lane comparison BLIND to this family, so acceptance is

ORACLE-anchored, never identity-anchored.

ACCEPTANCE (ORACLE-ANCHORED; oracle = ./bin/heyc <f> --run, NOT ./bin/hey)

Every case: compiled stdout+rc equals oracle stdout+rc exactly, BOTH emitters.

1. Flip set (full measured reach): let a = 1.5 → a * 2 = 3.0;

a - 2 = -0.5; a / 2 = 0.75; a % 2 (oracle's answer/diagnostic);

(a) * 2 = 3.0 with IR reaching mul_value NOT string_repeat_value;

float×float two-variable; laundering let s = 1.5 + 0.0; s * 2 = 3.0;

reassignment set a = a - 2; says a = -0.5 (assert no int_value

rebox in the store path); fn f(x) return x * 2 end; f(1.5) = 3.0;

[a*2] and {v: a*2} as oracle renders; says a.type still "float" in

the SAME program as the arithmetic; boxed division by zero

(a / 0.0; x/y with y=0 boxed) matches the oracle via hey_div_op.

2. D5 trace task per standing additions (fix in-slice ONLY if it lands

in touched arms; else report).

3. Static shapes byte-identical: 1.5 * 2, 7 / 2 = 3, i % 32 loops,

proven-string repeat, string concat, equality arms. Goldens move

ZERO lines. Any golden moving ANY line = stop and explain.

4. Corpus survey N/N IDENTICAL, 0 REFUSED, serial in the worktree.
