What carried forward on the compiler track

548a is the current landed version. The active work is the O(n²) performance campaign, and its pieces must be kept named separately — they are distinct mechanisms, not one lever:

  • Perf B — insertion-order hash index: landed. Map lookups no longer scan an association list; an insertion-order-preserving hash index answers has?/get/keys. This is the map lookup track, distinct from the clone-per-put win that COW closed earlier.
  • A1 / A2.1 — non-retaining borrow: landed. A value-sensitive move-on-return (A1) relaxes ret <name> to a move, and A2.1 lets a non-retaining map borrow (has?/get/keys) not escape a self-consuming build. Together these were the 548a milestone: a map O(n²) eliminated.
  • A2-core — interprocedural consuming-operand move authorization: running on a WIP branch. A direct interprocedural-reduce receipt collapsed clones from quadratic to linear. This is analysis-side work, decoupled from codegen.
  • W9 receiver-form ownership fix — proven, land-ready, intentionally not merged yet. Making m.has?()/get/keys non-retaining in condition position fixes the has?-guarded map-overwrite pattern, and it is measured: W9 55.73s → 0.84s, ~66×, O(n²)→O(1). It is deliberately held back to land after A2-core 3b/4, so it does not sit on top of a moving ownership implementation. This is proven-but-unlanded and sequenced — not an open cliff, and not the same thing as the A2-core interprocedural work above.
  • Track C — string-concat runtime: landed but inert. The geometric string-concatenation runtime landed, but it is inert pending the emitter move; it is not yet exercised on the authoritative path.

Nothing here invents a number. The honest three-state summary: the map lookup and non-retaining-borrow levers landed at 548a; the W9 receiver-form ownership fix is proven at ~66× but intentionally unlanded, sequenced behind A2-core 3b/4; and A2-core interprocedural move authorization is running on a WIP branch. This daily's substance is the new track below.

The invariant carried this cycle

The compiler discipline established over the cross-unit campaign still holds: canonical MIR handed to codegen carries the resolver's proven facts, never re-inferred names, and how it lowers is a backend choice. The performance campaign adds a second invariant it must not violate — a borrow that does not escape must not force a clone. A2.1 encodes exactly that: a non-retaining map read used only to build a self-consuming result is proven not to escape, so the backing store is reused rather than copied. The move-on-return relaxation (A1) is the same principle at the return boundary. What is not yet true is the interprocedural generalization — authorizing a consuming operand to move across a call boundary — which is why A2-core lives on a WIP branch and is reported as in progress, not landed.

Distributed Hey — stdlib-first / no-VM track

Today opens a new track. Its foundational ruling is an architecture decision, and it is deliberately unglamorous: distribution is runtime and library work, not compiler or VM work. Hey does not grow a virtual machine, does not ship bytecode between machines, and does not offer distributed shared memory. It gets distribution the same way it got its actor model and its standard library — by composing runtime services in .hey over a thin layer of native primitives.

The architecture ruling

The pipeline is a straight line, and LLVM appears in it only once — to compile each node to native code:

Hey source
  → native Hey program (per node, via LLVM)
    → existing local actor runtime
      → Distributed stdlib/runtime services
           (node identity/discovery · remote addressing · wire codec ·
            transport + TLS · monitors / failure detection)
        → network

LLVM is irrelevant to distribution beyond producing the native binary for each node. Every distribution concern above lives in library and runtime code. When a choice presents itself between changing the language or the compiler and composing a stdlib/runtime service, the ruling favors composition.

The key strategic choice: explicit remote references first

Hey ships explicit remote actor references before it attempts magically location-transparent PIDs. The unit of addressing is an immutable RemotePid — a NodeId, an ActorId, and a node_incarnation — reached through an explicit API: Remote.send(pid, msg), Remote.monitor(pid), Remote.call(pid, req, timeout). Because remoteness is explicit, distribution ships without changing the local PID representation. Making an ordinary send transparently route across nodes is a later ergonomic decision layered on top — never a prerequisite for the first working system.

The first milestone

The near-term goal is stated as one falsifiable event: two native Hey binaries, on two machines, over TLS, send an immutable structured value to a named remote actor, receive a reply, then one node is killed and the remote monitor fires — built from stdlib modules plus thin native socket/TLS primitives. If that event is reached, distributed Hey is real. Everything else — transparent PIDs, gossip, virtual actors, stronger delivery guarantees, cluster-global registries, rolling upgrades — becomes evolution rather than a blocker.

The census is done; the vertical slice is running

The D0 capability census is complete, and its verdict is the first hard evidence for the whole architecture ruling: 12 of 15 primitives are already ready, and the single load-bearing native gap for the secure v0 substrate is TLS server-side accept. There is zero compiler or language dependency in that gap — it is a native primitive, not a syntax, MIR, or LLVM change — which is exactly what the stdlib-first / no-VM ruling predicted.

With the census closed, the vertical slice is now running, all behind decoupled interfaces: the Distributed.Codec (D3 wire format), the TLS-server primitive (the one native gap), and the Transport / Node / RemotePid / Remote.send / Remote.call / Remote.monitor substrate. All of it is written in .hey over a thin native socket/TLS surface — no compiler change, consistent with the D15 ruling that v0 needs zero new syntax, MIR, or LLVM.

The remaining construct frontier

On the compiler track the construct frontier is unchanged from 547a: the cross-unit call boundary is crossed, and the remaining families are bounded, enumerable arms — callable/comparator arguments (the largest remaining group), json of a nested field, len/value of a cross-unit call in scalar position, tail-self boxed recursion, and native intrinsic byte forms. The hard architectural problem — resolved cross-unit interfaces crossing the MIR boundary without embedding runtime dispatch in the IR — was solved over the 547a campaign. The performance campaign, not the construct frontier, is where the compiler track's active energy sits this cycle.

Verification & falsification

The compiler track's landed levers carry their own mutation contracts and the differential-verify standard from prior cycles; the version at stdlib/Version.hey now reads 0.99.548a, bumped under that standard rather than absolute-green.

The Distributed track has its D0 census done and its substrate slice running, but it is not yet verified end to end — so its falsification is stated as design commitments to be honored when code exists, not as checks that pass today:

  • The first milestone is the falsification test: two nodes, TLS, a value and a reply, a kill, and a monitor that fires. Until that event is produced, no rung above D0 may be reported as proven — a running slice is code under way, not a cross-node receipt.
  • Honest failure detection: no rung claims perfect failure detection; partition and death are observationally indistinguishable, so D6 monitors report DOWN/NODE_DOWN as observations, not certainties.
  • Delivery honesty: at-most-once — a successful Remote.send means accepted for transport, not processed remotely (D4).
  • The D17 matrix and protocol fuzzers (peer kill, mid-frame reset, truncated/oversized/invalid frames, TLS/version mismatch, reconnect, monitor/timeout races, slow receiver, queue full) are the standing falsification suite the track must satisfy as rungs land.
  • Wire compatibility is its own contract (D21), distinct from the compiler's byte-identity standard — cross-release fixtures, not source reproducibility.
