Immutable record style#

Hey records hold data. Modules hold behavior. Receiver syntax makes statically selected module functions readable without introducing classes or mutable instances.

Data stays data#

let account = {
  owner: 'Ada',
  balance: 100,
}

Create a changed record with spread syntax:

let deposited = {...account, balance: account.balance + 25}

The original account remains unchanged.

Behavior lives in a module#

module BankAccount
  fn deposit(account, amount)
    return {...account, balance: account.balance + amount}
  end

  fn withdraw(account, amount)
    return {...account, balance: account.balance - amount}
  end

  fn current_balance(account)
    return account.balance
  end

  exposes deposit forms: [:qualified, :unqualified, :dotted]
  exposes withdraw forms: [:qualified, :unqualified, :dotted]
  exposes current_balance forms: [:qualified, :unqualified, :dotted]
end

Choose the calling form at import time#

Qualified style:

import './bank_account.hey'

let next = BankAccount.deposit(account, 25)

Receiver style:

import './bank_account.hey' \
  exposing: [deposit, withdraw, current_balance] \
  forms: [:dotted]

let next = account
  .deposit(25)
  .withdraw(10)

says next.current_balance()

The chain lowers to nested ordinary calls. No runtime shape search occurs.

Why this is not a class API#

  • A record has no hidden identity or mutable slots.
  • A module function can accept any value satisfying its runtime contract.
  • Imports select names and forms lexically.
  • Receiver calls insert the receiver as argument one.
  • State that truly requires identity belongs in an actor.

This style keeps business values serializable, comparable, testable, and safe to move between functions, actors, workers, and Jobs.
