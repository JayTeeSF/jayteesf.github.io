The standard library

93 public modules and 261 builtins, sorted into families so you can find the one you need. Each family has a program that was compiled and run, with its real output. The complete name lists are folded under "all public names" and are generated from the toolchain's own exposure catalog, so they can't drift from what the compiler accepts.

How to use this pageThe name lists come from the exposure catalog, a generated file listing every public name the compiler accepts. Find the family, read its example, then import 'stdlib:Module' and call Module.name(...). Builtins (len, split, put, to_json …) need no import at all. Every module and builtin here is Works today unless a badge next to it says otherwise.

Three layers: builtin, stdlib module, package

Hey's built-in functions are bound to the runtime inside the toolchain; your code calls them like any other Hey function: len(xs) is just len(xs). The mechanism is in the compiler article.

Text and strings Works today

  • Text: split, trim, case, padding, words, replace, natural comparison.
  • Re: regular expressions (match, find, scan, replace, split). Note the argument order: Re.matches?(pattern, value) but Re.scan(value, pattern).
  • StringAlgorithms: Knuth-Morris-Pratt and Rabin-Karp substring search.
  • Markdown: check Markdown files and their links.
Spot the trap. Re.matches?('^[0-9]+$', '4096') and Re.scan('a1b22c333', '[0-9]+') are both in the program below. Which argument is the pattern in each? (Answer: the first in matches?, the second in scan. Name your variables pattern and text and the trap goes away.)
text.hey
import 'stdlib:Text'
import 'stdlib:Re'
import 'stdlib:StringAlgorithms'

program
  let line = '  Hey   is   fast  '
  says Text.squish(line)
  says Text.split('a,b,c', ',').to_json
  says Text.words('the quick brown fox').length
  says Text.pad_left('7', 3, '0')
  says Text.replace_all('a-b-c', '-', '+')
  says Text.upper('ada') + ' ' + Text.lower('LOVELACE')
  says Text.starts_with?('hello', 'he')
  says Re.matches?('^[0-9]+$', '4096')
  says Re.scan('a1b22c333', '[0-9]+').length
  says Re.replace('12-34-56', '-', '/')
  says StringAlgorithms.kmp_all('abababa', 'aba').to_json
end

Bytes and binary Works today

  • Bytes: immutable byte strings; slice returns a view that shares memory instead of copying.1 How Bytes and Strings share a layout is in Values, memory and Strings.
  • Binary: write and read u8/u16/u32 in little or big endian.
  • Bits: test, set, clear, rotate and extract bit fields of whole numbers.
  • Codec: versioned binary encoding of Hey values with size limits (used by distributed Hey).
  • Archive: pack and extract archives, refusing unsafe paths like ../.
bytes.hey
import 'stdlib:Bytes'
import 'stdlib:Binary'
import 'stdlib:Bits'

program
  let raw = Bytes.from_text('Hey!', 'utf-8')
  says Bytes.at(raw, 0)
  says Bytes.decode(Bytes.slice(raw, 0, 3), 'utf-8')
  let packet = Binary.concat([Binary.u8(7), Binary.u16_be(513), Binary.u32_le(1)])
  says Binary.to_integers(packet).to_json
  says Binary.read_u16_be(packet, 1)
  says Bits.bit_at(10, 1)
  says Bits.set(0, 3)
  says Bits.rotate_left(1, 1, 4)
end

Data formats Works today

  • Json: decode, encode, and encode_canonical (sorted keys, for hashing and comparing).
  • Jsonl: one JSON value per line, with atomic writes and appends.
  • Schema: describe a shape (Schema.object, Schema.string …) and validate values against it.
  • Ehy: ERB-style templates (<%= %>, <% %>); hey_web views use them (Web server guide).
formats.hey
import 'stdlib:Json'
import 'stdlib:Jsonl'
import 'stdlib:Schema'

program
  let doc = Json.decode('{"name":"Ada","tags":["math","code"]}')
  says doc.name
  says Json.encode({b: 2, a: 1})
  says Json.encode_canonical({b: 2, a: 1})
  says Jsonl.encode([{id: 1}, {id: 2}])
  let shape = Schema.object({name: Schema.string(), age: Schema.integer()}, ['name'], false)
  says Schema.valid?({name: 'Ada', age: 36}, shape)
  says Schema.valid?({age: 'old'}, shape)
end

Collections Works today

Arrays and objects are built in, and builtins like put, push, keys and len work on them directly. Collections adds the everyday toolkit: map, filter, reduce, sort, uniq, group, chunk, frequencies. The other modules are named data structures, each an immutable value: Set, Dictionary, OrderedMap, OrderedDictionary, List, Queue, Deque, Stack, Heap, PriorityQueue, Ranges. Map.put is the put the compiler can recognize as one operation so it can update a uniquely owned map in place (Values, memory and Strings). Iteration.times(n, f) calls f(i) for i from 0 to n - 1.

collections.hey
import 'stdlib:Collections'
import 'stdlib:Set'
import 'stdlib:Dictionary'
import 'stdlib:Heap'
import 'stdlib:Queue'
import 'stdlib:Iteration'

fn double(x)
  return x * 2
end

fn even?(x)
  return x % 2 == 0
end

fn add(acc, x)
  return acc + x
end

fn ascending(a, b)
  return a - b
end

fn shout(i)
  print i
end

program
  let xs = [3, 1, 4, 1, 5, 9, 2, 6]
  says Collections.map(xs, double).to_json
  says Collections.filter(xs, even?).to_json
  says Collections.reduce(xs, 0, add)
  says Collections.sort(xs, ascending).to_json
  says Collections.uniq(xs).to_json
  says Collections.frequencies(['a', 'b', 'a']).to_json
  says Collections.chunk(xs, 3).to_json
  let counts = {}.put('a', 1).put('b', 2)
  says counts.to_json
  let s = Set.from_array([1, 2, 2, 3])
  says Set.length(s)
  says Set.includes?(s, 2)
  let d = Dictionary.put(Dictionary.empty(), 'x', 10)
  says Dictionary.get(d, 'x', 0)
  let h = Heap.from_array([5, 2, 8], ascending)
  says Heap.peek(h, nil)
  let q = Queue.enqueue(Queue.enqueue(Queue.empty(), 'first'), 'second')
  says Queue.peek(q, nil)
  Iteration.times(3, shout)
  says ''
end

Trees and graphs Works today

Balanced search trees (AVLTree, RedBlackTree, SplayTree, BinarySearchTree), range trees (SegmentTree, FenwickTree), generic Tree and BinaryTree, graphs in three representations (Graph, AdjacencyList, AdjacencyMatrix), GraphAlgorithms (BFS, DFS, Dijkstra, Bellman-Ford, Floyd-Warshall, A*, topological sort, Kruskal, Prim), MinimumSpanningTree, UnionFind and its twin DSU, and BloomFilter. The story of how these were added, from Fenwick trees to attention, is its own article; the overlay documents STDLIB-DATA-STRUCTURES-OVERLAY.md and STDLIB-ALGORITHMS-ML-OVERLAY.md list each module's contract.

graphs.hey
import 'stdlib:Graph'
import 'stdlib:AVLTree'
import 'stdlib:UnionFind'
import 'stdlib:BloomFilter'

fn compare(a, b)
  return a - b
end

program
  let g = Graph.add_edge(Graph.add_edge(Graph.empty(true), 'a', 'b'), 'b', 'c')
  says Graph.breadth_first(g, 'a').to_json
  says Graph.reachable?(g, 'a', 'c')
  says Graph.reachable?(g, 'c', 'a')
  let t = AVLTree.put(AVLTree.put(AVLTree.put(AVLTree.empty(compare), 3, 'c'), 1, 'a'), 2, 'b')
  says AVLTree.keys(t).to_json
  says AVLTree.height(t)
  let uf = UnionFind.union(UnionFind.new(4), 0, 1)
  says UnionFind.connected?(uf, 0, 1)
  says UnionFind.component_count(uf)
end

Files and I/O Works today

  • Files: read, write, list, copy, move, lock and memory-map files and directories.
  • Io: handles with read_exact, read_line, read_until, memory mappings, select and select_async waits, cancel tokens. Readiness runs on kqueue (macOS), epoll (Linux) or poll, reported by Io.reactor_backend().
  • Streams: map, filter and each over items with N workers, optionally keeping order (Workers, Jobs and streams).
  • Pipes: Pipes.create(capacity) makes a bounded byte pipe; a writer waits when it's full.
  • StaticFiles: resolve and read files under a root safely, for web servers.
files.hey
import 'stdlib:Files'

program
  let dir = 'build/files-demo'
  let made = Files.ensure_dir(dir)
  let path = Files.join(dir, 'notes.txt')
  let written = Files.write_text(path, "one\ntwo\nthree\n")
  says Files.exists?(path)

Concurrency and sync Works today

The modules are listed here; what they mean is in their own pages: Actor (call and reply, Actors and failure), Workers and Jobs (Workers, Jobs and streams), JobsRemote, DistNode, DistRemote, DistTransport (Distributed Hey).

Sync merges edits to the same field made on different devices: every edit carries a clock (time, counter, device) and its ancestors, and merge_field picks the same winner on every device no matter which order the edits arrive in. A later edit that descends from an earlier one simply wins; two concurrent edits are a reported conflict resolved by clock. Below, the phone and laptop edit the same title at nearly the same time; both merge orders choose the laptop's (later clock).

sync.hey
import 'stdlib:Sync'

program
  let phone = Sync.clock(1000, 0, 'phone')
  let laptop = Sync.clock(1000, 0, 'laptop')
  let base = Sync.first_revision('title', 'Draft', phone, 'r1')
  let on_phone = Sync.edit(base, 'Phone title', Sync.tick_for(phone, 2000, 'phone'), 'r2')
  let on_laptop = Sync.edit(base, 'Laptop title', Sync.tick_for(laptop, 2001, 'laptop'), 'r3')
  let a = Sync.merge_field(on_phone, on_laptop)
  let b = Sync.merge_field(on_laptop, on_phone)
  says a.winner.value
  says b.winner.value
  says a.reason
  let later = Sync.merge_field(base, on_phone)
  says later.winner.value + ' (' + later.reason + ')'
end

Known gaps

  • Ehy only renders from inside a Hey source checkout (it shells out to ./bin/heyc).
  • Matrix.from_rows, and so every Matrix program, is refused by the 606a code generator.
  • Cli.parse treats --name value as a switch plus a positional, unlike Cli.flag.
  • Crypto.random_bytes returns a Result object, unlike Bytes functions.
  • Argument order differs inside Re: matches?(pattern, value) but scan(value, pattern).
  • Eval is unavailable in compiled programs; Reflection answers may differ by lane.
  • Standard library modules resolve without an import line on 606a (Reference 2), so forgetting one isn't caught:
    stdlib_ambient.hey
    program
  says Text.upper('no import line above')
end
    $ hey stdlib_ambient.hey
    NO IMPORT LINE ABOVE
  • Proposed: a Sys facade replacing ambient builtins.
  • The inventory counted "149 functions" in Collections; the 606a exposure catalog lists the public names shown here. The lists on this page come from the catalog, which is what the compiler accepts.
