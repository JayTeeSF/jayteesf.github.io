Hey architecture · canonical current reference · 28 August 2026

One compiler. One meaning. Then make it fast.

Hey’s architecture is easiest to understand as a promise: the front of the compiler decides what the program means; every later stage carries that answer forward. The project has made real progress toward that promise. The remaining work is no longer “invent the compiler.” It is to close the places where later stages still reconstruct meaning from printed names or printed IR, then turn those closures into measurable speed.

Where we are: version 0.99.554a is an uncertified development checkpoint. Function target identity and the link plan are real; occurrence-exact call targeting exists; the wrong-code two-helper case is closed on the production path. What remains is complete expression/emitter coverage, the module-member producer gap, deletion of name recovery, and the ownership/intrinsic path that still keeps .put far from C-class performance.

The architecture in one picture

1 · SourceRuby-like syntax, simple functions, modules, actors, immutable values.
2 · ResolutionImports, bindings and call targets become semantic identities.
3 · HIREvery resolved occurrence should carry the identity it was given.
4 · MIRExecution, ownership and effects become explicit records—not guesses from text.
5 · Link planTarget identity maps to one native symbol.
6 · LLVM/runtimeMechanical lowering and fast reuse, with no semantic rediscovery.
The architectural rule: spelling is for people; identity is for the compiler. If two functions share a name, they may still be different functions. If put(map,k,v) and map.put(k,v) mean the same intrinsic operation, they must converge to the same semantic operation before ownership and code generation.

What is actually finished

Resolved function identity

ProgramResolution publishes target unit/function identity and an identity-derived link plan. The production two-helper wrong-code case now stays distinct through code generation.

Occurrence-exact call facts

HIR can now consume exact call occurrences with full coordinates, including two same-named calls on one line. The resolver—not a text scan—decides which spans are calls.

Fail-closed link authority

A target-bearing call whose link row is missing fails as an invalid compiler artifact. It does not silently recover a native symbol from the source name.

Bootstrap runaway repaired

The stage-0 return-cleanup leak was fixed with frame-scoped LIFO cleanup. The bounded resolver run dropped from multi-gigabyte growth to a low, stable footprint in the measured Darwin control.

The shortest path from here

Lane A · finish A1a

First classify the 18 default-on failures. Fix the smallest common HeyLlvm expression seam instead of adding one arm per syntax spelling. 1BRC compiling with the production consumer is a hard activation gate.

Lane B · prepare A1 in parallel

Carry real import edges into module resolution and prepare module-member definitions for target identity without turning the producer switch on yet.

Lane C · R-MIR census

Inventory every semantic ownership decision that scans MIR text. This is read-only work and should run while the write lane builds.

Lane D · performance

Keep Linux reproducing the same structural failures and the .put scaling fixture. Once identity coverage closes, promote MAP_PUT and rerun 1BRC before broad benchmark suites.

Integration discipline: the orchestrator should not be the only person doing every grep, fixture and investigation. Use several narrow research/write lanes, but one local heavy-build token. Only one self-host rebuild, full sweep, 1BRC compile/timing run or large profiler job runs locally at a time. Static analysis and remote Linux work can proceed in parallel.

What “done” means now

A component is not done because a gate has a green line. It is done when its semantic authority is singular, its fallback is removed or explicitly bounded, its real product path runs, and the performance curve matches the architecture. For the compiler, that means one Hey-owned semantic compiler. For 1BRC, it means the method spelling reaches the same O(1) operation as the builtin form. For distribution, it means the transport and later cluster services fail closed and have product-level examples. For the language, it means Ruby-like ergonomics without hiding semantic ambiguity in compiler string scans.
