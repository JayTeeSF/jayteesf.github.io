One ruling, followed from source to native code

606aRelease 0.99.606a, the one shipping now. Everything below lands in the release after it.
ResolutionThe step that decides which declaration each name refers to, by identity, never by spelling.
HIRThe first compiler layer after parsing. It works out what the program does and each value's type.
MIRThe layer below HIR. It decides evaluation order, how values sit in memory, and who frees them, and when.
LLVMThe code generator that turns MIR into machine code. It only follows MIR's plans.
externInternal only: how Hey's own built-in library is bound to the runtime. User code never writes it and the compiler refuses it there.

Take one line of ordinary Hey:

let clean = trim(name)

Today the compiler knows clean is a String only because the word trim appears in one of six hand-written name lists inside HeyHir.hey (231 names in all). Rename the function and its type quietly becomes Value, the slow "could be anything" type. That's the kind of fact-from-spelling the compiler rules forbid.

Your rulings: "SCRAP the cruft and do the right thing", and then that extern is only for Hey's internal built-in library. It is a hidden syntax inside the toolchain: never shown to users, never taught, and refused in user code, packages, the REPL and hey run. Ordinary Hey functions have no types and no arrows: fn shout(name).

Now follow the call down the chain. The parser reads the built-in's declaration, found only in the built-in binding module. Resolution binds trim(name) to that declaration's identity, not to its spelling. HIR types clean as a String from the declaration. MIR reads the declaration's borrow facts: no copy and no reference-count change for name. LLVM calls trim in the runtime, and a table of runtime functions is checked against these declarations so the two can't drift. The six lists and the side tables that duplicate them are deleted.
