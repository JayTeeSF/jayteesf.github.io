First, preserve what the program means

The language contract defines what a Hey program means. Comparing interpreter and native results is one practical check that both lanes preserve that contract: given the same input, they must produce the same observable answer. The compiler may choose smaller representations and reuse memory, but it may not change the answer. Checked examples are evidence for those examples, not proof that every language form is covered.

That sounds obvious. The difficult part is keeping the answer stable while a friendly expression becomes machine instructions. A stable internal identity—an ID chosen by resolution, not a printed function name—lets every later stage know which definition a call selected. The architecture guide follows that handoff.

private fn root_step(value, guess, remaining)
  if remaining == 0
    return guess
  end
  return root_step(value, (guess + value / guess) / 2.0, remaining - 1)
end

program
  says root_step(9.0, 3.0, 4)
end

A self-tail call is a function's final action calling itself. The compiler can turn it into a loop so the call stack does not keep growing. Numbers such as 2.0 are floating-point values: a binary approximation used for numbers with fractional parts.

One hidden route is gone, and one hard path is real

Official commit 6bf118f1f deletes the runtime standard-library interpreter service: its C service block, exported declaration, command protocol, and compiler emission route. That is an architectural closure. It does not say that every file named “sidecar,” every compatibility default, or every fallback elsewhere has disappeared.

The floating-point tail-call repair is similarly specific. MIR planning now carries typed floating-point loads and arithmetic for a composed self-tail argument, and the generated compiler projection consumes it. On Darwin arm64, native runs reached 100,000 iterations with copy-on-write off and on. Withdrawing cleanup, representation, or plan authority makes the controls fail. This is correctness and bounded-stack evidence, not a speed benchmark.

The latest focused refusal belongs to high-level typing

The latest focused provider run selected Transformer and discovered Matrix as a private provider, moved past that tail call, and then stopped in Transformer. A floating-point argument reaches a parameter inferred as an integer. The complete archive as a whole remains unaccepted. The backend already passed 29 of 29 focused application-binary-interface assertions. An application binary interface is the agreement about how a function receives values and returns a result.

That result changes the diagnosis: adding an integer conversion in LLVM would hide the wrong high-level representation. The pending repair belongs in high-level intermediate representation type inference, keyed by resolved call identity. It is planned, not implemented. Applications close the compiler claim

Focused ordinary application proofs can proceed with their required provider closure before the complete archive is accepted. A full product release still requires the complete archive and real-consumer gates. MMeow, top5_game, and my_queue_2 have not yet passed ordinary build and runtime checks with fallback forbidden. Linux still needs a fresh compiler, image/link, and correctness run. A focused green fixture cannot stand in for those consumers.

There is one essential distinction. Stage0 may create the bootstrap seed that builds the next compiler. That is part of a compiler bootstrapping itself. A production application silently choosing Stage0 because ordinary lowering failed is a different route and is not accepted. The pinned bootstrap trunk at a406cdd8d remains untouched.

The ladder continues after compiler correctness

A focused higher-order ownership mechanism has landed: a known reducer identity can carry a consume-and-return contract, while an ordinary indirect call remains borrowed. Its specification checks observable output and MIR authorization with copy-on-write disabled; it does not measure speed. The larger acceptance still needs ordinary immutable rebuilds, clone and allocation counts, scaling, and real consumer evidence.

Repeated copying and repeated computation are different costs. Ownership can remove a copy when a value has one owner and no later observer of the old logical version—a proven last use. It cannot fix an algorithm where every new item revisits all previous items, a quadratic pattern. Those scans need indexes or summaries at the semantic layer.

Beyond that are the already-decided language directions: ordinary module authority and imports, type evidence from explicit casts, specification behavior, and nullability rules. These are not freshly retested here. Local actors, jobs, remote transport, and distributed product gates likewise need their own runtime and failure receipts; a compiler milestone does not close them.

Measure only after the path is named

Measure compiler memory, copying, and repeated work now, on a named compiler and route; those measurements help diagnose the current blockers. Each comparison must name the commit, host, architecture, flags, workload, and available fallbacks. Publish broad product-speed claims only after the corresponding correctness and consumer gates pass. A result from one route is not evidence about another.
