The Hey Project Glossary

This is the shared glossary the daily reports and articles link into: skim it never, jump into it always. Every term below has its own anchor, so any piece that uses the word can point straight at its definition instead of re-explaining it.

The cast

The Hey language

Hey is a small, statically-typed language where every value is immutable — once created, it can never be changed, only replaced. Its compiler is being rewritten in Hey itself instead of C, and its web server is being pushed toward matching Go's per-core throughput. Both efforts are tracked as the project's two standing goals: see G1 and G2.

The orchestrator

The seat that owns the only branch code is allowed to land on. It reviews and gates everyone else's work (and its own sub-agents'), red-teams risky plans before they're built (see red-team / pre-chew), and keeps the project's map of where things stand current. Other seats propose, measure, and challenge; only the orchestrator commits.

Seats

A seat is one ongoing Claude Code session with a standing role and its own machine. The bench seat (macOS) owns load harnesses, probes, and the production apps' performance configs; the Linux seat runs the same measurements on hardware the bench machine doesn't have. Seats never edit each other's files — they measure and report, and cross-check each other's numbers instead of trusting either one alone.

The bus

~/dev/cagents, a plain git repository used as a message queue between seats on different machines. Nothing one seat says exists for another seat until it's pushed and pulled — there's no live channel, only the repo. Each seat runs a background watcher that checks its inbox every few minutes; skip that step and a seat goes deaf for the rest of its session, which has already cost a full day of missed messages once.

How work ships

Slice

The project's unit of work: one focused change, built and tested in its own worktree, small enough to land and gate in a single sitting. Roughly 70 slices have shipped this way. "That's its own slice" is how the project defers a real idea without losing it.

Landing / the train

A slice becomes a landing when the orchestrator merges it to the mainline branch after every gate passes, bumping the version (say, 442a to 443a). Landings queue and merge one after another in strict order — the project calls that sequence the train. You don't skip your place in line, and a stuck landing blocks everything behind it.

Worktree

A separate, isolated checkout of the code where one agent builds and tests a slice without stepping on anyone else's in-progress work. Each worktree gets its own environment settings and its own cache directory — two agents once collided by sharing a cache, which is why that's now a hard rule rather than a suggestion.

The chain

The full sequence of gates a slice must clear, in order, before it can land: goldens, contracts, regressions, and more, run back to back. "In the chain" means a slice is partway through that run. Like a real assembly line, the chain can jam if too many runs compete for the same machine at once.

Red-team / pre-chew

Two adversarial reviews that bracket a piece of work. Red-teaming happens before anything is built: someone tries to break the plan itself. Pre-chewing happens after an implementer finishes but before their diff is trusted: a reviewer walks the actual change looking for what the plan missed. Both exist because "the plan looks right" and "the code is right" have turned out, repeatedly, to be different questions here.

Correctness machinery

The two compilers & byte-identity

Hey is compiling itself out of C: an old, trusted compiler written in C and a newer one written in Hey itself must produce bit-for-bit identical output for every program that runs through both. Any disagreement is treated as a bug and blocks the change — the project calls this posture fail-closed. Byte-for-byte agreement is the actual evidence that the new compiler is safe to eventually replace the old one.

Goldens

A fixed set of expected outputs, pinned in the repo, that a gate compares fresh output against byte-for-byte. Goldens are a reference, never a shortcut: if new output differs from a golden, the rule is to find out why, never to just update the golden and move past the failure.

The survey

A full run of every example program the project keeps as its corpus, done after any change broad enough to shift behavior in places nobody was specifically testing. It's the tripwire for the failure mode where a change quietly breaks something distant and unrelated — a shift in the survey's own results has caught exactly that before.

Gate / known-red

A gate is a test wrapper that prints one plain green-or-red line, and a commit requires every gate green. Known-red is the maintained list of gates already known to be broken for understood, unrelated reasons, so nobody loses a night rediscovering the same bug twice. A gate that can never turn red isn't testing anything either, so that gets checked for too.

Load-flake

A test that passes reliably alone but fails only under real parallel load — not because the feature is broken, but because the test collides with itself or its neighbors under contention. The fix isn't to delete it; it's to name it explicitly and re-run it in isolation before trusting a red result from it.

The goals

G1: fast

Goal 1: get Hey's web throughput within 3% of Go's, per CPU core, under matched conditions — a ratio, re-checked every time Go's own number is re-measured, not a fixed target. The matched-row version of that bar has now been beaten, not just met, certified on two operating systems.

G2: self-owned

Goal 2: finish deleting the old C compiler and its C-based REPL entirely, so Hey's own compiler is written in Hey with no duplicated logic left behind in a second language. The project tracks progress toward this as a literal countdown of remaining files.

The R-ladder (R2–R8)

The staged plan for retiring the old C compiler, rung by rung, R2 through R8 — each rung closing one category of "the C version can still do something the Hey version can't" before the next rung starts. You can't delete years of trusted C in one leap; you retire it a proven rung at a time.

Performance & memory

I5 / the refcount program

The plan to change how Hey shares values in memory: instead of always copying a value when it's handed somewhere new, sometimes share the original by reference and count who's using it — like a library tracking who has a book out instead of reprinting it for every reader. It's currently ranked as G1's single biggest remaining lever.

K8 / the retention bug

A memory bug where compiled Hey code created values inside a loop and never freed them, so a running server's memory climbed request after request until it had to restart itself. Its root cause in the language's own loop-compilation code has been fixed; a second copy of the same class of bug, living in different code the web server alone uses, is still open and precisely located.

Just-in-time compilation (JIT)

Turning code into machine instructions inside the already-running program and calling it immediately — no file written, no linker, no new process started. Hey's interactive session currently does the opposite: every line you type rebuilds a real executable and launches it, which is where most of the waiting goes. A just-in-time session is a design under measurement, not shipped software.

Dynamic symbol table

The list of names a program publishes so that code can look them up while it runs. It is smaller than the table a debugger reads, and by default a program does not publish itself into it at all. That gap is why a function can exist, be perfectly callable directly, and still come back “not found” when something asks for it by name — the exact failure behind The Test That Never Ran.

The mux / event core

An alternate design for the web server's connection handling: instead of giving every open connection its own OS thread (expensive, and mostly idle), a small pool of threads takes turns servicing whichever connections have work ready — the same core idea as an event loop in Node.js or nginx. Measured on both operating systems, it wins on threads used for the same load, with no memory penalty.
