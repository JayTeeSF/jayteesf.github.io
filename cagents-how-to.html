Cagents · how-to · 31 August 2026

Talk to agents through Cagents. Open direct edges only when you mean to.

The Maintainer is the default communication hub. Agents do not get an automatic mesh simply because they share a project. Cagents messages, grants, tasks and live activity are the interface; provider wrappers are transport adapters underneath it.

1. Start or resume an actor

The desired operator command is intentionally small:

cd ~/dev/cagents
export CAGENTS_ACTOR=orchestrator

bin/cagents agent run \
  --project hey \
  --provider claude \
  --cwd ~/dev/hey

The wrapper does the plumbing: validates project membership, reads agents/orchestrator/START.md, starts or resumes the provider session, watches the actor's Cagents inbox, and publishes normalized provider activity back into Cagents.

The startup prompt is not the project. “Go” can be enough because durable context lives in START.md, tasks, refs, decisions, evidence, lessons, messages and prior run/session records.

2. Message an actor

By default, the Maintainer is the intermediary between peer actors. The Maintainer can always communicate with project actors directly.

Maintainer → orchestrator
Maintainer → overseer
Maintainer → linux

# but, by default:
overseeer → Maintainer → orchestrator

In the app, compose a normal project message to the target actor. On disk, the message body exists once and delivery is represented by a mailbox ref:

projects/hey/messages/posts/maintainer/2026/08/<message>.md
projects/hey/messages/mailboxes/orchestrator/unread/2026/08/<delivery>.ref

Once durably consumed, the delivery ref moves from unread to read. There is no second SaaS-only inbox and no special Claude control socket.

3. Let actors communicate directly when useful

The Maintainer can open a communication edge without changing project membership or command authority.

ModeMeaningTypical use
Through MaintainerDefault. Sender's request reaches Maintainer first.New or sensitive relationship.
OnceOne direct delivery opportunity, then grant is consumed.Quick handoff or question.
ScopedDirect communication while a task/run/session scope is active.Orchestrator + specialist during one task.
ContinuousDirect access until Maintainer revokes it.Overseer continuously supervising orchestrator.

Conceptually the Maintainer action is:

overseer → orchestrator
mode: continuous
scope: project
authority: advisory

Cagents records an immutable grant decision plus a small active ref. Revocation removes/moves the active ref; Git history and the grant record preserve provenance.

Direct communication is not command authority. A peer can be allowed to reach an actor continuously while remaining advisory. Maintainer instructions and binding project/task decisions still outrank peer suggestions.

4. Watch what the actor is doing

The app should show semantic activity, not just the final answer:

ORCHESTRATOR · working

10:31:02  PLAN       prove ownership repair
10:31:08  READ       runtime/hey_runtime.c
10:31:18  DISPATCH   static lane A
10:31:42  FINDING    receiver path still copies here
10:31:51  TOOL       focused grep / source inspection
10:32:03  EDIT       runtime/hey_runtime.c
10:32:10  TEST       focused ownership test passed

Provider adapters normalize structured native output into events such as plan, tool, finding, dispatch, edit, test, approval and result. Provider-exposed thinking/reasoning summaries may be included when available; hidden private chain-of-thought is not an assumed interface.

High-volume deltas should be batched into bounded semantic chunks. Do not create a Git commit per token. A richer raw provider stream may be retained for drill-down, but routine oversight should use semantic events.

5. Redirect an actor while it is working

You do not need to inject text through a special terminal session. Send another ordinary Cagents message.

@orchestrator
Don't edit that yet. Compare the ownership path against the legacy implementation first.

The wrapper is already watching the actor's authorized Cagents mailbox. It delivers accepted messages into the running provider session through the adapter's native transport. For Claude that may be structured stream input; Pi or Codex may use different mechanisms. The rest of Cagents remains provider-neutral.

If overseer has a continuous direct grant to orchestrator, overseer can send the same kind of message without Maintainer relay. If the grant is absent, the message is routed to/held for Maintainer mediation rather than silently creating a peer mesh.

6. Forward instead of opening an edge

When an agent asks to tell another actor something and no direct grant exists, the app should make mediation cheap:

Overseer wants to tell orchestrator:
"Do not benchmark yet; ownership proof is incomplete."

[ Send ] [ Edit & send ] [ Ignore ]
[ Allow direct once ] [ Allow scoped ] [ Allow continuously ]

Forwarding should preserve provenance with stable source-message linkage so the receiver can distinguish original author, Maintainer relay and Maintainer-authored interpretation.

7. Move work through the task graph

A task object is stable; workflow is a moving ref. Do not create a manually maintained STATE.md.

projects/cagents/tasks/live-provider-bridge/TASK.md

# current state is represented by exactly one workflow ref
projects/cagents/refs/workflow/todo/live-provider-bridge.ref
projects/cagents/refs/workflow/in_progress/live-provider-bridge.ref
projects/cagents/refs/workflow/done/live-provider-bridge.ref

Use semantic transitions so Cagents updates refs and records events atomically:

bin/cagents task show live-provider-bridge
bin/cagents task start live-provider-bridge
bin/cagents task event live-provider-bridge --type progress --stdin
bin/cagents task done live-provider-bridge

The exact CLI spelling may evolve, but the invariant must not: one workflow authority, one accountable owner, durable events/evidence, and no duplicated hand-maintained status document.

8. Subagents are attempts, not extra project owners

The orchestrator may dispatch child runs aggressively for static investigation while preserving a single accountable task owner. Each run has provenance and results; it does not automatically become a permanent project participant or gain peer messaging rights.

task: ownership-repair
owner: orchestrator

runs:
  static-lane-a   → actor/run provenance
  static-lane-b   → actor/run provenance
  focused-test    → serialized heavyweight execution

Communication for a child run can be task/run-scoped where needed. This is especially useful for an orchestrator giving a worker a narrow, temporary channel while keeping the project graph controlled.

9. Durable display and realtime

For Cagents-controlled output, the durable boundary remains fail-closed:

provider event
   ↓
normalize/batch
   ↓
write canonical Cagents event
   ↓
commit/sync authoritative repo
   ↓
derived realtime fan-out
   ↓
web / native / CLI display
Realtime is not the authority. A websocket/SSE/mobile push event is a projection. If the durable semantic write fails, the system must not pretend the event is safely recorded.

10. Restart after a crash or shutdown

Pull the Cagents repository.
cd ~/dev/cagents
git pull --rebase
Resume the project view.
export CAGENTS_ACTOR=orchestrator
bin/cagents resume hey
Restart the actor wrapper.
bin/cagents agent run --project hey --provider claude --cwd ~/dev/hey
Let Cagents reconstruct current work. The wrapper resolves START.md, active tasks/refs, unread messages, applicable lessons and prior provider-session identity. Do not paste a giant recovery prompt unless there is genuinely new Maintainer intent.

What each repository is for

cagents

Actual durable project records: actors, project membership, messages, tasks, decisions, evidence, lessons, sessions and active refs.

generic_cagents

CLI/engine, semantic transitions, authorization/grant checks, provider adapter contract, durable event handling and machine-local runtime integration.

cagents-application

Server, auth, derived index/realtime services and web/macOS/iOS/Android clients. It must consume the same semantics; it must not invent parallel truth.

Operating principle: use Cagents for communication and control; use the provider wrapper only to translate between the Cagents actor contract and the provider's native session/event protocol.
