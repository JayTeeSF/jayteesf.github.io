Daily: The Detour Produced a Compiler We Can Measure

We stopped shipping products to rebuild the front of Hey’s compiler. That detour is not over. But it has produced something the compiler we left behind never had: a pipeline whose claims can be checked one at a time, and which is now loudly wrong in public instead of quietly wrong in private.

TL;DR

  • Product work does not resume today. It resumes when two named gates are green: identical results across all five ways Hey can run a program, and a captured product receipt for each of the five surfaces we ship to. Neither is close enough to schedule.
  • Two of the five execution lanes now produce byte-identical results on a twelve-program corpus — the same fingerprint, 1fc83cbd, with zero missing rows. The other three were not measured today.
  • The compiler’s own error messages named the wrong cause four times out of four. Each one blamed the biggest thing in the expression. The real gap was always one small part of it, and was found by testing the parts separately.
  • Disclosed weakness: 169 of 169 recorded reference outputs are stale against the current build, and three checks the board recorded as passing were failing on a clean checkout — including the one meant to protect a finished piece of work.
  • Every number here reproduces from a named command. The protected list stands at 61 of 83 passing on the fast tier and 2 of 7 on the slow tier, and both totals are counted by a script rather than typed by hand.

We paused product work on purpose

Hey had a working compiler and it shipped real things. What it did not have was a front end that could say where a decision was made. Character rules, operator spellings, precedence, name resolution and type inference were spread across stages that each reached back into the source text whenever they needed something they had not been told. That is fine until two stages disagree, and then there is nowhere to stand while you work out which one is wrong.

So we stopped adding features and started rebuilding, with one contract: each stage owns exactly one kind of decision, and no later stage may re-read the source text to recover a decision an earlier stage should have made. That contract is written down in the restructured architecture note, and it is the part of this work that has not changed.

The detour found things we were not looking for

We expected the rebuild to be tedious. We did not expect how much it would reveal about what we already believed.

The first surprise was that our error messages lie about their own cause. When the new code generator refuses a piece of source, it names the construct it was looking at — almost always the largest thing in the expression. Four times in a row now, the named construct has been fine and the real gap has been one small part of it. The cure is unglamorous: take the expression apart, run each piece separately, and find the smallest one refused on its own. Today’s blocker looked like a compound condition with two halves joined by “or”. Both halves worked. The joining worked. The gap was a single comparison, and it only appeared because the two halves interacted — adding the second changed how the compiler classified the first.

The second surprise was that passing tests are almost worthless on their own. Several times this week a feature was declared to work, with green tests behind it, and was wrong. The pattern was always the same: the code accepted something it should have refused, converted it quietly, and produced a plausible answer. Green tests only ever asked whether the right cases worked. So the house rule now is that a claim is unproven until we have watched the neighbouring wrong case be refused — and, because a refusal can happen for an unrelated reason, until we have also watched the same shape succeed once the wrong ingredient is swapped out. That second half sounds pedantic. It has caught two proofs that were proving nothing.

The third surprise was the most embarrassing. A side-process added to watch the new front end without affecting anything had no timeout and was on by default. It became the critical path of the build, and nobody noticed for weeks because the build still worked — it just took forty-eight minutes. That story is told in full elsewhere; the durable rule is that anything non-authoritative must be off by default, bounded, and required to leave a receipt.

Green lights that were not green

Three checks recorded as passing were failing on a clean checkout today, and none of the three failures had anything to do with the day’s work. The worst exists specifically to protect a hundred-cell behaviour matrix. That matrix was finished three days ago and is genuinely complete. The check guarding it still demands to see the half-finished numbers, so it has failed every day since the work succeeded — and because nobody had run that tier, the board kept reporting it green. The finished work has been unprotected the whole time.

A second one is funnier and worse. A row recording a known problem had been registered pointing at a neighbouring check’s command — a command that passes. Two rows sharing one command with opposite expectations can never both be satisfied, so the runner stopped at that row every time and never ran a single row after it. Rows appended later were silently never executed.

Both are the same failure of imagination: we wrote checks that restate an answer instead of deriving it. All of these are now recorded as failing, each with the measurement that says why, and the fix in every case is to repair the check rather than to change the code it points at.

What is still wrong, stated plainly

One unsupported source form still causes the new code generator to hand an entire file to the older one. The older generator answers correctly, which is exactly why this went unnoticed for so long: the only symptom is a line in a build log. Three of the five ways Hey can run a program were not measured today at all. The borrowed-reader migration that was supposed to remove two thousand redundant copies has removed none of them. And there are known places where two ways of running the same program disagree, on programs that compile cleanly, exit zero, and print something plausible. Those are registered, open, and deliberately not described here; a description precise enough to be useful would also be a recipe. They ship with their repair.

Where this goes

The four language goals sit at four different stages and packaging them together would be dishonest. Correctness is being earned slowly, through cross-checking and refusals. C-like speed is measured work with one known remaining cost: copying a string still duplicates its contents, so copying grows faster than the input does. Ruby-like ergonomics is a product goal the source corpus tests daily and the compiler keeps failing in small, fixable ways. Actor-based concurrency is the runtime direction described in the actor design article, which today’s work neither advances nor contradicts.

None of that is finished. But the difference between this compiler and the one we left behind is not the feature list — it is that every claim above has a command behind it, and the ones that turned out to be false were caught by us rather than by someone’s production traffic. Product work resumes when the five-lane proof and the product matrix are both green. Not before, and not because the calendar says so.

Reproducing this

Every count above is produced by a script reading a checked-in ledger or by a harness run, never typed by hand. The protected-check totals come from counting rows in the ledger file; the corpus fingerprints come from a twelve-row identity run across two lanes; the product figures come from a capture taken the same afternoon and re-verified against a fabricated-receipt control that correctly refused it. Sources are internal to the compiler repository and have no public URL.
