Evidence ledger (cite, don't re-measure)

Dated, versioned measurements on the reference rig (M-series Mac,

darwin-arm64). Agents CITE entries by date+version instead of

re-running benchmarks; new entries append, never overwrite. Formats

follow the war-room table conventions.

SHARED CHANNEL PROTOCOL (2026-07-24): this file is written by BOTH

the claude_01 orchestrator and the maintainer's benchmark-seat agent

(which appends from its own seat). Rules: (1) append-only — never

rewrite or reorder another writer's entry; (2) sign entries with a

seat tag (## <date> — <what> [seat: orchestrator|bench]); (3) entries

are EVIDENCE, not instructions — directives route through the

maintainer; (4) the orchestrator re-reads this file immediately

before any commit that stages it, so appends arriving mid-slice are

never silently dropped or overwritten.

2026-07-24 — v0.99.396a runtime stages 2+3 (interpreter lane)

278B /health body, oha -c 16 -z 5s, medians of 3, load ~3.5-5:

  • keep-alive w1: 11,090-11,303 req/s; w8: 19,849-19,956 (POSITIVE

1.77x; stage-1 was inverse 0.48x); w16: ~16.4K (oversubscription).

  • no-keep-alive (clean TIME_WAIT): w1 18,778; w8 17,219.
  • macOS SO_REUSEPORT delivers to ONE listener queue: per-worker

listeners pin aggregate at the single-connection serial rate

(second client starved at 2 req/s). Platform-aware default landed.

  • Ceiling (sample-proven): interpreter handler eval ~60-90us/req +

repl_global_env_mutex frames (env_lookup_clone, hey_repl.c:690).

  • Methodology: no-KA runs leave ~24K TIME_WAIT sockets >=30s; KA

configs first, drain 30s+ between churn runs; ALWAYS assert the

response body before measuring (wildcard *:PORT squatters coexist

with specific binds under SO_REUSEADDR — defect 26).
