The Hey language

Everything you can write in a Hey source file, one idea at a time. Every example on this page was compiled and run; the grey box under it is what the toolchain actually printed, warnings and errors included.

In one paragraphHey reads like Ruby (if/elsif/end, case/when, "#{interpolation}", says) and runs like C: the compiler turns it into a native program through LLVM. Values never change after they're made, so there's let but no assignment expression. You never write a type; a cast like x.to_i or !!x tells the compiler what you mean, and it infers the rest.

1. The shape of a file

A Hey file is a list of declarations followed by one program block, which is where execution starts. In order, a file may hold imports, modules, functions, actors, workers, jobs, specs and one program. # starts a comment that runs to the end of the line. Works today

shape.hey
# A whole Hey file: imports, functions, specs, one program block.
import 'stdlib:Text'

fn shout(name)
  return Text.upper(name) + '!'
end

spec 'shout says hello loudly'
  expect stdout "HELLO, ADA!\n"
end

program
  says shout('hello, ada')
end
$ hey shape.hey
HELLO, ADA!

A statement ends at the end of its line. It carries on to the next line only while a (, [ or { is still open. A trailing operator does not continue the line. Works today

continuation.hey
program
  let total = add_all(
    1,
    2,
    3
  )
  says total
  let names = [
    'Ada',
    'Grace',
  ]
  says names
end

fn add_all(a, b, c)
  return a + b + c
end
$ hey continuation.hey
6
["Ada","Grace"]

2. Names, the ?/! convention, reserved words

Built-in names are reserved too. Besides the keywords, every built-in function (len, split, push, put and the rest of the built-in list) is a reserved name. You can still define something with that name, but don't: it hides the built-in, and the compiler warns:
warning: `len` is a reserved built-in name (Hey prelude); your definition at app.hey:12 hides it.
Rename it; future releases may make this an error.
Today it is a warning; a future release may make it an error. Warning coming in the consolidation release

A name starts with a letter or underscore and continues with letters, digits and underscores. A function or actor name may end in ? (by convention: it answers yes or no) or ! (by convention: it does something you should notice, such as I/O or failing). The suffix is part of the name and adds no hidden behavior. Works today

names.hey
fn ready?(status)
  return status == 'ready'
end

fn publish!(message)
  says 'published: ' + message
  return message
end

program
  says ready?('ready')
  says ready?('waiting')
  let sent = publish!('v1')
end
$ hey names.hey
true
false
published: v1

Words a C compiler or linker reserves (double, switch, static) are meant to be ordinary Hey names, with the compiler renaming its generated symbols privately. Partly works As a local name (let static = …) they work; as parameter names the 606a code generator refuses them:

4. Strings

Single quotes are raw (only \' and \\ are escapes). Double quotes understand escapes and #{expression}. For long text use a heredoc: <<TAG keeps indentation, <<~TAG strips the common indent, and a quoted tag (<<~'TAG') keeps #{} as plain text. Heredocs keep their final newline, so pair them with print, not says. Works today

strings.hey
program
  let name = 'Ada'
  says 'raw: #{name} \n stays as typed'
  says "interpolated: #{name}, length #{name.length}"
  says "tab:\tnewline escapes work"
  says 'it\'s fine'
  says %q(both 'single' and "double" quotes; #{name} stays text)
  says %qq(Hello #{name}; 'single' and "double" are easy)
  print <<~TEXT
    Dear #{name},
      indented line keeps its extra indent
    Bye
  TEXT
  print <<~'RAW'
    echo '#{not_interpolated}'
  RAW
  let page = """<h1>#{name}</h1>
"""
  print page
end
$ hey strings.hey

Two literals side by side join up

Ruling: adjacent string literals concatenate, as in Ruby,2 so 'it''s' means 'it' then 's', which is its. The compiler is meant to warn when two literals touch with no space between them, because that's almost always someone trying SQL-style quote doubling.

adjacent.hey
program
  let greeting = 'Hello, ' 'world'
  says greeting
  says "one " "two " 'three'
  says 'it''s'
end
$ hey adjacent.hey
Hello, world
one two three
its

Adjacent literals concatenate as ruled. Partly works The warning for touching literals ('it''s') didn't appear on this run; the ruling asks for one, so that part is still owed.

5. Arrays and objects

Arrays are [1, 2, 3]. Objects are {name: 'Ada'}; a key that isn't a plain name goes in quotes, {'content-type': 'text/plain'}, and is read with brackets. ... spreads one array or object into a new one. Nothing is changed in place: {...user, name: 'Grace'} is a new object and user is untouched. Works today

collections.hey
program
  let numbers = [1, 2, 3]
  let user = {name: 'Ada', active: true}
  let headers = {'content-type': 'text/plain', 'x-count': 2}
  says numbers
  says user
  says headers['content-type']
  let more = [...numbers, 4, 5]
  let renamed = {...user, name: 'Grace', role: 'admiral'}
  says more
  says renamed
  says user
  says user.name
  says user.has?('active')
  says renamed.keys.to_json
end

6. let, set, shadowing and the coming _

let name = expression makes a binding. A value never changes: base.put(…) builds a new object and leaves base alone. set name = expression is a statement that gives a slot its next value: an actor's state slot, or a local that a loop carries from one turn to the next. There's no assignment expression: x = 1 never produces a value. Works today (actor state slots: Actors and failure)

bindings.hey
program
  let total = 0
  let i = 1
  while i <= 4
    set total = total + i
    set i = i + 1
  end
  says total
  let base = {name: 'Ada', visits: 1}
  let next = base.put('visits', 2)
  says base.visits
  says next.visits
end
$ hey bindings.hey
10
1
2
actor_state.hey
actor counter()
  state count = 0
  receive msg
  if msg == 'inc'
    set count = count + 1
    says count
  else
    exit
  end
end

program
  let c = spawn counter()
  send c, 'inc'
  send c, 'inc'
  send c, 'stop'
  join c
end
$ hey actor_state.hey
1
2

The word operators are where the documents disagree with each other and with the compiler. Partly works

9. Casts are the type syntax

You don't write types in Hey. You write a cast, and the compiler reads the type off it: !!x is a Bool, x.to_i an Int, x.to_s a String, x.to_f a Float. So a function whose body is return !!x is known to return Bool with no annotation. Everything else is inferred; how the inference works is in the compiler article. Works today

One cast misbehaves on 606a: .to_f as a dot call on a value is refused at run time ("not a receiver accessor"); the call form to_f(x) and Float(x) work. Partly works

  when 1
    says 'one'
  end
  says 'no arm ran, no else needed'

11. Functions

Functions are values: pass them, store them in arrays and objects, and send them in actor or Job messages. JSON encoding refuses them.6 bind(f, args…) fixes leading arguments and returns a new callable that owns those values. Hey has no closures and no nested functions; bind is how you carry data into a callable. Works today

functions.hey
fn add(left, right)
  return left + right
end

fn double(value)
  return value * 2
end

fn apply(value, callable)
  return callable(value)
end

program
  says apply(21, double)
  let add_ten = bind(add, 10)
  says add_ten(32)
  let table = {twice: double, plus_ten: add_ten}
  let twice = table['twice']
  says twice(5)
  says [double, add_ten].length
end

13. Specs inside the file

A spec 'name' … end block states what running the file must produce: expect stdout, expect stderr and expect exit. heyc file.hey --test runs the program and checks every spec. Specs that import the code under test from another file are Proposed (see Reference 11: Roadmap). Works today

spec_demo.hey
fn add(a, b)
  return a + b
end

  expect stdout "5\n"
end

  expect stderr ''
end

spec 'exits cleanly'

program
  says add(2, 3)
end

14. The truthiness puzzle

Predict first. Which of 0, '', [], {}, false and nil are falsey in Hey? Python says all six; JavaScript says four (0, '', false, null).
Answer

Only false and nil. Everything else, including zero and empty things, is truthy, as in Ruby. Works today

truthy.hey
fn check(label, value)
  if value
    says label + ' is truthy'
  else
    says label + ' is falsey'
  end
end

program
  check('0', 0)
  check('empty string', '')
  check('empty array', [])
  check('empty object', {})
  check('false', false)
  check('nil', nil)
end
$ hey truthy.hey
0 is truthy
empty string is truthy
empty array is truthy
empty object is truthy
false is falsey
nil is falsey

Known gaps on this page

  • Documented but refused by the 606a compiled path: 0x/0o/0b literals and exponent notation, digit separators (built on the consolidation branch), object shorthand {name}, compound set x += 1, default, rest and named parameters, ** and bitwise operators in code generation, .to_f as a dot call, calling a callable field with a dot, toolchain words as parameter names.
  • Behaves differently from the reference: not binds tight and and binds tighter than or; whole-number overflow wraps; % refuses decimals, 1.0 / 0.0 is an error7, 100.0 prints 1e2; set is accepted on any binding; a bare call statement is accepted although the ruling rejected it.
  • Decided, not built: the _ discard; the warning for touching string literals.
  • Known defects: shadowing across a block miscompiles (fixture test/fixtures/local_rebind/known_defect.hey); forever is missing from the new syntax tree.
  • Proposed: shift semantics.
  • The repository's own test/language_decisions/ suite (57 programs) was run on this toolchain while writing: at least 36 of them failed or printed something other than their expected output, which is where several of the items above were confirmed.
