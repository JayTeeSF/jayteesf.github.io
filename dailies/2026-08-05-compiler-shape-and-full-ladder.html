Module and import systemcurrent primary blocker

The final contract is clear: the resolver owns lexical names, module aliases, public export surfaces, exposing:, selector aliases, conceals:, re-exports, and operator overrides. The application program then includes the reachable imported function bodies exactly once.

The current failure is architectural, not a missing special case: LLVM-direct and self-host see calls to imported functions, but the application MIR unit does not contain those functions' bodies. The fix must close over the resolved module graph before MIR/LLVM; no emitter may reopen source files to rediscover imports.

Operators and truthinessone correctness gap

The target architecture has one closed operator registry projected into the tokenizer, parser, resolver, HIR, MIR, and LLVM layers. The parser alone owns grouping and precedence. Algebraic, comparison, boolean, bitwise, shift, range, and state-update forms are lowered once and consumed downstream.

The immediate defect is narrower: LLVM boxed conditions currently pass through numeric conversion. A borrowed non-empty string therefore becomes strtol("return") == 0 and is treated as false. A dedicated truthiness primitive and a full value-kind matrix are in progress.

The three active critical paths

P0

Complete application module closure

Build one resolved application program containing reachable imported bodies. Prove qualified imports, exposures, aliases, re-exports, conceals, duplicate prevention, unused-body exclusion, and deterministic cycle diagnostics.

P0

Correct boxed truthiness

Replace numeric conversion in condition lowering with one runtime truthiness contract shared by ordinary values and live borrows across every lane.

P1

Finish self-host lifetime parity

Move from the minimal happy-path fixture to stale-handle, escape, error, early-return, branch, loop, wrong-arity, and diagnostic parity through the self-rebuilt compiler.

The campaign now distinguishes reported, landed, centrally tested, verified, released, and deployed. Mutation-proven census and gate-accounting checks are stronger, but the rung remains an ongoing discipline rather than a one-time checkbox.

R5 - tests and compiler code stop depending on the retiring representationactive

Generated-node construction and storage are green; owned escapes are 260/260; scoped local reads are 153/190. The remaining work is the last 37 compatibility reads, full lifetime parity, clone-performance repair, and executable gates that cannot become green through stale caches or incomplete denominators.

R6 - the REPL and interpreter stop being a separate language implementationnot authoritative

REPL now executes the complete candidate identity receipt, which is progress, but it still does not consume the same authoritative structural HIR evaluator as compilation. The target fork remains HIR: one semantic program, two consumers.

R7 - delete the bootstrap C backendfuture deletion

The self-host compiler can now lower a minimal scoped reader and rebuild itself cold, with zero legacy fallback for that fixture. That is a foundation proof, not yet permission to delete Stage-0 or the C backend.

R8 - no part of the language is implemented twiceend state

R8 requires the new frontend to be authoritative, the shared HIR evaluator to replace independent interpreter parsing, MIR and LLVM to consume structure rather than raw source, the old counters to reach zero, and compatibility paths to be deleted.

Corrections that changed the roadmap

The 48-minute buildmechanism understood

The build was waiting on candidate frontend shadow processes, including an orphan. The incident exposed severe interpreted-lane cloning and tokenizer behavior; it was not 48 minutes of LLVM emission.

213 local / 257 escapereplaced by measured census

The context-aware scanner derives 190 local and 260 escape sites. The four missed escapes were reader calls inside heredoc interpolation; the false escape was a reader-shaped string literal containing put(.

Self-host was not six independent red behaviorsreporting corrected

It was one compile-time inability to lower the scoped-reader consumer. That minimal lowering is now green through a cold self-rebuild. The corpus remains blocked for a different reason: imported module bodies are absent from application MIR.

Three matching identity lanes did not prove a clean digestreceipt regeneration required

A cached rerun could omit a failed authoritative-HIR re-emission and fold a placeholder into the digest. The accounting and correctness gate are split now; the old agreement is not silently promoted.
