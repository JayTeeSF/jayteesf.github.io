The north star

“Equal ergonomics, overwhelming speed — so a Ruby developer has to try it.”

A Ruby column in every benchmark. Speed is being won. Ergonomics is what this docket is about.

Hard rule · no types in user code

Annotations are compiler-only. Conversions are Ruby-style to_i / to_s. Infer, or offer options — never make the author declare.

Standing rule 30 · dot-methods

Sugar, existing only via explicit import. They lose to conflicting names, and the compiler “generously” warns.

Program goals, for cost context

Retirement ladder R2–R8 to semantic_debt_files=0; web runtime within 3% of Go — ~97K req/s on one core. Neither is helped by this docket; both compete with it for time.

The lens I used to rank these

Your own “first hour vs Ruby” test. A Ruby developer sits down with Hey for sixty minutes — which of these do they hit, and what do they conclude when they do? An item they hit in the first hour and read as broken costs more than a deeper gap they never reach. That ranking is the First hour column below, and it is a judgement, not a measurement — overrule it freely.

ITEM A Ruby parity

Should len() count characters instead of bytes?

Ruby’s String#length counts characters. Hey’s len() counts bytes, and split(s, '') is byte-wise too.

Evidence · verified in stdlib

len('a—b') is 5. An em dash is three bytes and one column, so every column calculation is wrong on typographic text.

There is no character-length function anywhere in the stdlib — I checked Text.hey. The reporting team hand-rolled one that counts non-continuation bytes. This is the same family as the bytes gap that shipped “Cellules V g tales”.

Touches: the north star directly. Text handling is first-hour territory, and any Ruby developer with a non-ASCII string will find this.

ITEM B Ruby parity

Add to_i / to_s, which your own hard rule already requires?

This one may not need a decision so much as a confirmation — I flag it because the rule exists and the code does not match it.

Evidence · verified in stdlib

parse_int exists as a builtin and Cli.hey, Env.hey and Packages.hey all use it internally. There is no to_i or to_s spelling, so a Ruby developer looking for the mandated form finds nothing and concludes conversions are missing.

Touches: the hard rule verbatim — “Ruby-style to_i/to_s conversions”. The capability exists; only the name is absent.

ITEM C Ruby parity

Should Text.squish collapse all whitespace, as Ruby’s does?

Evidence · verified at Text.hey:168

Text.words is split(trim(value), ' ') — a space only. So squish cannot collapse newlines or tabs, and 'a\nb' squishes to itself.

Touches: parity, narrowly. The lowest-cost item here — but squish borrows a Rails name, which sets an expectation it currently fails.

ITEM D Silent wrong answer

Rule 30’s warning half does not exist — what should the warning channel be?

This is the item I most want a ruling on, because the rule is already settled and only half of it is built.

Evidence · four collisions and counting

exists? — a hand-written fn exists? never runs, the builtin answers. A spec was passing for a reason its author did not intend.

entries — info.entries resolves to entries(info), the whole object as pairs. get — becomes the string-key accessor; every call returns nil. count — reported separately by the RecallCoach team.

Ten names shadow map keys, measured at 470a. Shadowing also crosses frames: a caller’s local breaks a callee, and the trace blames the callee.

Touches: standing rule 30 — “they lose to conflicting names. At which point the system will (generously) produce a warning message.” The losing half works. The warning half was never built, and Hey has zero compiler warnings today, so this decides whether a warning channel exists at all.

The three questions owed to you, verbatim

1. Warning-channel policy — suppressible, and how? Does --check fail CI on a warning? Can a warning ever harden into an error?

2. Warning site — at key definition only, or also best-effort at the access site?

3. The migration — once the receiver-split number exists, how much existing code moves, and over what schedule?

ITEM E Silent wrong answer

Should read_text fail closed on binary instead of truncating?

Not a parity question — a correctness one. It is the most severe item in the docket and I include it because it shares a cause with the text/bytes items above.

Evidence · their measurement

A 35,856-byte zip read back as 5 bytes. HTTP 200, body beginning PK, content-type correct. Every shape check passed, because a truncation preserves exactly what a prefix assertion looks at.

A working spelling exists — Files.read_bytes_at(p, 0, Files.size(p)) — but the obvious one is the trap.

Touches: the fail-closed doctrine. Everywhere else we have banned shapes that return a plausible wrong value rather than refusing.

Your call
ITEM F Design

Computed object keys — {...obj, [k]: v}

Evidence

Currently a syntax error (bad object key), and there is no generic merge loop. Ruby has {**h, k => v}.

The reporting team argued the restriction helped them: building from a declared field list meant an undeclared form field could not enter a record. That is a real safety argument, not a rationalisation.

Touches: the deferred member/key-collision question. I would not rule this one in isolation — the two interact.

Your call
ITEM G Silent wrong answer

command() switches between exec and shell on an invisible property

Evidence

command() execs directly when the string contains no shell metacharacter. So command('test -s x') does not run the shell builtin — it resolves test on PATH, finds the Hey trunk’s own bin/test, prints its help and returns false.

command('cd a && find b') works, because && forces a shell.

Touches: the type-vs-shape dispatch disease — behaviour determined by an invisible property of the input. That pattern produced seven wrong-answer classes in one cycle and is the standing example behind “widen the fix”.

Your call
ITEM H Design

Env.default treats an empty value as absent

Evidence

GC_SPEC_ADAPTERS= returns the fallback, not ''. Convenient — but it means a guard against “the variable was set to nothing” is dead code, because that path cannot be reached through the environment.

Touches: nothing structural. Included for completeness — dead-code-by-design is worth an explicit yes or no.
