Settled

Negative division stays as it is

-7 / 2   is   -3

Rounds toward zero, like C and Go. Ruby would say -4. You reversed an earlier choice here after it measured at 15% slower on the benchmark that certifies our speed. Ruby's version is available on request — see Overrides below.

Reversing it also removed a real bug: our benchmark's averaging code rounds on top of the current behaviour, and the Ruby version would have made it compute wrong averages silently.

Overrides are per-file, not program-wide

import "stdlib::RubyMath" exposing *   → this file gets Ruby's math
import "stdlib::RubyMath"              → RubyMath.div(-7, 2) to compare

A file that asks gets Ruby's arithmetic. Libraries it calls keep the behaviour they were written and tested against. The system will report every override in effect, so you can always ask what a program is really doing.

Nobody pays for someone else's choice. Research is running on how four other languages did this and what it cost them.

Dividing by zero

1   / 0     stops with an error     ← shipped today
1.0 / 0.0   Infinity
inf.to_i()  stops with an error

Whole numbers and decimals differ on purpose — that's what Ruby does and what the floating-point standard requires. Infinity is a real decimal value; no whole number means it, so that's where it stops.

Verified as safe to build. One thing must be fixed first: a bug where Infinity inside JSON output writes a wrong number instead of failing.

You described the good answer and I hadn't offered it: ask the chip whether it overflowed — it already knows — and redo that one calculation in a wider type. Almost always no, so almost always free.
