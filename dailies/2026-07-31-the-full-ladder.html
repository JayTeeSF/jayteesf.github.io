The retirement ladder — R2 → R8

"Get rid of native C." Two separate deletions. Nothing on this ladder moved today, and saying so plainly is the point of this section — a status page that only reports motion is a changelog.

  • R2 ~490aalive rung▸ what it means▾ hide

    The Hey-owned compiler must accept every program the old C one accepts. ~12–18 refusals left, was ~30. No change today.

     
    # Every build prints a receipt naming which emitter did the work:
selfhost_consumer=hey-llvm-text   # the Hey-owned emitter — the future
selfhost_consumer=direct-mir      # fell back to the C emitter — debt

    All 106 corpus examples already route through the Hey-owned emitter with zero fallbacks; the remaining refusals are harder shapes in the wider spec suite. R2 is the live rung and the one everything else waits on.

  • R3 ~515adeletion #1▸ what gets deleted▾ hide

    DELETES the native LLVM emitter — ~14,900 lines of heyc.c. Needs R2 closed.

    Two emitters exist today and every landing proves them byte-identical across the whole corpus. R3 deletes the C copy. This is why fixes go into shared runtime helpers rather than emitter branches — code written there dies with the file.

  • R4small · any time after R2▸ what it means▾ hide

    Honest labels, and a tripwire against new native code.

    Rename comparison-only "native-c" labels to explicit stage0, and add a checker that fails the build if ordinary tooling grows a new call into the native backend. Cheap insurance that the debt only shrinks.

  • R5 ~500agates R6 + R7 · today's work bears on this▸ why it gates everything▾ hide

    The test suite itself must stop running on the thing being deleted. You cannot certify a deletion with gates that run on the deleted thing — that is circular.

    R5 builds the compiled spec runner, migrates suites in batches with both lanes agreeing, then flips the default.

    Today made this rung's real risk visible, and it is not the one we had written down. The circularity problem assumes the battery is otherwise trustworthy. Today we learned that on one machine it had been silently stopping a third of the way through for two days — so roughly a hundred checks were neither passing nor failing, they were unobserved. A deletion certified by a battery that can quietly skip a third of itself is not certified. Fixing that is now a prerequisite for R5 meaning anything, and it is why a day went into test infrastructure rather than rungs.

  • R6 ~530adeletes hey_repl.c · largest schedule risk▸ what gets deleted▾ hide

    The REPL stops being a second implementation of the language.

    The interactive session moves onto a JIT — compile each fragment with the ordinary pipeline, load it hot, target under 100 ms per entry. Then ~2,600 lines of C expression evaluator, which must otherwise agree with the real compiler forever, is deleted. One unproven runtime re-entry probe is the swing item. Still the largest schedule risk on the board.

  • R7 ~540adeletion #2 — ends native C▸ what gets deleted▾ hide

    The bootstrap C backend goes — the deletion that actually ends native C.

     
    # The fixed-point proof that makes the seed compiler deletable:
stage1 = hey_compiler_built_by_C_seed(source)
stage2 = hey_compiler_built_by_stage1(source)
assert bytes(stage1_output) == bytes(stage2_output)   # byte-identical

    Once Hey-built-by-Hey reproduces itself byte-for-byte without the C seed, the seed backend (~1,650 lines) is deleted and recovery becomes published per-platform bootstrap binaries — the model Go and Rust use.

  • R8 ~550athe end · realistic ~Aug 14▸ the end state▾ hide

    semantic_debt_files = 0 — no language semantics live in C.

    heyc.c shrinks to what a launcher honestly needs: CLI argument handling, build-mode dispatch, object and link mechanics. Every rule about what Hey programs mean lives in Hey source, compiled by Hey, verified by compiled specs.

Past R8 — where the language takes shape, and this is what moved today

After the cruft is gone, the language program. This is the section that advanced today, and it is the one that ends with beta users. Ordered by leverage, not calendar.

  • 1 · The module systemsubstantially ruled 2026-07-31▸ what was decided▾ hide

    Zero reserved names. Your data, your functions, your names — always. Today this went from "names, finished" to something considerably larger and clearer.

    The end state is now stated: there are no built-ins at all. Every function lives in a module. The language becomes consistent because there is no privileged ambient layer that user code has to dodge. The familiar feel returns through one opt-in line:

    import 'stdlib:Sys' exposes *      # the first hour of Ruby, in Hey
sort(items)                        # reads like it always did

# or, without the second word, everything stays qualified:
import 'stdlib:Sys'
Sys.sort(items)

    Today's rulings, in the order they were made:

    · Modules compose. A module may extend another rather than duplicate or replace it — Encoding imports and exposes Bytes, then adds base64, hex and the rest on top. That single decision is what makes a no-built-ins world tractable instead of a giant flat dump.

    · Sys is a curation layer, not a merge. It imports the real modules and re-exposes them. Where two modules genuinely disagree on a name — and 14 of the 60 common names do, with get meaning three different things and read four — Sys wraps both under distinct names rather than letting one silently win.

    · Collisions have a rule: the last definition wins, and every override after the first warns. Most local wins, which is the same principle that already says your own name beats an imported one. Qualified forms always survive, so nothing is ever unreachable.

    · Warnings become real. Hey has zero compiler warnings today; this builds the first channel, suppressible by environment variable. A syntax for suppressing at the import site is sketched for later — with one caution recorded: a blanket suppressor would also silence collisions that appear in future, whereas naming the specific collisions you are accepting cannot.

    · The compiler will suggest the import you forgot. Not intelligence — a table lookup, because Hey ships its own standard library and knows every name in it. This is migration infrastructure rather than polish: when the ambient names move into modules, every existing program breaks with exactly this error, and a good diagnostic turns a breaking change into a guided migration.

    Deliberately not now: the exposes * mechanism itself is post-R8 work. A linter and a language server are each their own project, later and independent — explicitly not a reason to defer the compiler diagnostic, which works in a terminal, in CI, and in a container where no editor integration ever runs.

  • 2 · A standard library that is actually standardnew finding 2026-07-31▸ the gap▾ hide

    Hey has no maths library. Not a small one — none.

    Surveying the ambient names for the module work turned up something nobody had written down: integer division is the only arithmetic function in the language. There is no sqrt, abs, floor, ceil, round, pow, exp, log, no trigonometry and no random numbers — in the runtime or in any module.

    That is a larger gap against Ruby than anything in the language-ergonomics list, and it is load-bearing for anything numerical. It also means the maintainer's interest in non-linear functions for machine-learning work currently has no foundation under it.

  • 3 · A web framework worth the nameroot cause found 2026-07-31▸ what the only real app proved▾ hide

    One missing capability explains roughly 5,000 lines of workaround in the one application built on Hey.

    A request handler cannot reach anything created when the application started. The evidence is a single dead variable: the app creates a pool of two background workers at boot, and that variable is never mentioned again anywhere in the codebase. It sits idle because there is no way to hand it to a handler. The real work instead creates a fresh four-thread pool inside each request, and every request additionally opens a database connection and issues a table-creation statement.

    For a language chasing 100,000 requests per second on one core, that is the shape to fix before any framework feature. It also forced a 4,388-line file of HTML pasted into source — a compile-time template cache, because there is no runtime one.

    The good news: Hey already has the mechanism. It has closures; they are simply not called that, and web dispatch discards the captured values because it resolves handlers by name. Carrying them costs one setup per route at startup, not per request. A literature review confirmed the underlying fear was unfounded — Koka, Lean 4 and Roc all ship closures under the same reference-counting design Hey uses, with no garbage collector.

  • 4 · Recursion, guaranteedunchanged▸ what it means▾ hide

    Full tail-call depth in both lanes; a clean error where depth is real.

    Compiled already turns scalar tail calls into loops. The script lane still overflows around depth 500 with no message. Target: the same answer in both lanes, and "recursion depth exceeded" instead of a crash where the depth is genuine. This is also the Erlang idiom Hey's actors want — the server loop as tail recursion.

  • 5 · Multi-core webthe honest broken row▸ the numbers▾ hide

    8× the workers currently buys 1%.

     
    workers=1   135,152 req/s
workers=4   134,544 req/s
workers=8   134,870 req/s      # the plateau is the SERVER —
                               # proven with an ordering control, both boxes

    Post-R8 this is the largest performance frontier, and the slice where a cross-machine load generator finally earns its hardware — one box cannot honestly load-test many cores.

Where this is going, in one paragraph. R2–R8 is subtraction: ~19,000 lines of C deleted, ending with no language semantics living outside Hey. Everything above is addition, and it is what a first beta user would actually touch — one import line instead of an invisible name-collision minefield, a maths library, a web framework where a handler can reach the pool you made for it. The ladder is not the destination; it is the last thing standing between here and a language that can be handed to someone who did not build it.

What today actually was

The battery on the Mac had been dying before check 105 of 294 for two days. Four attempts, four different causes. Behind it: a tool that walked 284,760 files to select 2,684 and never finished; a briefing document that had stopped generating because a three-item limit turned out to bound the wrong quantity; and a version label that had been wrong for 93 releases because the bump tool renames the template and never touches its contents.

One check runs make clean on the live project mid-run and restores one of the deleted artifacts. We posted that prediction with its falsifier before testing it; the Linux seat confirmed it within the hour and cancelled an investigation they had planned into the wrong check — one was the disease, another the victim.

Two numbers we retracted. We published the wasteful search as "683,282 files, 255×" — measured with a tool that counted directories the real code skips. Honest figures: 284,760 and 106×, overstated by 2.4×. We also reported Ruby-style to_i/to_s as missing and in breach of a project rule; both exist and work. We had checked one namespace and concluded about the language. Corrections at the same volume as the claims — that is the only thing that makes the first number worth anything.

Why 475a did not land. The battery now runs to completion: 294 verdicts, 12 red. Five are pre-existing failures the Linux seat's records prove predate this release. The rest are being worked individually, including two in code we changed today. We could have shipped by widening the definition of green; the reason not to is the whole subject of this page. A check that cannot fail, or that never runs, is worse than no check at all — because it is indistinguishable from one that passed.
