Hey · full ladder · 19 August 2026

Hey 533a is fast, settled, and still split.

Hey now has near-C array paths, a fast aggregate web result, central box ownership, a real structural front end, and a detailed language design. It does not yet have one semantic authority, linear default frontend scaling, bounded actor handles, a competitive 1BRC runtime, or product-grade release evidence. This is the complete ladder, including every standing language ruling and every executable decision row.

Current landed source: 0.99.533a at f7e85961 Authority campaign: live edits remain uncommitted Article status: current truth, not a release announcement

TL;DR

  • Verdict: do not bump or switch authority yet. Finish every structural-emitter rung, close the separate borrowed-reader lifetime contract, prove both by mutation, then land one 534a change before retiring the old semantic path.
  • Strongest measured result: Hey’s M3 Pro sum/search paths are 1.02–1.03× C; the finished array shapes are 1.65–1.92× C; on Linux with four pinned workers, the web server measured 288,811–323,932 requests/s with bodies verified.
  • Mechanism: generated syntax and structural HIR remove duplicated facts, explicit ownership makes value lifetime visible, and native-versus-Hey LLVM identity turns the old emitter into a differential oracle while the new one grows.
  • Language status: the design is much more settled than the implementation: 19 of 56 executable decision rows pass in both interpreter and compiled lanes, 35 pass in neither, and 2 are blocked from observation.
  • Disclosed weakness: authority is still split; frontend clone growth remains red by default; actor handles retain about 240 B/spawn; and 1BRC remains around 215–227 microseconds per row—roughly 7,500× C in the current report.
  • Falsification: rerun the two golden suites, the authority and borrowed-reader gates, the language registry, the ownership controls, and the exact dated benchmark commands. A claim stays only if its deliberate negative control fails.

The project needs six status words, not one

The biggest risk in a long compiler campaign is turning evidence from one layer into a claim about another. This article uses the following terms literally.

Decided

The maintainer has chosen the language or architecture rule. It may have no implementation yet.

Implemented

Code exists for the rule or mechanism. It may be inactive, incomplete, or unverified.

Verified

A named command passed under stated conditions. Working-tree verification is not a commit.

Landed

The change is committed in the cited source checkpoint. Rungs 3–4 are deliberately not described this way.

Released

A versioned artifact or source release was promoted through its release process. A version string alone is not enough.

Deployed

A product environment runs the exact artifact. Nothing in this article silently promotes source work to deployment.

The compiler ladder: a built frontend waiting for convergence

Hey’s new path is not a proposal. HeyTokens, HeySyntaxTree, HeyNames, and HeyStructuralHir exist, run, and have structural gates. The old HeyParser → HeyHir route still produces the semantic HIR used by normal compilation. That is the split.

The full candidate shadow currently crosses into the legacy direct-MIR consumer when stdlib/HeyLlvm.hey meets an unsupported expression. That fallback prints a Boolean receipt as 1 instead of true, so the authority gate remains red. The harness is right; the emitter is incomplete.

Live emitter decision

Finish the whole subset serially, including the spread/update mountain. Permit audited local set growth because the historical absolute ratchet is already red in the 533a baseline. Keep byte identity, no fallback, negative controls, and both golden suites as the hard bars.

Rung 3 added boxed indexed reads with arithmetic such as x[len(x)-1]. Rung 4 generalized boxed slice operands and corrected boxed equality so a slice stays type-tagged instead of being diverted into raw-C-string comparison. Both are verified and uncommitted. Rung 5 is mixed-type concat whose operands are cross-module calls returning integer, String, and Boolean.

The web log used four pinned workers, wrk -t4 -c64 -d8s, and byte-verified response bodies. Hey measured 323,931.74 requests/s on plain text, 303,657.13 on JSON, and 288,811.40 on parameters. Go measured 218,906–227,252; Ruby 70,491–76,780.

Boundary: these are four-worker aggregate results. They do not satisfy the editorial requirement for 1/2/4/8 worker curves, per-core verdicts, latency tails, soak memory, startup, edit-to-serving, or artifact size.

1BRC: compile correctness is no longer the excuse

528a fixed the LLVM compile bug and 529a fixed the native-C self-host miscompile. The binary is now correct in both paths. The remaining wall is runtime: about 215–227 microseconds per row, approximately 7,500× C in the live daily, with a five-million-row projection near nineteen minutes. This remains red by the project’s own done criterion.

The ownership ladder: boxes have one home; actor handles do not

Central ownership put a non-atomic reference count into existing box padding, keeping the box at 32 bytes. The compiler tracks fresh values created by a statement, retains anything that escapes, and releases the rest. On the measured compiled web workload, retained memory fell from 308 to 6 bytes per request, and disabling the release restores the leak.

The proposed returned-parameter clone-to-retain step remains useful, but its former leak story was retracted. The minimal identity(x) { return x } workload is already flat at approximately 0.0 B/call. Replacing a deep clone with retain should now be justified as an allocation/performance improvement with alias-safety tests, not as a memory-leak repair.

Actor handles are a different object. They can cross threads, live in containers, and outlast join. The runtime therefore preserves a tombstone instead of letting a user-held handle dangle. The measured retained record is about 240 bytes per spawn. The correct next mechanism is a separate atomic actor-handle lifetime count—not making ordinary box counts atomic and not adding a blind free.

This separation matches the language rule: ordinary bindings are immutable; actors, monitors, and supervisors own private state slots and process messages serially. The runtime must make that ownership safe without pretending every value has the same concurrency lifetime.

Frontend scaling: the switch is visible, but not thrown

The default candidate frontend still fails the linear clone-growth target. The measured worst doubling ratio is 2.288. Enabling refcounted String backing does not move the count because it changes bytes copied, not the number of clone calls. Enabling copy-on-write does: the ratio falls to 2.050 and the five-point sweep passes the 2.20 target.

The same option changes the 1,200-item array-append path from about 87.7 million array appends to 738 thousand and clone calls from about 95 million to 3.28 million. That is not a micro-optimization. It is evidence that whole-array copy-on-append is the dominant interpreter/front-end mechanism.

The remaining choice is architectural: promote HEY_RC_COW=1 to the default with its safety gates, or teach immutable owning built-ins to borrow arguments so the copies never start. The parse-time wall and the clone-count wall likely share this root but are different stages and different gates; neither may be closed by relabeling the other.

Every settled language and architecture decision

The design is no longer “whatever the current compiler happens to do.” The following rules are settled even where the implementation table below still says no.

One source of program meaning

Authoritative facts get an authoritative home

Operator meaning, names, argument binding, imports, JSON rules, child fields, lowering, and runtime capabilities each have one definition from which checks or code are generated.

One path, not five

Hey source becomes tokens, generated syntax, resolved structural HIR, MIR, and machine code. Interactive execution and compilation fork only after shared resolved meaning.

Generated compiler nodes

One schema produces constructors, field slots, accessors, child lists, walkers, rewriters, validators, and coverage checks. Handwritten code does not know node layout in parallel places.

No user-facing type annotations

Types live in the compiler. Source stays readable; structural HIR records the facts downstream stages require.

Small, explicit lowerings

Each pass has a narrow structural contract. LLVM emission prints earlier decisions instead of reparsing expression text.

Old authority retires only after proof

The ~190 text-inference lines go after both authority preconditions pass. The native emitter remains a differential oracle until replacement gates are mutation-proven.

Bindings, state, and concurrency

Bindings are immutable

A let, parameter, import, function name, loop variable, actor, or job keeps the same meaning. set never rebinds a local name.

State belongs to actors

set replaces the contents of a private state slot owned by an actor, monitor, or supervisor, each processing its own messages one at a time.

State-update spellings are closed

= += -= *= /= %= appear only after set. They are not ordinary expression operators and modules cannot claim them.

One read, one evaluation, one write

set count += amount() reads the slot once, evaluates amount() once, combines once, and writes once.

No indexed or local mutation

Collection updates build new values with operations such as put. Indexed, nested, property, parameter, map-entry, and local targets are outside set.

No classes

The language favors immutable values, module functions, and actors with explicit state ownership instead of class-shaped mutable APIs.

Operators, arithmetic, ranges, and casts

The operator set is closed

Arithmetic + - * / % **; comparison == != < <= > >=; Boolean && || and or not !; bitwise & | ^ << >>; state updates; ranges ..</..; and spread ....

Precedence is explicit

! binds tightly. not is loose. && binds tighter than ||. Word and/or are equally loose and group left-to-right.

One pow

Math.pow serves integers and decimals. ** is an ordinary declared library operator, keeps whole results whole, handles roots and reciprocals, rejects complex results, and rejects ambiguous chains.

Visible ranges

1 ..< 5 excludes 5; 1 .. 5 includes it. Spread keeps ..., avoiding Ruby’s one-dot ambiguity.

Integer semantics

Whole-number division by zero errors. Negative division truncates toward zero. Overflow promotes to a wider integer instead of wrapping.

Decimal semantics

Decimal division by zero produces Infinity; Infinity cannot convert to an integer; decimal modulo exists; decimal printing follows Ruby’s observed format.

Casts are functions

The next language task is a Cast module with to_i, to_s, to_f, and to_bool. Receiver forms and !!x are sugar over those functions.

Overrides are lexical

A file can import alternate arithmetic behavior. Libraries it calls retain the behavior they were written and tested against; the system reports active overrides.

Functions, names, defaults, and values

Full signature order

req, opt = 1, ...rest, kw_req:, kw_opt: 2, ...kw_rest is the six-slot order, and each slot is represented structurally.

Defaults run left-to-right

A default may see earlier parameters already filled at call time and may not refer forward to a later parameter.

Functions are values

Functions can be passed and stored in lists or maps. JSON refuses them instead of inventing an unsafe or ambiguous encoding.

Names remain readable

User functions may end in ? or !, may not start with a digit, and may not be punctuation-only. Compiler helpers use descriptive verb-first names and question marks for predicates.

JSON is strict

Functions and Infinity are not valid JSON values. Encoding stops with an error rather than silently writing null or a misleading number.

Call shape is structural

The callee, positional arguments, named arguments, receiver, and spreads occupy separate fields rather than one text blob.

Modules, imports, receiver calls, and operators

Four jobs, distinct words

Modules declare what they exposes; imports adopt selected names with exposing: or exposing *; conceals removes names; old as new renames one import.

Plain import is qualified

A bare import introduces only the module handle. as renames rather than aliases, so the original handle is gone.

Selectors are literal

Import selectors cannot be runtime-computed lexical names. Reusable bundles are ordinary facade modules such as WebPrelude, WebPrelude/All, and WebPrelude/Fast, not a second manifest system.

Public surface is exact

exposes * adopts all public names, not private helpers. A public function may still call its module’s private helpers.

Built-ins can be concealed

stdlib:BuiltIns supplies the default surface, but its names remain ordinary lexical facts that conceals can remove.

Receiver calls are lexical and static

x.f(a) resolves a known callable and lowers x as argument one. Chains resolve left-to-right. Runtime Module.load returns a value and introduces no lexical names.

Shadowing follows ordinary precedence

Later same-scope lexical definitions win with a warning. A callable field can be parenthesized when a receiver candidate shadows it.

Missing receivers fail at compile time

The diagnostic names the call location and suggests qualification, import, spelling, or concealment fixes instead of waiting for runtime lookup.

Operator functions have words

A module exposes a pronounceable function and declares its symbol separately. Precedence belongs to the symbol, never the importing module.

Testing, releases, packages, and “done”

Ruby is an oracle, not the specification

Ruby can compute expected answers while the new compiler is immature. Deliberate differences—such as negative division—are pinned by Hey’s own tests.

Golden retirement is mutation-proven

An old exact-byte test goes only after a clearer semantic test is written, deliberately broken, observed red, restored, and marked superseded. Published byte contracts remain exact.

Failures become loud

Web request failures return 500 rather than an empty success. Jobs use a name registry instead of being silently re-created.

One clean deploy path

Version bumps regenerate embedded goldens. Deployment sync uses exact tree checkout rather than cherry-picking through version-stamped artifacts.

Core, packages, apps stay separate

Core owns generic compiler/ABI/package primitives; packages own platform/domain adapters; applications own product behavior, credentials, and release cadence.

Three performance exit criteria

Fast web servers at the per-core bar, fannkuch, and 1BRC must all meet the chosen bar. Then existing iOS, Android, AppleTV, web, CLI, and actor applications become the regression suite.

Beta is evidence, not a version label

Multiple signed desktop archives, stable package contracts, blocking performance budgets, reproducible CI/SBOM/licenses, truthful mobile/TV receipts, and at least two maintained applications are required.

Obsolete work is not authority

Old work folders were pruned or archived with restore manifests; unfinished code was retained. Current measurements and current rulings outrank stale plans.

Corrections at claim volume

The 531a String fix did not switch semantic authority

It repaired a silent wrong answer in the old text-inference path. The reason to switch remains stronger because another bespoke heuristic was added to code slated for retirement.

Clone-to-retain is not a leak fix for the minimal returned parameter

The identity(x) workload is already flat at approximately 0.0 B/call. The work remains a performance and allocation cleanup requiring alias-safety proof.

Frontend scaling is not closed by compiled return emission

The gate counts clone calls while the tokenizer runs through the interpreter. Copy-on-write changes the count; compiled return retention does not.

The M3 Pro W7/W8 DNF is historical, not current

That matrix predates the later string-build repair. The Linux 526a run completes both at about 2.24 seconds. The current claim is “linear but about 4.3× C,” not “does not finish.”

The web number is not a per-core result

It used four pinned workers and 64 connections. It is a strong aggregate receipt, but the project’s per-core and full-latency acceptance work remains.

Rungs 3–4 are not in the supplied source zip

The uploaded 533a snapshot has 4,276 set sites in HeyLlvm.hey and lacks the new helpers. The live agent reports 4,272 after verified edits. This article keeps “landed” and “working tree” separate.

Research and repository sources

The architecture interpretation was checked against primary compiler literature rather than inferred from fashion:

  • MLIR publications and rationale: progressive lowering, explicit IR levels, verifiers, and modular infrastructure.
  • LLVM Language Reference: typed SSA is the output contract Hey’s emitters must agree on.
  • Rust MIR construction: MIR built from typed higher-level IR rather than source-text guesses.
  • Keep, A Nanopass Framework for Commercial Compiler Development: small passes, specified intermediate languages, well-formed outputs, generated boilerplate.
  • Yang, Chen, Eide, and Regehr, Finding and Understanding Bugs in C Compilers: differential testing and frontend wrong-code evidence.
  • Pnueli, Siegel, and Singerman, Translation Validation of Optimizing Compilers: validating individual compiler runs.
  • Leroy, Formal Verification of a Realistic Compiler: semantic-preservation proof as a stronger category than Hey’s current differential gates.
  • Python AST/ASDL documentation: generated node classes from one grammar.
  • Hewitt, Bishop, and Steiger, A Universal Modular ACTOR Formalism: local actor behavior and message-driven state as historical context, not a proof of Hey’s runtime safety.
