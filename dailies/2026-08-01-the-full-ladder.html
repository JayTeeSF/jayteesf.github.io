The day the speed problem stopped being a mystery

One cause, measured three ways. A multi-core panic that dissolved into an accounting error. And a set of rulings that make the road to fast Hey concrete for the first time. No rung moved today — and that is the honest headline.

Three words we are using precisely on this page

  • VERIFIED — a gate produced a verdict. Not shipped.
  • LANDED — merged to trunk. Not necessarily in anyone's hands.
  • DEPLOYED — running where it is used. Only this one is real to a user.

Today produced no new DEPLOYED artifact. It produced measurement and decisions.

The headline: the 162× is one thing

Hey's IPC is nearly double C's. The processor is not stalling — it is faithfully executing far too many instructions. That eliminates prefetching, allocator swaps, NUMA and governor tuning as levers, permanently. hey_value_clone deep-copies on every array write, so set x = put(x, i, v) rebuilds the whole array.

The fix already exists and has never once run. hey_rc_cow_enabled sits at hey_runtime.c:1248. Turning it on moves RSS by 0.008% — if clone had become a refcount bump, allocation would have collapsed. Every put(x,i,v) also reads x, uniqueness fails, and the deep copy is taken anyway.

The multi-core panic, and how it dissolved

The day opened with “we used to get 130K RPS single core, 8 cores was only slightly better.” Four measurements later: nothing regressed. Hey is ~30K rps/core on both platforms (Darwin 31.4K, Linux 27–30K) and a five-version bisect across 471a → tip is flat. The remembered 130K was w=1 → 132,349 rps at 4.21 CORES — because one worker is not one core. The “drop” was a 4-core number compared against a per-core number. Both measurements were correct; they measured different things.

What survives is smaller and real: the worker knob is inert on both platforms. 4.21 → 4.24 cores for an 8× change in workers is a flat line, not a scaling curve. Dead configuration, not a performance cliff.

What the maintainer ruled — the roadmap's new shape

Two decision dockets were published and answered today (Problem A, failure & containment). The rulings:

  • No visible types. Stdlib-only types are unfair to programmers who avoid them, and that unfairness becomes a feature request.
  • Conversion-directed hints. The compiler names the site and the to_i/to_s that unlocks it. The hint is a value, never a type — so the code still reads like Ruby.
  • Hybrid specialization — prove first, speculate second, hint always. Static proof where available; deopt where proof fails; the diagnostic reports which is which.
  • nil proven at the boundary and the check hoisted out of the loop, so the hot path stays pure i64.
  • Actor supervision, no VM. Erlang isolates by separate heaps, not address spaces — and Hey already isolates via hey_value_copy_isolated.
  • The interpreter retires as a semantics authority; scripts route through the compiler, on top of a new compile cache.
  • The two emitters collapse — last, not first. Oracles are replaced before the arm goes.
The argument that settled the last one

“We don't need native-c and llvm to tell us that 2.5 * 3 is not simply 6 — that's a bug cuz we know math.” The mirror is a relative oracle: it reports that two lanes disagree, never which is right, and it is blind to bugs where both are wrong together. A spec asserting 7.5 is an absolute oracle at half the implementation cost. wfloatparam is the live case: M.scale(2.5, 2) returns 4 compiled and 5.0 interpreted. The mirror reported a disagreement; a spec would have named the defect.

The sequencing, stated so it cannot be reordered

  1. Compile cache — scripts compile once, re-run the binary unless source changed.
  2. Absolute oracles — spec goldens asserting real answers, plus a specialized-vs-generic differential.
  3. The risky work — hybrid specialization, in-place mutation, the proven predicate.
  4. Then drop the C emitter to stage0.

Dropping C is how we stop paying double. It is not how we go fast, and doing it first would remove a safety net exactly while adding the most dangerous machinery this project has attempted.

A live hole in the shipped compiler

No Makefile target installs libhey_stdlib.a, and there are no lib/hey/runtime install lines at all. A distributed heyc fails closed on any program touching an archive member. Same family as make dist-host shipping no heyc. Item A was verified on the local build lane and shipped with this gap.

The retirement ladder — R2 → R8

No rung moved today. Saying so plainly is the rule. But the rulings changed what several rungs cost, which is the first time that has happened from a decision rather than a landing.

The clearest structural gain: the compile cache, R5 and R6 turn out to be the same road. Scripts routing through the compiler is what retires the repl as a semantics authority, and the cache is what makes that affordable. Three items collapsed into one sequence today.

Past R8 — where the language takes shape

This moved further than the ladder did. The unboxing decision is a language decision, and it was taken without adding a single visible type: to_i and to_s — conversions a Ruby programmer already writes — become the mechanism by which the compiler learns a type. The optimizer may insert them; the diagnostic explains where it could not.

Supervision also became concrete. Hey can have Erlang-style “let it crash” containment without a VM, because the isolation Erlang buys with BEAM, Hey already pays for with hey_value_copy_isolated at every callable and actor boundary. That isolation is currently paid for in exactly the copying we are trying to remove — which is the tension the in-place work has to resolve without breaking.

One invariant that constrains everything above

A supervisor contains logic failures. It cannot contain memory corruption. A checked boundary rejecting "abc" is safe to unwind and restart; an unsound uniqueness predicate mutating an array someone else still holds is not — it corrupts state that already escaped. Containment does not reduce the need to prove the predicate.

Nine claims we published and retracted today

  1. “Throughput collapsed 132K → 29K, possibly a 475a regression.” It was c=32 vs c=64 in the same arm, both arms equally — and the cliff did not reproduce at n=3.
  2. “The collapse is refcount cacheline contention.” Refuted: CPU stayed flat at 0.79 cores. Contention burns CPU; this consumed none.
  3. “Darwin reaches 4.14 cores, so it is a Linux-only defect.” From an n=1 smoke test. The worker knob is inert on both.
  4. “We lost 130K single-core throughput.” It was always a 4.2-core number. Nothing regressed in any version.
  5. “The elders test failure is pre-existing, not my auth change.” The baseline was run in a broken environment where both arms died for an unrelated reason. The maintainer was right.
  6. “bind is effectively closures.” It is clone-then-append with an isolating copy. Hey has no arbitrary-capture closures — and refcount-only reclamation is sound because of that.
  7. “You ruled out deoptimization.” Never said. Deopt is a correctness mechanism, not a risk, and it is now part of the chosen design.
  8. “The mirror is our best bug detector.” It is a relative oracle. Specs are absolute.
  9. “hey_sqlite3 needs republishing.” It was fine; the app's own bin/db-lib hard-coded a version and blamed the package.

Every one of these was caught by a seat going and getting a witness instead of accepting a shape. That is the only reason the day converged.

Glossary — every piece of shorthand on this page

  • The ladder (R2–R8) — the staged retirement of Hey's original C implementation. R2 is the gate; R8 is the end.
  • The mirror — two emitters, heyc.c (C) and stdlib/HeyLlvm.hey (Hey), required to emit byte-identical output.
  • Boxing — storing a plain integer as a tagged heap value instead of a raw machine word.
  • COW — copy-on-write: share until someone writes, then copy. Hey's exists and never fires.
  • Refcount / Perceus — reclaiming memory by counting references rather than by a tracing garbage collector.
  • Uniqueness predicate — the test asking “can anyone else observe this value?” If no, it is safe to mutate in place.
  • Read-borrow — reading a value creates a temporary reference; that is what currently defeats the uniqueness test.
  • Deoptimization — running fast code that assumed a type, and falling back to a generic version if the assumption fails. Correct either way.
  • The sidecar — a compiled binary spawning a child heyc to run stdlib calls it cannot lower. Not a compile cache.
  • Item A — libhey_stdlib.a, the precompiled stdlib archive that eliminates the sidecar spawn.
  • IPC — instructions retired per CPU cycle. High IPC means the processor is busy, not stalled.
  • Absolute vs relative oracle — a spec asserting the right answer, versus two implementations checked against each other.
  • fannkuch — a benchmark permuting an integer array; the worst case for boxed values, hence the magnifying glass.
