The two faces of Hey. W11 and W12 were added to bracket the language. On n-queens — pure recursion, arrays, branches — Hey is 4.5× C and ~12–13× faster than Ruby and Python: native compilation shows. On binary-trees — nothing but allocating and walking 260k+ two-field nodes — Hey is 14× C and slower than both Ruby and Python. Small-object allocation (each node is a reference-counted hash-object) is Hey's real bottleneck, the same root as the string-array gap in W7/W8. Compute is a strength; allocation is the work left to do.

The O(n²) reckoning

Three defects, two closed

A complexity-slope probe (doubling N, watching whether cost-per-op stays flat) found three quadratic hazards. Here is exactly where 549a stands — including the one the headline number almost hides.

FIXED

Defect 1 — push-built arrays

A push loop degraded to clone-per-element whenever the array was later passed to any call. Now O(1) amortized. This also unblocked the compiled tokenizer.

PARTIAL

Defect 2 — maps were association lists

A hash index made insert/lookup O(1), and 549a made in-place update O(1) — but only when the map is also read via has?/get/keys in the same function. A write-only put loop, and any map passed into a function that mutates and returns it (the 1BRC merge shape), still deep-clone the whole map: O(map-size) per update. That gap is why 1BRC has not moved.

OPEN

Defect 3 — string concatenation s = s + x

Still O(n²): each concat copies the whole prefix. An amortized string backing exists but the + operator isn't wired to it. Also affects the planned distributed wire codec.

NOTE

Immutable prepend [x, ...a]

O(n²) in a loop — it copies the array each time. Append [...a, x] is O(1); build with append (or push) and reverse.

1BRC keeps a per-station statistics map and updates it once per row, with the map threaded through a merge function. That interprocedural update is precisely the shape Defect 2 still misses, so the cost is O(rows × stations). The map fix that gave W9/W10 two orders of magnitude simply doesn't fire here — which is the single most important thing this re-evaluation surfaces, and the next thing to fix.
