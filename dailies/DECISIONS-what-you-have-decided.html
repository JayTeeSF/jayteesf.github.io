Settled

Negative division stays as it is

-7 / 2   is   -3

Rounds toward zero, like C and Go. Ruby says -4. You reversed an earlier choice here after it measured at 15% slower on the benchmark that certifies our speed. Ruby's version is available on request — see Overrides.

Reversing it also removed a real bug: our benchmark's averaging code rounds on top of the current behaviour, and Ruby's version would have made it compute wrong averages silently.

Overrides are per-file, and cost nothing unless you ask

import "stdlib:RubyMath"              → RubyMath.div(-7,2) to compare
import "stdlib:RubyMath" exposing *   → this file gets Ruby's math

A file that asks gets Ruby's arithmetic. Libraries it calls keep the behaviour they were written and tested against. The system will report every override in effect.

Known trade, taken knowingly: the number-one documented reason nobody uses Ruby's equivalent feature is having to write the import in every file. We took the safe option over the convenient one. Revisit if the friction bites.

How you write an operator

fn add(a, b) ... end
exposes add infix: '+'

You never name a function +. You name it something pronounceable and declare the symbol separately — so an error says add failed, not + failed, and a stack trace has a word in it. Redefining + still works; you just keep the name.

Precedence comes from the symbol, never from the module. Two languages that let modules set precedence were tested: an import silently changed how an expression parsed, with no warning.

Function names

?       no      a name can't be only punctuation
2       no      a digit can't start a name

The last one is what stops 3.2 being ambiguous with a call to a function named 2.

Dividing by zero

1   / 0     stops with an error     ← shipped
1.0 / 0.0   Infinity
inf.to_i()  stops with an error

Whole numbers and decimals differ on purpose — that's what Ruby does and what the floating-point standard requires. Infinity is a real decimal value; no whole number means it, so that's where it stops.

One bug must be fixed first: Infinity inside JSON output currently writes a wrong number instead of failing.
