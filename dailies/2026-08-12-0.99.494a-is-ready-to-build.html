Before you build: clear the caches

This failure is silent, which is why it is the first instruction and not a footnote. The self-hosting pipeline consumes a checked-in copy of the generator bundle, not the library source. Editing the source alone produces a build in which your change never reaches the code generator, under a hash that looks perfectly correct. Regenerate the bundle and delete the pipeline caches before every build.
# regenerate the checked-in bundle, then drop the stale pipeline caches
ruby tools/generate_agent30_selfhost_bundle.rb --write
rm -f build/hey-selfc-pipeline-* && rm -rf build/compiler-sidecars

# then build the image
HEY_ROOT=$HOME/dev/hey-lang-bootstrap-plan ./bin/toolchain-image --platform linux/amd64

If the toolchain build fails with HeyParser.parse_file (response deadline expired), that is the 30-second per-call timeout on reading from the helper process, not a compiler fault. Pin HEY_STDLIB_SIDECAR_TIMEOUT_MS=600000 in toolchain.Dockerfile.

Where this release leaves the roadmap

Every release carries the roadmap, including the rungs it did not touch. Two moved. Five did not. Open any rung for its current position; the reasoning behind the two that moved is in the companion status page.

R2 Narrow the ordinary build path moved

The Hey-written generator's opening section now matches the older one exactly, which is what let the 51-program comparison run for the first time: 42 of 51 byte-identical, up from 38. Ordinary programs still fall back to the older generator when they contain a shape the new one refuses.

R3 Delete the native code generation blocked

Unmoved, and the most consequential item on the board — this is the rung that would let the older generator actually be deleted. Its 90 reference files are pinned sixteen releases stale on purpose, because their checker fails on its first program for a live disagreement between the two generators. Regenerating would launder that disagreement into the baseline and destroy the instrument.

R4 Label the comparison-only generator, guard new callers unmoved

Not closed. Requires making the comparison-only role explicit in naming, and preventing ordinary tools from adding new callers of the native backend outside the seed, recovery and reference set.

R5 Verify by compiling rather than interpreting unmoved

Foundation only. Requires running the specification suites as compiled programs, running both ways until parity is proven, then making compile-and-run the default.

R6 Retire the native script evaluator unmoved

Future, and newly complicated: that evaluator destroys a loop's own header text while parsing it, so from the second iteration it evaluates a truncated condition. One of the three outcomes prints the wrong number and exits reporting success. No ledger row yet; writing one is queued.

R7 Bootstrap fixed point, delete the seed unmoved

Future. Requires publishing seed artifacts and proving the compiler rebuilds itself to byte-identical output before the native backend and its subcommands can be deleted.

R8 Thin launcher, zero semantic debt unmoved

Future. C remains only as command-line and linker mechanics; requires reconciling every document and ledger and shipping the fully self-hosted release receipts.

Past R8 The language program itself moved

Of the 56 published language decisions, 19 now hold in both lanes, 2 are blocked on primitives that do not exist yet, and 35 are not yet implemented. "Not yet" is the normal state and is not a bug list — most of these describe a language still being built. There are currently zero decisions on which the two lanes disagree.

Glossary

Reference for the shorthand used above. Terms marked new were coined since the previous daily.

Tier
A group of automated checks run together. The fast tier is 110 checks and takes about twelve minutes; the heavy tier is 8 slower checks and takes about ten.
Gate
One automated check with a recorded expected result — green or red. A known-red gate is a tracked defect, not a surprise.
Ledger
The file recording every gate and its expected result. Totals derived from it can be compared against a run's totals; when the two agree you have two independent witnesses.
Flaky row
A gate registered as sometimes passing, sometimes failing. Neither outcome is news, and it is deliberately never promoted to expected-green.
Promotion new
Moving a gate's recorded expectation from red to green because the defect it tracked is fixed. Doing it in the wrong commit order is how a gate ends up registered green on a tree where it would fail.
Boxed value new
A value carried with a label saying what kind of thing it is. Messages between actors carry boxed values.
Tag-typed comparison new
Comparing two boxed values by checking their kind labels first, rather than converting both to text and comparing characters.
Lane
One route from source to a running program. The shipping lane is the one users' programs actually take.
Parity sweep new
Running the same programs through both code generators and comparing the output byte for byte. Currently 42 of 51 programs match.
Control
A measurement that must not move when a fix is applied. Its job is to rule out the possibility that the improvement came from somewhere else, or that the measurement itself broke.
Self-hosting bundle new
A checked-in copy of the code generator that the build pipeline actually consumes. Because it is a copy, editing the original library source without regenerating it produces a build where the change never took effect.
Byte-identical
Two paths producing exactly the same output, byte for byte. This project uses it as the standard of proof in place of "it seemed to work".
Ratchet
A gate that records a running count of known debt and fails if the count goes up. It permits the number to fall but never to rise, so debt can only be paid down.
HIR and MIR
The two intermediate forms a program passes through between source code and machine instructions — first a form close to the source, then a lower-level one with types and calling conventions made explicit. The reference files for both are checked for unexpected changes on every release.
ABI, and abi_id
The Application Binary Interface: the exact machine-level types and calling conventions a caller and a callee must agree on. The abi_id is a fingerprint of that agreement, and it folds in the version number — which is why every version bump requires it to be regenerated before anything is built.
Sidecar
A separate helper process the compiler hands work to and waits on. Its read timeout is what produces the "response deadline expired" failure above.
Landed / Verified / Deployed
Verified: on a branch, with reproduced evidence. Landed: committed and through the check battery. Deployed: available to users through the released route. 494a is landed and certified. Building the image is what makes it deployed, and that step has not been taken.
