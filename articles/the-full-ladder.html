Hey · full ladder · 28 August 2026 · evening

Stop counting activity. Close components.

Hey has made real architectural progress, but the project has also accumulated a habit of proving narrow slices faster than it closes whole product boundaries. This ladder measures something stricter: what a user can trust, what the compiler can prove end to end, and what still blocks native-class performance.

Today’s state

  • 0.99.554a is an uncertified development checkpoint.
  • The old 90/91 LLVM-fixture story is closed: current native and Hey emitters agree on 91/91 pinned fixtures.
  • The broader corpus is still open: four examples have genuine emitter divergence, while other examples fail closed before comparison.
  • Release certification itself is a component that must be finished: the written contract is stronger than the checked-in runner and resource guard.
  • The main performance debt remains structural: method-form map update can still scale as O(map), so 1BRC is nowhere near the product bar yet.

The ladder

1 · Language surface

Functions, values, modules, actors, jobs, IO/networking, packages and distributed transport are substantial enough that the source language is no longer the main uncertainty.

SUBSTANTIAL
2 · Semantic compiler identity

The resolver can publish function identity and link authority; same-spelling functions no longer have to collapse to the same body. The remaining goal is to make source/module/function identity uniformly authoritative instead of letting filenames or printed names re-enter later.

MAJOR THRESHOLD CROSSED
3 · Self-hosted emitter parity

The 91 pinned LLVM fixtures agree. The next proof is wider: four examples still diverge between the Hey and native emitters, and the fail-closed set must be classified one by one rather than hidden in an aggregate.

FIXTURE CLOSED / CORPUS OPEN
4 · Release trust

The certification contract now says the right things—immutable HEAD, clean tree at gate boundaries, bounded resource use, exact known-red signatures—but the checked-in harness does not yet mechanically enforce all of it. Until that code catches up, a long green-looking run is not enough.

ACTIVE BLOCKER
5 · Ownership representation

Some ownership/reuse decisions still derive semantics from serialized MIR or expression spelling. That is why equivalent source forms can reach different cost models.

STRUCTURAL DEBT
6 · MAP_PUT / 1BRC

Builtin map update can be flat in controlled tests while method .put remains O(map). This is the clearest current example of language ergonomics and compiler semantics disagreeing about what “the same operation” means.

SPEED GATE
7 · FAST suite

After MAP_PUT, prove 1BRC, fannkuch and web under fixed compiler identities, fixed inputs and serialized local benchmarking. One fast path is encouraging; a product needs a repeatable family of them.

NEXT PERFORMANCE PHASE
8 · Distributed product

Transport is real; clustering, placement and upgrade orchestration are the next layer. Keep this behind compiler/release/performance closure so distribution does not become another permanently half-finished frontier.

HELD INTENTIONALLY
9 · Module authority / Sys cutover

Hey is removing the privileged ambient built-in layer: every operation gets a real module home, and the recommended everyday vocabulary arrives through an ordinary import of a curated facade rather than through a compiler exception. Sequenced with rungs 2 and 6, not after rung 8 — it is the same identity work seen from the language side. Exit conditions: receiver, bare and qualified forms all publish one binding identity; every real operation has a module home; the facade’s membership is curated from an application corpus rather than settled by import order; first-party migration is complete; legacy ambient-resolution hits read 0; legacy receiver tables are deleted. Background: Imports that change the flavor of the language.

CUTOVER IN PROGRESS

What changed today

A false last-defect story died

The previously reported “90/91, one remaining statement-position concat divergence” was re-audited against the true current producers and disproved. The useful lesson is bigger than the fixture: artifact identity belongs in every performance/parity receipt.

The stage-0 memory failure was fixed at the cause

Return-local cleanup now follows function lifetime rather than leaking every returned frame’s locals. Bounded resolver measurements went from catastrophic growth to a small stable footprint.

The release gate exposed the next layer of reality

Instead of one clean “pass/fail” answer, the suite surfaced stale projections, real emitter gaps, silent gates, parser/runtime failures and known-red registry drift. The correct next unit is a causal family, not a raw red count.

The docs themselves were stale

The previous 8/28 architecture and ladder still centered “18 A1a failures,” even though the active problem had moved. A canonical current page must change when the product’s bottleneck changes.

What counts as a closed component

Not enough

A green microfixture, a correct printed answer, one fast benchmark, a checked-in generated file, a known-red label, or a successful fallback path.

Enough

One semantic authority; the production path uses it; negative controls prove the gate can fail; fallback is zero or explicitly bootstrap-only; real programs exercise it; and the scaling curve matches the claimed complexity.

Performance north star

The project should keep the ambition high without turning marketing numbers into engineering requirements. Mojo’s “orders of magnitude over Python” story is useful because it demonstrates the point of compiler specialization: friendly source does not have to imply interpreter-level overhead. Hey’s proof should be more concrete:

Friendly source → proven meaning → cheap representation → native work
