Collections#

Import stdlib:Collections for immutable array and object helpers.

Eager higher-order operations#

Module functions and their receiver forms provide synchronous immutable list processing with ordinary named callables:

import 'stdlib:Collections' \
  exposing: [each, each_with_index, map, filter, reduce, find_value, any?, all?] \
  forms: [:dotted]
import 'stdlib:Iteration' exposing: [times] forms: [:dotted]

fn show(value)
  says value
  return value
end

fn show_with_index(value, index)
  says index + ':' + value
  return value
end

fn double(value)
  return value * 2
end

fn even?(value)
  return value % 2 == 0
end

fn add(total, value)
  return total + value
end

3.times(show)
let values = [1, 2, 3, 4]
values.each(show)
values.each_with_index(show_with_index)
let doubled = values.map(double)
let evens = values.filter(even?)
let total = values.reduce(0, add)
let first_even = values.find_value(even?, nil)
let has_even = values.any?(even?)
let all_even = values.all?(even?)

The equivalent module calls are Iteration.times, Collections.each, Collections.each_with_index, Collections.map, Collections.filter, and Collections.reduce. times yields indexes starting at zero. Both each operations return the original collection. map and filter return new arrays; reduce returns its final accumulator. Inputs are never mutated.

Bare .map, .filter, and .each execute synchronously in the caller. A bounded worker-backed stream is intentionally visible through workers::

import 'stdlib:Streams' exposing: [map, collect] forms: [:dotted]

let stream = values.map(double, workers: 4)
let doubled_in_parallel = stream.collect()

any?, all?, and find_value short-circuit. Parallel collection work is explicit through stdlib:Streams.

Default, key-based, and natural sorting#

Lexical ascending order needs no comparator:

import 'stdlib:Collections' exposing: [sort, sort_by, natural_sort] forms: [:dotted]

let names = ['grace', 'ada', 'linus'].sort
let reverse_names = names.sort(order: 'descending')

Use sort_by when ordering records by a derived key. Hey uses a stable decorate-sort-undecorate implementation, so the key function runs exactly once per item and equal keys retain input order:

fn score(record)
  return record.score
end

let ranked = records.sort_by(score)
let highest_first = records.sort_by(score, order: 'descending')

Natural sorting compares numeric runs numerically and is useful for versions and numbered paths:

let versions = ['v0.2.10', 'v0.2.2', 'v0.2.0'].natural_sort
# => ['v0.2.0', 'v0.2.2', 'v0.2.10']

All forms return new arrays. They never mutate the receiver. The default, key-based, ordered, and natural forms execute directly through the LLVM runtime ABI.

Stable comparator sorting#

Collections.sort(items, comparator) returns a new array. It never mutates the input and is stable: records that compare as equal retain their input order.

A comparator receives left and right and returns:

  • a negative integer when left belongs first;
  • zero when the values are equivalent for ordering;
  • a positive integer when right belongs first.
import 'stdlib:Collections' exposing: [sort] forms: [:dotted]

fn descending_score(left, right)
  return Collections.compare_desc(left.score, right.score)
end

let ranked = records.sort(descending_score)

Use Collections.compare for ascending scalar order and Collections.compare_desc for descending scalar order. Both support compatible numbers and strings, booleans (false < true), and nil (nil sorts first in ascending order).

Collections.compare_chain describes multi-key precedence without embedding a sorting algorithm in application code:

fn compare_users(left, right)
  return Collections.compare_chain([
    Collections.compare_desc(left.pro, right.pro),
    Collections.compare_desc(left.duration, right.duration),
    Collections.compare_desc(left.db_time, right.db_time),
    Collections.compare_desc(left.allocations, right.allocations)
  ])
end

The function form and receiver form are equivalent:

Collections.sort(records, compare_users)
records.sort(compare_users)

Callbacks may be private module functions when the owning module passes the callable value:

module PackageIndex
  private fn compare_paths(left, right)
    return Collections.compare(left, right)
  end

  fn ordered(paths)
    return paths.sort(PackageIndex.compare_paths)
  end

  exposes ordered forms: [:qualified]
end

The private name is checked when PackageIndex.compare_paths becomes a callable value. Collections.sort invokes that already-authorized capability. Semantic HIR/MIR may canonicalize the definition to PackageIndex__compare_paths; direct LLVM resolves the dotted source spelling to that same identity before dispatch.

Use bracket access for dynamic keys. Use dot access for fixed fields:

record.duration       # fixed field
record[field_name]    # dynamic key
