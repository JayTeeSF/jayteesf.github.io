Compiler pipeline#

Hey has one frontend and one lowering path.

source files + import graph
        |
        v
TOKENIZER
  token kind, spelling, source span
        |
        v
FINAL SYNTAX
  grammar shape, operator form, precedence, associativity,
  calls, arguments, blocks, imports, module declarations
        |
        v
NAME RESOLUTION
  lexical binding IDs, module surfaces, import selections,
  receiver-call targets, operator bindings, state-slot validity
        |
        v
STRUCTURAL SEMANTIC HIR
  semantic operations and structured control flow
        |
        v
ABI MIR
  blocks, temporaries, representation, ownership, runtime ABI
        |
        v
LLVM
  mechanical instructions and runtime-helper calls

Sources of truth#

compiler/schema/ contains machine-consumed normative sources and generated-contract inputs:

  • node shapes and logical fields;
  • operator registry;
  • module exposure model;
  • runtime/intrinsic registry.

Host-side generators produce checked-in projections. Ordinary builds consume the checked-in output. Verification regenerates and diffs, avoiding a bootstrap cycle.

Forbidden duplication#

  • The tokenizer never decides prefix versus infix -.
  • The parser never invents precedence outside the operator projection.
  • The resolver never changes precedence or associativity.
  • HIR/MIR never split raw expression strings.
  • LLVM never chooses language arithmetic because an instruction seems convenient.
  • REPL/interpreter do not keep a second tokenizer/parser/resolver contract.

Exact compiler nodes#

Compiler nodes are generated exact values. One schema produces constructors, physical field slots, readers, child enumerators, walkers, rewriters, validators, and coverage checks.

Local readers use non-returning scoped consumers; escaping values use explicitly owned readers. A borrow handle cannot become a general Hey value or survive its synchronous consumer.

Authority invariants#

  • Interpreter, REPL, Stage-0 recovery, self-host, and direct LLVM consume the same tokenizer, final-syntax, and resolved-name facts.
  • Local generated-node readers use scoped borrows with zero snapshot clones; every value that outlives the consumer is promoted or read explicitly as owned.
  • CLI, web, iOS, Android, and AppleTV compile receipts exercise the same frontend contract.
  • Frontend scaling gates reject unresolved superlinear copying rather than hiding it behind larger timeouts.
  • A compatibility path may exist only as bounded recovery evidence and is removed once stronger replacement tests are proven able to fail.

Release availability and any active promotion work are reported on Implementation status, not encoded into this architecture page.
