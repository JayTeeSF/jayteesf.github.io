P1 closes, and fannkuch gets a bill of materials

2026-07-30 · Hey v0.99.473a · working notes from the language program

Two stories today, both with receipts: the program that removes type-guessing from the compiler finished its catalogue, and the worst benchmark number the project has ever produced was traced — in a single day — from a wall-clock ratio to two named malloc call sites.

Three landings, one disease

The disease: the compiled lane deciding what an operation means by looking at the spelling of its source text instead of asking what the values are. It produced silent wrong answers that byte-identity checks structurally could not see, because both compilers agreed on the wrong answer.

let a = 1.5
says a * 2      2 on every version before yesterday — now 3.0   (472a)
says (a) * 2    "1.51.5" — a redundant paren string-repeated — now 3.0

fn look(coll, k)  return has(coll, k)  end
says look([10,20,30], 1)   crashed (exit 70) on every version — now true  (473a)

With 473a, the catalogued conversion program (P1) is closed: put (470a), boxed arithmetic (472a), has/has? (473a). Each landing was proven on the deployed binary and independently certified on a second machine. The known stragglers — ordering comparisons, division-by-zero, parameter and return-type inference — each have a version slot and, as of tonight, complete acceptance evidence.

Fannkuch: the first real scores, and then the autopsy

fannkuch-redux ran correctly in Hey for the first time (reference values reproduced at n=7 and n=10), because the 471a store fix removed the O(n)-copy wall — the same store measured 7,369 ns at N=512 two days ago and 33 ns today, flat. The honest verdict at n=10, one machine, compiled-vs-compiled verified:

lanemedianvs C
C (gcc -O2)151 ms1.0×
Go161 ms1.07×
Hey (compiled)24,354 ms161×

The contrast that localised it: a registers-only tight loop is within 6% of C on the same box, same compiler. Between 6% and 161×, the only difference is touching array elements.

Then the autopsy, each step killing the previous theory: the research literature bounds value-representation wins at ~2–4× (can't supply 161×); cycle arithmetic kills the function-call theory (a call is 5–20 cycles against a 92–155 cycle budget); allocation counters find the real bill: two heap allocations and two frees per element store, 64 bytes, flat in N. Backtraces then named both sites: the array read boxes its result (created and consumed in the same expression — never escapes, freed the same iteration), and the store shim boxes its return because the runtime's calling convention returns boxed values.

That sets an honest ceiling: the first fix removes the dead-on-arrival read box (2→1 allocations, projected to cut the constant roughly in half — measured after it lands, not before). The second box is the shim calling convention itself; removing it means emitted code holding unboxed values across the runtime boundary — a real program, aligned with the compiler-retirement ladder, not a quick patch. Three plausible mechanisms were proposed and killed by measurement in one day before this account closed; every retraction was published at the same volume as the claim.

Also today

The name-collision design was ruled in full (your names win, with a mandatory, explicitly-suppressible warning; ergonomic defaults become an ordinary forkable Sys module — no hidden prelude). The verification harness gained structural guards against four instrument-defect classes it caught in itself this week — gates that can't parse, can't execute, can't speak, or register signatures that can never fire. And a silent wrong answer hiding behind a zero-byte log for days (non-finite floats printing INT64_MIN with exit 0 in one lane) now announces itself with its mechanism in every test run.

Numbers in this note carry their conditions in the program's evidence ledger; projections are labeled and dated, and a slipped date gets updated, never silently kept.
