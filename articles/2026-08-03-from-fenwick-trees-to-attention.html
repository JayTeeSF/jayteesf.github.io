From Fenwick trees to attention

Machine learning looks exotic when it arrives as one giant framework. It looks much less mysterious when you build the ladder underneath it: immutable trees, matrices, weighted graphs, dynamic programming, gradients and finally a small attention block.

The verified library

The current Hey overlay adds 25 reusable stdlib modules, backed by 12 runnable examples and 12 integrated language specs. Every example produces identical output in the interpreter and the Stage-0 native compiler. The new code uses ordinary Hey module functions and immutable values; it does not add classes or teach mutable local programming.

The ladder starts below machine learning

A neural network is not one algorithm. It is a pile of smaller ideas that have already appeared elsewhere in computer science.

FoundationWhat it teachesWhere it reappears in ML
Balanced treesMaintain useful structure while updates change shape.Training systems constantly reorganize indexes, batches and schedules without wanting accidental mutation.
Segment and Fenwick treesStore summaries so a range question does not rescan every element.The same instinct drives cached statistics, cumulative weights and batched reductions.
Weighted graphsSeparate representation from traversal and cost.Attention is also a weighted relationship system, though its weights are dense and learned rather than hand-authored edges.
Dynamic programmingRemember subproblem results and make dependencies explicit.Backpropagation is a reverse dependency walk over intermediate values.
MatricesGive repeated scalar operations one structural vocabulary.Dense layers, projections, attention scores and feed-forward blocks are matrix-shaped computations.

The point is not that a Transformer secretly contains a Fenwick tree. It does not. The point is that both reward the same habit: choose a representation that makes the important operation explicit.

Three kinds of “remembering”

1  A Fenwick tree remembers partial sums

A naïve prefix sum walks every earlier element. A Fenwick tree stores overlapping summaries, so updates and prefix queries touch only a logarithmic number of positions.

values:       3  1  4  1  5  9
stored idea:  partial sums at carefully chosen ranges
question:     sum [0, 5)
answer:       combine a few stored summaries

Hey's public value stays immutable. Updating the tree returns a new value, even though the algorithm is taught in many languages as an in-place array trick.

2  Dynamic programming remembers solved subproblems

The 0–1 knapsack, longest common subsequence and longest increasing subsequence modules all make a dependency table visible. A result is not guessed; it is assembled from earlier states.

LCS[i][j] depends on:
  LCS[i-1][j]
  LCS[i][j-1]
  LCS[i-1][j-1]

That is already close to the mental model needed for automatic differentiation: record how a value was produced, then propagate information through those dependencies in the appropriate direction.

3  Backpropagation remembers influence

The educational NeuralNetwork module performs a forward pass, computes mean-squared error, and returns inspectable gradients together with a new network. Training is therefore a value transformation rather than hidden mutation:

forward(parameters, input)       -> activations
backward(parameters, activations, target)
                                -> gradients
apply_gradients(parameters, gradients, rate)
                                -> new_parameters

The implementation is intentionally small and sequential. That makes the chain rule visible instead of burying it under a tensor runtime.

A graph view of attention

Weighted graph algorithms ask which relationships matter. Dijkstra asks for cheapest cumulative cost. Prim and Kruskal ask which edges connect everything without unnecessary weight. Greedy best-first follows the most promising local estimate. Attention asks a different question:

For this token, how much should every visible token contribute to the next representation?

In a single-head attention block, each token becomes a query, key and value. Query-key compatibility creates a dense matrix of scores. A causal mask removes future edges. Softmax turns the remaining scores into weights. Weighted value combinations produce the next token representations.

tokens
  │
  ├──▶ query projection ─┐
  ├──▶ key projection   ─┼──▶ scores ─▶ causal mask ─▶ softmax ─┐
  └──▶ value projection ────────────────────────────────────────┼──▶ weighted sum
                                                                  ▼
                                                           residual + norm
                                                                  ▼
                                                           feed-forward block

This is graph-like, but it is not Dijkstra in disguise. The graph is dense, the edge strengths are learned, and the operation aggregates all permitted neighbors rather than selecting one route. Comparing them is still useful because it separates three concerns:

  • representation: which relationships can exist;
  • weighting: what each relationship costs or contributes; and
  • algorithm: whether we choose a path, a tree, or a weighted aggregate.

Why immutability helps the teaching version

The old value remains inspectable

An AVL insertion, a union operation, a gradient update and a Transformer block all return new values. That makes before/after comparison natural and removes the question, “which helper mutated this object?”

Intermediate states can be part of the API

The neural-network example can return gradients rather than hide them. Graph searches can return distances and parents. Tree validation can return a report. Educational code becomes easier to interrogate when state transitions are values.

But immutable does not automatically mean fast

Persistent arrays make some updates more expensive than a specialized persistent vector or tensor buffer would. The current modules are readable reference implementations, not a production ML runtime. The right next move is measurement-led specialization behind the same public APIs—not teaching users to mutate everything.

The facades matter. RedBlackTree delegates to the canonical Tree implementation instead of forking balancing logic. DSU delegates to UnionFind. The new graph algorithms build on weighted adjacency surfaces instead of baking one representation into every algorithm.

What this does not claim

A teaching Transformer is not a production tensor stack

The current module has one attention head, ordinary Hey arrays, approximate scalar math, a causal mask, layer normalization and a feed-forward block. It demonstrates structure and semantics. It does not claim GPU kernels, automatic batching, mixed precision, industrial numerical stability or large-model throughput.

  • The neural network uses sequential single-sample SGD, ReLU and mean-squared error.
  • The longest-increasing-subsequence implementation is the readable O(n²) version.
  • Persistent array updates can dominate algorithms that are traditionally taught with mutable arrays.
  • Recursive reference algorithms still depend on Hey's broader bounded-stack roadmap for huge inputs.
  • Bloom filters intentionally permit false positives.

Those limitations are features of an honest teaching library: they tell us what should be optimized next without pretending the public abstraction is wrong.

The useful lesson

Machine learning is easier to reason about when it is the top of an algorithmic ladder instead of a separate magical kingdom. Trees teach invariants. Range structures teach cached summaries. Graphs teach representation versus traversal. Dynamic programming teaches dependency. Matrices teach repeated structure. Backpropagation and attention then become new compositions of familiar ideas.

The same principle guides the compiler restructure happening beside this stdlib work: one authoritative representation, explicit ownership, generated traversal, and no downstream stage rediscovering facts that an earlier stage already knew.
