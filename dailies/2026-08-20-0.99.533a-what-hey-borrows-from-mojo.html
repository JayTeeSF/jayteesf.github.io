The clean-up has a blueprint now — and it comes from under Mojo.

The emitter campaign reached the hardest target on the board — the frontend-shadow gate receipt, a twenty-five-segment interpolated string — and now emits the whole of it through the Hey lane with zero fallback. In getting there it produced a first: a construct where the Hey-written compiler is authoritative over its own C reference. Bool interpolation renders environment_isolated=true in the Hey lane and 1 in the legacy native emitter, which has no bool arm — so for the first time the “one true compiler” outvotes its oracle rather than matching it. Separately, the uniform lowering-table refactor that yesterday's note named but could not source now has an external blueprint: MLIR, the compiler substrate under the new Mojo language, plus the Perceus reference-counting work — with a round-trippable IR as the cheapest first step.

Where the campaign got to: the gate receipt

The pipeline is Hey → HIR → MIR → {native-C emitter, Hey emitter}. Two back ends consume the same MIR; the native-C emitter (heyc.c) is the reference oracle, and every shape the Hey emitter learns is compared byte-for-byte against it. Since the 533a report the campaign closed four more structural rungs, and the last of them is the one that matters most, because it is the gate's own output.

Rungs 56–58String-return conventions.
Rung 56The return f(digest, "form " + kind(node) + " " + span_text(...)) wrapper: the outer call now reloads its string arguments through native's expression-call convention, and the concatenation folds recursively. Both the call-operand and field-operand spellings are byte-identical.
Rung 57len(frontend_shadow_list(value)) — the length of a boxed-returning call — lowers to the call plus json_len_i64, matching native.
Rung 58local s:str = f(g(...), ...) — the local-binding twin of rung 56, extended so a nested string call reloads its own arguments through the same convention.
Rung 59 — the receiptTwenty-five interpolation segments.
Every segment kindBoxed fields, string locals, a Crypto.sha256_text facade, single-quoted Env.default('K', ''), an i64 call with a boxed-field argument, and the boxed-domain return epilogue — each verified byte-identical to native in isolation.

The milestone inside the receipt: Hey outvotes its oracle

The receipt contains the gate's own verdict field: environment_isolated=#{frontend_shadow_env_clean()}. Interpolating a boolean call is where the two lanes stop agreeing. The native emitter formats the boolean as a number and prints 1; the Hey emitter renders the text true. This is not a Hey bug — it is a native one. Native's interpolation lowering has no boolean arm, a fact this project decided and documented on 7 August: the interpreter and the Hey lane write true, and only the legacy native lane writes 1.

This is the first construct on which the Hey-written compiler is authoritative over its C reference rather than matching it. The whole campaign has, until now, treated native as the oracle. Here native is the buggy lane, so byte-identity to native would reproduce the defect the gate exists to catch. The receipt is byte-identical to native for every segment before the boolean, then diverges by one temporary and two constants from the boolean on — by design. For this rung the reference is not the C emitter; it is the two lanes' produced strings, and the north-star build --backend llvm was run to confirm it prints environment_isolated=true.

The consequence for the gate is direct: environment_isolated reads 1 today only because the whole shadow still falls back, whole-file, to native's interpolation emitter. The moment the Hey emitter lowers the receipt itself — which it now does through the pipeline — the field becomes true. This rung is the mechanism that flips it.

The deferred refactor now has a blueprint — from under Mojo

Yesterday's note named the end state the emitter is heading toward: not N bespoke, name-coupled arms, but one structural rule. It could name the shape but not source it. It can now. The shape has a mature reference implementation and a body of literature, and the fastest way to see both at once is the language everyone is currently talking about: Mojo. Mojo is the fastest thing with Python's syntax, and Modular's own docs call it “syntactic sugar for MLIR.” The borrowable part of Mojo is not a keyword; it is MLIR, the compiler substrate beneath it (Lattner, Amini, Bondhugula, Cohen, Davis, Pienaar, Riddle, Shpeisman, Vasilache, Zinenko; arXiv:2002.11054). MLIR's paper even draws Hey's exact situation — Swift, Rust, and Julia each hand-building a mid-level IR down to LLVM — as the redundancy it exists to remove.

Five borrows fall out of that, ranked by value over cost. Four are properties of the substrate under Mojo; the fifth is a mistake Mojo made and corrected.

Do first — nearly freeUnlocks the rest.
1 · A parseable IRHey emits its mid-level IR as text but cannot read it back. Give it a parser so print(parse(x)) == x holds — a correctness producer that cannot be wrong the same way the emitter is, because it never consults the emitter.
3 · Verify the IRMLIR builds op verifiers into the IR that fail the instant a pass produces malformed output. A verifier over HIR and MIR — well-typedness, single-assignment dominance, reference-count balance — localizes a failure the byte-diff can only report from the far end, and catches the “both emitters wrong the same way” case the oracle structurally misses.
The refactor properThe uniform rule, sourced.
4 · Rewrite, don't scanLowering as structural rewrite — match a shape, produce a lower one — is the general form of the segment-scanner-to-recursive-fold move already landed. A small match-and-rewrite layer written in Hey retires the eight-named-plus-five-anonymous scanners and dissolves the wall that made a right-associative ** inexpressible.
2 · Ownership on the MIRHey is immutable and reference-counted — the exact setting of Perceus (Reinking, Xie, de Moura, Leijen, PLDI 2021). Its reuse analysis updates a uniquely-owned value in place, which is how an immutable language stops copying and reaches C speed. Like a borrow checker, it belongs on the desugared mid-level IR.
The lesson from Mojo's scarA design retreat worth copying.
5 · One surface languageMojo once had a strict fn and a dynamic def; by 2026 it collapsed them to def and deprecated fn. The lesson: do not split the language into a fast dialect and a friendly one. Keep one surface, and put the strictness in the IR and the verifier.

What we are not taking, and the argument we can't fully beat

The tempting sixth item is “adopt MLIR itself.” We are not going to. MLIR is a C++ and TableGen project; Hey is written in Hey and keeps a native second emitter purely as a differential oracle. Putting a C++ core under a Hey-written compiler breaks the self-hosting story and makes that oracle incoherent — there is no longer a second, independent emitter to disagree with. So we take the ideas, implemented in Hey, and leave the framework.

The steelman, stated honestly. MLIR would hand Hey a mature LLVM path, a pass manager, and diagnostics for free — replacing exactly the hand-written scanners this campaign keeps calling a bug source — and the MLIR paper says a bespoke per-language pipeline is the redundancy it exists to kill. That case is not defeated on cost alone. The refusal rests on one load-bearing constraint: self-hosting plus the two-emitter check. If Hey ever relaxes either — and retiring the C oracle is this very campaign's endpoint — this decision should be reopened.

The handoff: where this goes next

  • The campaign continues, unchanged in method. The next shadow blocker is a nested Collections.reduce whose seed is another reduce; the serial, byte-identical, goldens-gated loop carries on to gate-green, then one 534a bump.
  • The cheapest borrow can begin as design in parallel. A parser for the mid-level IR and a print(parse(x)) == x check over the golden corpus is additive, needs no bump, and would catch a class of malformed IR that the entire two-emitter apparatus cannot — the round-trip is a producer that never consults the emitter.
  • The oracle stays until a verifier and property gates can replace it. The byte-identity check is not deleted for the ideas above; it is complemented. A verifier bounds ill-formedness; the oracle catches semantic divergence between two emitters. The bool-interpolation rung is the first proof that Hey needs both — there, the oracle would have been wrong.
