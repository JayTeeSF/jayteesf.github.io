Hey Without a C Compiler

With Go you can type one command on a Mac and get a program that runs on a Linux server. You never install a C compiler. Hey can't do that yet: every Hey build runs clang. This page shows what clang does for Hey, how Go, Zig and Rust get by without it, and a four-step plan to get Hey there.

Short version

  • Recommended: step 1 first. Ship LLVM's code generator and its linker, lld, inside Hey, plus a prebuilt runtime for each platform, so hey build --target linux-x64 works on a Mac with no clang. About 5–9 engineer-weeks.
  • Step 1 is on the path, not a detour. About 80–90% of it is still there in the end state. Every later step needs the same target list, linker, macOS stubs and test rig.
  • The one rule that keeps it that way: no clang in your build. Shipping clang in the download would work, but it's the detour.
  • Then static Linux binaries, then the runtime in Hey. Talking to Linux directly, with no C library (Go's way), should be written in Hey as part of that rewrite, never in C.

Today clang does four jobs in every Hey build

Hey's compiler turns your program into LLVM IR, a text format that LLVM (the toolkit Rust and Swift also use) turns into machine code. Then one clang command finishes the build. It does four separate things:

Hey is closer than it looks. Its downloads can already carry their own clang, lld and prebuilt runtime, so you don't have to install them. But they only build for the machine they run on, and they still run clang.

A system call is a request straight to the operating system's kernel: "open this file", "start a thread". A C library (glibc or musl on Linux, libSystem on macOS) wraps those requests in ordinary functions. Linux promises its system calls stay stable, so Go can skip the library there. macOS and Windows don't, so even Go goes through their libraries.

The four steps

Is step 1 a detour? No: the later steps need almost all of it

Step 3 takes C out of the runtime. It doesn't take away the need for a list of targets, a linker, stubs for macOS and Windows libraries, the code signature every Apple Silicon program must carry, or a rig that builds on the Mac and runs on Linux. Go has all of those too. It just wrote them in Go.

So going straight to step 3 doesn't skip step 1. It builds the same pieces later, and nothing reaches users until the end, perhaps a year out. Going straight to direct Linux system calls in C is worse: that code is thrown away when the runtime moves to Hey.

What the runtime asks of the operating system decides how hard steps 2 and 3 are

Hey's compiled code calls only the runtime. The runtime is what calls the C library. Counting its calls:

That's a small C library. It's why direct system calls belong inside step 3, written in Hey, and why step 2 should start with musl, a small C library that's easy to bundle and link statically.

The decisions

Recommended

Step 1 in v608, with no clang in the user's build

Start with Linux x86-64 and arm64 from the Mac. Done when a binary built on the Mac, with no clang on PATH, runs on the Linux machine and matches its native build.

Recommended

Static Linux through musl next

Programs that use TLS or native extensions stay dynamic at first; TLS linked in, then TLS in Hey, come later.

Recommended

Direct system calls only in Hey

Part of the runtime rewrite, one subsystem at a time, each release at C speed or better.

Not recommended

Shipping clang as the answer

It works today on the host, but it keeps the C driver and its hidden flags, and adds over 100 MB.

Open

Building Hey from the previous release

The C seed was decided as the permanent bootstrap. Step 4 needs that decision reopened; nothing in steps 1–3 depends on it.

What shipping LLVM costs
  • LLVM is under the Apache 2.0 license with the LLVM exception, which lets it be shipped inside another product without passing its notice requirements on to the programs that product builds.
  • lld links ELF (Linux), Mach-O (macOS) and COFF (Windows) programs from one tool, and it can be linked in as a library.
  • For macOS on Apple Silicon, lld writes the required ad-hoc code signature itself, as Go's and Zig's linkers do.
  • For scale: Zig, which ships LLVM, lld, Clang and C library files for dozens of targets, is about 50 MB to download for Linux or macOS. A Go hello world is about 2.4 MB on every platform.
  • Start with LLVM's tools shipped as programs; link LLVM into Hey later if starting them costs too much time per build.
