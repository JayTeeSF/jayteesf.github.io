The coordination record is the product boundary.

Cagents gives humans and software agents one durable graph of intent, work, messages, decisions and evidence. Git is the semantic authority. CLIs, agent harnesses, browser clients and cloud indexes are different ways to operate that graph—not different versions of the truth.

The design rule that removes most coordination bugs: one fact gets one authority. Current workflow is a ref, a message body exists once, project membership is a participant ref, and UI state is derived. There is no second handoff tree hiding nearby.

Stable objects. Moving refs.

The mistake Cagents avoids is making every status change rewrite the object that describes the work. A task remains a task; small refs say where it is now.

projects/hey/tasks/fix-map-put/TASK.md

projects/hey/refs/workflow/in_progress/fix-map-put
projects/hey/refs/owner/orchestrator/fix-map-put
There is deliberately no tasks/fix-map-put/STATE.md. cagents task show fix-map-put joins the canonical task object to its refs, events, linked decisions/evidence, child runs and applicable learned constraints. cagents now performs the shallower project-wide query.

Membership is a graph edge, not a name lookup

agents/orchestrator/START.md
        ^
        | exact target
projects/hey/participants/orchestrator.ref

A global actor can exist without belonging to a project. That distinction is now enforced inside the hosted coordination service itself, not merely at an HTTP route. The browser, service and CLI therefore share the same project-membership fact.

Messages exist once

messages/posts/orchestrator/2026/08/msg-123.md
        |
        +--> mailboxes/maintainer/unread/msg-123.ref
        +--> mailboxes/linux/unread/msg-123.ref

Acknowledging does not mutate the post and does not create an acknowledgement database. It moves one recipient's mailbox ref from unread to read.

Agents learn without inventing hidden memory

Reusable experience becomes an explicit typed record:

agents/orchestrator/lessons/lesson3.md

kind: require
scope: project
project: hey
ref: projects/hey/tasks/real-one-brc-map-put/TASK.md|evidence source

Applicable lessons are derived into startup, task views and delegated-run context. They never outrank Maintainer decisions, explicit task constraints or canonical decisions.

Two planes, one authority

Durable semantic plane

Git-backed prompts, goals, tasks, refs, messages, decisions, evidence, sessions, results and lessons. These facts must survive machines, restarts and clients.

Local execution plane

Provider session ID, process ID, heartbeat, processing/waiting state, pending-response obligation and intercepted buffers. Fast operational facts live in ~/.local/state/cagents.

The local plane is not a second coordination database. If a fact matters to future work—an answer, finding, decision, result or task transition—it crosses into the durable Git graph.

Observed and guarded are different guarantees

BoundaryWho launches/renders?What Cagents can promise
ObservedAn independent interactive harness/TUI.Cagents can watch hooks/status and require durable follow-up, but cannot stop the TUI from drawing directly.
GuardedCagents launches the child process and owns its stdout/stderr boundary.Captured output is withheld until Cagents records and synchronizes it. A fake --boundary guarded label is rejected.

Guarded subprocess interception is real today. Rich provider-aware event rendering is the layer on top: structured provider streams can expose public reasoning summaries/thinking blocks, tool calls and partial response events, while the model's unavailable private chain-of-thought is not assumed to exist as an interface.

The server may cache and index the graph for speed. Every semantic answer must be reproducible from canonical Git records. A stale or corrupt index is repairable by rebuilding it.

The core architectural transition is clean: no compatibility archive is needed in the active coordination tree. Git history preserves the old designs. The active core no longer carries the superseded docket or future-prompt workflow subsystems.
