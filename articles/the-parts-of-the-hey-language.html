Hey language · reference · 22 August 2026

All the parts of the Hey language, in categories

A map of what Hey is, grouped the way a person would remember it rather than the way the compiler stores it. Hey is a small, always-compiled, immutable language whose compiler is written in Hey and compiles itself. Some of what follows is built and running today; some is ruled but not yet coded. This page keeps those two apart on purpose — because on this project they are genuinely different states.

How to read the labels

Decided
A design ruling has been made. The behavior is settled, but it may not exist in the code yet.
Implemented
It is in the compiler and runs today, on trunk 547a.
Open
An active investigation as of 547a (22 August 2026). No ruling yet — do not read the current behavior as final.
Landed
A specific change merged to trunk, with a commit and a passing gate behind it.

1Values & types

Hey has the value shapes you would expect — integers, floats, strings, booleans, nil, byte strings, arrays, and JSON-shaped maps — and every one of them is a value, not an object with a hidden identity. What is unusual is how a program says what type something is.

Types via casts, not annotations Decided

You never write -> type annotations in Hey source. Instead the type is conveyed by a cast: !!x yields a boolean, x.to_i an integer, x.to_f a float, x.to_s a string. The program is still fully typed and the compiler's internal representation still carries the types — the cast is just how a human indicates one.

The ruling adds a sharp corner: a cast may change the representation of a value that is present, but it may never manufacture a value out of absence, so nil.to_i is an error rather than a silent 0.

A cast is a function; .to_f is sugar over it Decided Implemented

Casts are not built-in operators. Underneath, x.to_f is the ordinary call to_f(x) — the same receiver-as-first-argument sugar that turns account.deposit(25) into deposit(account, 25). The type-conveying property lives on the function, not on a magic keyword, which keeps Hey a fast, largely function-based language. The conversions to_i, to_s, and to_f exist and run today; the explicit force-cast spelling !! is decided but not yet built.

2Functions & callables

A function is fn name(params) … end. Functions are first-class values: a function reference can be stored in a list or a map and passed around like any other value. That much is built and settled. What a callable means once you start composing them is the part still under the microscope.

Functions as values Implemented

Hey carries a first-class callable value: a bare function reference is a real value you can put in a collection and hand to another function. Notably, Hey has no closures — no construct captures its surrounding scope. That absence is deliberate: with no captured references there are no reference cycles, so the runtime can reclaim memory by reference counting alone, with no cycle collector to build. A whole subsystem is missing because one construct is.

bind and the shape of a partial call Open

Hey exposes bind for pre-supplying arguments to a callable — the intent of something like bind(multiply, 3) is "a callable that multiplies by 3." Here the honest statement is that the exact semantic meaning of bind through HIR, MIR, and the runtime is still being characterized. This is an open investigation as of 547a, ahead of a ruling. We are deliberately not claiming full first-class callables or closures on the strength of it — until the pass-by-pass behavior is pinned down, treat the callable story as unfinished.

3Modules & imports

A module … end block groups names; import pulls another unit's names into scope. Plain import is quiet namespacing: you reach a name qualified, as Module.name, and nothing about your file's meaning changes. The cost appears only when you bring names in unqualified with exposing — that is where collisions and shadowing become possible.

exposing carries the conflict cost Decided

The module surface (exposes, exposing, as, conceals) is ruled but largely not yet built. Importing a unit and calling it qualified forces no sugar and carries no cost; most of the surface lowers at essentially zero runtime cost, so it earns no performance warning — a warning for a cost that does not exist is noise.

Warnings are reserved instead for the real correctness hazard: bringing names into a file unqualified via exposing, where a name can conflict with, shadow, or override an existing one. There the rule is that the later decision wins and the collision is reported (an error under a strict compiler mode).

private visibility Decided

Visibility is enforced structurally by name resolution: a name is reachable only if the module exposes it. private is an optional definition-site marker whose job is to catch accidental exposure — exposing a name marked private is a warning normally and an error in strict mode. It is scoped to the module declaration, not the file, and specs reach privates only through a co-located test hatch, never a general bypass.

Cross-unit resolution as neutral facts in the IR Landed

When a call reaches into another compilation unit, the resolver (HeyNames) works out what it refers to and records that as a semantically-neutral extern fact carried through MIR — the checkable IR stays the single source of truth, and the backend lowers the fact mechanically. This is the cross-unit campaign described in the last section. One design point it settled: modules are not first-class runtime values; passing a module as an argument is a compile-time selector only.

4Actors & concurrency

Concurrency in Hey is actor-shaped: independent units that own their state and communicate only by message. Because a value can never be mutated, there is nothing to lock — an actor is the one place a mutable slot is even allowed.

actor, spawn, send, receive Implemented

An actor is a serialized owner of its own state. You spawn one, send it messages, and it handles them in a receive block; stop and join manage its lifecycle. Inside an actor — and only there — state declares a mutable slot and set replaces its contents. Everywhere else, names are bound once with let. Related constructs (worker, job, supervise) build on this core; whether some of them are best seen as sugar over the actor is an open question the project is careful to measure rather than assume.

5Collections

The two workhorse collections are the array literal […] and the JSON-shaped map {…}, read with a[i] and a[key]. Every collection is immutable, which raises an obvious question: if updating an array makes a new array, isn't that slow?

Immutable collections, copy-on-write underneath Implemented Open

Operations like push, put, spreads, and indexed access preserve value semantics: an update produces a logically new collection. Underneath, the runtime's copy-on-write mode is default-on at 547a (HEY_RC_COW=0 deliberately disables it, for falsification). COW is a useful fallback — it is not the proof of correctness, and not the final answer to quadratic builders.

The real lever is compiler-proven reuse, which has already landed for some rebuild shapes: MIR carries ; own as the ownership fact and ; reuse as a separate code-generation authorization. The next hard case is not merely a local push — real tokenizer accumulation rebuilds a nested state.tokens field through Collections.reduce. Greening that path needs value-sensitive move-on-return, interprocedural ownership transfer, and a path-sensitive proof that the nested backing is unique: a unique outer record does not automatically make every child unique.

Maps have a separate complexity problem. The landed runtime representation at this checkpoint still uses linear association-list lookup, so perfect reuse would remove the copying but would not make lookup constant-time. One experimental branch has demonstrated an insertion-order-preserving hash index with flat lookup cost; another has demonstrated local push/put reuse microbench wins. Neither is described as landed in 547a until it passes the normal integration and differential gates.

6Immutability

Immutability is not a style guideline in Hey; it is the core. A value, once created, is never changed — only replaced. The ruling here is firm, and it is what everything else leans on.

The core stays immutable Decided

There is no move toward mutable everyday programming. The only mutable state in the language is an actor's own serialized slot. This is what makes reference counting sufficient and copy-on-write safe — the immutability is load-bearing, not decorative.

7The spec / testing model

Tests are a first-class part of the language, not a bolted-on library. A spec block is an irreducible construct — and, importantly, it costs nothing in production.

Immutable specs, any file Decided Implemented

The spec framework pairs a minitest-style assertion base with an immutable, ExUnit-style model: fixtures are a builder function plus an immutable context map passed to each test — no mutable instance variables, no closures, no mocking. A spec block may live in any file, including inline with the code it tests; a dedicated foo_spec.hey that imports foo is a supported convention once the import system lands, not a requirement. The assertion surface (to_equal, to_raise, to_fail) is built today.

Specs run only under the test runner Decided

By design, a production build emits no spec code and pays nothing for it — spec blocks execute only under the test runner, the way Rust's #[cfg(test)] and Go build tags work. Failure has three honest levels: an expected failure is a Result value; a recoverable crash is a supervised error that a test can observe as data; and a hard fail is a process-fatal abort, reserved for broken invariants. A crashing test subject never kills the test process.

8The compiler pipeline

Hey is one always-compiled pipeline — source → tokens → syntax tree → HIR → MIR → LLVM — with the compiler written in Hey and compiling itself. The middle three stages are real, parseable, verifiable intermediate representations, not print-only strings. That three-IR core is unchanged; the recent work is about which authority produces the bytes.

Three real IRs, one true compiler Implemented

The syntax tree, the structural HIR, and MIR are each a checkable IR with its own verifier that fails the instant a pass produces malformed IR. The goal is a single Hey code generator with the checkable IR as the authority — retiring the trusted native-C emitter that currently serves as an oracle. Recent progress is authority convergence toward that end, not a new architecture.

The cross-unit campaign Landed

A linear run of slices on trunk taught the compiler to resolve calls that cross compilation units entirely through the shared pipeline. The mechanism: HeyNames-resolved cross-unit facts are carried as semantically-neutral extern records in MIR and lowered mechanically by the backend — a lowering choice, with no sidecar and no second source of truth. Native-facade precedence, a census fix, a json(<extern call>) arm, resolver-informed receiver-sugar canonicalization, and a resolver-to-MIR canonicalization stage with HeyMir.validate round it out.

  • Measured against trunk 547a, the corpus stands at 132 programs: 111 covered, 2 where Hey refuses but the native path is fine, and 19 that both refuse to build.
  • The compiler-contract lane came out byte-identical to the parent — its 25 pre-existing failures are exactly the ones that were already there, with zero introduced by the campaign, proven by a differential verify after each slice.
