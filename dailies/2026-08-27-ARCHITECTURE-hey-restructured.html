Hey compiler architecture · canonical current reference

Decide meaning once. Carry identity all the way down.

The shape is Source → Final Syntax → Names/Resolution → HIR → MIR → Link Plan → LLVM. The important part is not the boxes; it is who is allowed to decide what a program means. The resolver now publishes stable binding and function identities. The active compiler work is making the production HIR/MIR/LLVM path stop collapsing those identities back to names.

ProgramResolution identity: landedidentity-derived link plan: landedproduction HIR/MIR identity wire: activeMAP_PUT operation identity: next
Current boundary: the compiler already knows more than its backend representation carries. ProgramResolution records call-site target identity as (target_unit,target_function), and its link plan maps that identity to symbols like hey_f1_0. Production HIR/LLVM still have name-keyed function maps and ordinary calls such as call helper(...). That gap is the live P0.

The pipeline — with authority, not just stages

1 · Source + Final SyntaxOwns occurrence structure, spans, grouping and syntax. Does not decide bindings by string scanning.
→
2 · HeyNamesOwns lexical bindings, import/module resolution and direct-call target meaning.
→
3 · ProgramResolutionVersioned program artifact: units, signatures, call spans, target IDs, declarations, binding IDs, link rows.
→
4 · Structural HIRTarget representation seam. Resolved prototype lane consumes authoritative facts without guessing; production cutover is not complete.
→
5 · MIRShould own explicit representation, control flow and ownership/effect facts. Still carries too much source-like call text today.
→
6 · Link PlanMaps resolved function target identity to native symbol. Identity → symbol, never spelling → identity.
→
7 · HeyLlvmTarget is mechanical lowering. Current call decoder/function tables still look up ordinary functions by lexical name.

A1 and A2: how the cutover is being made safely

A1 · centralize decoding

Most of the apparent dozens of LLVM call parsers are strip/re-add plumbing around one real decoder. A1 routes semantic call decoding through a small canonical seam while requiring HIR/MIR/LLVM bytes to remain unchanged.

behavior change: zerobyte parity required

A2 · change the wire once

Definitions and calls gain explicit target identity. The link plan consumes it. Ordinary functions stop deriving their native identity from "hey_fn_" + source_name. ABI-pinned externs remain a separate target kind.

live P0

Ownership belongs in MIR — but by identity

MIR is where representation and ownership become explicit. It is allowed to say “this update may reuse this storage,” but that authorization must come from semantic operation identity plus ownership facts.

Native runtime capability closure

The same architectural principle now applies below the compiler. A target should carry only runtime capabilities it can actually implement.

North star: Final Syntax carries structure. Resolution carries meaning. HIR carries semantic structure. MIR carries representation and ownership. The Link Plan carries target-to-symbol mapping. LLVM prints what it is told.
