Documentation organization#

Hey separates stable public documentation from current implementation status and operational history.

docs/
  public-docs.tsv          curated public catalog
  publication-status.tsv  one transition/stability banner
  developers/              people writing Hey programs
  humans/                  language/compiler/runtime maintainers
  agents/                  operational handoff; not public language docs

Public site#

./bin/hey docs publish renders the curated public-docs.tsv catalog and atomically replaces the destination after validation. The default destination is $HOME/dev/jayteesf.github.io/hey_docs.

The public catalog includes durable developer guidance and selected stable maintainer references. It excludes:

  • agent prompts and campaign logs;
  • alpha release archaeology;
  • stale migration plans;
  • application-specific scratch documents;
  • pages whose primary purpose is reporting a temporary red/green gate.

./bin/hey doc-site --kind all remains an internal audit view and must not be used as the public publishing command.

Developer pages#

Rules:

  1. Teach the settled language contract first.
  2. Use readable current syntax, especially spread literals and explicit module surfaces.
  3. Keep backend/campaign telemetry out of tutorials.
  4. Link to one implementation-status.md page for temporary frontend gaps.
  5. Do not document open grammar choices as settled syntax.
  6. Every source example intended to run should have an executable fixture or conformance contract.

Human maintainer pages#

Human docs explain stable ownership boundaries, sources of truth, verification rules, runtime/compiler interfaces, and product acceptance. Current counts and forecasts belong in status/daily pages unless they are generated from a canonical ledger.

Agent pages#

Agent docs are current operational state. They may be detailed and temporary. They are not published under the default public catalog and must never silently override Decisions, Architecture, Plan, or executable gates.

Contract banner#

During the frontend transition, publication-status.tsv adds one banner to public pages. When the new frontend becomes authoritative, changing that one record removes the banner. The language guide should not require a transition rewrite.
