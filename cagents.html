Cagents · architecture · 31 August 2026

The Maintainer owns the edges. Cagents owns the record.

Cagents is a provider-neutral coordination system for humans and software agents. Git stores the durable project graph. A Maintainer controls which actors may communicate directly; everyone else is mediated through the Maintainer. Agent wrappers turn provider activity into live, durable Cagents events, so the app can observe and redirect work without inventing a second control channel.

Core rule: project membership, permission to communicate, and command authority are three different facts. Membership never implies an all-to-all agent mesh.

Three facts that must never collapse into one

Membership

projects/<project>/participants/<actor>.ref says an actor belongs to the project. Nothing more.

Communication permission

A Maintainer-issued active grant says one actor may bypass Maintainer mediation and reach another directly.

Command authority

The receiver evaluates who sent the message and the sender's role. Direct access does not magically make advisory input binding.

Default topology: mediated, not mesh

overseer ──► Maintainer ──► orchestrator
linux    ──► Maintainer ──► orchestrator
worker   ──► Maintainer ──► overseer

# Maintainer may open an edge:
overseeer ═══════════════► orchestrator
             continuous until revoked

Every durable message still uses the same Cagents post + mailbox mechanism. “Mediated” means the Maintainer decides whether to forward it. “Direct” means Cagents has an active grant that allows delivery without the Maintainer being the intermediary.

Grants are durable decisions with small active refs

projects/hey/grants/comm-017.md
projects/hey/refs/communication/overseer/orchestrator/comm-017.ref

comm-017.md
  issuer: maintainer
  from: overseer
  to: orchestrator
  mode: continuous
  scope: project
  authority: advisory

A one-shot grant is consumed by moving/removing its active ref and recording the consumption event. A task- or run-scoped grant becomes inactive when that scope closes. A continuous grant remains active until the Maintainer revokes it. The immutable grant record remains as provenance.

The provider wrapper is a device driver, not a second coordinator

Cagents actor contract
        │
        ├── Claude stream adapter
        ├── Pi RPC adapter
        ├── Codex JSON adapter
        └── local-model adapter

inbound:  ordinary authorized Cagents messages
outbound: normalized Cagents activity events

The wrapper starts or resumes the provider session, points it at the actor's START.md, watches the actor's Cagents mailbox, and converts provider-visible structured output into durable semantic events. It must not invent a private human-to-provider channel.

Reasoning boundary: Cagents records provider-exposed thinking summaries/blocks when available, plus observable plans, tool activity, findings, edits, tests and subagent events. It does not claim access to a provider's hidden private chain-of-thought.

Clients subscribe to derived realtime projections, but durable success still means the underlying Cagents mutation is committed to the authoritative repository. Realtime is a view, not another source of truth.

One-line prompts are triggers, not context dumps

"go"
   ↓
actor reads START.md
   + current project graph
   + tasks / refs / decisions / evidence
   + lessons
   + unread messages
   + prior session/run identity
   ↓
agent works and publishes activity back into Cagents

The durable project carries context. Restarting an actor should not require reconstructing the project in a giant prompt.
