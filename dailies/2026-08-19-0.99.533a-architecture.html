Hey architecture · daily · 19 August 2026

Hey 533a has the new front end. Two gates still block one authority.

The structural tokenizer, generated syntax tree, name resolver, and structural HIR exist. Normal compilation still takes program meaning from the established text-inference path. The correct move is to finish the Hey-written LLVM emitter serially, allow audited stateful loops where spread lowering requires them, close the separate borrowed-read lifetime contract, and only then switch semantic authority.

Source checkpoint: 0.99.533a, commit f7e85961 Live campaign: rungs 3–4 verified, not yet landed Deployment: not asserted

TL;DR

  • Verdict: keep the authority-gate emitter campaign serial and finish the whole structural shadow program before one 534a bump. Authorize controlled set growth for spread-heavy lowering; do not loosen the gate, touch heyc.c, or switch authority early.
  • Strongest live result: indexed reads and arithmetic slice/boxed comparisons are now byte-identical to native in the working tree; the 91 LLVM goldens remain green, and the edited emitter reports 4,272 set sites versus 4,276 in the supplied 533a source snapshot.
  • Mechanism: each unsupported structural expression is lowered one rung at a time, compared against native LLVM text, then guarded by fixtures and the stored golden suites. The legacy direct-MIR fallback must reach zero.
  • Landed foundation: 531a fixed a silent String-ABI wrong answer, 532a fixed the returned-string lifetime SIGBUS and roughly thirty same-class hazards, and 533a made 0/0.0 truthy across five lanes.
  • Disclosed weakness: the emitter census still includes roughly 140-plus spread/struct-update sites, the borrowed generated-node reader contract is separately red, and about 190 lines of text-based semantic inference remain authoritative.
  • Falsification: the landing is acceptable only when the full shadow emits without fallback, environment_isolated is the Boolean text true, 91 LLVM and 24 HIR/MIR goldens pass, a deliberate mutation makes the gate red, and restoring the source makes it green again.

The agent’s question, answered

Continue through every remaining emitter rung. Do it serially. Allow audited set growth where Category 6 genuinely requires a stateful emission loop. Do not use the old absolute count as a stop sign.

The supplied 533a snapshot already fails the historical absolute ratchet: the whole census is 5,581 against a maximum of 5,178, and HeyLlvm.hey alone is 4,276 against 4,042. The current uncommitted work moves that file down to 4,272. A threshold that is red before the next necessary change cannot distinguish a regression from deliberate compiler construction. Keeping it as a veto would reward awkward code and stop the only path that removes the legacy fallback.

The replacement is not “anything goes.” It is a tighter change-local contract:

One editing lane

Emitter arms are ordering-sensitive. One person or agent edits; parallel seats may only extract native targets, classify shapes, or design fixtures.

Per-rung state delta

Record the exact set delta for each rung, why pure helpers are insufficient, and which loop owns the mutation. Unexpected growth blocks the rung.

Native is the live oracle

For every new shape, compare the Hey emitter’s textual LLVM byte-for-byte with the native emitter before broad testing.

No escape hatches

Do not weaken != 'true', do not teach the harness to accept 1, do not edit heyc.c, and do not count fallback output as support.

Mutation-proven gates

Every broad green must have a negative control: stash or mutate the repair, observe red, restore it, and observe green.

One version landing

Rungs 3, 4, 5, and the spread mountain remain one campaign. Stay on 533a until the finder is clean; then regenerate, gate, falsify, and bump once to 534a.

Not authorized: switching authority after Rung 5, landing a partial version bump, deleting existing specs, accepting a Boolean rendered as an integer, or calling the gate green because ordinary self-host output happens to report zero fallback on a smaller program.

Why an “environment” gate is really exposing an emitter fallback

The gate receipt contains a Boolean field named environment_isolated. The structural shadow reaches an expression the Hey LLVM emitter cannot lower, so execution falls back to the legacy direct-MIR consumer. That consumer prints the Boolean as 1. The harness requires the language-level text true and correctly reports environment_not_isolated=1.

# The gate is intentionally strict.
[ "$environment_isolated" = "true" ]

# Wrong fixes:
# - accept "1"
# - rewrite the receipt
# - patch the native emitter
# - call fallback output structural support

# Right fix:
# teach stdlib/HeyLlvm.hey the remaining structural shapes
# until the full shadow lowers with zero legacy fallback

The name is therefore not misleading evidence. It catches exactly the property the project needs: the candidate path must be isolated from the legacy semantic consumer, not merely produce an equivalent-looking integer on one receipt field.

The durable division of responsibility

Hey’s design is now clearest when each stage is allowed to answer one kind of question and forbidden from rediscovering earlier answers.

Tokenizer

Owns spelling, token boundaries, and source spans. It does not decide names or types.

Syntax tree

Owns grouping, precedence, argument shape, and generated node structure. The schema generates constructors, accessors, child lists, walkers, rewriters, and coverage checks.

Name resolution

Owns lexical bindings, module surfaces, aliases, receiver candidates, private names, and actionable missing-name diagnostics.

Structural HIR

Owns program meaning and compiler-internal types. Users do not write type annotations; calls, casts, operators, and values carry structural facts downstream.

MIR

Owns explicit evaluation order, named temporary identities, representation choices, and ownership/lifetime operations.

LLVM emitters

Lower MIR decisions to typed SSA text. They must not infer source semantics from strings. The native emitter is an oracle today, not the permanent architecture.

Runtime

Owns values, reference counts, actor mailboxes and handles, built-ins, I/O, web primitives, and target ABI behavior.

Products and packages

Recapture web, CLI, iOS, Android, tvOS, and application behavior after authority changes. Compiler gates are necessary, never sufficient product evidence.

The source snapshot also shows where the current cost lives: HeyTokens.hey is 1,318 lines, HeySyntaxTree.hey 1,377, HeyStructuralHir.hey 1,477, HeyNames.hey 898, HeyHir.hey 3,771, and HeyLlvm.hey 15,211. Line count is not quality, but it makes the leverage visible: removing semantic duplication and emitter fallback is more valuable than adding another parallel path.

What compiler research supports—and what it does not prove

MLIR’s rationale describes progressive lowering through representations suited to different abstraction levels, while the project emphasizes IR specifications, verifiers, textual round-tripping, and modular passes. That supports Hey’s choice to keep syntax, structural HIR, MIR, and LLVM distinct rather than forcing one representation to answer every question. It does not prove Hey’s particular lowering is correct.

Rust’s compiler documentation says MIR is built from typed high-level IR/THIR. That is a useful analogue for Hey’s target: type and call facts should be established before MIR/LLVM emission, not guessed from expression text in the emitter.

Andy Keep’s Nanopass dissertation argues for many small passes, formally described intermediate languages, well-formed output checks, and generated boilerplate. Hey’s one-rung campaign is compatible with that discipline: each extension should have a narrow input contract and a checkable output.

Python’s AST documentation notes that concrete node classes derive from the Parser/Python.asdl grammar. That is direct precedent for Hey’s decision to generate node construction and traversal from one schema instead of relying on every hand-written walker to remember every field.

The Csmith study by Yang, Chen, Eide, and Regehr, Finding and Understanding Bugs in C Compilers, found wrong-code defects even in unverified frontend portions of CompCert. The lesson for Hey is practical: a strong backend does not compensate for semantic facts being wrong before code generation.

Translation validation checks each compilation result rather than proving the compiler once. Hey’s native-versus-Hey byte identity is inspired by the same “validate this run” instinct, but it is narrower: byte equality between two related emitters is differential evidence, not a proof of semantic preservation.

Xavier Leroy’s CompCert account is the important contrast. CompCert carries machine-checked semantic-preservation proofs across defined languages and passes. Hey does not. Its current evidence is executable gates, differential text, mutation tests, and application receipts, and the article keeps those categories separate.

What not to claim

“The new front end is unused.”

Wrong. It runs. The missing property is semantic authority.

“The authority switch is one green gate away.”

Wrong. The full candidate shadow and the borrowed generated-node reader are two preconditions; the actual authority switch is a third landing.

“Rungs 3 and 4 shipped in 533a.”

Wrong. They are verified in the live working tree and deliberately remain uncommitted until the campaign can land as one coherent 534a change.

“Byte-identical LLVM means the compiler is verified.”

Wrong. It is strong differential evidence against one independent implementation and a useful regression oracle. It is not a semantic proof.

“The 119 green gates make Hey product-ready.”

Wrong. The same ledger records 21 known red and one flaky gate, and product evidence must be recaptured after the authority commit.
