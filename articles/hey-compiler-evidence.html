September 16: a library is no longer a second resolver

A source call needs one identity. The resolver chooses the function; later stages carry that choice. A static library is simply a collection of compiled functions. It must not get a second vote on what the source meant.

Previously, the LLVM emitter consulted a generated name-and-argument-count table to find a standard-library function. A test exposed the danger: an unknown function ID still compiled when its printed name matched a familiar library member. Commit 8578b643b removes that fallback. Commit 3d46e9167 removes the archive-routing table dependency from the emitter, its helper module, and both generated emitter bundles.

The link-planning pass now joins the resolved identity to a selected provider inventory and carries an explicit bodytarget into MIR. The calling agreement, or ABI, describes how arguments and results cross that boundary. A bootstrap library and a product library have different inventories; neither inventory resolves source names. A separate correction, 86dc53fa3, excludes already-defined functions by their IDs rather than their printed names.

Compiling successfully was not enough. Running the Re regular-expression fixture exposed a second defect: high-level type inference treated an ordering comparison as proof that a character parameter was an integer. The caller consequently converted a letter to zero. Commit 2bd16e143 repairs that high-level evidence rule, without changing Re or adding a special case to LLVM.

The focused native check builds Re, Minispec, Jobs, and Result from their real source units. The application then compiles through the ordinary Hey-to-LLVM path with zero legacy fallback. Eight assertions match the interpreter, including positive and negative regex matches and generic character, integer, and fractional ranges. The executable passes with its environment cleared. Removing the carried Re provider makes compilation refuse. Twenty-two separate type-evidence assertions and the existing concatenation and floating-point regression gates also pass.

This closes a specific authority defect, not the whole compiler. The complete 1,144-export product archive remains unaccepted. A fresh Transformer provider run still refuses at its floating-point call boundary. A self-built compiler pipeline, full Linux toolchain and relocated-SDK checks, and ordinary MMeow, top5, and My Queue builds remain separate acceptance requirements. Bootstrap/native code outside this emitter still contains historical inventories; other compatibility and ownership work remains. No new performance claim follows from these correctness checks.

The ownership and compiler-quadratics decision

The September 12 decision says that ordinary immutable Hey should not need a special “fast spelling.” The compiler should carry ownership facts through its intermediate representations, including when a function is passed to another function.

Reuse needs two facts: the storage has one owner, and nobody can observe the old logical value afterward. With those facts, MIR may authorize reusing the allocation. Without them, correct copying or copy-on-write preserves the program's meaning. Missing optimization proof is not itself a reason to reject a valid program.

A fold repeatedly passes its accumulator into a reducer and receives the next accumulator back. Passing that reducer as a callable must not accidentally lose a proven ownership contract. The proof must follow the resolved function identity, not its printed name. Code generation consumes the proof; it must not invent one.

Ownership can remove unnecessary copies. It cannot fix an algorithm that repeatedly scans everything it has already processed. Those repeated computations need indexes, summaries, or better traversals at the responsible compiler layer. Tests must distinguish the two costs, check aliases and unknown callables, and compare observable results with the safe path.

This is a public explanation of the decision, not the full internal document. See the ownership diagram and compiler-layer explanation. The complete archive, ordinary applications, and Linux acceptance remain separate requirements.

Runtime interpreter-service removal

Official commit 6bf118f1f63c93788299c7d3e6447aee62871761 removed the runtime standard-library interpreter service and its compiler route. Absence checks guard that removal. This does not prove every library provider compiles, nor that every other fallback has disappeared.

Floating-point self-tail calls

Commit e79b6e9f4cb72f9f25f7c83186c48cd7008f26a1 carries typed floating-point operations in the MIR tail-call plan. Commit f4d5356cab8abe367b666393477be0843b85c419 updates its generated compiler projection. Reported native Darwin arm64 checks reached 100,000 iterations with copy-on-write off and on; removing required plan, representation, or cleanup facts made the negative controls fail. This is a bounded correctness result, not a speed measurement.

Call-boundary checks

Commit 580a3ae2b3f138532f1c19c820bfcba1e4e94c3c records 29 passing focused assertions for composed calls and floating-point argument representation. An incompatible integer signature is rejected. These checks narrowed the Transformer investigation; they did not close its high-level parameter-inference defect.

Ownership through a known callable

Commit c482af47a593067779db6e99401e91cb4460d656 added a focused consume-and-return effect mechanism for known callable identities. Its specification checks MIR authorization and observable results with copy-on-write disabled, while ordinary indirect calls retain borrowed-input behavior. Full immutable-rebuild scaling and application performance are not established by that test.

The fold example

A reducer receives the current accumulator and the next item; its result becomes the next accumulator. The public runnable example adds four numbers and prints 10. This explains the call boundary without requiring access to the private library source.

Local actors

The public actor example receives two numbers, keeps their sum in private state, and prints 30. It checks local behavior, not multi-machine delivery.

Job supervision

The private supervision specification exercises a bounded retry flow and dead-letter observation. That is focused behavior, not a service-level or distributed-product guarantee. The full test source is not published here; the language guide explains the role of jobs.

September 16 review: the next phase is not another workaround

This is a reviewed plan, not a new compiler release or a new benchmark. The source checkpoint remains development 2bd16e143, historical d7a4bb477, and official 607548db7. Two independent read-only audits checked the pending high-level typing work, the Web boundary, the build tools, and these guides. No compiler implementation was changed during that review.

The first real application failure comes before LLVM. In a September 16 report, MMeow's ordinary build failed during high-level representation emission while the same compiler built the same source through Stage0. On the historical checkpoint, the ordinary pipeline rejected the runtime identity for Argon2id. Current source already declares that identity. The next investigation must compare the actual executable and generated-table identities, rather than add another crypto declaration or weaken authentication. Older shared-checkout runs also reported large memory use; that is a separate measurement to repeat on coherent current artifacts.

Review exposed why a green-looking test is not enough. A pending numeric-inference test only required an escaped parameter to be “not Float.” Its saved high-level output still called that parameter an integer while a caller supplied a fraction. The replacement test must positively require a safe general value when specialization is not justified. Likewise, a pending Web patch still chooses a handler by name; moving that choice into generated data does not create a generic callable. These candidates remain unaccepted.

Work proceeds in parallel, with ownership kept clear. First identify the actual compiler artifacts and preserve function-value identities. High-level typing then combines complete call evidence; mid-level planning owns argument adaptation, captures, and memory lifetime; the backend translates those facts. In parallel, measure repeated copies and repeated semantic scans, exercise focused application builds, and check Linux and relocated SDKs. Correct subset results can arrive before the complete archive; they do not certify it.

Deletion follows replacement evidence. Remove printed-code ownership guesses, special handler tables, normal interpreter-hosted build passes, and alternate semantic fallbacks when their replacements pass positive and deliberate-withdrawal tests. Retain the one-time bootstrap seed, the real static library, operating-system support, crypto, and safe copy-on-write. They are mechanisms the architecture needs, not obsolete bypasses.

September 16 execution: the compiler must get its own answers right

Three bounded repairs are now in the official source branch, but switching applications to this compiler is still unaccepted. The checkpoint is development 759199746, historical 3a2ceacd8, and official 4ed4d3648. These are source and test milestones, not a new production-ready compiler release.

A local source map should not rebuild every imported program

A statement map records where statements in one file came from, including statements continued across lines. The old implementation built the imported syntax trees too, then discarded them when returning the local map. The repair keeps one grammar: it asks the parser to walk local syntax without opening imported providers. Normal full-program parsing still follows imports. It also preserves map entries for statements before an import.

The local-map tests passed 80 assertions and ten checks that full parsing still rejects missing imports. Twelve additional assertions passed in a seed-compiled native test under an empty environment. Removing the map-only behavior makes the controls fail. These results establish the bounded parser contract; they do not establish overall compilation speed.

A compiler that builds successfully can still compile itself incorrectly

The next repair makes the intermediate-code cache distinguish the bytes of the compiler pipeline actually selected. Previously, replacing that executable at the same path could reuse old high-level and mid-level output. The test changes the selected executable, checks that those phases run again, and confirms that moving identical bytes does not change their identity.

The driver coordinates compilation; the pipeline executable performs the compiler passes. Stage0 is the bootstrap compiler. That test passed in the interpreter and with a Stage0-built driver. The driver then built through Hey's ordinary LLVM path with zero legacy fallback, while the pipeline executable remained Stage0-built. But running that produced driver exposed a different bug: every recorded selected-pipeline digest became the string 0. A successful self-build had not proved correct self-built behavior.

High-level and mid-level output still described a String result. The backend's shared integer probe mistakenly accepted a known boxed String call (a String held in the runtime's general value representation), converted it to an integer, and boxed zero. The repair uses the already-known return type carried with the resolved function identity before that conversion. Existing String handling then preserves the value. It adds no hash-function exception, driver-source conversion, new type inference, or ownership rule.

The remaining costs and failures stay visible. In the MMeow diagnostic, HIR (the high-level intermediate representation) took about 383 seconds and the command's peak resident memory was about 4.8 billion bytes. The earlier baseline was stopped, so there is no valid before/after speed ratio. That diagnostic used an absolute application source from the compiler working directory, not the full application-launch contract. Top5's corrected test explicitly used its own working directory; an earlier package-marker failure was a test-harness mistake, not a compiler finding.
