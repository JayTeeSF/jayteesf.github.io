Hey architecture · reference page · revised 19 August 2026

Memory has one home. Program meaning still needs one.

The August 5 target architecture survived. The implementation map did not: module closure, boxed truthiness, self-host fallback, and the main web-request leak have moved from blockers to working foundations. The next hard problem is making the structural front end authoritative before another type guess silently changes a program.

Hey 530a source checkpoint 94e04138 current truth through August 19

TL;DR

  • The target is unchanged: one front end should understand every Hey program once, then hand that meaning to an interactive runner or a native compiler.
  • The strongest landed result is the memory model: central box ownership reduced the compiled web-request leak from 308 to 6 bytes per request on the measured workload.
  • The old blocker list is obsolete: imported-module closure, boxed truthiness, native/Hey emitter agreement, and automatic self-host fallback are no longer the reasons authority is off.
  • Authority is still off for a better reason: the shipping front end can still infer a String parameter as an Int and emit a silent wrong answer. The generated structural HIR exists, but it is not yet the program every lane consumes.
  • The current checkpoint is reproducible: 530a reports 118 green, 22 known red, and 1 flaky; both native emitters are byte-identical across 91 LLVM goldens.

What the August 5 page still got right

Its central sentence remains the right design: one front end, one resolved program, two consumers.

A source file should be tokenized once, grouped into a real syntax tree once, resolved once, and lowered into one structural description of what the program means. Interactive execution and native compilation may represent that meaning differently after the fork, but neither should reopen source text and guess.

The stage responsibilities also survive. Tokenization owns spelling, syntax owns grouping and precedence, resolution owns names, HIR owns language meaning, MIR owns representation and lifetime operations, and LLVM emission should print decisions already made.

Memory now has an architectural home

Earlier fixes tried to prove, one expression at a time, that a temporary value could not escape. That produced several separate “licences,” and two of those licences shipped with safety defects. The current model puts a small reference count in space the value box already had, so the box remains 32 bytes and the runtime can keep or release it explicitly.

# Ordinary source can create several temporary boxed values in one statement.
let response = Web.response(
  200,
  {'content-type': 'application/json'},
  Json.encode(payload)
)

The compiler now looks at the values created by the statement, preserves anything returned or otherwise carried forward, and releases the rest. The result is not merely prettier LLVM: on the measured compiled web workload, retained memory dropped from 308 to 6 bytes per request. Turning off that release makes the leak return, which is the falsification test that keeps the claim honest.

This does not mean memory work is finished. Actor handles still retain a small tombstone after join because they lack their own cross-thread-safe lifetime count. The current registered cost is roughly 240 bytes per spawn. That belongs below the box layer and needs an atomic lifetime rule of its own.

Program meaning still has no single authority

The most important remaining example is short enough to read:

fn tag(b)
  return 'T'
end

fn build(xs, acc)
  return acc + tag(xs)
end

program
  let xs = [1, 2]
  let seed = 'A'
  says build(xs, seed)
end

The interpreter and Stage-0 print AT. The native path can print a pointer-like number followed by T. The damage is visible before machine code: HIR describes acc as Int even though every caller passes a String.

This is why frontend authority is still off. The native emitter is not inventing the wrong type; it is faithfully compiling a wrong semantic fact produced earlier.

The replacement already exists as a prototype: tokens become generated syntax nodes, then a generated structural HIR with distinct fields for a call, an index operation, a binary operation, short-circuit behavior, and errors. What remains is to connect it, measure its failure rate over real programs, and make every consumer use it instead of carrying expression text forward.

# Today, conceptually
expression_text = "acc + tag(xs)"
# Several later helpers inspect that text and infer types.

# Target
binary_op(
  left: local_ref(acc, type: String),
  operator: add,
  right: call(tag, [xs], result_type: String),
  result_type: String
)

That change is the next correctness program. It is separate from ownership and should not be smuggled into a memory optimization.

A correction to the next rung

The August 19 handoff initially said the next ownership step would turn a returned-parameter leak from 434.8 bytes per call to flat and also green the frontend scaling gate. A focused measurement disproved both links.

fn identity(x)
  return x
end

On 530a, this workload is already flat at approximately 0.0 B/call. The compiled function still deep-clones the returned box, so replacing that clone with a retain is a legitimate allocation and performance cleanup—but no longer a leak fix.

The scaling gate is also a separate path: it counts clone calls while running the tokenizer through the interpreter. Changing compiled return emission cannot move that number.

Roadmap correction: the clone-to-retain return cleanup remains useful, but the silent wrong answer now outranks it. Frontend scaling remains its own measured campaign.

What happens next

  1. Fix the structural type error first. Trace where String evidence disappears, connect the minimum structural-HIR path needed to prevent it, and require interpreter, Stage-0 and native output to agree.
  2. Decompose frontend and build scaling. The old recursion wall was fixed; the remaining large-program wall is superlinear parse work and a sidecar deadline. Measure whether that and the tokenizer clone ratio are the same disease before choosing an optimization.
  3. Return to clone-to-retain only with a real performance result. Keep RSS flat, remove the deep clone, prove aliases and forwarded returns remain safe, and apply the same rule in both emitters.
  4. Give actor handles their own lifetime. Box references are non-atomic because boxes stay thread-local; actor handles cross threads and need a different, atomic construction.
  5. Recapture product evidence after authority changes. Web, CLI, iOS, Android and AppleTV checks are the final proof that the compiler work serves the applications rather than becoming the product.

What not to claim

“The new front end is done.”

No. Its generated components exist, and small cross-path comparisons are encouraging, but the structural HIR is not the authoritative program.

“The memory problem is solved.”

No. The main web box leak is nearly flat, but actor tombstones and other registered lifetime work remain.

“More green gates means product-ready.”

No. The 118/22/1 ledger is a compiler checkpoint. Product checks must be recaptured against the exact authority commit.

The durable architecture

The old reference page’s final destination remains right. The updated status is simply more honest about where the project now is.

one source of syntax
+ one source of resolved meaning
+ explicit ownership in IR/runtime
+ two consumers that do not reinterpret the program
+ one runtime shared by interactive and native execution
+ product gates after every authority change
=
a stable, fast, actor-based immutable language for real applications

The compiler is not the product. But it must be correct enough, fast enough, and internally singular enough that web, mobile, AppleTV and command-line developers can stop thinking about compiler lanes and return to writing Hey.
