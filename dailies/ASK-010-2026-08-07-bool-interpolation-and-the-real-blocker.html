What landed

The gate inside hey_llvm_interpolated_fold_value read marker_entry != '' and marker_kind == 'bool'. Because marker_entry is a locals lookup, a call could never satisfy it and fell through to the numeric tail, where a bool printed its raw 0/1 payload. It now reads marker_bool.ok, backed by three new helpers that resolve the i1 from any source shape.

The helpers return the i1 already compared rather than the raw i64, so the arm emits a select and nothing else. That is what preserves the local's bytes exactly — load at %t<n>, icmp at %t<n+1>, so the select still lands on %t<n+2>. Verified by diffing emitted LLVM IR before and after: identical.

They lower through a path that spends basic blocks to short-circuit; an interpolation fold is straight-line text with no block to branch to. Admitting the spelling would not lower it — it would move the refusal one function deeper and make the predicate claim coverage it does not have.

Mutation proof — both directions

Narrowing the gate back to its locals-only form reproduces clean?() → 1 with the Hey emitter still answering, which is the reported defect exactly; the bool local stays true through the same mutation. Restored and re-verified green. The census moved 4042 → 4031, so the widening cost fewer set statements than the narrow arm it replaced.

The finding that matters

The corpus gate is not held by bool rendering

The twelve-row corpus reran clean: candidate identity byte-identical across interpreter and llvm_direct, missing_rows=0, environment_mismatch=0. But environment_not_isolated=1 persists — the interpreter writes environment_isolated=true and llvm_direct still writes 1.

The sidecar build log says why. One unsupported shape drops the entire file to the legacy direct-mir consumer:

MIR-to-LLVM emission failed; using legacy direct-mir consumer (exit 70):
  unsupported return expression for the Hey LLVM emitter slice:
  ret boxed [...node.slots[0], ...node.slots[1]]

  compiler/generated/final_syntax/HeyFinalSyntaxNodes.hey:767

An array-spread return. Nothing to do with bools. Because the fallback is whole-file, native's consumer emits every interpolation in the shadow sidecar — and native has no bool arm in its interpolation emitters, so the receipt gets 1.

The handoff warned "check which lane answers before editing an emitter." That trap caught the diagnosis one level up: the bool defect was real and is now fixed, but it was never the thing holding this gate.

Prune the stale images?

Two tags are two versions behind. Note the name hey-toolchain is not produced by this repo's Makefile — which builds hey, hey-dev, hey-devtools — so these came from elsewhere and I would rather not assume they are disposable.

Port the three Python tools to Ruby?

Real consistency argument — Ruby is already the sanctioned maintainer language and one scripting host beats two. But it is about 451 lines that change no image size and no gate, and the module-closure generator feeds a checked-in manifest consumed across the compiler, so it needs care rather than a quick transliteration.

My recommendation: B4-a. Say the word if you would rather I take it anyway.
