ProgramResolution is the architectural hinge

What is landed

  • Produced before HIR by the authoritative self-host pipeline.
  • One semantic resolution event per compilation.
  • Versioned deterministic rows.
  • Exact full-source spans for resolved call sites.
  • Resolver signatures for cross-unit calls.
  • Definition-level wrapper semantic facts.
  • HIR and extern annotation consume the shared artifact instead of running resolution again.

Why it matters

The earlier compiler repeatedly reconstructed meaning from text: names in expression strings, module paths, facade tables and backend conditionals. ProgramResolution gives later phases a durable identity seam: an exact call site points to an exact resolved function, and later transformations can join on that identity rather than infer it again.

Typed intrinsics: capability registry, not emitter folklore

The compiler now has a declarative typed-intrinsic registry with generated projections. An entry carries neutral capability facts such as identity, arity, result kind, typed-native lowering kind, wrapper-canonicalizable status and shared runtime ABI symbol. A drift gate verifies the projections, and a backend-completeness gate requires both emitters to satisfy registered entries.

Still active: Bytes.at and Bytes.slice have not yet completed the replace-and-delete migration. The legacy Text.replace('Bytes.at(', 'byte_at(') / Bytes.slice rewrite and duplicate result-kind entries are still present in this snapshot. The resolver/registry spine is green; D is the migration that must consume it and delete those old authorities.

P2-LINK: cross-unit Hey becomes ordinary linked Hey

The old shortcut: a resolved pure-Hey cross-unit call could be delegated through hey_llvm_stdlib_json_call. That was tolerable for JSON-shaped values and disastrous for callables: a same-process function value is not a wire value and must not be serialized.

“Linked” is therefore not a new hand-declared module ABI. It is a program-specific consequence of resolver truth.

Callables: semantic type, ordinary boxed machine ABI

The callable crash did not justify a new callable ABI letter. HEY_CALLABLE already travels as a boxed pointer at the machine boundary. The fix is architectural: the provider must be linked into the same process and the final link unit must own one dispatcher for each used arity over the whole link closure. Provider objects contribute callable-arm metadata; they do not each export competing dispatchers.

  • No JSON serialization of functions.
  • No runtime function-name table.
  • No hidden dispatcher parameter.
  • Canonical module-qualified callable identity prevents collisions such as A.compare vs B.compare.

The module system is now a front-end contract

Modules are lexical and static. A module declares a complete public surface with exposes. A bare import provides only the qualified namespace. as renames the namespace. exposing: adopts selected bindings; forms: narrows qualified/unqualified/dotted/infix access; selector aliases use old as new; conceals: removes adopted/default names; facade re-export is explicit through exposes *.

This distinction also resolves an architectural ambiguity: a static module namespace is not an ordinary runtime object passed through call ABI. Separately, Module.load(...) may return a runtime module value, but that value cannot create already-compiled identifiers, receiver forms or operator bindings.

Distributed Hey converges onto the same compiler

The distributed stack is deliberately ordinary Hey plus runtime primitives: Codec encodes values, DistTransport frames bytes over TCP/TLS, DistNode handles node identity/incarnation and routing, and DistRemote provides immutable remote PIDs plus send/call semantics. The two-machine TLS milestone proved the runtime substrate. P2-LINK is what makes those modules compile like any other pure-Hey provider instead of requiring an interpreted cross-unit escape hatch.

Actor-owned IO now has an explicit v1 rule: ordinary crossing of a raw socket/listener/TLS handle is rejected; Io.into_actor(handle) moves a sole top-level handle and poisons the source reference. That is an ownership capability, not distributed serialization.
