Hey · language tour · 15 September 2026

Start with values and functions. Add an owner when state must live.

Hey aims for one readable language from a small calculation to a concurrent service. The source stays ordinary; the compiler is responsible for finding lower-cost representations without asking you to learn a separate “fast” dialect.

The verdict

  • Hey's center is small: values flow through functions; actors own long-lived changing state.
  • let introduces a binding and set advances that binding. An immutable update still behaves as though the old and new values are separate.
  • Functions can be values. Higher-order tools such as reduce receive a callable, not a special compiler-only syntax.
  • Modules organize vocabulary; actors and jobs organize responsibility. Remote work adds transport and failure, not a second object model.
  • Disclosed weakness: these checked-in examples establish language behavior, not complete native coverage, application migration, Linux acceptance, or performance.
  • Falsifiability: run each marked example through the interpreter; then test native compilation separately with fallback forbidden and record the exact compiler identity.

Values stay separate even when a binding advances

let gives a name to a value. set makes that name refer to its next value. The important distinction is between a binding—the local name—and the value it currently names.

program
  let original = {name: 'Ada', visits: 1}
  let current = original
  set current = {...current, visits: current.visits + 1}
  says original.visits
  says current.visits
end

Expected output: 1, then 2. The record spread creates the meaning “old fields plus this change.” The compiler may reuse storage only when that cannot change what either name observes.

Functions do the ordinary work

A function takes values and returns a value. A callable is simply a function carried as data, so another function can invoke it later. This makes map, filter, and reduce ordinary library tools.

import 'stdlib:Collections'

fn add(total, value)
  return total + value
end

program
  says Collections.reduce([1, 2, 3, 4], 0, add)
end

Expected output: 10. The real library's reduce explanation repeatedly calls its reducer parameter.

A focused compiler mechanism now carries a known reducer's ownership effect through that callable boundary. The broader performance claim remains open: ordinary immutable rebuilds still need clone, allocation, scaling, and real-application evidence. There is no magic “fast function” syntax.

Modules organize vocabulary, not object identity

A module groups related functions. An import makes another source unit available. Internally, the compiler needs a stable source and function identity so two helpers with the same printed name do not become the same function by accident.

visits.hey — first half of a cross-file example

module Visits
  fn bump(user)
    return {...user,
      visits: user.visits + 1}
  end
end

main.hey — run this file beside visits.hey

import './visits.hey'

program
  let user = {name: 'Ada', visits: 1}
  says Visits.bump(user).visits
end

Module authority and exposure are still transitional. The direction is ordinary source declarations and lexical imports, but compatibility tables remain; this guide does not claim the planned Sys migration is complete.

Actors own state that outlives one function call

An actor has a mailbox and private state. Other code sends messages instead of sharing that state directly. Use one for a session, connection, coordinator, or other thing that continues to exist; use a function when input-to-output is enough.

actor Total
  state sum = 0
  receive value

  if value == 'report'
    says sum
    exit
  else
    set sum = sum + value
  end
end

program
  let total = spawn Total
  send total, 10
  send total, 20
  send total, 'report'
  join total
end

Expected output: 30. This is a local actor example, not a claim about cluster-wide delivery.

Jobs put bounds around background work

Workers describe work. Jobs add capacity, result handling, retries, and dead-letter observation. The summary of the checked-in supervision example proves a particular bounded retry flow; it does not promise a general service-level guarantee.

Remote work adds failure, not a new programming model

The application still talks in messages. Transport adds node identity, framing, timeouts, reconnect behavior, and the possibility that another machine is unavailable. A remote send has at-most-once transport semantics; a remote call is correlated messaging with a timeout. Focused localhost tests do not certify a multi-machine product.

The compiler should make friendly source inexpensive

The intended path is source → parser → resolver → high-level intermediate representation → mid-level intermediate representation → LLVM → linker → native executable. The architecture guide explains what each layer owns.

The language promises immutable behavior. Copy-on-write preserves that behavior when sharing is possible. When the compiler proves one owner and a last use, Perceus-inspired reuse can update storage in place. That removes avoidable copying; it does not repair an algorithm that repeatedly scans everything it has already seen.

The complete archive, existing application migrations, and fresh Linux correctness remain open. A reported Linux Cli failure is currently scoped to a native compiler crash during MIR-to-LLVM emission; it is not yet a proven Cli runtime-language defect.
