Compiler engineering · 10 September 2026 · development checkpoint

A working bootstrap is not a working language

A compiler can build an archive, print a reassuring receipt, and still violate the contract that makes the next program correct. Executable experiments in Hey show how to distinguish a real repair from a green light that measures the wrong thing.

Development checkpoint, not consumer cutover. This article describes verified boundary repairs. It does not certify the final standard library, a compiler fixed point, Linux parity, or migration of MMeow, My Queue, and Top5.

Latest measured boundary: the range and ABI checkpoint advances the full clean build through 26 of 53 provider objects. It now refuses a composed callback in Http. The live toolchain has not been promoted.

The result

  • The seed calling interface and a mandatory compiler-stage boundary now have executable regression tests.
  • The recorded Minispec failure has not been closed by an ordinary-build acceptance test. Passing its interpreter tests is not a substitute.
  • The tests must also detect the broken implementation. Restoring the driver without the freshness repair changes the six-case suite from six passes to five passes and one failure.

The first false reassurance: the symbol exists

A static archive is a collection of compiled object files. A linker can find a requested function name without knowing that the caller and callee disagree about the values crossing their boundary. That agreement is the application binary interface, or ABI. LLVM's calling-convention rules make clear that compatible machine-level calls are a correctness requirement, not a naming convention.

The unfinished seed-archive producer exposed a C function returning a whole HeyValue structure. Its consumers expected a pointer to a boxed value. Both sides used the same public function name. A symbol-presence test therefore passed while an actual call returned the wrong result.

Expected boundary:  pointer argument → pointer result
Emitted boundary:   value argument   → value result

Test input: 20       Expected result: 41

The control mattered. Calling that same object through its actual, by-value interface returned 41. The arithmetic body was not the cause. The defect was the interface advertised to its caller. The seed repair keeps the body private and publishes a generic adapter, rather than changing the language operation.

Borrowing is part of the interface

The pointer caller retains ownership of its arguments. The old seed body consumes its by-value parameters. The adapter must therefore clone each borrowed payload before passing it into that body, then transfer the owned result into a fresh box. Returning the correct integer alone would not prove this lifetime contract.

The tests also release a returned string and then read the caller's original string, pass the same box in both argument positions, exercise zero-argument calls, and verify the seed adapter's tested null-to-nil behavior. Removing the argument clone makes the lifetime control fail. Independent review additionally caught malformed selection records that could be silently skipped; those now fail instead of producing a partly populated archive.

Platform names need the same care. GCC's assembler-label documentation explains that an explicit label does not receive the usual target underscore automatically. The implementation uses the target's prefix, not a hard-coded Mac spelling. The local tests establish Darwin behavior; they do not certify another operating system.

The second false reassurance: no fallback was counted

Hey joins resolved provider and linkage information to its middle-level intermediate representation (MIR) before emitting machine-facing code. That annotation step was treated as optional by the driver: when its producer failed, the driver could continue with unannotated input.

A fault-injecting wrapper made the annotation producer fail deliberately. The compiled driver still built a runnable application and reported zero legacy-emitter fallbacks. That number was accurate only about the emitter counter. It said nothing about the required stage that had just been bypassed.

Producer fails       → stop before emission
Producer omits output → stop before emission
Producer succeeds     → consume its output

The repair enforces this boundary in the driver. Both failed execution and missing output stop compilation, whether the separate emitter-coverage policy says warn or error. The harness computes the observed results; Minispec asserts and reports them. Four injected refusal cases and a valid executable control pass. Restoring the old driver makes the refusal assertions fail again.

Review then found a warm-cache gap: a previous output file could survive a successful producer that wrote nothing. An added test reproduced it. The driver now removes old annotation output, verifies removal, and only then launches the producer. The expanded suite passes all six cases; restoring the driver without that freshness check restores the single stale-output failure.

A tail instruction is not a lifetime proof

The next clean-build failure was an indexed value inside a scalar self-tail call. The body needed to read an element, add it to a running total, release its frame-owned values, and transfer control without retaining another stack frame. Simply accepting the previously refused instruction could have freed the collection before its element was read.

The indexed-tail repair puts the decision in MIR. Its structured operand plan identifies the collection binding, requests the existing scalar element-read representation, and gives that borrow an explicit lifetime ending before frame cleanup. LLVM consumes those records; it does not recover ownership by inspecting the text it has already emitted. All outgoing values are evaluated before any frame-owned value is released.

The native test runs 100,000 transfers on a 512 KiB stack, with copy-on-write both disabled and enabled, and checks 400,000 release calls. Removing cleanup fails the lifetime test. Withdrawing the guaranteed transfer in an isolated copy of the compiler source makes the same input fail its bounded-stack test. Removing the MIR license prevents emission. These are different controls for different claims: a correct answer alone cannot establish bounded stack use or reclamation.

This is a bounded capability, not a completed ownership pass. Calls inside scalar tail operands and newly owned pointer arguments remain separate work. In particular, forwarding a freshly extracted next-node box cannot be made sound by removing the borrow guard. LLVM's musttail contract guarantees the transfer only under its stated ABI and lifetime constraints; it does not decide Hey's ownership policy.

A string pointer is not a value-type contract

Cli then exposed a different boundary. Its predicate needed to test args[i + 1]. The question-mark forms of the predicates lacked declared runtime ABI rows, while their other exposed forms used raw-string arguments. Converting an arbitrary Hey value to a string would make the compiler accept cases that the interpreter rejects.

The predicate repair declares the exposed forms through the existing registry and shares the interpreter's strict string-type checks with borrowing native helpers. The runtime helpers neither retain nor release the incoming boxes. The argument producer reports whether it created a temporary, so the caller can retire that temporary after the predicate has read it.

The tests compare ten invalid-input cases with the interpreter, check left-to-right single evaluation, and run 2,000 native lifetime iterations in each copy-on-write mode. Removing the borrowing declaration from an isolated schema and regenerating its projection makes the native reclamation test fail. A future representation-specialized ABI may avoid boxes for statically known strings; it must not regain speed by accepting the wrong value types.

A conversion must leave its caller alive

The same ABI audit found a more serious error in to_f(value): a resolved call borrowed its operand, but the declared native helper freed that incoming box. AddressSanitizer reported a heap-use-after-free when the test read the caller's value after conversion. Producing the right floating-point result had concealed a broken lifetime contract.

The repair binds the ordinary resolved call to an explicitly borrowing conversion helper. The older consuming helper remains separate for its legacy native-C callers; silently changing its contract would instead abandon the owned carriers those callers supply. The repaired ordinary call survives 100 caller-lifetime iterations in each copy-on-write mode. Restoring the old consuming declaration in an isolated schema and regenerating it restores the AddressSanitizer failure. Retirement of the legacy route is still work to do.

A neighboring integer-conversion repair needed no new language behavior: the runtime already had a borrowing value_to_i64 implementation. Its missing ABI row prevented a resolved call from accepting a complete floating-point expression. Tests now preserve fractional arithmetic until the explicit conversion, observe one nested function call, and verify retirement of its temporary.

Codec also exposed an artificial 18-digit ceiling in literal recognition. Signed 64-bit values require up to 19 decimal digits. The representation repair checks the actual signed bounds in MIR using decimal text, without overflowing an intermediate accumulator or passing through floating-point conversion. LLVM's helper uses that result. Native tests at optimization levels zero and two preserve both endpoint values and the special division-overflow guard. This changes the representation check, not Hey's source-language overflow policy.

A selected body is not an exported function

A further archive check found that Cli's helper symbols were globally visible. The selection plan answered which bodies the object needed, but did not separately answer which functions its public interface promised. Expanding a dependency closure must not expand that interface.

Product plan, simplified:
  export Cli parse
  select -   cli_parse_value

Linked MIR carries separate facts:
  materialize ...       which bodies belong in this object
  exportabi ...         the promised public calling interface
  objectlinkage ...     internal or external native linkage

The linkage repair makes that distinction in the canonical product inventory. Annotation joins the explicit export and selection roles to resolver identities and closes body dependencies without adding exports. MIR carries object linkage separately from source-language visibility. LLVM consumes it without matching helper names or native-symbol prefixes. The seed object producer reads the same role distinction; no source function is made private as a workaround.

The regression links two independent objects that intentionally use the same internal helper symbol. Both public entry points remain callable. Withdrawing the linkage facts recreates the duplicate-symbol link failure. A real source fixture also confirms that the helper's language-level visibility remains unchanged. This establishes the tested object-boundary contract, not the correctness of every standard-library module.

The recovery execution receipts identify these scoped changes, their source and native gates, and the remaining full-build boundary. They are correctness evidence, not a compiler-speed benchmark.

Later checkpoint: the range belongs to MIR, not LLVM

Added 10 September 2026, after the earlier f0f80742b checkpoint. The historical failure below is retained rather than silently rewritten. The later isolated branch has passed Codec and built the real Files provider. The dated range and ABI receipts identify the tests and limits; they are not a whole-toolchain release certificate.

The original bytes(key, "utf8") refusal was repaired by declaring both supported ABI shapes. Selection uses the resolved target and argument count. It does not teach LLVM that a function spelled bytes deserves special treatment. Unary and binary calls preserve bytes inputs, invalid-value and encoding errors, borrowing, and left-to-right child evaluation. Withdrawing either shape makes that shape refuse while the other remains unchanged. Withdrawing borrowing or owned-result facts makes the native temporary-reclamation observer fail.

Files then exposed for index in 1 ..< len(parts). The range repair separates two facts that initially looked like one. The iterator produces integers, but the source program may rebind its loop variable to another value. HIR therefore carries integer semantics for an unchanged element and tagged-value storage for a rebound element. Assigning "kept" must preserve that string; it must not silently become zero.

MIR proves the bounds' scalar representations from bindings and resolved declarations. It evaluates the lower bound, then the upper bound, once each. It expands the loop into existing local, store, comparison, and while operations before ownership analysis. A separate private cursor controls progression, so rebinding the source variable cannot change the next iteration. Slots are placed at function entry so repeated nested loops do not keep adding stack storage. LLVM receives operations it already understands; no range-syntax parser was added there.

The source tests pass forty assertions. Native output agrees with the interpreter at optimization levels zero and two, with copy-on-write disabled and enabled. The cases include a million-iteration sum, 50,000 repeated nested loops on a 512 KiB stack, empty and descending intervals, signed endpoints, early returns, ordered bounds, tagged rebinding, and a deliberate temporary-name collision. Removing the MIR expansion, removing the declared length ABI, or removing HIR's rebound-storage decision makes the appropriate control fail again.

This remains a bounded implementation. Unknown dynamic bounds refuse rather than undergo permissive conversion. Ambiguous lexical bindings and the transitional text transport still need structured-operand work. The existing fresh-pointer tail guards remain intact. A separate alias-gate repair also illustrates why a red test needs diagnosis: its extractor had read an earlier call site instead of the definition. All seventeen real alias entries agreed. Anchoring the definition fixes that false failure; deleting an actual entry in a copied source tree still makes the test fail.

The subsequent complete clean build remains red. At 7b2cc7f4d, the compiler driver builds with a zero-fallback receipt and 26 of the 53 original provider objects complete. Http then refuses a record containing step(progress.state, piece). Its MIR already identifies step as a callable parameter. This connects an expression-position gap to an older, separately recorded ABI defect: unit-local name-dispatch trampolines cannot generally invoke a callable supplied by another compilation unit. That older runtime failure was not replayed here; this build stopped at emission first. A fix must preserve complete ordered arguments and cross-unit callable identity, not merely make one Http object compile. The existing callable-ABI task calls for direct entry thunks, not another name registry. Local trunk and the official checkout remain unchanged until full-build and consumer acceptance succeeds.

Why this is still bootstrap work

A seed compiler makes it possible to build the next compiler. It is not automatically the compiler that should build applications. The Rust compiler development guide similarly distinguishes bootstrap stages and explains why artifacts from different stages are not casually interchangeable. That is a useful comparison, not proof that Hey has completed the same process.

Hey's seed archive now crosses its declared interface, and the rebuilt driver executes. The final standard library still needs to be built through the ordinary Hey-owned pipeline. The resulting toolchain must then compile the real consumers and run them without compiler source or an interpreter service at application runtime.

The next proof belongs to the consumers

The observed Minispec refusal does not, by itself, establish where provider information was lost. Existing source-graph and materialization investigations are the next place to test that hypothesis. A standard-library directory must not decide language meaning, and a special case named Minispec in LLVM would not repair the owning layer.

The isolated development branch now contains the tested indexed-tail, strict-predicate, conversion, literal-range, and object-linkage changes described above. Its complete final archive and clean-build acceptance remain open. None of these scoped results authorizes a new consumer pin or certifies the compiler fixed point, Linux build, or application execution without the toolchain present.

The final clean-build checkpoint at f0f80742b rebuilds the compiler and ten real standard-library objects, then stops in Codec at bytes(key, "utf8"). The missing builtin ABI must account for both unary and two-argument forms; adopting a fixed two-argument interface alone would leave another valid call shape broken. The final archive was not produced, and the recovery batch has not been promoted to the live toolchain.

The completion criterion is the real application, not another bootstrap receipt. MMeow and My Queue must leave their Stage-0 build commands behind because their ordinary builds work. Top5 must obtain its required packages without adopting that workaround. Until those programs pass, the boundary repairs are useful progress, not a finished language.
