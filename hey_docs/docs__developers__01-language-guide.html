Hey language guide#

This guide describes the settled source language owned by the frontend.

Programs and specs#

spec 'answer'
  expect stdout "42\n"
end

program
  says 40 + 2
end

A source file may contain declarations, specs, imports, modules, and one executable program block.

Bindings are immutable#

let user = {name: 'Ada', visits: 1}
let next = {...user, visits: user.visits + 1}

let binds a name once. Parameters, imports, functions, loop variables, actors, workers, and jobs are bindings too and are not reassigned.

set updates only state slots owned by an actor, monitor, or supervisor:

actor Counter
  state count = 0

  receive message
    set count += 1
  end
end

Values#

Hey's core values include:

  • nil;
  • booleans;
  • whole numbers and decimals;
  • strings and bytes;
  • immutable arrays;
  • immutable objects/maps;
  • functions, bound callables, and actor definitions;
  • opaque runtime capabilities.

JSON is a codec over ordinary values, not the language's object model. Functions and opaque capabilities cannot be encoded as JSON by default.

Strings#

Single-quoted strings are raw except for \' and \\:

let path = 'tmp/#{literal}/file'

Double-quoted strings support escapes and interpolation:

let name = 'Ada'
says "Hello, #{name}\n"

Use heredocs for long text. See Multiline strings.

Arrays and objects#

let values = [1, 2, 3]
let more = [...values, 4]

let user = {name: 'Ada', visits: 1}
let visited = {...user, visits: user.visits + 1}

Known fields use dot access; dynamic keys use brackets:

says user.name
let key = 'name'
says user[key]

Dot access never falls through to an unrelated lexical variable when the receiver lacks the field.

Functions#

fn greet(name, punctuation = '!', ...rest, loud:, prefix: 'Hello', ...options)
  let message = prefix + ', ' + name + punctuation
  if loud
    return message.upper()
  end
  return message
end

Parameter order is:

  1. required positional;
  2. optional positional;
  3. positional rest;
  4. required named;
  5. optional named;
  6. named rest.

Defaults are evaluated left to right and may refer only to parameters already bound.

Functions are ordinary values:

let handlers = {save: save_document, quit: quit_app}
handlers.save(document)

Receiver calls#

A dotted call is lexical sugar for an ordinary function call when the selected import/module exposure permits dotted form:

account.deposit(25)
# deposit(account, 25)

Each chain segment resolves independently:

account.deposit(25).withdraw(10).balance()

No runtime method table is consulted.

Modules and imports#

module Accounts
  fn deposit(account, amount)
    return {...account, balance: account.balance + amount}
  end

  exposes deposit forms: [:qualified, :unqualified, :dotted]
end

import './accounts.hey'
import './accounts.hey' as Bank
import './accounts.hey' exposing: [deposit]
import './accounts.hey' exposing: [deposit] forms: [:dotted]

A module surface is explicit. Imports are lexical. Re-export is explicit. See Modules and imports.

Control flow#

if ready
  start()
else
  wait()
end

for item in items
  says item
end

while condition()
  work()
end

Boolean operators short-circuit. false and nil are falsey; every other value is truthy.

Operators#

2 + 3 * 4
2 ** 8
mask & allowed
value << 2
ready && start()
fallback or recover()
1 ..< 5
1 .. 5

One registry defines every operator. Parser context decides prefix/infix form; imports decide binding; lower stages consume those facts. See Operators and arithmetic.

Actors#

Actors own private mutable state and process one message at a time:

actor Counter(reply_to)
  state count = 0

  receive message
    set count += message.amount
    send reply_to, count
  end
end

Messages own transported values. Actors do not share mutable application objects.

Workers and Jobs#

Workers are stateless declarations suitable for bounded parallel pools. Jobs add named lifecycle, receipts, retries, cancellation, idempotency, durability, metrics, and result retrieval.

See Workers and Jobs and concurrency.

Errors and diagnostics#

Tokenizer, syntax, and resolver diagnostics carry source spans. A missing name, invalid import exposure, wrong operator form, or invalid set target is diagnosed before HIR. Runtime errors are reserved for genuinely dynamic facts such as division by zero or invalid capability state.
