Hey — full status since 07:00, Mon 28 July 2026

Written 2026-07-29 ~03:30 PT · shipping release **v0.99.470a** on trunk

Plain English. Every shorthand is defined the first time it appears.

Tense is explicit: **DONE** means finished and verified, **IN PROGRESS**

means running right now, **FUTURE** means planned and not started,

**NOT DOING** means decided against so nobody resurrects it.

---

THE ONE-PARAGRAPH VERSION

We shipped four releases and fixed five real defects, including two ways

a shipped Hey program could have been made to run someone else's code.

We also discovered that **eleven of our own measuring instruments were

lying to us — and not one of them was in the compiler.** That second

sentence is the more important one. It cost us a public correction: we

withdrew every response-time figure we had published, in our own words,

before anyone asked. The compiler is measurably better than it was

yesterday morning. Our ability to tell when we are wrong improved more.

---

DONE — and it went well

1. Four releases shipped, each verified on two operating systems

releasewhat it fixed
**467a**A compiled program stored the *text* `"true"` where the interpreter stored a real true/false value. No error, no warning — just a wrong answer that only showed up if you converted the data to JSON.
**468a**The runtime could be tricked into running a program of an attacker's choosing (details below). Closed.
**469a**Request logging for web apps actually works now. It had been **declared and wired to nothing** — you could switch it on and it silently did nothing at all.
**470a**You can now put a value into an array *inside a helper function*. Before this, that crashed at runtime, and there was no way for a user to work around it.

2. We closed two real security holes

Hey's runtime sometimes asks a helper program to do work the compiler

cannot yet do itself. To find that helper it worked through a list of

places to look — **and the list had no bottom.** When every sensible

option failed, instead of stopping, it fell back to looking in

*whatever directory the program happened to be started from*.

Two ways to exploit that were **measured, not theorised** — we put a

harmless stand-in program in place and watched Hey run it, twice:

  • a program named by an environment variable was found through the

system search path and executed;

  • with no configuration at all, a file planted in the working directory

was executed.

Both now **refuse loudly** instead of guessing. A third route — pointing

an environment variable at a specific absolute path — still works

**deliberately**, and is now documented as a trust boundary: if you do

not control a program's environment, you do not control what it runs.

3. We are faster than Go on one core, and it is properly certified

**131,000–135,000 requests per second on a single core, about 10% ahead

of Go** under identical conditions, with the confidence interval

comfortably inside our accuracy target.

We also found that our *previous* figure understated us — it had been

measured at a load where Go was working flat out and Hey still had room

to spare. **A ratio taken where one side has headroom and the other does

not is not a fair comparison**, so that measurement point is retired.

4. First raw-loop speed number in the project's history

On a tight integer loop — no I/O, no allocation, nothing to hide behind:

time
Hey (compiled)**394 ms**
C, gcc -O2373 ms
Go316 ms

**Hey is within 6% of C.** The gap to Go is a specific compiler

optimisation that C's `-O2` also missed here, not a weakness in how we

generate loops.

5. A large speed win, landed and measured

Writing into an array where the value being written *reads from the same

array* — the shape at the heart of many real algorithms — used to copy

the entire array on every write.

array sizebeforeafter
512 elements2,915 ns per write**41 ns per write — 71× faster**

And it now costs the same regardless of array size, where before it grew

linearly. It also **closed a memory leak of 32 bytes per write** that

nobody had been looking for.

6. We fixed a bug that had been live for ten releases

Reading from a collection and writing to it had been using **two

different rules to decide what your key meant** since release 460a. The

read side was fixed back then; a comment in that fix even names the

disease — and the write side was left alone.

---

DONE — and it did not go well

7. We published wrong response times, and we corrected them ourselves

Every response-time figure we have published was measured with a tool

setting that produces **optimistic** results. The technical name is

*coordinated omission*: our load generator waits politely when the

server stalls, so the slow requests never get sent and never get counted.

We corrected the published articles **in place, in our own voice**,

before anyone raised it. What the corrected measurement shows:

HeyGo
typical response**642 µs**738 µs✅ we still win
slowest 1%1,686 µs1,612 µs⚖️ effectively a tie
slowest 0.1%22,874 µs9,716 µs❌ **we are 2.4× worse**

**Throughput was not affected** — requests-per-second is a count, and the

flaw distorts timing, not counts. The "faster than Go" headline stands.

What we lost is the claim about response times.

How we found it: a literature review commissioned that morning **for an

unrelated reason** predicted this class of error, so we tested our own

tools. **We did not find this by being careful.**

8. Adding cores does almost nothing

workersrequests/sec
1133,500
4132,842
8134,339

**Eight workers buy 1%.** We proved this is genuinely our problem and not

a measurement artefact: Go pushed 152,047 requests/sec through the *same*

load generator on the *same* machine — 13% above our ceiling — so the

generator was not the limit. We also re-ran the ladder in reverse order

to rule out measurement bias. Both objections closed.

9. Eleven instruments were lying, two of them mine

Checks that could not fail, or that measured something other than what

we quoted them for. A representative few:

  • a test whose pattern could **never match**, due to a shell quoting bug;
  • a benchmark that could not distinguish *"the system is slow"* from

*"I ran the wrong build"*;

  • a process check using a command-line flag this operating system does

not support, whose fallback quietly reported "zero";

  • **our race detector itself** — it only reports problems on code paths

that a test actually exercises, so "no races found" has always meant

"no races on the paths we happen to test". Nobody had stated that

limit before.

**Not one was in the compiler.** The compiler's defects were all caught.

The instruments' defects are what let them hide.

10. Three of my own briefs were wrong, and the agents caught them

  • I named the wrong cause for a defect. The implementer fixed what I

pointed at, rebuilt, **measured that the defect survived**, and found

the real cause.

  • I asked for a test arm that would have **passed while proving nothing**.

The implementer built an honest version instead.

  • I hand-edited a working directory while an automated agent was still

active in it. My changes were silently discarded, and I then spent an

hour diagnosing a "regression" in code that no longer existed.

---

IN PROGRESS — running right now

  • **`wtakeput`** — the 71× array-write fix above is committed and

verified; it lands as release 471a next.

  • **Isolation fixes on the Linux side** — five places where a value was

handed between threads without being properly copied. Two were found

by tests; **three more were found only by reading every relevant call

site**, and two of those three were real. They would have shipped.

  • **More repetitions of the slow-response measurement** — the "2.4×

worse" figure above is currently a *lead, not a finding*: our two runs

disagree with each other by a factor of three, so it needs more data

before we treat it as true.

---

FUTURE — planned, not started

1. **`a[i] = v`** — the natural way to write into an array still does not

work. Worse: the compiler refuses it loudly while the interpreter

**silently does nothing**. The loud-failure half ships first.

2. **One remaining function** still uses the old broken key rule.

3. **Automatic numbering for tests and gates** — we had *five* numbering

collisions in one session because separate work streams each picked

"the next free number" from a stale view. This is my debt.

4. **Three function renames**, approved: `Process.ok?` → `Process.run_ok`

(it runs a command, so it should not look like a question),

`Http.get` → `Http.fetch` (it was the opposite direction from

`Web.get`), `Ranges.start` → `Ranges.lower`. Eleven call sites, none

in any application.

5. **The subsidy audit** — what does Go's web server do on every request

that we do not? Every item is either a fair difference or a hidden

advantage in our numbers, and we would rather find them ourselves.

6. **Two middlewares are still declared and inert** — rate limiting and

CORS can be switched on today and do nothing, exactly like request

logging did before 469a.

---

NOT DOING — decided against, do not resurrect

  • **Shrinking actors to match another runtime's 64 bytes.** Three

independent architects examined it and two argued against their own

assignment: the workloads we care about **contain no actors at all**.

Verified three ways. It buys bytes, not speed.

  • **Actors as mutable cells** to work around a missing feature —

measured at 2,600× slower than a plain array write.

  • **Making a reference count atomic** to silence the race detector. Our

own source comments explain why that would hide the defect rather than

fix it.

  • **Chasing a web-framework leaderboard** — the best-known one was

archived in March 2026 after criticism that it was being gamed.

---

GLOSSARY DELTA — terms coined or first used since yesterday morning

  • **Coordinated omission** — a measurement flaw where the tool waits for

a slow system instead of keeping up, so the worst delays never appear

in the results. Makes response times look better than they are.

  • **Fail-open ladder** — a lookup that returns *something* when every

option fails, instead of stopping. The opposite of what we want.

  • **Instrument blindness** — when a test or measurement cannot detect the

thing it is trusted to detect. Green light, no information.

  • **Green for the wrong reason** — a test that passes without exercising

the property it claims to check.

  • **Take discipline** — moving a value out of its slot rather than

copying it, so the runtime can see that nobody else is using it.

  • **Structural census** — checking every place in the code where a

pattern occurs, rather than relying on tests to find them. Tests

confirm *instances*; a census establishes the *class*.

  • **Pre-registration** — publishing a prediction *and how you would know

you were wrong* before running the experiment.

  • **Corpus anchor** — an example program added purely so a shape gets

exercised by our whole-project comparison.

---

DECISIONS — BOTH ANSWERED 2026-07-29

**1. `.count` on your own data → `get('count')` / `['count']` FOR NOW,

and the question goes to research.**

Both escape hatches verified working on 470a, with the interpreter and

the compiled binary agreeing — so this is a **design question, not a

defect**. Commissioned to the bench seat to orchestrate researchers:

how have other languages resolved this, and does any other language

even have the problem? Brief:

`docs/agents/orchestration/research_member_vs_key_collision.md`.

**The probe reframed the question.** The ticket said "`.count` gives

the field count." True, but `h.other` returns **7** — so **dot does

reach your data**, except on a hidden list of builtin names where the

builtin wins **silently**. The two languages we benchmark against don't

have this problem, and they avoid it in *opposite* directions:

what `.` means on a plain mapcollision?
Ruby**never** data — `h2.other` raises `NoMethodError`no
JavaScript**always** data — `h.length`/`h.size`/`h.keys` are `undefined`no
**Hey**data **except** on a shadow list, silently**yes**

That may make ours the worst of the three — not because either

alternative is obviously right, but because ours is the only one where

a habit the language actively encourages silently returns something

else. The research is authorised to refute that framing.

**2. Cross-machine measurement over a cable → NOT YET.** Parked.
