Commands, tools and platforms

Two commands do almost everything: hey runs and builds programs, heyc checks, tests and inspects them. This page lists every subcommand and flag, shows the help each one really prints, and ends with where Hey runs and how versions work.

The four you'll use dailyhey app.hey compiles (once, then cached) and runs. hey build app.hey -o build/app makes a native executable to ship. heyc app.hey --test runs the spec blocks in the file. heyc app.hey --check checks the file without running it.

3. Look inside the compiler

Each stage of the compiler (syntax tree, HIR, MIR, LLVM) can be replayed on its own and saved to a file, so you can see exactly what the compiler made of your code. The stages themselves are explained in the compiler article. Works today

tiny.hey
fn square(n)
  return n * n
end

program
  says square(7)
end
$ hey phase syntax tiny.hey -o build/tiny.syntax.json && wc -c build/tiny.syntax.json
hey phase emitted deterministic AST
    1116 build/tiny.syntax.json
Types here are the compiler's notes, not yours. You never write a type in Hey. The words after the colons below (Value, Int, boxed, i32) are what the compiler worked out on its own, printed so you can see its reasoning.

6. Cache and checkout maintenance

hey FILE.hey keys its cached executable by the absolute source path, every file in its import graph, the compiler inputs and the target. To find imports quickly, the key is computed by scanning only top-level import lines (no full parse), resolving them the same way the compiler does, and hashing each file once with SHA-256. Change one imported file and the next run recompiles; change nothing and it reuses the executable.2 Compiled HIR and MIR ("sidecars") are cached under the same key. You never need to clear a cache to see a change. Works today

$ hey cache path
cache_home=<cache>
parser_cache=<cache>/parser
run_cache=<cache>/run
source_index_cache=<cache>/source-index
runtime_object_cache=<cache>/runtime-objects
compiler_build_dir=<toolchain>/build
compiler_ir_cache=<toolchain>/build/compiler-sidecars

The last two lines matter: compiled HIR and MIR sidecars go into the toolchain's own build/compiler-sidecars, not under HEY_CACHE_HOME, so a shared or read-only toolchain directory gets written to.

`gc` removes unused parser, source-index, runtime-object, and LLVM application

## Source-handoff format

Source-development handoffs are accepted by tests and a reviewable diff, not by a SHA-256 checksum or byte-for-byte ZIP identity. A complete replacement file or executable overlay script is acceptable during focused iteration. When you return a full Hey source ZIP, include one directly copyable command block that applies the provided archive:

```sh
cd "$HOME/dev/hey-lang-bootstrap-plan"

HEY_VERIFY_MODE=full \
HEY_RUN_PROMOTION=1 \
./PROCESS-HEY-SOURCE-HANDOFF.sh \
  "$HOME/Downloads/EXACT-RETURNED-SOURCE-ZIP-BASENAME.zip"
```

Replace `EXACT-RETURNED-SOURCE-ZIP-BASENAME.zip` with the basename of the source ZIP provided in that response. Recompression or regeneration is allowed and no source-handoff checksum comparison is required. Full and report handoffs require `HEY_RUN_PROMOTION=1`; promotion is the final commit-blocking gate.

Some of these help screens print internal paths such as ./bin/subcmds/hey-clean; type the hey clean / hey rebuild form instead. hey clean and hey rebuild deliberately throw away build products; you don't need them for everyday work. hey zip --downloads makes a safe, complete source ZIP. Works today

9. Versions and releases

Hey versions look like 0.99.606a: the number after 0.99. goes up by one on every landing, and the a marks the alpha series. Every landing bumps the version, because the Docker toolchain image is cached by its version tag; an unbumped landing would reuse a stale image and force a long rebuild. stdlib:Version is the one place the version lives (Version.current(), Version.next()). Which release lands when is Roadmap. Works today

version.hey
import 'stdlib:Version'

program
  says Version.current()
  says Version.next()
  says Version.current_tag()
end

In a source checkout, bin/hey sets HEY_ROOT, HEY_STDLIB_PATH and HEY_COMPILER_BUILD_DIR itself. If you have several checkouts, clear inherited HEY_* variables first (unset $(env | grep -o '^HEY_[A-Z_]*')) or one checkout's paths will leak into another's run.

11. Glossary

Run cache
Where hey FILE.hey keeps compiled executables, keyed by content; see hey cache path.
Sidecar
A cached HIR or MIR file stored next to a compiled program so an unchanged program skips those stages.
Import graph fingerprint
One SHA-256 over every file a program imports; part of the cache key.
Target
An operating system and processor pair Hey builds for, such as darwin-arm64 or linux-x64.
Target archive
One download containing the compiler, runtime, linker and standard library for one target, installable without a C compiler.
Receipt
A small JSON record proving a step happened (a build, a native run, a verification), with hashes.
Spec block
A spec … end block in a source file stating expected output; run with heyc --test.
Conformance spec
A spec in specs/ that pins one language rule.
Gate
A check that must pass before a change lands.
Landing
A change merged into the release line; every landing bumps the version.
Stdlib archive
The standard library precompiled once so programs don't recompile it.
Builtin
A function available in every file with no import, implemented in the runtime.
Native package
A package that wraps a C library through a manifest (Native code and C).
Syntax tree, HIR, MIR, LLVM
The compiler's stages; defined in the compiler article's terminology table.

Known gaps

  • hey docs publish --dry-run fails on this toolchain (links leaving the curated catalog).
  • hey doc doesn't know many symbols (Text.trim, says, len); heyc --describe fails outside a source checkout.
  • Compiler sidecars are written into the toolchain's build/ directory regardless of HEY_CACHE_HOME.
  • heyc FILE --run (the interpreter lane) is decided to become native-only; meanwhile it can hang on programs the compiled path refuses (a set i += 1 loop never finished in 120 seconds while writing the language reference).
  • Proposed, not built: WebAssembly browser target (its task still targets the retired Real IR lane), compiled REPL, porting the project coordination CLI to Hey.
  • Not offered: a Windows compiler distribution; desktop GUI packages.
  • Not exercised for this page (they build or publish real products): hey target release, hey verify full, hey rebuild, hey docs publish without --dry-run, the perf benchmarks.
