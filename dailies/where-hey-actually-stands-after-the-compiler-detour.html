Where Hey Actually Stands After the Compiler Detour

We paused product work to stop different parts of Hey from disagreeing about what the same program means. That detour is finally producing concrete wins—but the new front end is still not in charge, and we are not pretending the product work is done.

TL;DR

  • The compiler detour is paying off, but it is not over. The new front end can now produce the same result through all five tested execution paths on a 12-program comparison set, but it still watches the old front end rather than replacing it in normal builds.
  • The strongest new result is memory, not syntax. Three separate lifetime rules now flatten four measured leaks: 32.1 → 0.0, 48.2 → 0.0, 32.1 → 0.0, and 32.1 → ~0.0 bytes of growth per call on the measured workloads.
  • The fixes are concrete. The compiler is learning to name temporary values, free caller-created conversion boxes after safe calls, and free one-use expression temporaries immediately after their last use.
  • We are not calling Hey stable yet. A native type-inference wrong answer is still registered, some compiler forms still fall back to older code, ownership has more cases to cover, and actor messages still deep-copy arrays, maps, and strings by default.
  • The evidence is deliberately bounded. The latest fully reconciled whole-suite report available for this checkpoint is 107/107 checks at 0.99.484a. The 0.99.485a nil-temporary repair is landed, measured, and focused-gated; its next full-suite report is not part of the evidence used here.

The compiler is not the product

That is the big picture the August 5 checkpoint made hard to see. We did not stop product work because tokenizers are intrinsically interesting. We stopped because Hey had too many places independently deciding what a program meant. That is how silent wrong answers survive.

The new source-reading path now agrees across five tested execution paths on a 12-program comparison corpus. That is meaningful progress. It is also not the finish line: the old front end still controls normal compilation, the Hey-written native-code path still has refusals and known reds, and older C code remains as a compatibility route.

The detour is finally fixing things users can feel

Here is the clearest example. This ordinary-looking line used to leak a boxed value every time around a loop:

set n = n + br(xs)

The compiler generated a value for br(xs), used it, and then lost track of it. The repair was surprisingly small: make the hidden result explicit so the release machinery that already exists can see it.

before
  n = n + br(xs)

after, conceptually
  left = n
  result = br(xs)
  n = left + result

Measured growth fell from 32.1 bytes per call to 0.0 with the same answer and clean Guard Malloc.

The next leak looked similar in source and turned out to be completely different:

fn hs(x)
  return 7
end

let s = 'ABCDEFGH'
set n = n + hs(s)

hs accepts a general Hey value, while s is stored as a string. The caller therefore creates a temporary boxed copy just for the call. The callee borrows it, returns 7, and the temporary used to be forgotten. Releasing that caller-owned temporary after a proven-safe call changed the measured curve from 48.2 bytes per call to 0.0. The same rule, measured separately for an integer box, changed 32.1 to 0.0.

Then a third mechanism appeared in code as simple as:

if value == nil
  return 0
end

The native-code generator creates a temporary boxed nil solely to perform the comparison. Nothing outside that comparison can own it. Releasing it immediately after its last use changed 32.1 bytes per call to approximately zero. Better still, a combined test that had been leaking 64.2 bytes per call fell to 32.1—exactly one 32-byte allocation disappeared while the other remained. That is unusually strong evidence that we are distinguishing lifetimes rather than merely making a graph look flatter.

What is still broken

The compiler still has known correctness debt. One current example is a function parameter that is passed a string and used in string concatenation but is inferred as an integer in the native path. The interpreter and bootstrap compiler produce AT; the native binary produces pointer-like numeric garbage before the trailing T. That defect is registered rather than hidden behind the memory work.

Not stable yet. Five-path agreement on one comparison corpus is not the same thing as one authoritative compiler, zero fallbacks, or zero known wrong answers.

The verification boundary matters too. The latest mechanically reconciled full run included 107 of 107 selected checks, with no unexpected regression, at 0.99.484a. The source used for this article is 0.99.485a and contains the newer nil repair plus its focused gate and measurements. The next whole-suite report is not part of this evidence set, so this article calls that repair landed and measured, not fully re-verified.

Actors are real; the cheapest version of them is not here yet

This is already ordinary Hey:

actor Counter(label)
  state count = 0
  receive message

  if message == 'increment'
    set count = count + 1
    says label + '=' + count
  end
end

Ordinary compiled actors already use a pooled, stackless worker system with work stealing; the old thread-per-actor model is the legacy path. But Hey does not yet get its isolation by freely sharing immutable arrays, maps, and strings between actors. Those values are deep-copied at mailbox insertion by default. The long-term actor goal—cheap isolated concurrency over shared immutable values—is still ahead of the compiler work, and the old actor performance numbers are stale enough that I am not repeating them here.

Are we back to building products yet?

Not quite. The repository now defines 43 product checks across CLI, web, iOS, Android, and AppleTV. That is good infrastructure, but the current snapshot does not contain a clean, commit-bound capture of all of them for this compiler. The archived captures predate the provenance rule and are kept as history rather than proof.

1 · Finish lifetimesClose the remaining measured ownership holes without widening claims past the evidence.
2 · Put one front end in chargeDrive semantic fallback toward zero and stop maintaining duplicate answers to “what does this program mean?”
3 · Re-run the 43 product checksBind CLI, web, iOS, Android and AppleTV evidence to one clean compiler commit.
4 · Return to productsWeb apps, mobile apps, AppleTV, CLI tools—and then the actor/runtime performance work that motivated the language.

The compiler is not the product. But for the first time in this detour, the compiler work is producing results that look like the language we wanted in the first place: explicit lifetimes, fewer silent guesses, bounded memory where we have measured it, and failures that stay visible until they are actually fixed.
