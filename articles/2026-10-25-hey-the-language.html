The Hey language

Everything you can write in a Hey source file, one idea at a time. Every example marked Works today is compiled and run by the documentation test; the box under it is what the toolchain prints, warnings and errors included.

In one paragraphHey reads like Ruby (if/elsif/end, case/when, "#{interpolation}", says) and runs like C: the compiler turns it into a native program through LLVM. Values never change after they're made, so there's let but no assignment expression. You never write a type; a cast like x.to_i or !!x tells the compiler what you mean, and it infers the rest.

1. The shape of a file

A Hey file is a list of declarations followed by one program block, which is where execution starts. In order, a file may hold imports, modules, functions, actors, workers, jobs, specs and one program. # starts a comment that runs to the end of the line. Works today

shape.hey
# A whole Hey file: imports, functions, specs, one program block.
import 'stdlib:Text'

fn shout(name)
  return Text.upper(name) + '!'
end

spec 'shout says hello loudly'
  expect stdout "HELLO, ADA!\n"
end

program
  says shout('hello, ada')
end
$ hey shape.hey
HELLO, ADA!

A statement ends at the end of its line. It carries on to the next line only while a (, [ or { is still open. A trailing operator does not continue the line. Works today

continuation.hey
program
  let total = add_all(
    1,
    2,
    3
  )
  says total
  let names = [
    'Ada',
    'Grace',
  ]
  says names
end

fn add_all(a, b, c)
  return a + b + c
end
$ hey continuation.hey
6
["Ada","Grace"]

Reading a failure box. The message names the file, line and column, then what is wrong. A ... line stands for lines that depend on your machine, such as the folder the file is in. "exit status 70" is what Hey returns for any compile error, and for a runtime error in the main program.

2. Names, the ?/! convention, reserved words

Built-in names are reserved too. Besides the keywords, every built-in function (len, split, push, put and the rest of the built-in list) is a reserved name. You can still define something with that name, but don't: it hides the built-in, and the compiler warns:
warning: `len` is a reserved built-in name (Hey prelude); your definition at app.hey:12 hides it.
Rename it; future releases may make this an error.
Today it is a warning; a future release may make it an error. Warning coming in the consolidation release

A name starts with a letter or underscore and continues with letters, digits and underscores. A function or actor name may end in ? (by convention: it answers yes or no) or ! (by convention: it does something you should notice, such as I/O or failing). The suffix is part of the name and adds no hidden behavior. Works today

names.hey
fn ready?(status)
  return status == 'ready'
end

fn publish!(message)
  says 'published: ' + message
  return message
end

program
  says ready?('ready')
  says ready?('waiting')
  let sent = publish!('v1')
end
$ hey names.hey
true
false
published: v1

Words a C compiler or linker reserves (double, switch, static) are ordinary Hey names, as locals and as parameters; the compiler renames its generated symbols privately. Decided, coming As a local name they work today; as a parameter name the current code generator still refuses them.

toolchain_words.hey
fn combine(double, switch)
  return double + switch
end

program
  let static = combine(20, 22)
  says static
end
$ hey toolchain_words.hey
42

elsif, case and when are only keywords at the start of a statement followed by a space, so code with a variable called case still compiles. Object keys are data, so {'not': false} is fine.

Built-in functions aren't reserved words. Each one lives in a namespace (Path.basename, Json.encode), and the qualified name is what's reserved, so your own basename never collides with it. A small core set (print, len, Int and the like) is visible without a prefix; shadowing one of those is allowed, and the compiler warns only where your name changes which function a call reaches. hey doc --reserved lists them, straight from the built-in declarations.8 Decided, coming

4. Strings

Single quotes are raw (only \' and \\ are escapes). Double quotes understand escapes and #{expression}. For long text use a heredoc: <<TAG keeps indentation, <<~TAG strips the common indent, and a quoted tag (<<~'TAG') keeps #{} as plain text. Heredocs keep their final newline, so pair them with print, not says. Works today

strings.hey
program
  let name = 'Ada'
  says 'raw: #{name} \n stays as typed'
  says "interpolated: #{name}, length #{name.length}"
  says "tab:\tnewline escapes work"
  says 'it\'s fine'
  says %q(both 'single' and "double" quotes; #{name} stays text)
  says %qq(Hello #{name}; 'single' and "double" are easy)
  print <<~TEXT
    Dear #{name},
      indented line keeps its extra indent
    Bye
  TEXT
  print <<~'RAW'
    echo '#{not_interpolated}'
  RAW
  let page = """<h1>#{name}</h1>
"""
  print page
end
$ hey strings.hey

Ruling: adjacent string literals concatenate, as in Ruby,2 so 'it''s' means 'it' then 's', which is its. The compiler warns when two literals touch with no space between them, because that's almost always someone trying SQL-style quote doubling.

5. Arrays and objects

Arrays are [1, 2, 3]. Objects are {name: 'Ada'}; a key that isn't a plain name goes in quotes, {'content-type': 'text/plain'}, and is read with brackets. ... spreads one array or object into a new one. Nothing is changed in place: {...user, name: 'Grace'} is a new object and user is untouched. Works today

collections.hey
program
  let numbers = [1, 2, 3]
  let user = {name: 'Ada', active: true}
  let headers = {'content-type': 'text/plain', 'x-count': 2}
  says numbers
  says user
  says headers['content-type']
  let more = [...numbers, 4, 5]
  let renamed = {...user, name: 'Grace', role: 'admiral'}
  says more
  says renamed
  says user
  says user.name
  says user.has?('active')
  says renamed.keys.to_json
end
$ hey collections.hey
[1,2,3]
{"name":"Ada","active":true}

{"name":"Grace","active":true,"role":"admiral"}

{name, city} is shorthand for {name: name, city: city}. Decided, coming

shorthand.hey
program

  let city = 'Arlington'
  says {name, city}.to_json
end
$ hey shorthand.hey

A key can also be computed: {[expr]: value}. Computed keys mix with name: value and ...spread; entries are evaluated once, left to right, and a later entry replaces an earlier one, so {...defaults, ...overrides} is the general merge. A key that can't be a map key stops the program. Decided, coming

computed_key.hey
program
  let field = 'color'
  let defaults = {color: 'black', size: 1}
  says {...defaults, [field]: 'red'}.to_json
end
$ hey computed_key.hey
{"color":"red","size":1}

The last three lines are the "JSON sugar": user.name reads a field, and small helpers such as has?, put, keys and to_json can be called with a dot. Those calls aren't methods; Reference 2 explains how a dot call becomes an ordinary function call.

6. let, set, shadowing and _

let name = expression makes a binding. A value never changes: base.put(…) builds a new object and leaves base alone. set name = expression is a statement that gives a slot its next value: an actor's state slot, or a local that a loop carries from one turn to the next. There's no assignment expression: x = 1 never produces a value. Works today (actor state slots: Actors and failure)

bindings.hey
program
  let total = 0
  let i = 1
  while i <= 4
    set total = total + i
    set i = i + 1
  end
  says total
  let base = {name: 'Ada', visits: 1}
  let next = base.put('visits', 2)
  says base.visits
  says next.visits
end

Shadowing is a warning

A let that reuses a name from an outer block, or from the same block, is allowed. It may draw a warning, never an error.3 Nothing is changed: the inner name is a new binding. Works today

shadow.hey
program
  let label = 'outer'
  if true
    let label = 'inner'
    says label
  end
  says label
end
$ hey shadow.hey
inner
outer

The inner label is a new binding that lives until its block's end; after that, the outer one is visible again.

Throwing away a result: _

A call to a function that returns nothing is an ordinary statement. If the function returns a value and you don't want it, say so with _ = f(). Dropping a value silently gets a warning (and hey fix inserts the _ = for you); once existing code has moved over, it becomes an error.3 Decided, coming

discard.hey
fn noisy()
  says 'side effect'
  return 42
end

program
  _ = noisy()
  says 'done'
end
$ hey discard.hey
side effect
done

9. Casts are the type syntax

You don't write types in Hey. You write a cast, and the compiler reads the type off it: !!x is a Bool, x.to_i an Int, x.to_s a String, x.to_f a Float. So a function whose body is return !!x is known to return Bool with no annotation. Everything else is inferred; how the inference works is in the compiler article. Works today

Every cast works as a dot call and as a plain call: x.to_f, to_f(x) and Float(x) are the same. The dot form x.to_f on a whole number is still refused by the current build. Decided, coming

to_f_receiver.hey

  says x.to_f

13. Specs inside the file

A spec 'name' … end block states what running the file must produce: expect stdout, expect stderr and expect exit. hey test file.hey runs the program and checks every spec. Specs that import the code under test from another file are Proposed. Decided, coming (the hey test FILE spelling)

spec_demo.hey
fn add(a, b)
  return a + b
end

spec 'adds and prints'
  expect stdout "5\n"
end

spec 'nothing on stderr'
  expect stderr ''
end

spec 'exits cleanly'
  expect exit 0
end

program
  says add(2, 3)
end
$ hey test spec_demo.hey
PASS: adds and prints
PASS: nothing on stderr
PASS: exits cleanly

14. The truthiness puzzle

Predict first. Which of 0, '', [], {}, false and nil are falsey in Hey? Python says all six; JavaScript says four (0, '', false, null).
Answer

Only false and nil. Everything else, including zero and empty things, is truthy, as in Ruby. Works today

truthy.hey
fn check(label, value)
  if value
    says label + ' is truthy'
  else
    says label + ' is falsey'
  end
end

program
  check('0', 0)
  check('empty string', '')
  check('empty array', [])
  check('empty object', {})
  check('false', false)
  check('nil', nil)
end
$ hey truthy.hey
0 is truthy
empty string is truthy
empty array is truthy
empty object is truthy
false is falsey
nil is falsey
