Git-backed coordination for humans and agents.

Cagents is a coordination system for supervising many long-running agents without trusting fragile handoff notes as the source of truth.

Preview. This page intentionally lives at the repository root, outside /articles/. It is not meant to be indexed until reviewed and moved.

The bookkeeping problem

Long-running agents rarely fail because they cannot produce another answer. They fail because the surrounding state becomes unreliable: a task is still marked active after the process stopped, a handoff note claims work is blocked when the agent was simply turned off to save money, or five sub-agents finish and nobody records which result actually won.

Do not ask an agent to remember to update state. Require the operation that changes state.

Stable objects. Movable refs.

Cagents borrows a useful idea from Git. The task itself is a stable object. Its current role in the system is expressed through small refs around it.

projects/cagents/
├── PROMPT.md
├── goals/
│   └── goal_hosted_product/GOAL.md
├── tasks/
│   └── server-web-control-plane/TASK.md
└── refs/
    ├── workflow/ready/server-web-control-plane
    ├── owner/cagents-orchestrator/server-web-control-plane
    └── contains/goal_hosted_product/server-web-control-plane

The overriding prompt becomes durable

Every serious project can have one durable human prompt. Goals say what outcomes must become true. Tasks say what bounded executable work advances those goals.

PROMPT
Build Cagents into a self-supervising control plane.
        │
        ├── GOAL: reliable coordination graph
        │       ├── TASK: ref-backed workflow
        │       └── TASK: backlinks/index
        │
        ├── GOAL: algorithmic supervision
        │       ├── TASK: heartbeat
        │       └── TASK: watchdog
        │
        └── GOAL: hosted product
                ├── TASK: server/web control plane
                ├── TASK: repo provisioning
                └── TASK: billing

Presence is not task status

The person paying for the agents may turn one off. That is operational presence, not necessarily a statement about the work.

WorkflowPresenceMeaningSystem behavior
in_progressrunningOwner is alive.Let it work.
in_progresspaused: budget_pauseCompute was intentionally stopped.Show paused; do not call it blocked.
in_progressheartbeat missingThe owner disappeared unexpectedly.Nudge, then reconcile if needed.
blockedanyThe work itself has a real dependency.Track that dependency.
bin/cagents presence start
bin/cagents presence heartbeat
bin/cagents presence pause --reason budget_pause
bin/cagents presence stop --reason normal_shutdown

Algorithmic supervision first

A permanent “reconciler agent” would be expensive and would turn bookkeeping back into an agentic problem. The default supervisor should therefore be deterministic.

Current truth expanded. Historical truth compacted.

A project may accumulate months of failed approaches and sub-agent attempts. Keeping every historical relationship expanded as tiny files would eventually make Git operations and filesystem traversal painful. Cagents therefore separates live operational refs from compactable history.

LIVE
  active / blocked / waiting / recent done
          │
          │ cooling + no strong refs
          ▼
COLD
          │
          │ compact
          ▼
ARCHIVED
  immutable packed segments + Git history

The stable object ID survives the move. Storage location does not define identity.

The hosted product surrounds Git; it does not replace it

What is done—and what is not

Coordination coreRef-backed workflow, goals, project prompt, derived NOW, heartbeat/presence and clean START instructions exist.
Product frontierServer/web control plane, managed repo acceptance, watchdog execution and billing still need production receipts.
Later scale workHistory packing, non-GitHub adapters and mature native clients follow the P0 server/web boundary.

The important part is that the coordination model can now be exercised on the Cagents project itself rather than existing only as a diagram.
