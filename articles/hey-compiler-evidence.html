September 18: aggregate children and short-circuit results keep their Real IR plans

A fallback-forbidden build of the resolver tool exposed a property access inside a nested aggregate: {...state, items: [...state.items, ...chunk]}. HIR had already resolved state.items to a carried property @p… node, and MIR preserved that child inside the boxed record-and-array plan. The shared property-IR decoder nevertheless skipped the node because it did not recognize the preceding ... spread token as a structural boundary.

The repair is in the shared Property IR grammar, not in an LLVM expression arm. Aggregate spread is now a legal boundary before a carried property node. LLVM therefore consumes the declared dot_property runtime identity already selected upstream. The focused property-identity suite passes all nine assertions, including refusal for an unknown identity after a spread. A separate regression preserves the identity in HIR, preserves the boxed aggregate in MIR, consumes the marker in LLVM, links, and matches the interpreter in native execution.

The next fallback-forbidden refusal was a returned short-circuit expression shaped like out_cycle or call @t…. MIR had already supplied the boxed Boolean plan. LLVM's shared scalar adapter rejected that plan only because its temporary-label allocator was in negative-label mode, even though the Boolean evaluator already supports temp-ID-namespaced short-circuit blocks. The repair makes the adapter consume that existing plan and box the Boolean result once. The focused native regression passes; no callee spelling or application name participates in the decision.

After rebuilding the self-host compiler pipeline, tools/hey_resolve_program.hey completes fallback-forbidden LLVM emission. It then fails during linking because the current build/libhey_stdlib.a is stale or partial and does not provide the required Collections and Ranges symbols. That later failure is evidence that the IR frontier moved; it is not an accepted resolver product, complete standard-library archive, application cutover, Linux acceptance, or removal of every fallback.

Evidence scope: focused property identity 9/9; HIR → MIR → LLVM → native aggregate-spread regression; focused native short-circuit return regression; and one fallback-forbidden resolver-tool build through LLVM emission. The complete archive and linked product remain open.

September 18: callable identity and box ownership survive the native MIR boundary

A function value in MIR is now joined by its resolver identity before the native MIR-to-LLVM consumer lowers any function body. A link row supplies the physical symbol for @t<unit>.<function>, and the targeted function header supplies the matching local definition and ABI. Every targeted fnref must join those records. A missing link row, definition, or malformed duplicate makes the consumer refuse.

The readable label in fnref @t… label remains available for reflection and diagnostics, but it does not select code. The native consumer replaces that surface node with a target-only internal carrier, __mir_fnref_<unit>_<function>. Callable construction and the generated internal wrapper then use the symbol from the joined link plan, including wrapper names of the form hey_callable_entry_<link-symbol>. Changing only the label leaves target selection unchanged; changing the target changes the selected wrapper; withdrawing the target's link row refuses.

The same slice closes a separate ownership seam. Native boxed-expression producers now return a structured HeycLlvmBoxOwnership result—unknown, borrowed, or owned—alongside the produced register. Direct and dynamic call lowering consumes that result when deciding which argument carriers to release and which MIR-authorized first argument transfers ownership. It no longer scans the rendered LLVM text at that seam to guess whether a register is fresh.

The focused native ownership fixture covers a structural spread successor, forwarded consume, direct and dynamic calls, borrowed aliases, fresh values, non-consuming callbacks, target-label spoofing, target replacement, and missing-link refusal. The complete structural gate reports C1 through C5 passing: MIR proves the ownership facts, application and library dynamic calls carry the transfer, independent resealing cannot forge or remove those facts, both LLVM consumers obey them, and native answers remain correct.

A fresh self-host receipt publishes distinct HIR and MIR SHA-256 digests, identifies hey-llvm-text as the consumer, and reports selfhost_legacy_fallback_count=0. This is a bounded identity-and-ownership result. It does not yet prove the complete cross-unit callable archive path, the whole standard-library archive, application cutovers, or Linux acceptance.

Evidence scope: test/gate_structural_spread_callable_ownership.sh C1–C5 PASS; test/fixtures/ownership/structural_spread_callable_native.hey; native target/link withdrawal and identity controls; focused ownership-withdrawal and native execution controls; and a fresh zero-fallback self-host receipt. The implementation is a current development candidate and is not described here as a released compiler commit.

September 17: My Queue turns an ABI mismatch into a MIR plan

My Queue exposed a call whose meaning and machine-level representation were both already known, but had not been joined. The resolver identified Friends.notify. HIR said its result was Boolean. The public cross-unit ABI said the call returned an owned box. The old Boolean consumer fell into a name-based fallback and emitted an integer comparison against a pointer. Whether that happened depended on whether the caller appeared before the callee definition.

The repair makes the join explicit. MIR consumes the target identity, semantic result, and physical export ABI. It chooses either an identity operation or a boxed-to-scalar conversion and records when the owned bridge result must be released. LLVM renders that plan. It does not inspect the application name, function spelling, argument list, or definition order. A caller-before-callee fixture is the positive control; removing or contradicting the carried facts makes the operation refuse.

September 17: one build must describe one version of the source

A compiler error can point at the wrong problem when files change between compiler passes. A My Queue build ran for 579 seconds while its source changed. The edits shifted the source positions used to connect calls to their resolved identities. A nested get expression was initially blamed, but its runtime and operation identities, carried as @r and @o, were present. The investigation instead exposed a build that had combined facts from different versions of the source.

The repair starts in ProgramResolution, the pass that chooses what names and calls mean. It now captures each source file's bytes once and publishes a digest—a fingerprint of those bytes—for every source unit. It also publishes an identity for the complete source graph, computed from the ordered unit semantic keys and content digests. HIR, the high-level intermediate representation, checks that the artifact's root locator matches the requested source and verifies the source digests before and after its work. HIR carries the graph digest forward, and MIR, the mid-level representation, preserves it. Malformed artifacts, duplicate graph-identity records, a wrong root, and digests containing nonhexadecimal characters are rejected.

This detects changed inputs without yet making the whole build a frozen snapshot. HIR still reparses live files. A file could change from version A to B during that work and return to A before the final check; both checks would then see A. Closing that gap requires HIR to consume the captured source rather than reopen changing files. The final build receipt also still lacks the ProgramResolution graph identity, so it does not yet provide the complete provenance record.

The native gate passes, and the focused Minispec suite passes all nine assertions. The hey-selfc compiler driver also builds through the ordinary hey-llvm-text path with zero legacy fallback. These are bounded correctness results. They establish neither a performance improvement nor a fully self-built compiler toolchain.

The saved My Queue 5fa3d92 source still needs one verified application correction: server/season_jobs.hey uses Text.trim without a direct stdlib:Text import. The source-identity repair does not make that input valid. An accepted ordinary build and runtime check remain necessary before switching the application away from Stage0.

September 17: facts move through the compiler layers

A comparison such as left == right does not reveal whether its operands are strings, integers, or general values. The source text is deliberately ambiguous at that point. The high-level representation has the semantic evidence, so it now records the operand kinds. The mid-level representation maps those kinds to physical forms and plans temporary lifetimes. The LLVM emitter consumes that plan. It no longer guesses from parentheses or the printed shape of an operand.

This is the same rule for a comparison in a branch, a returned value, or an aggregate child. Arrays and maps keep control of their delimiters and order, while each child keeps its resolved property and call identity. Removing the comparison fact makes emission refuse; keeping it produces the same answers as the interpreter. That withdrawal check matters because a hidden spelling rule would continue to accept the text.

The unchanged MMeow source corrected an earlier diagnosis. Its expression v == true or v == 'required' is valid Hey: equality observes runtime values and returns false when their tags differ. HIR had treated equality with a string literal as proof that v used the String ABI. Removing that textual inference keeps the parameter semantic kind Value and its MIR representation boxed. The compiler, rather than the application, owns that repair.

The next real refusal already carried the needed fact: @cmp:str:boxed. LLVM did not consume it. The comparison operation now accepts the carried pair in either order, evaluates the operands in source order, uses the runtime's tag-aware value-versus-C-string comparison, and releases only a value box minted by the expression. It neither boxes the raw string nor consults an operand, callee, or application name. Removing either carried pair makes emission refuse, and the compiled results agree with the interpreter on equal strings and mismatched Boolean/string tags.

Structured facts on every short-circuit Boolean child remain an architectural obligation. They were not the cause of this exact refusal, and calling them the cause would have sent the repair to the wrong layer. Existing textual recovery for unstructured logical children remains compatibility debt to delete after the HIR/MIR child schema carries the complete tree.

Correctness and speed are separate obligations. The current 129-unit MMeow high-level run took 331.52 seconds and reported a peak memory footprint of about 4.40 GB on Darwin arm64. A source-interpreted replay of its saved 1.4 MB MIR was stopped after ten CPU-bound minutes without a semantic result; the freshly compiled current-source emitter reached the next real refusal in 25.79 seconds. That is a diagnostic contrast, not a benchmark, because the hosts differ. My Queue separately reported 8.25 GB maximum resident memory on an older compiler pin under contention. Perceus ownership can remove repeated copies of uniquely owned values; repeated semantic scans still require indexes, summaries, or better traversal algorithms.

September 17: property identity and receiver meaning meet in HIR

A bare property such as x.to_i can mean two things. If x is a dynamic record with its own to_i key, that key wins. If HIR already proves that x is a scalar value, it cannot contain an own record key, so the declared receiver operation applies. The property ID alone cannot choose between those cases, and LLVM is too late to make the semantic decision.

The property schema now declares both language results. HIR combines the carried property identity with the receiver's semantic kind. A dynamic receiver keeps a Value property node. A proven scalar receiver becomes an ordinary identity-bearing runtime call with the declared result, such as Int for to_i. MIR maps that result to i64; LLVM consumes the call and its declared ABI. The generator checks that the physical ABI agrees with the semantic schema, but the physical ABI does not define HIR meaning.

The focused corpus lives outside compiler code. It proves scalar HIR/MIR facts, native/interpreter parity, dynamic own-key precedence, and refusal when the selected runtime target is withdrawn. Existing property transport and runtime-identity gates also pass. No selector, receiver variable, module, application, or printed LLVM expression is privileged.

Unchanged MMeow crosses the former x.to_i refusal and completes HIR and MIR. Its next failure is a separate large record-return expression in LLVM. That run took 390.40 seconds and reported 3,481,862,144 bytes maximum resident set size. My Queue is now the primary application-driven compiler corpus, with MMeow second; its ordinary fallback-forbidden compile is being measured against the same official frontier.

September 17: a consumer does not choose a value's representation

Hey source has no user-facing type annotations. The compiler still needs semantic facts in HIR and physical representations in MIR. A later arithmetic use can establish that an operation requires numeric operands, but it cannot prove that a dynamic value is specifically an integer. The old HIR fixed point crossed that boundary: it skipped arithmetic assignments, let a numeric-use rule override conflicting assignments, and retroactively changed dynamic locals to integers because a later expression used division or subtraction.

The repair applies one rule to every local. Every assignment contributes its result to the HIR join. A dynamic initializer remains Value. Polymorphic + also remains Value when either operand is tagged, because the runtime may perform numeric addition or text concatenation. MIR maps that semantic value to boxed; LLVM consumes the existing tag-aware arithmetic plan. There is no application, field, function, or provider-name exception, and no new LLVM conversion arm.

The focused test corpus is separate from compiler code. It exercises integer and fractional arithmetic, tagged text concatenation, nested arithmetic, and an invalid tag. Native answers match the interpreter; HIR and MIR carry Value/boxed; changing that MIR representation back to i64 makes emission refuse. This catches the architecture failure as well as the sample answer.

The unchanged MMeow build now crosses its remaining, total_value, and nested Bayesian arithmetic failures. At the final frontier, the 129-unit run took 373.63 seconds and a maximum resident set size of 4,047,388,672 bytes. It then exposed the next valid-source defect: let i = x.to_i, where HIR already knows x is a Float. The property identity survives, but the current own-key protocol lowers it as a dynamic object property and loses the declared integer result before MIR. That next repair belongs in property resolution and HIR, followed by MIR representation; an LLVM spelling rule would repeat the mistake.

September 16: a library is no longer a second resolver

A source call needs one identity. The resolver chooses the function; later stages carry that choice. A static library is simply a collection of compiled functions. It must not get a second vote on what the source meant.

Previously, the LLVM emitter consulted a generated name-and-argument-count table to find a standard-library function. A test exposed the danger: an unknown function ID still compiled when its printed name matched a familiar library member. Commit 8578b643b removes that fallback. Commit 3d46e9167 removes the archive-routing table dependency from the emitter, its helper module, and both generated emitter bundles.

The link-planning pass now joins the resolved identity to a selected provider inventory and carries an explicit bodytarget into MIR. The calling agreement, or ABI, describes how arguments and results cross that boundary. A bootstrap library and a product library have different inventories; neither inventory resolves source names. A separate correction, 86dc53fa3, excludes already-defined functions by their IDs rather than their printed names.

Compiling successfully was not enough. Running the Re regular-expression fixture exposed a second defect: high-level type inference treated an ordering comparison as proof that a character parameter was an integer. The caller consequently converted a letter to zero. Commit 2bd16e143 repairs that high-level evidence rule, without changing Re or adding a special case to LLVM.

The focused native check builds Re, Minispec, Jobs, and Result from their real source units. The application then compiles through the ordinary Hey-to-LLVM path with zero legacy fallback. Eight assertions match the interpreter, including positive and negative regex matches and generic character, integer, and fractional ranges. The executable passes with its environment cleared. Removing the carried Re provider makes compilation refuse. Twenty-two separate type-evidence assertions and the existing concatenation and floating-point regression gates also pass.

This closes a specific authority defect, not the whole compiler. The complete 1,144-export product archive remains unaccepted. A fresh Transformer provider run still refuses at its floating-point call boundary. The ownership and compiler-quadratics decision

The September 12 decision says that ordinary immutable Hey should not need a special “fast spelling.” The compiler should carry ownership facts through its intermediate representations, including when a function is passed to another function.

Reuse needs two facts: the storage has one owner, and nobody can observe the old logical value afterward. With those facts, MIR may authorize reusing the allocation. Without them, correct copying or copy-on-write preserves the program's meaning. Missing optimization proof is not itself a reason to reject a valid program.

A fold repeatedly passes its accumulator into a reducer and receives the next accumulator back. Passing that reducer as a callable must not accidentally lose a proven ownership contract. The proof must follow the resolved function identity, not its printed name. Code generation consumes the proof; it must not invent one.

Ownership can remove unnecessary copies. It cannot fix an algorithm that repeatedly scans everything it has already processed. Those repeated computations need indexes, summaries, or better traversals at the responsible compiler layer. Tests must distinguish the two costs, check aliases and unknown callables, and compare observable results with the safe path.

This is a public explanation of the decision, not the full internal document. See the ownership diagram and compiler-layer explanation. The complete archive, ordinary applications, and Linux acceptance remain separate requirements.

Two independent read-only audits checked the pending high-level typing work, the Web boundary, the build tools, and these guides. No compiler implementation was changed during that review.

September 16 execution: the compiler must get its own answers right

Three bounded repairs are now in the official source branch, but switching applications to this compiler is still unaccepted. The checkpoint is development 759199746, historical 3a2ceacd8, and official 4ed4d3648. These are source and test milestones, not a new production-ready compiler release.

A local source map should not rebuild every imported program

A statement map records where statements in one file came from, including statements continued across lines. The old implementation built the imported syntax trees too, then discarded them when returning the local map. The repair keeps one grammar: it asks the parser to walk local syntax without opening imported providers. Normal full-program parsing still follows imports. It also preserves map entries for statements before an import.

The local-map tests passed 80 assertions and ten checks that full parsing still rejects missing imports. Twelve additional assertions passed in a seed-compiled native test under an empty environment. Removing the map-only behavior makes the controls fail. These results establish the bounded parser contract; they do not establish overall compilation speed.

A compiler that builds successfully can still compile itself incorrectly

The next repair makes the intermediate-code cache distinguish the bytes of the compiler pipeline actually selected. Previously, replacing that executable at the same path could reuse old high-level and mid-level output. The test changes the selected executable, checks that those phases run again, and confirms that moving identical bytes does not change their identity.

The driver coordinates compilation; the pipeline executable performs the compiler passes. Stage0 is the bootstrap compiler. That test passed in the interpreter and with a Stage0-built driver. The driver then built through Hey's ordinary LLVM path with zero legacy fallback, while the pipeline executable remained Stage0-built. But running that produced driver exposed a different bug: every recorded selected-pipeline digest became the string 0. A successful self-build had not proved correct self-built behavior.

High-level and mid-level output still described a String result. The backend's shared integer probe mistakenly accepted a known boxed String call (a String held in the runtime's general value representation), converted it to an integer, and boxed zero. The repair uses the already-known return type carried with the resolved function identity before that conversion. Existing String handling then preserves the value. It adds no hash-function exception, driver-source conversion, new type inference, or ownership rule.
