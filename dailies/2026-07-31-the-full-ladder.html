Three words we are using precisely on this page

Because the difference is the whole story today, and blurring it would be the easiest lie to tell:

  • VERIFIED — the change exists on a branch, its own acceptance evidence has been reproduced, and an independent party has checked it. It is not in the product.
  • LANDED — it is committed on the development branch and has passed the full battery.
  • DEPLOYED — it is on trunk. This is the only one users feel. Nothing below is deployed.

Glossary — every piece of shorthand on this page

We use codenames internally and they leak into these pages. Rather than strip them out, they are defined here and used consistently. New terms since the previous daily are marked NEW.

  • The ladder / R2 → R8 — the staged plan to delete the original C implementation of Hey. Each rung is one deletion or the groundwork for one. It finishes when no rule about what Hey programs mean lives in C.
  • R2 — the live rung: the Hey-written compiler must accept every program the old C one accepts. Measured by a build receipt that names which compiler did the work. NEW today: R2 is now the top priority, because it is also the biggest speed fix — see delegation, below.
  • R6 — the largest deletion: the interactive shell currently contains a second, independent implementation of the language that must agree with the real compiler forever. R6 deletes it.
  • Self-hosting — the compiler is written in the language it compiles. Hey is most of the way there; the ladder is the rest of the way.
  • Delegation / the sidecar — NEW. When a compiled Hey program calls a standard-library function the compiler cannot yet compile natively, it hands the call to a separate child process over a pipe and waits. Measured today: ~7.9 ms once to start that process, then ~61 microseconds per call. Closing R2 removes the need for it entirely.
  • Codenames beginning with w — one per fix, so a change can be discussed before it has a version number. wleakfix = the memory-leak fix. wpushinplace = the fix making array-append stop being quadratic. wboundroute = the fix letting a web handler reach something created at startup. They are labels, not products.
  • Tribunal — NEW. A formal review by several independent reviewers with deliberately different priors, used when a decision is expensive and there are two credible designs. Currently convened over two competing fixes for the same array-copying defect: they cannot be merged, so one wins or they are proven not to overlap.
  • The four-cell matrix — NEW. The experiment that settles that tribunal: run the benchmark with neither fix, each fix alone, and both together, on one machine. The "both" cell is the only one that can reveal a fix that has silently stopped working.
  • Coverage cliff — NEW. The point in a test run past which nothing produced a result, because the run died earlier. Dangerous because it is indistinguishable from everything having passed.
  • Voiceless gate — NEW. An automated check that, when it fails, prints nothing at all. You learn that something broke and not one byte about what.
  • Fail closed — when in doubt, refuse loudly rather than return a plausible wrong answer. The opposite failure — returning something that looks fine — is the one this project spends most of its effort hunting.
  • Falsifier — a switch that turns a fix off. If disabling the fix does not bring the bug back, the fix is not what was doing the work. Every performance claim here is expected to have one.
  • Byte-identical — two compilers producing exactly the same output, byte for byte. This is the bar for every change until the old compiler is deleted; "looks equivalent" does not count.
  • The battery — the full set of automated checks a change must pass before it can land. Currently 294 of them.
  • fannkuch — a standard benchmark that stresses array manipulation. Used here because it exposed the array-copying defect the tribunal is about.
  • VERIFIED / LANDED / DEPLOYED — see the section above. Only deployed means users have it.

The recovery — the largest single result of the day

A sweep of stale working copies left by sessions that died mid-task turned up an uncommitted notes file. In it was the R6 runtime re-entry probe — already run, already answered, days ago:

P1b  gen0/gen1 sequential           PASS
P1c  100 iterations, alternating     0 failures / 100
     iter=0   rss_kb=31472  threads=1  fds=3
     iter=99  rss_kb=35568  threads=1  fds=3
P1d  actor fragment + Jobs fragment  PASS

Threads and open file descriptors are perfectly flat across all 100 cycles — no leak from the Hey runtime. Memory grows ~41 KB per iteration, linearly, and is attributable to the JIT host layer, which this same research document already budgets as a separate concern.

Why this matters more than it looks. That probe is the swing item for R6 — the largest schedule risk on the entire ladder. The estimate carries "one unproven runtime re-entry probe, 5-8 agent-days." The research document still said Unknown. The answer had been sitting on disk, unread, the whole time. That is 5-8 agent-days recovered by reading a file, and it should bring R6's risk rating down.

We have marked it a strong PASS pending one confirmation run rather than certified, because the numbers were recovered rather than re-run, and we are not going to launder someone else's instrument into a certification.

Why it had been lost, and why that is the general lesson

Sessions here get terminated without warning when they exhaust their context. That is a fact of the environment, not a failure to engineer against — you cannot prevent it. What you can do is clean up, and recover what was left behind.

Nobody had been doing the second part. The work was never lost; it was unowned. Every stranded change sat in a working copy that survived the session that made it, and no routine existed to go and get it.

The near-miss worth recording. Earlier the same day we pruned 82 stale working copies to free a full disk. The audit that classified them was deliberately conservative — anything whose landing could not be positively confirmed was kept. That caution is the only reason the entire speed pipeline still exists: four unlanded fixes were among the twenty retained. A cleanup that had trusted the obvious signal — how far ahead each copy was — would have deleted all four. Prune what is provably landed; salvage the rest.

The speed work — where each piece actually stands

Both of these were implemented days ago by sessions that died before landing them. Both were recovered, rebased onto the current tip, and re-verified today.

    32 bytes leaked per arithmetic operation. Dead in both compilers.

     
    shape        BEFORE (m:f)   AFTER (m:f)
sh_ctrl        0:0            0:0      control, unaffected
sh_1op         1:0            1:1
sh_2op         1:0            1:1

    Allocation counts are identical before and after in every shape — the fix adds no allocation, it only adds the frees that were missing. Program outputs are unchanged, so there is no behaviour change.

    Verified independently on Linux and then on macOS, where the measuring instrument was validated against a control with a known exact answer before any Hey number was read, and a second build of the unfixed code was made so the comparison was a real before/after rather than a switch. 90 and 24 golden fixtures byte-identical on both.

  • wpushinplaceVERIFIED · NOT deployed▸ the evidence▾ hide

    Building an array by appending stops being quadratic.

     
                  appends        ratio
FIXED        1000 / 4000        4     linear — 4x the elements, 4x the work
UNFIXED    500500 / 8002000    15     quadratic

1,000,000 elements:
  before   "could not be built"
  after    11 ns per append  ≈  11 ms total

    The witness is a count of appends, not a stopwatch, so a busy machine cannot move it. The unfixed arm reproduces the original author's documented before-numbers to within 3% — which is how the instrument was validated. Both falsifiers invert correctly: disable the fix and the quadratic behaviour returns.

    This is one of the two changes that trigger a promise we made: to say so unmistakably, in plain English, the moment the fast version reaches trunk. It has not. When it does, that notice goes out with the version number and what to run to feel it.

What has to happen before either is DEPLOYED. Both touch the same generated reference files that the pending version bump also regenerated, so the bump is now stale and must be redone on top of them. That means one full battery covering the version bump and both fixes together. Standing between that battery and trunk is a single unexplained failure in the contract gate — two worker-pool specs that a known timing-sensitive family already covers on Linux, but which have never been observed on macOS because the battery never used to get that far.

"Get rid of native C." Two separate deletions. No rung landed today — but R6's risk profile changed materially, and R5's real risk turned out not to be the one written down.

    All 106 corpus examples already route through the Hey-owned emitter with zero fallbacks. R2 is the live rung and everything else waits on it.

    Rename comparison-only labels to explicit stage0, and fail the build if ordinary tooling grows a new call into the native backend. Cheap insurance that the debt only shrinks.

    The test suite must stop running on the thing being deleted. You cannot certify a deletion with gates that run on it.

On one machine it had been silently stopping a third of the way through for two days — roughly a hundred checks neither passing nor failing, simply unobserved. A deletion certified by a battery that can quietly skip a third of itself is not certified. Fixing that is a prerequisite for R5 meaning anything.

Past R8 — where the language takes shape, and this moved a long way today

  • 1 · The module systemsubstantially ruled today▸ what was decided▾ hide

    Zero reserved names. Your data, your functions, your names — always.

    The end state is now stated: there are no built-ins at all. Every function lives in a module, so there is no privileged ambient layer for user code to collide with. The familiar feel returns through one opt-in line:

    import 'stdlib:Sys' exposes *      # the first hour, in Hey
sort(items)                        # reads like it always did

    · Modules compose — a module may extend another rather than duplicate it. That decision is what makes a no-built-ins world tractable rather than one flat dump.

    · Collisions have a rule — the last definition wins and every override after the first warns. Most local wins, the same principle that already says your own name beats an imported one.

    · Warnings become real. Hey has zero compiler warnings today; this builds the first channel.

    · The compiler will suggest the import you forgot — a table lookup, not intelligence, because Hey ships its own standard library and knows every name in it. This is migration infrastructure: when ambient names move into modules, every existing program breaks with exactly that error.

  • 2 · A standard library that is standardnew finding today▸ the gap▾ hide

    Hey has no maths library. Not a small one — none.

    Integer division is the only arithmetic function in the language. No square root, absolute value, floor, ceiling, rounding, powers, logarithms, trigonometry or random numbers — in the runtime or in any module. A larger gap against Ruby than anything on the ergonomics list.

  • 3 · A web framework worth the nameroot cause fixed today (verified, not deployed)▸ the dead variable▾ hide

    One missing capability explained roughly 5,000 lines of workaround across the applications built on Hey.

    A request handler could not reach anything created when the application started. The evidence is a dead variable, and it appears in two independent applications: each creates a pool of background workers at startup, and in both, that variable is never mentioned again anywhere in the codebase. It sits idle because there was no way to hand it to a handler.

    The consequences were paid per request: one application opens a database connection and issues a table-creation statement on every request; another builds a fresh four-thread pool inside the request and destroys it before returning. For a language chasing 100,000 requests per second on one core.

    Fixed today by an application-team contributor — dispatch now carries the handler's captured environment instead of reducing it to a name. One setup per route at startup, not per request. It works in the interpreter; the compiled path still refuses, and will now refuse by name rather than crashing, with a deliberate tripwire test that turns red the day compiled support lands.

  • 4 · Multi-core webthe honest broken row▸ the numbers▾ hide

    More workers currently makes it slower.

     
    workers=1   5,977 req/s
workers=8   1,589 req/s     # measured in an application, not a benchmark

    And both applications ship a default of 4. Post-R8 this is the largest performance frontier. A separate measured finding from the same survey: every stdlib call from compiled code costs ~7 ms in delegation, which is why both applications hand-wrote their own response builders instead of using the framework.

Three numbers we published and retracted

"683,282 files, 255×" for a wasteful search — measured with a tool that counted directories the real code skips. Honest figures: 284,760 and 106×, overstated by 2.4×.

"Hey is missing Ruby-style number conversions." Both exist and work. We checked one namespace and concluded about the whole language.

"A four-minute compile for a simple script." Reported from a real observation, but we could not reproduce it: cold, with every cache empty, the same script takes 4.7 seconds. Something else consumed those minutes and we have not proven what. Recording it as unexplained rather than quietly dropping it.

The corrections matter more than the findings they qualify. A team that measures everything has to be equally quick to un-measure — and today a fourth self-correction came from a contributor who caught their own mistake three times in one session and wrote down the pattern instead of apologising: "I measured a tree that was not the tree I had changed." That is the most useful sentence anyone produced today.
