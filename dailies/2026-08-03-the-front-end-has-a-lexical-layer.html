The honest headline

At the beginning of this work, Hey still had several independent answers to “what does this source mean?” Source text was re-read downstream. Operators, expression boundaries and names were interpreted in more than one place. The architecture calls for one route: source becomes tokens, tokens become a structural tree, names in that tree resolve to bindings, and only then do HIR, MIR and LLVM act.

Today the first half of that route is executable. HeySource.hey and HeyTokens.hey form a bounded lexical layer. Generated compiler nodes are also no longer an inert C experiment: the active Hey parser constructs them through generated APIs, passes them through the existing HeyValue ABI, and converts them to ordinary maps only at explicit compatibility boundaries.

What is newly real: source spans and line indexes; generated longest-match operator spellings; strings, heredocs and interpolation with exact relocated spans; bounded source/token traversal; exact generated node storage; immutable Hey-facing node values; compiled native-C and LLVM-direct linkage; and a zero construction meter in HeyParser.hey.
What is still missing: generated access for every node read and child traversal; the one-time private n_ physical-slot cutover; direct borrowed reads; a candidate syntax-tree parser; name resolution and module graph ownership; structural HIR/MIR; a shared HIR interpreter; full shadow execution; and deletion of the old paths.

The architectural line is now sharp. Tokenizer ownership includes string, heredoc and interpolation boundaries. Parser ownership includes precedence, associativity and unary-versus-binary interpretation. Resolver ownership includes scopes, imports and binding identity. A minus sign therefore remains one MINUS token; no lexical look-behind guesses its arity.

The exact-node bridge that made step 5 honest

The missing design problem was not “how do we spell generated constructor names?” The active parser is Hey code and the generated exact storage is C. A wrapper that merely returned another ordinary map would have made the source look migrated while preserving the old mutation, lookup and allocation behavior.

The bridge instead carries a private exact node through the existing HeyValue ABI. The node has one final allocation, indexed slots, generated kind/field metadata and explicit retain/release behavior. Existing property reads remain temporarily compatible so the migration can proceed in ordered steps, but generic mutation and generic JSON serialization fail closed. Generated APIs own construction, immutable field replacement, validation and recursive conversion.

One compatibility boundary is deliberate.

Parser caches and stdlib-sidecar transport still need JSON/map-shaped data. They now call the generated recursive legacy adapter before serialization and reconstruct exact nodes at the parser boundary. That is not permission to serialize exact nodes everywhere; it is the one visible bridge required while the old and new front ends coexist.

Why “map-shaped” caused authority drift

The Review described compiler nodes as map-shaped because Hey code should continue to see named fields and immutable value behavior. Later runway steps require exact-sized construction, a one-time n_ physical-key cutover and direct borrowed reads. Those statements can coexist only if “map-shaped” describes the logical interface, not an ordinary mutable hash/map as the physical representation.

The earlier handoff dropped the Review from its authority list and treated that ambiguity as if the Review had become obsolete. That was wrong. The Full Ladder still names Decisions, Architecture, Plan and Review as the four-document set. The Review remains authoritative for evidence and rationale; Decisions, Architecture and Plan control normative behavior when a later ruling sharpens the implementation.

ChoiceAdvantagesCosts
Ordinary map as node storagereuses current property reads, JSON, interpreter paths and cache formats; easiest bootstrapgeneric mutation, string-key lookup, accidental fields, repeated clone/write, no exact slots, no honest borrowed reads
Private exact node behind a map-shaped interfaceone allocation, fixed indexed slots, invalid shapes become unrepresentable, generated traversal and a direct-read pathrequires an ownership bridge, interpreter/native/LLVM linkage, explicit transport conversion and distribution packaging

We did not reverse the architecture. We clarified an overloaded phrase and supplied the bridge that the later steps always implied. The costly mistake would have been to preserve ordinary maps merely because the first review used convenient interface language.

The lexical contracts already protected

Interpolated strings 
"outer #{get({name: "Ada"}, "name")}"

The candidate emits STRING_START, text, INTERPOLATION_START, ordinary nested expression tokens, INTERPOLATION_END and STRING_END. Nested expression spans remain in the original file/line/column coordinate system.

Heredocs

Cooked, raw, dedented, interpolated, malformed and unterminated forms have executable contracts. Two 20,000-character cases prove that source-length behavior does not consume proportional call stack.

Generated operator token spellings

The tokenizer no longer owns a handwritten duplicate symbol list. A checked-in registry generates the longest-match token projection. Parser, resolver, HIR, MIR and LLVM semantic columns remain pending where no decision has yet been encoded.

The next three steps

  1. Runway step 6 — reads and traversals. Census every compiler-node property read and child walk, generate or complete the named accessors, migrate all call sites, then lock a zero meter.
  2. Runway step 7 — one physical cutover. Rename private physical slots to the final n_ representation only after every caller goes through generated accessors. Never support two physical key schemes in parallel.
  3. Runway step 8 — direct borrowed access. Replace compatibility property lookup with generated indexed borrowed reads, validate lifetime rules, and remeasure construction/read/traversal cost.

Only then should HeySyntaxTree.hey consume candidate tokens and construct the final structural expression/statement tree. The parser must use explicit stacks for statement/block lists from its first implementation; the old parser’s scaling evidence already shows why recursion cannot be deferred as cleanup.
