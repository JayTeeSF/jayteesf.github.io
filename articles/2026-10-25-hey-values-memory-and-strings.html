Hey values, memory and Strings

In Hey a value never changes. "Updating" a map gives you a new map, and the old one is still there. That sounds like a copy every time. Usually it isn't, and this page shows why, what it costs when it is, and what's decided to make it cheaper.

Words used here.
Reference count
A number stored with each value: how many places hold it. When it drops to zero, the memory is freed.
Copy-on-write (COW)
Share a value until someone wants a changed version; copy only then, and only if someone else still holds the original.
MIR
The compiler's middle representation, where every intermediate value has a name. It's where Hey decides ownership. (The compiler article explains every stage.)
Last use
The final place in a function where a named value is read. After it, the value is dead.

1. Immutable values, and the cost puzzle Works today

Every Hey value (number, String, array, map, record) is immutable. put, push, merge and the spread {...doc, visits: 1} all return a new value:

  says next

That's the safe part: no function can change a value you passed it, and an actor can be handed a value (copied or moved) without locks, because nothing can change it. Now the puzzle. This is how everyone counts things in Hey:

set counts = counts.put(word, counts[word] + 1)

If put copied the map each time, counting a million words over a thousand-key map would copy about a billion entries. Does it?

count.hey: count a million words over a 1,000-word vocabulary

import 'stdlib:Cli'
import 'stdlib:Text'
import 'stdlib:Time'

fn count_words(n)
  let counts = {}
  let i = 0
  while i < n
    let word = 'w' + (i % 1000)
    if counts.has?(word)
      set counts = counts.put(word, counts[word] + 1)
    else
      set counts = counts.put(word, 1)
    end
    set i = i + 1
  end
  return counts
end

program
  let n = Text.parse_int(Cli.args()[0])
  let started = Time.now_ns()
  let counts = count_words(n)
  says counts['w7']
  says Time.ns_to_ms(Time.elapsed_ns(started))
end

2. Reference counts and copy-on-write Works today

Every map, array, record and String carries a reference count. Sharing a value is a count increment, never a copy. Copy-on-write has been on by default since 0.99.541a;2 it removed the clone-per-put on values with one owner.

The runtime has one uniqueness test, hey_rc_count_is_unique: is the count exactly 1? Every in-place decision passes through it, which is what makes the falsification switches in Performance possible: sabotage that one test and the ownership specs must fail. HEY_RC_COW=0 turns copy-on-write off (every update copies), for comparisons.

3. Perceus: release at last use, update in place

A count of 1 only helps if the old name lets go before the update. In set counts = counts.put(...), the old counts is never read again, so the compiler can hand the map straight to put instead of holding a second reference. That idea, from the Perceus paper (Reinking, Xie, de Moura and Leijen, PLDI 2021, used in Koka and Lean 4), has four parts:

Release at last use. A value is released right after its last use, not at the end of the scope.
Consume a dead value. A call that receives a value nobody uses afterwards takes it over (a move): no extra reference, so a unique map stays unique.
Borrow what you only read. A parameter the function only reads costs no count change on either side.
Reuse. A cell being freed can become the memory for a new value of the same size in the same function.

Where it lives: in MIR, and only there. MIR decides; the LLVM emitter obeys MIR's plan and never guesses; nothing imported may claim ownership. The mechanism is in the compiler article. Partly works

Today MIR writes these plans for the shapes it can recognize, which covers the counting loop above, a put inside an if, a helper that takes the map over, and maps of maps. The general version, ownership as typed MIR facts with a verifier on every module,3 is phase 9 of the consolidation release (forecast confidence low-medium; Roadmap). One measure of what's left: with copy-on-write switched off, the W9 benchmark takes 713 times longer, because MIR's static proof doesn't yet cover it and the runtime's refs-is-1 test is doing the work. Closing that gap is consolidation phase 14.

4. Strings today: SDS Works today

Hey has one String form. Since 0.99.604a/605a it's an SDS block ("simple dynamic string", the layout Redis made famous): one allocation holding a small header, then the bytes, then a NUL byte.

  • Almost always one allocation per String, header and bytes together. The exception is a buffer adopted from C, whose bytes stay in their own allocation.
  • Boxing and unboxing is a count change. Moving a String in or out of a generic value doesn't copy it.
  • Literals are immortal: their count starts so high it never reaches zero, so they're never freed or copied.
  • The NUL byte is only for C. Hey Strings can hold any byte, including zero; the NUL check happens only where a value crosses a declared C boundary.
  • Appending to a String you alone hold grows it in place (spare capacity, amortized like a vector), so set out = out + piece in a loop is linear. Works today

append.hey: build a long String with +

import 'stdlib:Cli'
import 'stdlib:Text'
import 'stdlib:Time'

fn build(n)
  let out = ''
  let i = 0
  while i < n
    set out = out + 'line ' + i + "\n"
    set i = i + 1
  end
  return out
end

program

  let started = Time.now_ns()

  says Time.ns_to_ms(Time.elapsed_ns(started))

Bytes Works today

Bytes is immutable binary data in a block of the same shape. slice on Bytes is a view: it shares the parent's block (one count increment) instead of copying. There's no mutable buffer: build output by joining immutable pieces.

bytes.hey

import 'stdlib:Bytes'

program
  let data = Bytes.from_text('station;12.5', 'utf-8')
  let name = Bytes.slice(data, 0, 7)
  says len(data)
  says Bytes.decode(name, 'utf-8')
  says Bytes.find_byte(data, 59, 0)
end

Run

$ hey bytes.hey

Output

12
station
7

12 bytes; the first 7 decode to station; byte 59 (;) is at index 7.

5. How a String is stored: the 16-byte value Decided, coming

Ruled by the Maintainer: Hey keeps one String form, and in Phase S that form becomes a 16-byte value (two machine registers) in the "German string" layout, layered on top of the SDS blocks of section 4 rather than replacing them. The layout's contract is now frozen. The 0.99.606a toolchain still uses the SDS pointer of section 4 for every String; nothing in this section runs in compiled code yet.

The rules, in plain English

  • Always 16 bytes, 8-byte aligned, passed in two registers. The first 4 bytes are the length, a 32-bit number, so one String holds at most 4 GiB; asking for a longer one fails fast. Large binary data belongs in Bytes.
  • The length is the only authority. A String can hold any byte, including zero. Nothing ever searches for a terminating NUL to find the end.
  • Short if and only if 12 bytes or fewer. Bytes 4–15 hold the string itself, and the unused bytes are always zero. It doesn't matter how the String was made (a literal, a slice, a concatenation): a 12-byte result is always short and a 13-byte result is always long. That makes two equal Strings look identical byte for byte.
  • Long Strings keep a 4-byte prefix. Bytes 4–7 copy the first 4 bytes of the text, and bytes 8–15 hold the address of the rest, in an SDS block, with a 2-bit class in bits 54–55. The top byte of the address is left exactly as the system gave it, so the layout is safe with Android and Arm memory tagging and with top-byte-ignore.
  • Four classes. Owned: a reference-counted SDS block, its count changed atomically. Static: a literal that is never freed, so counting it costs nothing. Borrowed: a view into another String's bytes that owns nothing. The compiler must prove a borrowed view never outlives its parent; before it is stored in a collection or field, returned, or sent in a message, it is copied into an owned String. Concat: reserved for a possible rope form; nothing makes one.
  • The bytes never change. Appending is done in place only when the String is owned, has exactly one holder, and its block has room; otherwise append makes a copy. So a String one thread is reading can never change under it.
  • Comparing. Equality compares the first 8 bytes (length and prefix), then the next 8, and only then the rest of the bytes. Ordering is plain byte order, as C's memcmp gives it.
  • Crossing into C. C wants a NUL-terminated string. An owned or static String already has one at the end of its block; a short String under 12 bytes has zero padding to spare. A 12-byte short String (no spare byte) and a borrowed view get a NUL-terminated scratch copy.

Why it's fast

Most comparisons stop early. Two Strings of different length, or with a different first 4 bytes, differ in the first 8 bytes, so one 8-byte compare answers without following any address. Sorting gets the same shortcut from the prefix.
Short Strings never allocate. Names, keys, codes, small numbers turned to text: most Strings a program makes are 12 bytes or fewer, and they live entirely in the two registers. No allocation, no count, nothing to free.
Sharing needs no locks. The bytes never change, so any number of threads and actors can read one String at once. Sharing an owned String is one atomic count change; a short one is just copied.
Slices don't copy. A borrowed view can point into the middle of a parent String, so slice, split and trim can hand back views, and only the views that escape are copied.

This design isn't new. It comes from the Umbra database at TU Munich and its successor CedarDB,9 and DuckDB, Meta's Velox and Apache Arrow's StringView use the same 16-byte layout.10

6. Maps and arrays

A map put takes over a dead, unique map Partly works

Map.put is declared in stdlib/Map.hey as consuming its receiver (receiver_effect=consume). When MIR proves the map is dead after the call, it moves the map in, and if the count is 1 the runtime writes in place. That works today for the shapes MIR recognizes (section 3). For every program shape, it needs the general MIR uniqueness and last-use facts: consolidation phase 14.

The map hash index redesign Proposed

A runtime branch that stored each index slot's probe position (so growing never re-hashes) is held: measured against ordinary programs it lost in places (102% more instructions on one shape) and its use of the top 32 bits of the FNV hash clustered keys into the same buckets. It will be redesigned and fed into the map work of phase 14; Phase S's S5 then replaces the table with SwissTable-style probing. Schedule: Roadmap.

Arrays and get must never copy Partly works

An open task tracks the measured places where array spreads, appends and reads still copy or leak, which make some array loops quadratic (task arrays-and-get-must-never-copy). Appending to an array you alone hold is in place today.

7. Regions and flat records

Reference counting frees values one at a time. A program that builds a tree, reads it and throws it away pays one allocation, one count update per share and one free per node. Two old, well-studied ideas remove that cost without changing what the program means.

The four facts and one solver Partly works

Which values go in a region, and which get reused, is decided from four facts, all computed in MIR:

  1. F1 fresh result: everything a function returns is newly built by that call.
  2. F2 escape: a value can be reached after its scope ends (returned, stored, sent, captured).
  3. F3 region scope: the smallest scope (one statement, one loop iteration, one call) that holds every use of a fresh value that doesn't escape. Never a whole loop, so a loop can't pile up garbage.
  4. F4 unique and dead: the value has one owner and isn't read after this operation, so it can be reused in place.

One worklist solver computes F2 and F4 over the same control flow. The rule above all of them: no special cases. No fact mentions a function name, a field name, a file or a benchmark. A first planner that classified calls by their names was reverted, and the 603a version whose rule only fit the binary-trees benchmark was deleted (Performance tells both stories). Today the runtime half is built and tested (test/gate_regions_runtime.sh)6; the MIR facts and their lowering aren't.

Flat records, then regions Decided, coming

The direction is both, in order: first a compact record header and then shaped records that store fields flat (task record-representation-compact-and-shaped), then regions for whole lifetimes. They solve different costs: flat records make each record cheaper; regions make freeing many records cheap.

Actor and turn regions Proposed

The same machinery applied to actors: an actor's memory, or the temporaries of one message-handling turn, freed in one step when the actor stops or the turn ends (task actor-and-turn-regions). The runtime has regions and a failure path that pops them, so a failed turn closes its region too; the ownership proofs that would open one per turn aren't built. Actors: Actors and failure.

8. The small-block allocator Works today

Record headers, array headers and short String blocks are 32 bytes to 1 KiB, and ordinary programs make and free them at a furious rate. In the 606a candidate they come from Hey's own pages instead of malloc,7 after mimalloc's free-list sharding (Leijen, Zorn and de Moura, 2019).

Three allocator changes finished it: medium blocks up to 1 KiB, the String lifecycle inlined (a 320-byte String's allocate-and-release went from 750 to 298 instructions; 604a was 692), remote frees settled before a thread abandons a page, and pages that dead threads leave empty retired.8 It runs under AddressSanitizer too, with every free block poisoned, so the sanitizer tests the allocator that ships. Its follow-on branch waits for the performance release.

Size-specialized allocation Partly works

An open task (post-closure-size-specialized-allocation) goes further: allocate each value from the exact size class known at compile time, skipping the size lookup. The size classes above are its foundation.

9. Watching memory yourself Works today

Three builtins: reset_allocations() zeroes the counters, allocations() returns them as a map, and memory_rss_bytes() gives the process's resident memory.

watch.hey: count in place, then count while keeping the old map

fn count_alone(n)
  let counts = {}
  let i = 0
  while i < n
    let word = 'w' + (i % 100)
    if counts.has?(word)
      set counts = counts.put(word, counts[word] + 1)
    else
      set counts = counts.put(word, 1)
    end
    set i = i + 1
  end
  return counts
end

fn count_keeping_old(n)
  let counts = {}
  let sizes = 0
  let i = 0
  while i < n
    let word = 'w' + (i % 100)
    let before = counts
    if counts.has?(word)
      set counts = counts.put(word, counts[word] + 1)
    else
      set counts = counts.put(word, 1)
    end
    set sizes = sizes + len(before)
    set i = i + 1
  end
  return counts
end

fn report(label)
  let stats = allocations()
  says label + ': in place ' + stats.json_write_inplace + ', copied ' + stats.json_write_cow_copy
end

program
  let ignored = reset_allocations()
  let a = count_alone(1000)
  let first = report('alone')
  let reset = reset_allocations()
  let b = count_keeping_old(1000)
  let second = report('keeping the old map')
  says memory_rss_bytes() > 0
end
