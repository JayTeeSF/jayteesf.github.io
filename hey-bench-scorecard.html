Method. Every variant of a cell first runs once and its output must match the oracle (the C reference's stdout or result file for shootout/1BRC, the declared literal or field contract otherwise, the exact HTTP body for web); a variant that does not match gets no time. Then n=5 interleaved repetitions run in rotated variant order, each one /usr/bin/time -v run (wall, max RSS) and one perf stat -e instructions:u run, with the output re-checked every time. Cells report the median. Web: per repetition a fresh server, body check, 2 s oha -c64 warm-up, then a measured oha run (8 s; websweep 5 s). Timed cells wait for a 1-min load of at most 1.5, at least 8 GiB free memory and no build units, and cells whose runs started on a busy host are re-timed once.

Measurement caveats & language notes (490 current-variant records)
  • Hey ÷ C is median Hey 608a ÷ median C. For wall time, above 1 means Hey is slower. For web it is req/s ÷ req/s, so below 1 means Hey is slower.
  • Wall time is for the whole process, so interpreter or VM start-up is included (Ruby, Python, Erlang erl).
  • Rust uses the repo's maintained rustc -O (opt-level 2). Go uses plain go build. Ruby runs with --yjit. Erlang runs BEAM via erl -noshell.
  • n/a means the repo has no implementation of that workload in that language. No implementation was written for this scorecard.
  • Actors: Rust is the Tokio reference (bounded channels: 1024 for fan-in, 16 for ring/pairs), Go is goroutines with buffered channels, and Erlang uses unbounded mailboxes (+S 8:8). Hey runs 8 workers. Timing windows differ per benchmarks/actor-reference/README.md, and the oracle checks counts only. Pony was not built because ponyc is not installed.
  • Web: C, Rust and Erlang are hand-rolled HTTP servers, Go uses net/http, Ruby uses Puma (4 workers, 4 threads, YJIT) and Hey uses Web.serve. All run 4 workers on port 3108, with oha on the same host.
  • Actor and web cells raise 1-minute load themselves (multi-threaded runtimes plus oha on the same host), with busy_units empty on every run.
  • Hey binaries were built in a clean environment from libexec/htgz-env.sh with HEY_PIPELINE_BIN set to the fixpoint-verified product, HEY_RELEASE_RUNTIME=1, and HEY_LLVM_CC=/usr/bin/clang.
  • Strings is C code linked against the Hey runtime (C is n/a), so heystr, sds and sds_inline compare string representations rather than languages.
