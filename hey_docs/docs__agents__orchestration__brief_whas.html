BRIEF whas — `has`/`has?` dispatches on the RUNTIME VALUE of its key (P1 final slice)

ORCHESTRATOR'S STANDING ADDITIONS (red-team pass, 2026-07-29 — these

override anything below on conflict):

  • READ FIRST: docs/agents/orchestration/agent_standing_rules.md (all

rules, incl. 16-22 sidecar security + 24 stderr-capture) and

docs/agents/lessons.md.

  • Worktree pattern: you work ONLY in .worktrees/whas (created for you,

off the v0.99.471a landing commit), with bin/claude01-env-whas.sh

(own build dir + cache home). FIRST ACTION: pwd + git rev-parse

--show-toplevel; abort if either is not the whas worktree.

  • ONE WRITER: never touch ~/dev/claude_01 main tree, never touch

docs/agents/** (orchestrator-owned), never kill processes by name.

  • INVERSION SURVEY IS DELIVERABLE #1, BEFORE ANY EDIT: the compiled

lane is currently PERMISSIVE where the oracle refuses (boxed int

key on a map receiver — it silently answers over a rendered key).

Sweep examples/ + specs/ + stdlib/ for any program leaning on that

accident and REPORT THE COUNT before you change dispatch. If any

hit is found, STOP and report — that goes to the maintainer, not

into a compat shim.

  • Your commit subject must start with "perf+fix:" or "fix:" and name

whas. Never a docs-prefixed subject over runtime/stdlib code (two

seats flagged this landing-hygiene defect this week).

  • Spec/gate numbers: use the literal placeholders <NEXT-SPEC> /

<NEXT-GATE> everywhere including filenames-in-comments; the

orchestrator derives real numbers at transplant.

  • Diagnostic parity is byte parity: fail-closed exits reuse the

interpreter's exact message strings.

  • Report format: verdict-first, measurements with commands, every

claim with file:line or a receipt. Commit in the worktree; do NOT

push; the orchestrator transplants and regates.

GOAL

Convert the last family member carrying the type-guessing disease:

`has(coll, k)` / `has?(coll, k)` must dispatch on the RECEIVER'S KIND

and the KEY'S RUNTIME TYPE — by calling one shared runtime helper that

delegates to the interpreter's own `hey_json_has` semantics — instead

of guessing the key's type from its source spelling and rendering it

to a string. After this slice, `fn look(coll, k) return has(coll, k)

end` compiles and agrees with the oracle (`./bin/heyc --run`; note

`./bin/hey` is NOT the oracle), in both emitters. This completes P1's

builtin-family conversions.

NON-GOALS (scope fence)

  • Do NOT touch `hey_llvm_dyn_key_cstr_value` (stdlib/HeyLlvm.hey:4868-4893) — shared; DIVERT boxed keys before it, exactly as the put arm did.
  • Do NOT widen `heyc_llvm_is_i64_index_expr` / `hey_llvm_i64_index_expr?` — shared with the S3 licensed in-place store, pinned across lanes. Claim arithmetic-key shapes with an additive tail, not a predicate change.
  • Do NOT convert `Docs.has` / `Docs.has?` (runtime/heyc.c:12398, :15674) — different family.
  • Do NOT touch `Collections.includes` / `includes?` / `contains?` / `Collections.empty?` or any sibling membership spelling (value membership, not key membership).
  • Do NOT change `heyc_llvm_is_string_expr` itself (198 call sites; it loses AUTHORITY at this boundary, not existence).
  • Do NOT change the C-transpile lane (heyc.c:2411, :2688) — already falls back to `hey_json_has`; verify, don't edit.
  • Do NOT change the interpreter (`hey_repl.c:3240-3242`) — it is the oracle. If you refactor `hey_json_has` over a borrowed sibling, its observable behavior (answers AND diagnostic strings AND order) must be bit-identical.
  • `a[i]`-sugar write divergence (wsetidx) is a separate queued slice. Leave it.

THE DESIGN (the 470a pattern)

One shared runtime helper, `hey_llvm_json_has_value_i64`, is the ONLY

new semantics carrier, and it decides NOTHING itself: it delegates to

`hey_json_has`'s dispatch (via the borrowed sibling), which IS the

interpreter's builtin. Receiver JSON + key STRING → membership;

receiver ARRAY + key INT → bounds; every other pairing raises the

interpreter's own diagnostic and exits 70 — FAIL-CLOSED, no default

arm. Both emitters call the same symbol; neither re-implements

dispatch. In native, the runtime-key arms go AHEAD of `is_string_expr`

because that predicate answers 1 for every boxed candidate (spec 1274)

— ordering is load-bearing. Static routes (string literal, int

literal, str/pstr locals, `.has?("lit")` at HeyLlvm.hey:7021 and

:12143) stay byte-identical so every golden moves by exactly the new

declare line and nothing else. Expect BOTH golden sets to regenerate.

Deliberate asymmetry vs put: `has` is a READ — the shim follows the

BORROWED READ PRIMITIVES convention (hey_runtime.c:20344-20347), not

put_value's clone-all-three ownership; nothing is consumed, nothing

moves. If you instead clone-and-call `hey_json_has`, measure the

diagnostic parity and say so.

ACCEPTANCE

1. Flip cases (oracle rc/output matched exactly, both emitters):

  • `fn look(coll,k) return has(coll,k) end`; `look([10,20,30], 1)` → true; `look([10,20,30], 7)` → false; today run rc=70. Also the `has?` spelling and the method spelling `coll.has?(k)`.
  • `look({a: 1}, 'a')` → true through the NEW route — assert the emitted IR reaches `has_value_i64`, not `value_to_raw_string_cstr`.
  • `has(m, k)` with boxed INT k on a map: oracle exits 70 "has object key must be a string"; compiled must now match the refusal (inversion survey is deliverable #1, see standing additions).
  • `has(a, i % 32)` / `has?(a, i + 1)`: today "cannot lower"; must lower and agree with the oracle.

2. Both-lane byte-identity for every already-working shape: identical IR on the fixture set AND the corpus survey stays N/N IDENTICAL, 0 REFUSED (106/106 at 471a) — run serially in the worktree, never against a building tree.

3. Goldens: every LLVM golden moves by EXACTLY the one new declare line, zero non-declare code lines; hir/mir pins move only by hash lines. Any golden moving a code line = a static route lost bytes — stop and explain.

4. Falsification gate, spec 1297's shape: env hook `HEY_FALSIFY_HAS_DISPATCH=1`, read through getenv at every call, compiled UNCONDITIONALLY, living in the NATIVE emitter (mirror subset has no env access; byte-identity carries the result). Flag on forces the old render-to-cstr route for boxed keys; gate asserts flag-off matches the oracle, flag-on reproduces rc=70 on the array reproducer, and off-IR != on-IR. GREEN and RED arms both named; RED arm must DISCRIMINATE at the base compiler (g16's 13/13 shape in test/regression_put_runtime_key_dispatch.sh).

5. Controls: S3 licensed accumulator golden untouched; specs 1266 and 1297 stay green and falsifiable; existing g16 stays green; full worktree chain (build, cold-cache rule 15, both golden sets regenerated AND re-checked, manifest, new specs, new gate, spec 980), all rc=0.

6. Specs: three new — <NEXT-SPEC> (runtime-value dispatch, 1292's shape incl. oracle-vs-compiled transcript in comments), <NEXT-SPEC>+1 (arith-key lowering, 1293's shape), <NEXT-SPEC>+2 (static routes untouched + falsification, 1294/1297's shape). Gate <NEXT-GATE> registered in test/run_release_verify.sh. PLACEHOLDERS — orchestrator derives at transplant.

RISKS TO PROBE (report on each, even if clean)

  • Sibling spellings: free `has` vs free `has?` vs `.has?` vs `.has` (heyc_method_sugar_allowed heyc.c:3094-3099; canonicalization `has?`→`has` at heyc.c:3432 and hey_repl.c:1362). Every spelling must reach the same dispatch; mirror lacks a free `has(` arm — probe whether any corpus/spec program hits it in the shipping lane.
  • `contains?`/`includes?` must not move (different contract).
  • The shadow-list minefield: confirm `h.has?` method-sugar still wins over a user map key named `has?` exactly as before, both lanes.
  • Ranges: `hey_json_get_borrowed` has a range fast-arm (:10385); `hey_json_has` has NONE. The new helper reproduces `hey_json_has` exactly, NOT get's ladder.
  • Bool facade: has_value_i64 returns i64 0/1; check `saybool`/branch consumers and `is_bool_expr` (heyc.c:12404) still classify the new arm's spellings so results print true/false, not 1/0.
  • `hey_json_has_key_borrowed` refactor blast radius: still serves the surviving static string-literal route; behavior on the JSON receiver must not change by a byte.
