What landed today

Compiler symbol lookup stopped dominating the build

The compiler rebuilt canonical symbol names one character at a time and repeatedly rescanned the whole function table. On this host, the lookup path occupied 93.5% of sampled time. Direct byte append plus a content-keyed canonical-name cache made two large units 10.3× and 11.9× faster; a pipeline case completed in 20.9 seconds after the baseline was killed at 150 seconds. A 915-unit sweep produced 812 LLVM files with byte-identical output and no diagnostic differences.

Equality and JSON serialization became typed again

false == 'false' had answered true because the LLVM path compared renderings. The typed path was present but hidden behind a display classifier that claimed booleans and boxed values. The repair reaches the existing non-consuming, tag-aware equality routine: booleans, strings, integers and nil remain distinct, and to_json(false) now emits false, not "false".

The borrowed-string crash was an ABI defect, not a string defect

The Hey-owned callable trampoline omitted its string parameter arm, passing an integer where LLVM declared a pointer. Clang accepted the mismatch; the correct string comparison later dereferenced garbage. A shared parameter-kind inventory plus structural, emitted-IR and behavioral checks now covers all four supported kinds, including a private self-host build with fallback count zero.

Borrow lifetimes are behaviorally covered in the Hey-owned emitter

Global escape rejection, stale-handle rejection, loop-slot release and slot-exhaustion control now execute through the Hey-owned LLVM emitter at fallback zero. Say covered self-host lifetime parity, not full parity: one spelling remains outside the emitter slice, direct heyc build is not independently driven, and no corpus program takes both guard lanes.

The run cache now knows which compiler built a program

hey script.hey could serve a binary built by yesterday's emitter because its cache stamp omitted the generated LLVM emitter, the pipeline bundle and build/heyc. Cache identity now follows the generated pipeline's independently derived 17-file transitive import closure plus the actual compiler binaries and drivers. A new imported dependency widens the closure and fails the gate until covered.

Two common immutable operations lost avoidable heap work

A uniquely owned collection can now be taken while its incoming value remains borrowed, including a dynamic key. The local mechanism gate moves array appends per indexed update from 8/64/512 to 0/0/0. Separately, sum = sum + a[i] now uses an unboxed integer element read and integer add instead of three allocations, three releases and a polymorphic dispatch. Both native and Hey-owned emitters are pinned byte-identical.

External performance receipt, clearly separated: the Linux seat measured a one-million-row, 4,096-slot aggregation moving from 58,939 ms to 22 ms after the collection-take repair, and a separate read-only integer loop 1.59× faster after unboxing. Those durations were not reproduced on this Darwin snapshot. What was reproduced here is the emitted mechanism and its falsification controls.

Corrections that changed the plan

  1. “85 unsupported constructs” is retracted. It had no recoverable corpus or list. The measured inventory is 1,549 sources: 621 lower, 719 are refused, and 209 stop before the emitter. The 719 refusals reduce to 136 normalized keys in nine structural families plus one visible unclassified singleton.
  2. The frontend scaling target was falsely green because the sweep stopped too early. Ratios were 2.015, 2.055 and 2.179, then crossed the 2.20 target at 2.288 on the next doubling. The five-size sweep costs about 1.54 seconds here; shortening it was not justified. The underlying copied bytes remain superlinear because immutable strings still deep-copy.
  3. The supposed Darwin/Linux collection-update disagreement was a route error. The Darwin probe used modulo in its index; % is not supported by the Hey-owned emitter slice and silently selected the legacy consumer, which lacks the unique-update pre-pass. With a supported index, Darwin reproduces zero appends per update.
  4. “Native 12 / mirror 0 loop releases” was a probe artifact. A structural gate searched the Hey source for native C symbol names that never existed there. Behavioral fixtures at fallback zero are now authoritative; structural counts remain supporting evidence only.
  5. Pre-repair authoritative-HIR digests remain invalidated. Matching hashes were taken over content that partly represented a placeholder, so agreement could not prove identity. Receipt v2 has not been regenerated.
  6. The has?(map, borrow) disagreement was a stale pin. A later trunk repair already taught the inspection path to peek borrowed values with zero promotions. The proposed two-operand reader is still held for different reasons: LLVM-direct deep-copies its owned operand by 16 bytes per read, and two of six safety mutations are not yet caught.
One ledger caveat is itself red: legacy_local_set_ratchet is registered expected-green, but the source-only census in this archive exits 1. Total debt improved to 5,172 versus a 5,178 maximum, yet stdlib/HeyTokens.hey contains six pre-existing local set uses absent from the per-file baseline. Fix the ratchet's baseline and mutation logic; do not rewrite load-bearing tokenizer state merely to make the row green.

The complete restructure runway

The daily carries every rung, including those that did not move. “Green” below means the named foundation is protected; it does not imply that later authority or deletion work is complete.

Phase 1 — operator × position behavior 100 / 100

All one hundred operator-position cells remain the behavioral baseline across the protected lanes.

Runway 0–7 — schema, exact nodes, generated reads and one physical shape green

Stable node schema, exact-sized construction, generated compatibility APIs, generated readers/traversal and private n_ slot storage remain protected. Direct node construction and direct raw node reads remain at zero.

Runway 8A — indexed owned readers green

Stable field IDs and direct physical-slot reads are active. A stable index is not itself a borrow: owned APIs still clone values.

Runway 8B — scoped borrowed readers 151 / 188 sites

The C scope, generation-checked handle ABI, read-only inspections and covered Hey-owned lifetime behavior are green. Owned escapes are reconciled at 260/260.

All 37 compatibility sites are classified: 36 are blocked on named backend operations, one is correctly owned, none is currently migratable, and none is ambiguous. Eighteen depend on the proposed one-borrow/one-owned two-operand consumer. That consumer remains unmerged until its 16-byte LLVM operand copy is eliminated and all six safety mutations fail correctly.

Runway 9 — candidate source, tokens, final syntax and names sidecar

The candidate source manager, bounded tokenizer, generated final-syntax structures and name facts run after authoritative HIR. They are non-authoritative. Final-syntax freshness is currently a known red caused by Ruby 4.0.6 formatting an empty array differently despite normalized JSON identity.

Candidate cross-lane identity 3 of 5 unproven

Interpreter and Stage-0 agree byte-for-byte on candidate facts and authoritative HIR over 12 corpus rows; REPL agrees only on tokens. LLVM-direct and self-host stop at build status 70. The candidate cannot take authority until all applicable lanes and the corpus agree.

Runway 10 — scopes, imports, modules and receiver/operator resolution partial

Candidate name facts and module-closure machinery exist. Full authoritative resolution, complete MIR call closure and the guarantee that missing imports fail at the correct phase remain open.

Runway 11 — structural HIR prototype prototype only

A generated structural HIR prototype cannot carry raw operand source and is protected by a gate. It is deliberately not authoritative, so this is a prototype green rather than an authority green.

Runway 12 — mechanical MIR and LLVM nine families

The Hey-owned emitter is still incomplete. Current explicit reds include integer division and modulo falling back to the legacy direct-MIR consumer, boxed-key has? rendering 1/0 instead of booleans, and the nine carried-body capability families. The cheapest taxonomy proof is the loop-element binding family; recursive non-atomic operands should not go first because temporary numbering is byte-identity-sensitive.

Runway 13 — one semantic interpreter and REPL route future dependency

The interpreter and REPL still need to consume the same structural HIR semantics as compilation. Until then, lane-specific meaning remains possible and compile-first verification cannot fully replace the tree walker.

Runway 14 — authority, deletion and self-hosted release not eligible

Authority remains off. The switch requires borrowed-reader cutover, five-lane candidate identity, zero unintended fallback, product receipts, linear copy behavior and a new authoritative-HIR receipt. Only after those gates can compatibility paths and old frontend semantics be deleted.

The zero-copy program is only partly won

Today's collection-take and integer-unboxing repairs are important because they remove concrete full-rebuild and boxing mechanisms. They do not prove that Hey has reached its intended data-movement model.

ONE immutable payload backing store, inside one process
        │
        ├── read / compare / pass / return     → borrow, handle, or refcount bump
        ├── same-process actor send            → ownership transfer or shared backing
        ├── unique update                      → reuse storage behind immutable semantics
        ├── shared update                      → detach once or copy only the changed path
        └── process / network / persistence    → explicit, measured serialization

The frontend scaling target remains red at a 2.288 copied-work ratio for the last doubling. Cursor tokenization and copy-on-write can make clone-call counts look linear while immutable strings still deep-copy their bytes. The next meaningful runtime step is refcounted immutable string/byte backing, followed by actor-send and retained-history proofs—not a shorter sweep or a looser threshold.

Beyond R8: what this work is for

Retiring compiler debt is not the product. The product is one readable language pipeline that can build real applications without making users pay for redundant copies:

  • one source/import graph becomes tokens, final syntax, resolved names, structural HIR, ABI-explicit MIR, mechanical LLVM and a native executable;
  • values are immutable by default, actors own state explicitly, and same-process messages share or transfer payloads instead of deep-copying them;
  • CLI programs, web applications, iOS, Android and AppleTV packages exercise the same semantics;
  • Ruby-like source remains readable while generated code and runtime data movement approach C-like cost;
  • the shipped toolchain is self-contained, reproducible and fast enough that developers do not need to understand its caches to trust it.

Glossary

ABI
Application Binary Interface: the exact machine-level types and calling convention shared by a caller and callee.
Authority
The compiler path whose output determines what ordinary Hey programs mean. The candidate frontend currently has 0% authority.
Borrow
A temporary, non-owning view of a value that cannot outlive its scope unless explicitly promoted.
Boxed / unboxed
A boxed scalar lives in a general runtime value container; an unboxed scalar stays in its direct machine representation such as i64.
Candidate frontend
The new source, token, final-syntax and name pipeline running as a non-authoritative sidecar.
Compiler identity closure NEW
The transitive set of source and generated files, plus binaries and drivers, whose contents can change a compiled program and therefore must invalidate the run cache.
Covered self-host lifetime parity NEW
The measured lifetime properties are green through the Hey-owned emitter, while named exclusions prevent the broader word “full.”
COW
Copy-on-write: shared immutable backing is copied only when an update cannot safely reuse unique storage.
Corpus
The checked collection of compiler and application sources used for broad identity or compatibility sweeps.
Fallback
Selection of an older compiler consumer when the candidate path cannot lower a construct. It must be visible and counted.
Gate
An executable contract that passes or fails. A useful defect gate is first observed red, then green after the fix, then made red again by a controlled mutation.
HIR
High-level Intermediate Representation: the compiler's structural statement of program meaning after parsing and name resolution.
Lane
One execution route—interpreter, Stage-0, LLVM-direct, self-host, or REPL—or one isolated agent workstream.
Ledger
The checked-in list of expected-green and known-red gates. It is not a substitute for a fresh full-tier run.
MIR
Machine Intermediate Representation: explicit control flow, ownership and machine shapes consumed by LLVM emission.
Mirror
The Hey-owned LLVM emitter corresponding to behavior also present in the native compiler.
Owned
A value whose lifetime and release responsibility belong to the current holder; it may safely escape a temporary borrow scope.
Ratchet
A gate that permits debt to decrease but prevents it from silently increasing or returning.
Receipt
Machine-readable evidence recording source/compiler identity, route, cache state, fallback count and result.
R2–R8
The retirement rungs from narrowing heyc build through deleting native emitters/interpreters and reaching a thin launcher with zero semantic-debt files.
Scoped reader
A generated compiler-node read performed inside a bounded consumer so the field can be observed without cloning an owned snapshot.
Sidecar
A non-authoritative analysis that runs beside the current compiler and records facts without controlling output.
Stage-0
The native-C seed/reference backend retained for bootstrap and comparison while the Hey-owned pipeline matures.
Take collection, borrow value / wtakecoll NEW
A unique-update lowering that transfers the collection into an update helper while observing the incoming value without consuming it.
Unboxed integer element read / wunbox NEW
A typed array read that keeps an integer in machine form instead of allocating general runtime boxes around a simple arithmetic expression.
