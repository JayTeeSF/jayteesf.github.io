The parts of Hey, without the archaeology

If you are learning Hey today, this is the map that matters: what you write, what the runtime provides, and where the compiler is still being made honest. Hey is an immutable, actor-friendly language with static modules, a native compiler, packages, networking and a real distributed transport. The remaining hard work is mostly not new syntax — it is carrying the meaning the compiler already knows all the way to machine code.

language surface: substantialnative compiler: active convergence1BRC performance: opentvOS security boundary: closed
One sentence: Hey tries to give a dynamic-looking language a compiler that behaves like a serious static pipeline internally — names resolve once, values stay immutable to the programmer, ownership reuse is an optimization, and later stages should carry identities instead of guessing from strings.

What a Hey program is made of

Values

Integers, floats, booleans, strings, bytes, arrays, maps/JSON-shaped values and nil. Source semantics are immutable even when the compiler proves an update can safely reuse storage.

implemented

Functions

Named functions are the basic abstraction. Functions can travel as callable values, but Hey deliberately does not depend on hidden lexical-closure state for ordinary callbacks.

implemented

Modules

Modules, imports, aliases, selective exposure, concealment and dotted/qualified forms are resolved lexically. Imports are not runtime name searches.

implemented

Collections

Arrays, maps and higher-level collection operations are central to the language. Copy-on-write and ownership reuse are compiler/runtime mechanisms, not programmer-visible mutation.

implementedperformance active

Actors

Actors own state and communicate by messages. The runtime also has explicit IO ownership/transfer rules so sockets and streams can cross actor boundaries without pretending shared mutable handles are ordinary values.

implemented core

Distributed Hey

Remote calls/messages, TLS transport, incarnation/stale-node rejection and actor-oriented distributed examples exist. The current transport fails closed on an unknown mode instead of silently choosing plaintext.

transport realclustering later

Packages

Packages have manifests, content/archive digests, lockfile v2 and verification. The installer now writes a lock/receipt that its own verifier accepts instead of downgrading projects to an old format.

verified path

Apple targets

tvOS builds now exclude unavailable TLS/OpenSSL capabilities instead of linking fake security symbols. Supported Apple crypto uses platform APIs; unavailable crypto fails closed.

build/sign/install/launch proven

The compiler

The public direction is one Hey-owned compiler. Stage-0 C remains bootstrap machinery, not the semantic fallback the project wants normal builds to depend on.

identity handoff active

The programmer's mental model

The unusual part is not the syntax. It is the rule underneath: meaning should be decided once, then carried forward.

Modules are static, not magical

At source level

module Accounts
  fn deposit(account, amount)
    return {...account,
      balance: account.balance + amount}
  end

  exposes deposit forms: [:qualified, :dotted]
end

import './accounts.hey' as A

What the compiler should remember

Not “the text said A.deposit.” It should remember the resolved module/function identity chosen by the resolver. That distinction is now a live compiler correctness issue: two different units can each define helper, and source spelling alone cannot distinguish them.

Immutability does not mean copying everything

Hey's source model is immutable. The implementation is allowed to reuse storage when ownership proves no other live value can observe the update.

Source semanticsnext = put(map,k,v) creates the next value conceptually.
→
Ownership proofIf the old storage has one owner, reuse is legal.
→
RuntimeUpdate in place without changing observable language semantics.
Why this matters now: builtin put(map,k,v) already gets the flat reuse path; method map.put(k,v) currently misses the same semantic operation identity and clones the map. Same operation, different spelling, enormous cost.

The security rule is now simple: TLS failure is not permission to fall back to TCP, and an unknown transport mode is an error. Plain TCP remains an explicit development/testing choice.
