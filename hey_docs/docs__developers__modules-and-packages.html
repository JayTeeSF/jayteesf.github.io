Modules, imports, and public surfaces#

Hey modules are lexical and static. The resolver chooses every imported name, receiver call, and operator binding before HIR is produced. Runtime never repeats those choices.

A module declares its complete public surface#

module BankAccount
  fn new(owner, opening_balance)
    return {owner: owner, balance: opening_balance}
  end

  fn deposit(account, amount)
    return {...account, balance: account.balance + amount}
  end

  private fn valid_amount?(amount)
    return amount >= 0
  end

  exposes new forms: [:qualified]
  exposes deposit forms: [:qualified, :unqualified, :dotted]
end

A non-exposed binding is unavailable outside the module. Exposed functions may still call private helpers inside their module.

Each exposure records the public name, supported forms, optional operator symbol, and source location used by reflection and diagnostics.

Bare import means namespace-only access#

import './bank_account.hey'

program
  let account = BankAccount.new('Ada', 100)
  says BankAccount.deposit(account, 25).balance
end

Bare import does not inject every public name into the file.

as renames the module binding#

import './bank_account.hey' as Accounts

program
  says Accounts.new('Ada', 100).owner
end

as on the import renames the namespace. It has no second meaning.

exposing: adopts selected bindings#

import './bank_account.hey' exposing: [new, deposit]

program
  let account = new('Ada', 100)
  says account.deposit(25).balance
end

The selected exposure brings its supported forms into the current lexical scope. Narrow those forms explicitly:

import './bank_account.hey' \
  exposing: [deposit] \
  forms: [:dotted]

That file may write account.deposit(25) but not bare deposit(account, 25).

exposing: * adopts the module's complete public surface.

Alias one selected binding with old as new#

import 'stdlib:Json' exposing: [generate as stringify]

program
  says stringify({status: 'ok'})
end

Selector lists are compile-time literals. A runtime array cannot decide which names exist after compilation.

Remove adopted names with conceals:#

import 'stdlib:BuiltIns' conceals: [length]

conceals: removes selected adopted/default bindings from the current lexical scope. It does not make the declaration private in its defining module, and it does not remove qualified access.

Built-ins are the outer lexical surface of stdlib:BuiltIns, so they follow the same conflict and concealment rules as other imports.

Conflicts are lexical and visible#

Resolution follows two rules:

  1. an inner lexical scope beats an outer scope;
  2. within one scope, a later declaration/import beats an earlier one.

An override produces a warning with the winner, the shadowed declaration, and fixes such as module renaming, a narrower exposing: list, selector aliasing, or conceals:.

HIR stores the selected binding identity. Runtime does not search again.

Receiver calls are imported forms#

When deposit is exposed for dotted use:

account.deposit(25, 50)

resolves to:

deposit(account, 25, 50)

The receiver is always argument one. Every explicit argument stays in source order. Receiver chains resolve one segment at a time:

account.deposit(25).withdraw(10).current_balance()

is structurally equivalent to:

current_balance(withdraw(deposit(account, 25), 10))

When a dotted call could mean either a callable field or an imported receiver form, the same lexical nearest/latest rule selects the meaning and the compiler warns with both locations. Qualify or alias one candidate to make the intent explicit.

Operator exposure names a function and a fixed symbol#

module MathExtensions
  fn pow(base, exponent)
    # implementation
  end

  exposes pow forms: [:qualified, :unqualified, :infix] infix: '**'
end

The function keeps a pronounceable name. The symbol's spelling, precedence, associativity, and forms come from the language operator registry. A module may reuse an allowed symbol; it cannot invent new punctuation or change parse shape.

Re-export is explicit#

Importing a module never expands the importing module's public surface by accident. A facade re-exports deliberately:

module WebPrelude/Fast
  import 'stdlib:Web' exposing: [serve, route, response]
  import 'stdlib:Json' exposing: [parse, generate as stringify]

  exposes *
end

exposes * includes eligible public declarations and deliberate re-exports. It never leaks private helpers.

Facade modules are the reusable compile-time import mechanism:

import 'stdlib:WebPrelude/Fast' exposing: *

Import path forms#

import './local.hey'
import '../shared.hey'
import 'stdlib:Text'
import 'package:Module'
import 'stdlib:WebPrelude/Fast'

Local paths are source-relative. Standard-library, package, and slash-qualified facade identities are resolver-defined and validated against traversal and malformed segments.

Runtime module values are separate#

let plugin = Module.load(plugin_name)

Module.load(...) returns a runtime value. It cannot create identifiers, receiver forms, or operator bindings in already compiled lexical scope.
